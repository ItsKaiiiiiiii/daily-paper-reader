## 摘要
复杂任务通常分解为可并行化但相互依赖的子任务，使得编排对多智能体系统（MAS）的性能至关重要。现有的评估通常依赖于端到端执行，这混淆了编排计划质量与工作能力、工具可靠性和环境噪声。此外，实际执行的时间和令牌成本随工作流规模快速增长，使得系统评估变得昂贵。我们提出OrchBench，一个基于模拟的基准，用于隔离评估多智能体编排计划。从真实世界任务出发，OrchBench构建有向无环图（DAG），编码任务依赖关系，具有可控的大小和并行度。给定DAG、每个智能体的上下文限制和智能体预算，被评估的规划器将子任务分配给智能体，并指定跨智能体信息传输及其保留率。一个确定性模拟器评估生成的计划，无需调用工作智能体，并返回结果质量、完工时间和令牌成本的可解释度量。OrchBench生成的模拟分数与Claude Code执行的质量分数强烈相关，皮尔逊相关系数r=0.816，而仅需1.3%的令牌和10.3%的挂钟时间。在多种规划器和工作流规模中，我们发现保留任务关键信息比简单地增加智能体数量更重要，并且随着协调失败累积，并行性的收益会减少。这些结果确立了OrchBench作为比较和诊断多智能体编排计划的高效且可解释的基准。

## Abstract
Complex tasks often decompose into parallelizable yet interdependent subtasks, making orchestration critical to the performance of multi-agent systems (MAS). Existing evaluations typically rely on end-to-end execution, which conflates orchestration-plan quality with worker capabilities, tool reliability, and environmental noise. Moreover, the time and token costs of real execution grow rapidly with workflow scale, making systematic evaluation expensive. We present OrchBench, a simulation-based benchmark for evaluating multi-agent orchestration plans in isolation. Starting from real-world tasks, OrchBench constructs directed acyclic graphs (DAGs) that encode task dependencies, with controlled sizes and degrees of parallelism. Given a DAG, a per-agent context limit, and an agent budget, the evaluated planner assigns subtasks to agents and specifies cross-agent information transfers and their retention ratios. A deterministic simulator evaluates the resulting plan without invoking worker agents and returns interpretable measures of result quality, makespan, and token cost. The simulated scores produced by OrchBench correlate strongly with quality scores from Claude Code executions, achieving a Pearson correlation of \(r=0.816\), while requiring only \(1.3\%\) of the tokens and \(10.3\%\) of the wall-clock time. Across diverse planners and workflow scales, we find that preserving task-critical information is more important than simply increasing the number of agents, and the benefits of parallelism diminish as coordination failures accumulate. These results establish OrchBench as an efficient and interpretable benchmark for comparing and diagnosing multi-agent orchestration plans.

- **核心问题**：多智能体系统（MAS）的性能高度依赖于**编排策略**（orchestration strategy），即如何将工作流组织到多个智能体之间。然而，现有评测大多采用**端到端执行**，导致编排质量与工作能力、工具可靠性、环境噪声等因素混在一起，无法孤立评估编排计划本身的好坏。此外，端到端执行随着工作流规模增长，时间和 token 成本迅速上升，难以进行系统的对比研究。
- **整体含义**：本文提出 **OrchBench**，一个基于确定性模拟的基准，旨在**隔离评估编排计划**，通过轻量模拟代替真实执行，实现快速、低成本、可重复的评估，从而揭示编排策略的真正瓶颈。

## 2. 方法论

### 核心思想
- 将编排评估与执行解耦：给定一个任务 DAG（有向无环图），让规划器生成编排计划（子任务分配到智能体、指定跨智能体信息传输及压缩比率），然后用**确定性模拟器**代替真实智能体执行，评估计划的质量、完成时间和 token 成本。
- 模拟器不调用任何工作模型，完全基于任务元数据和规则计算，从而去除 worker 能力、工具可靠性等干扰。

### 关键技术细节
1. **DAG 构建**：从真实种子任务（来自 Finance Agent、DS-1000、Qasper、BIRD-SQL）出发，通过 LLM 驱动的精炼循环生成具有可控子任务数量（10~1000）和自然并行度（k99/n）的 DAG。
2. **编排计划**：规划器输出一个 `workflow_script`（JSON格式），定义智能体池、匹配规则、分配策略和跨智能体传输规则（含压缩比率）。模拟器将脚本展开为具体的分配和传输方案。
3. **确定性模拟**（算法流程）：
   - 初始化每个智能体的时钟和内存。
   - 按拓扑顺序处理每个子任务：
     - 等待所有父任务完成且智能体空闲。
     - 收集父任务结果：同智能体直接复用；跨智能体则检查声明的传输，若缺失则标记缺失事件并乘以惩罚因子 λ。
     - 添加输入上下文到智能体内存；若超出上下文限制 L，则压缩内存中的包（记录质量损失和时间成本）。
     - 执行子任务（读取预设的时间、token、质量函数），计算产出质量。
     - 更新智能体状态，释放不再需要的父包。
   - 所有子任务完成后的质量 Q = 终端任务质量的宏平均；综合分数 = (Q + 速度效率 + token效率) / 3。

## 6. 主要结论与发现

1. **保留关键信息比增加智能体数量更重要**：在 100 子任务规模下，智能体数量与质量几乎无关（Pearson r = -0.021），而传输覆盖率与质量正相关（0.614~0.952）。更多智能体不能弥补未传递关键依赖的缺陷。
2. **并行性收益随协调失败累积而递减**：大规模 DAG（500→1000）下，Claude 和 DeepSeek 的传输覆盖率大幅下降（0.981→0.4），产生数百个缺失传输，质量严重受损。
3. **智能体可用性遵从边际递减**：增加 Amax 从 16 到 64 几乎不改善最终分数，说明超过一定数量后协调开销超过并行收益。
4. **多智能体 vs 单智能体取决于上下文压力**：当上下文限制较紧（16k）时，多智能体避免单一 agent 的过度压缩，质量提升显著（+0.302）；当上下文足够大（128k）时优势消失，多智能体可能因协调开销反而更差。
5. **模拟能高效筛选编排方案**：仅需 1.3% token 和 10.3% 时间即可达到与真实执行高相关性（r=0.816），可用于预算有限的模型排名（Spearman 0.754）。

## 7. 优点

- **方法论创新**：首次将编排规划与执行解耦，通过确定性模拟独立评估编排质量，避免了噪声干扰。
- **高效可扩展**：模拟比真实执行快 10~100 倍，token 消耗低，支持大规模（1000 子任务）系统性分析。
- **可解释性强**：模拟器明确输出缺失传输次数、压缩事件等诊断指标，可直接指导工作流改进（实验证明通过添加缺失手递可提升真实执行分数）。
- **跨框架稳健**：模拟分数与 Claude Code、SWE-mini、OpenHands、Crush 四种真实框架均正向相关，表明基准不依赖特定实现。
- **完备的验证**：包括结构对齐（智能体数量、并行度等）和结果对齐（最终质量），并经过留一模型、消融实验等稳健性检验。
- **机制设计合理**：引入压缩敏感性（robust/balanced/fragile）和上下文管理，模拟真实场景中的信息损耗，且消融证明这些机制是模型区分度的关键。

## 8. 不足与局限

- **实验局限**：
  - 未涵盖更多类型的任务（如机器人控制、多轮对话、工具链场景），种子数据集有限（4个来源）。
  - DAG 生成依赖 LLM，存在质量波动（约 34% 的生成 DAG 被拒绝），可能引入偏差。
  - 对任务难度估计时，仅使用了 5 个高分歧任务进行模型排序验证，小样本可能不稳健。
- **模拟局限**：
  - 时间与 token 的模拟与实际执行相关性较低（表 2 中时间 r=-0.264，token r=-0.607），说明这些维度受框架调度影响大，模拟精度有限。
  - 模型忽略真实环境中的网络延迟、重试、错误传播等细节，可能高估或低估某些编排策略。
  - 缺失传输的惩罚因子 λ 固定为 0.5，不同任务最佳值可能不同。
- **应用限制**：
  - 当上下文限制极大（>128k）时，多智能体优势消失，但 OrchBench 未覆盖更长的上下文场景。
  - 没有考虑动态任务分解（论文假设 DAG 固定），对动态编排场景不适用。
  - 规划器必须输出结构化的 workflow_script，对开放式提示模型可能存在转换偏差。
