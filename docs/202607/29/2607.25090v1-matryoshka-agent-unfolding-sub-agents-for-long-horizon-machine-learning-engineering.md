## 摘要
机器学习工程(MLE)任务需要迭代式解决方案调试与改进中的长周期决策，且环境交互成本高、依赖反馈。为此类任务开发并训练单一代理从根本上充满挑战，因为它必须同时管理极长且嘈杂的上下文、探索庞大的解决方案空间，并在有限的模型容量和计算预算下保持有效性。为应对这些挑战，我们提出Matryoshka Agent，一个用于复杂长周期任务的统一分层代理框架。Matryoshka Agent将代理问题求解分解为协调的决策与执行层次：高层 Orchestrator 维护紧凑的长周期探索状态并发出策略指令，而低层 Sub-Agents 通过标准化的 Tool 接口直接与环境交互执行具体解决方案尝试。该设计将策略探索与昂贵执行解耦，显著减轻了长上下文推理的负担，并实现了高效的迭代改进。我们进一步为Matryoshka Agent开发了高效的训练范式。在多种模型类型和规模的广泛MLE任务上的实验结果表明，Matryoshka Agent是长周期MLE任务和复杂代理问题求解的一种有效且可扩展的范式。值得注意的是，Matryoshka Agent使Qwen3-4B-Instruct达到了与o4-mini相当的Orchestrator性能。将Matryoshka Agent应用于Qwen3-30B-Coder，相对性能提升高达36.7%。

## Abstract
Machine learning engineering (MLE) tasks require long-horizon decision making over iterative solution debugging and refinement, under expensive and feedback-driven environment interactions. Developing and training a monolithic agent for such tasks is fundamentally challenging, as it must simultaneously manage extremely long and noisy contexts, explore vast solution spaces, and remain effective under limited model capacity and computational budgets. To address these challenges, we propose Matryoshka Agent, a unified hierarchical agent framework for complex long-horizon tasks. Matryoshka Agent decomposes agentic problem solving into a coordinated hierarchy of decision making and execution: a high-level Orchestrator maintains compact, long-horizon exploration states and issues strategic instructions, while lower-level Sub-Agents execute concrete solution attempts through direct environment interaction, mediated by standardized Tool interface. This design decouples strategic exploration from costly execution, substantially reducing the burden of long-context reasoning and enabling efficient iterative refinement. We further develop an efficient training paradigm for Matryoshka Agent. Experimental results on a broad range of MLE tasks with diverse model types and scales demonstrate that Matryoshka Agent is an effective and scalable paradigm for long-horizon MLE tasks and complex agentic problem solving. Notably, Matryoshka Agent enables Qwen3-4B-Instruct to reach Orchestrator performance comparable to o4-mini. Applying Matryoshka Agent to Qwen3-30B-Coder results in at most 36.7% relative performance gain.

- **挑战**：传统的**单一 agent（monolithic agent）** 在处理此类任务时面临三大根本困难：
  - 长上下文管理：每次交互产生的日志、中间输出和调试反馈会不断累积，导致上下文极度冗长且嘈杂。

  - 昂贵的交互成本：执行代码、训练模型、获取反馈均耗费大量时间与计算资源，限制了探索和训练。
- **研究意义**：提出一种通用的**层次化 agent 框架**来应对上述挑战，使较小模型也能通过协作达到甚至超越大模型的性能，从而降低对前沿大模型的依赖，提升长周期 MLE 任务的可行性和可扩展性。

## 2. 方法论：核心思想、关键技术细节、公式或算法流程

### 2.1 核心思想：层次化解耦

Matryoshka Agent 将 agent 系统分为三层：
- **Orchestrator（指挥层）**：维持一个紧凑的跨轮状态（包含历史指令摘要、结果和评分），负责决定下一步探索或改进哪个方向，不直接接触原始代码和完整日志。
- **Sub-Agent（执行层）**：每次以全新上下文实例化，负责具体实现、运行和调试一次解决方案尝试，与环境直接交互。
- **Tool（工具层）**：作为中间层，将 Orchestrator 的指令格式化为 Sub-Agent 的上下文，注入参考历史，启动 Sub-Agent 并返回结构化摘要和分数。

这种设计将**战略探索**与**具体执行**解耦，大大减轻了长上下文推理负担，同时保留了迭代优化的关键信息。

### 2.2 关键技术细节

- **Orchestrator 决策**：每轮指定三要素：
  1. **父尝试**（要改进的上一轮方案）
  2. **实现指令**（详细的建模、预处理、超参数等）
  3. **参考标签**（可选择性引用先前方案）
- **Tool 执行**：构建 Sub-Agent 上下文，管理其与环境交互的生命周期，最终返回（分数 + 摘要）。
- **Sub-Agent 执行**：在本地执行-调试循环中，最多进行 10 次调试；若成功则返回分数，失败则标记为无效。

### 2.3 训练范式：Solution Refinement Tree + 在线强化学习

**训练时构造 Solution Refinement Tree**：
- 从根状态开始，Orchestrator 采样两条不同的改进指令（二进制分支），各执行一次，产生两个孩子节点。
- 扩展多层，形成树结构，每个节点带有分数。

**偏好构建（Preference Construction）**：
- 对于每个内节点 u，将其两个子分支的**下游最大回报** R(c) = max_{v ∈ subtree(c)} r(v) 作为分支优劣的标签。
- 下行回报更高的分支被视为偏好分支，另一分支为非偏好分支。
- 这种方式保留了长周期优化目标（最好分数），且产生多个共享前缀的对比对。

**在线强化学习损失函数**：
- 基于能量形式的策略 π*(Δτ|s_u) ∝ π^(m)(Δτ|s_u) * exp( (1/β) r(s_u,Δτ) )。
- 使用排名式 NCE 目标：
  ```
  L_orch = -E_u [ log exp(rθ(s_u,Δτ_u^+)) / Σ_{Δτ∈C(u)} exp(rθ(s_u,Δτ)) ]
  ```
  其中 rθ(s_u,Δτ) = β log (πθ(Δτ|s_u) / π^(m)(Δτ|s_u))。
- 该目标使新策略在每轮更新中保持接近旧策略（KL 约束），同时鼓励偏好分支的概率更高。

**Sub-Agent 自我强化**：
- 从树中最高分的路径提取 Sub-Agent 的成功轨迹，进行监督微调（SFT），提升其指令遵循和调试能力。

## 6. 主要结论与发现

1. **层次化框架有效**：Matryoshka Agent 在几乎所有配置上都显著优于对应的单体 Dojo Agent。例如，o4-mini 从 0.4832 提升到 0.5465；Qwen3-30B-Coder 从 0.3302 提升到 0.4515（含 RL）。
2. **小模型可媲美大模型**：Qwen3-4B-RL 作为 Orchestrator 配合 o4-mini Sub-Agent 达到 0.5360，接近 o4-mini 作为 Orchestrator 的性能（0.5465），说明 RL 训练可使小模型具备优秀的决策能力。
3. **SFT 和 RL 均带来增益**：SFT 提供显著提升（例如 Qwen3-30B-Coder-SFT + self 达到 0.4197），RL 进一步改善（0.4515）。无 SFT 直接 RL 效果有限（0.3901）。
4. **Plug-and-Play 能力**：训练后的 Orchestrator（如 Qwen3-4B-RL 或 Qwen3-30B-Coder-RL）可与未在训练中见过的 Sub-Agent（如 GPT-5-nano）配合，并仍能带来性能提升。
5. **上下文管理优势**：Orchestrator 的上下文增长斜率（约 1202 tokens/轮）远小于 Dojo Agent（约 1870 tokens/轮），而 Sub-Agent 上下文恒定，从而支持更长的交互轮次（约 213 轮 vs 137 轮）。
6. **指令长度演化**：对于小模型（Qwen3-4B），RL 促使指令变长以补偿 Sub-Agent 的不足；对于大模型（Qwen3-30B-Coder），RL 后指令长度稳定，得益于 Sub-Agent 同时被训练，指令遵循能力提升。

## 7. 优点

- **创新性架构**：将决策与执行解耦，减少上下文负担，提升长周期可扩展性。
- **高效的训练范式**：Solution Refinement Tree 共享执行前缀，产生结构化偏好信号，结合在线 RL 使训练高效且稳定。
- **模型无关性**：适用于多种模型大小（4B 到闭源前沿模型），且 Orchestrator 训练后可即插即用。
- **实验设计全面**：涵盖多种组合、消融、案例分析和量化分析，验证了不同组件的贡献。
- **实用价值**：使小模型也能承担高复杂度的 MLE 任务，降低了对昂贵大模型的依赖，具有实际部署意义。

## 8. 不足与局限

- **基准单一**：仅在 MLE-Dojo 上评估，未在其他长周期 agentic 任务（如 SWE-bench、WebArena、AutoML 等）上验证泛化性。
- **Sub-Agent 能力瓶颈**：当 Sub-Agent 模型规模太小（如 Qwen3-4B）时，即使 Orchestrator 给出详细指令，执行仍可能失败（见附录 E），说明框架对 Sub-Agent 能力有一定下限要求。
- **训练成本高昂**：虽然训练样本收集利用了树结构，但仍需要实际执行多次代码（每次执行可能耗时数小时），且 RL 训练需要多次环境交互，计算资源需求高。
- **上下文截断策略简单**：对超过 5k tokens 的环境输出仅保留首尾各 2.5k，可能导致中间关键调试信息丢失。
- **缺乏与其他层次化 agent 框架的直接对比**：论文仅对比了单体 agent（Dojo Agent），未与其他类似的层次化或模块化 agent（如计划-执行分离的其他工作）进行定量比较。
- **随机性方差**：虽然采用了 best-of-three，但每任务中位标准差约 0.07，说明单次运行结果有一定波动，可能需要更多运行次数以提高稳定性。
