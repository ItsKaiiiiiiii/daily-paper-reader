## 摘要
基于大语言模型（LLM）的多智能体系统通过编排多个智能体的配置与协作方式来应对复杂推理。核心挑战在于如何让编排适应不断演化的协作状态。仅基于查询的路由无法适应中间进展或错误，这会损害准确性。基于完整执行历史的路由虽然提供了缺失的上下文，但迫使后续决策处理每一个先前步骤，包括冗余或低效用的步骤，从而造成执行历史过载，推高成本。有效的编排反而需要一个紧凑的状态，在捕获有用进展的同时不累积冗余上下文。我们提出门控记忆路由，将每个决策都基于查询和已习得的执行记忆。习得的记忆写入门只提交非冗余的推理步骤，习得的检索门为每个智能体提供紧凑的相关子集，因此每个决策都基于干净、信息丰富的状态。在每一步中，系统从该记忆中选择下一个角色和骨干模型，同时自适应停止控制器在记忆包含足够证据用于回答时停止执行。在五个推理和代码生成基准上，我们的框架既有效又高效：它达到了最佳平均准确率，比最强基线高出2.44个百分点，同时相较该基线将HumanEval的推理成本降低了31.9%。代码可在 https://github.com/rajibrhasan/gated-memory-routing 获取。

## Abstract
Large language model (LLM)-based multi-agent systems tackle complex reasoning by orchestrating how multiple agents are configured and how they collaborate. A central challenge is to adapt orchestration to the evolving collaboration state. Routing from the query alone cannot adapt to intermediate progress or errors, which hurts accuracy. Routing from the complete execution history supplies this missing context, but forces later decisions to process every prior step, including redundant or low-utility ones. This creates an execution-history overload that inflates cost. Effective orchestration instead requires a compact state that captures useful progress without accumulating redundant context. We propose Gated-Memory Routing, which conditions each decision on the query and a learned execution memory. A learned Memory Write Gate commits only non-redundant reasoning steps, and a learned Retrieval Gate supplies each agent a compact, relevant subset, so every decision conditions on a clean, informative state. At each step, the system selects the next role and backbone from this memory, while an Adaptive Halting Controller stops execution once the memory contains sufficient evidence for answering. Across five reasoning and code-generation benchmarks, our framework is both effective and efficient: it attains the best average accuracy, exceeding the strongest baseline by 2.44 points, while reducing HumanEval inference cost by 31.9% relative to that baseline. Code is available at https://github.com/rajibrhasan/gated-memory-routing

## 一、核心问题与整体含义

### 研究动机
- 基于大语言模型的多智能体系统（Multi-agent LLM Systems）通过分解任务、让多个智能体各自承担专业化角色（如求解、批判、验证）来提升复杂推理与代码生成能力，其性能**不仅取决于底层LLM本身，更依赖于协作编排（orchestration）**——即调用多少个智能体、分配什么角色、用什么骨干模型、提供什么上下文。
- 上述决策构成 **"路由问题"（routing problem）**。当前路由策略有两个对立范式，各有缺陷：

| 路由范式 | 问题 |
|---------|------|
| **仅依赖查询路由（Query-only）** | 在推理发生前就固化所有决策，无法根据中间进展、错误或新出现的信息修正路线，损害准确率 |
| **依赖完整执行历史路由（Full-history）** | 每一步决策都必须处理不断增长的、未过滤的完整轨迹，混合大量冗余或错误推理内容，导致**"执行历史过载"（execution-history overload）**，上下文长度和推理成本急剧膨胀 |

### 核心问题
- **有效的编排应依赖一个紧凑的、可学习的执行状态（compact learned state）**，既能捕获有用的中间进展，又避免累积冗余上下文。作者将其凝练为三个耦合问题：**学习保留什么（write）、学习呈现什么（retrieve）、学习何时停止（halt）**。

## 二、方法论

### 核心思想
- 提出 **Gated-Memory Routing（门控记忆路由）**：将路由条件从"查询"或"原始历史"转向一个**可学习的、经过门控的执行记忆 St**。
- 在每个决策步骤 t，状态定义为 st = (q, St−1)，其中 St−1 为经门控筛选后保留的执行记录集合。路由决策基于这一"干净、有信息量"的状态进行。

### 系统组件与流程
系统由一个联合训练的中央路由控制器和若干互补组件构成，每步执行以下流程：

1. **History-Aware Role Allocator（历史感知角色分配器）**
   - 从 st 中选择下一步的智能体专业化角色 rt ∈ R。
   - 角色通过 VAE 编码为连续潜在嵌入，采用 Softmax 随机策略：`πr(ri | st) ∝ exp(cᵀᵢ rᵢ)`。

2. **LLM Router（骨干模型路由器）**
   - 结合当前角色与状态选择骨干模型 mt ∈ M（共5个模型）。
   - 每个 LLM 用其自然语言能力描述经 VAE 编码为连续向量，策略：`πm(mi | st, rt) ∝ exp(uᵀmi)`。

3. **Retrieval Gate（检索门控）**
   - 独立判断每条已存记忆是否应被呈现给当前智能体，避免全量上下文暴露。
   - 对记录 j 的检索决策为伯努利采样：`zt,j ~ Bernoulli(σ(ℓt,j))`，其中 ℓt,j 为当前步骤检索向量与存储记录向量的相似度。
   - 检索子集 Ct 的大小可自适应（零条到全部）。

4. **Agent Execution（智能体执行）**
   - 选定的角色、模型与检索上下文共同生成推理步骤 yt。

5. **Memory Write Gate（记忆写入门控）**
   - 判断新记录是否进入记忆：只写入**任务相关且不冗余**的步骤。
   - 基于学习版 MMR（最大边际相关）评分：`ωt = λ·sim(yt, ct) − (1−λ)·max_j sim(yt, yj)`，其中第一项为相关度、第二项为与已有记忆的最大冗余度。
   - 写入决策通过伯努利采样完成：`wt ~ Bernoulli(σ(ωt))`。
   - 第一个记录仅凭相关度写入（记忆为空时省去冗余项）。

6. **Adaptive Halting Controller（自适应停止控制器）**
   - 通过 GRU 累计记忆状态变化：`h_haltt = GRU(h_haltt−1, enc(St))`，再采样停止动作 `ht ~ Bernoulli(σ(MLP(h_haltt)))`。
   - 每步结束后判定记忆是否已含足够证据；只需至少执行一个智能体（上限深度 ϕ = 6）。

7. **Aggregator（聚合器）**
   - 停止后，将门控记忆送入聚合 LLM（使用轨迹中出现频率最高的骨干模型）生成最终答案。

### 训练目标
- 所有策略以 **GRPO（组相对策略优化）** 风格联合训练：对每个查询采样 G = 6 条轨迹，以组内平均效用为基线，去掉标准差归一化以避免奖励近乎相同时数值不稳定。
- 轨迹效用：`ui = Ri − λc·Cost(τi)`（准确率与推理成本的加权折中）。
- 损失含熵正则项与 VAE 重构/KL 正则项。
- LLM 骨干与句子编码器全程冻结，仅训练路由参数。

## 六、主要结论与发现

1. **综合性能最优**：在所有5个基准宏平均上，Gated-Memory Routing 准确率达 **77.73%**，为所有方法中最高，超过最强基线 Puppeteer-32B（75.29%）**2.44 个百分点**，并在 MATH、GSM-Hard、HumanEval、MMLU-Pro 上取得第一。
2. **成本显著更优**：HumanEval 上较 MASRouter 成本低 **43.86%**，较 Puppeteer-32B 低 **31.9%**，且两者准确率更高——形成"精度与成本同时改善"而非此消彼长的局面；GSM-Hard 呈现一致趋势。
3. **消融发现分工清晰**：
   - **准确率主要由路由决策驱动**：去掉 LLM 路由器（随机选择骨干）最致命（GSM-Hard 下降14点）；角色分配器也贡献稳定但较小的增益；
   - **两个记忆门控都服务准确率**：去掉任一或两个都会使精度下滑（去掉双门控在 GSM-Hard 降2.56点、HumanEval 降6.25点），说明干净的记忆状态让路由和智能体都受益；
   - **停止控制器是成本关键杠杆**：去掉它是唯一一项导致成本激增 40%（GSM-Hard）到超过 100%（HumanEval）的决策，同时精度也下降。
4. **最大深度 ϕ 的收益快速饱和**：ϕ=6 位于拐点附近，ϕ 增至 10 只多增加不到 1 个准确率点，成本却持续爬升。
5. **路由范式对比结论**：门控记忆与完整历史路由准确率大致相当（70.55 vs 70.27 / 89.84 vs 89.06），但成本低约 40%–50%；仅查询路由准确率最差。**"记忆策展在保留精度同时大幅降本"是全文核心实证发现。**

## 七、方法的优点

1. **问题定义精准、动机有力**：清楚识别出"仅查询"与"全历史"两种极端范式的对称缺陷，并据此提出中间路线（选择性记忆），概念上有说服力。
2. **系统设计完整且组件间配合紧密**：写入门控解决"记忆质量"，检索门控解决"上下文精简"，两者互补而不过度重叠——写入门控抑制跨记录冗余、检索门控独立评分，逻辑自洽。
3. **角色与模型的可扩展表示**：用 VAE 将角色/模型的自然语言描述编码为连续潜在向量，而非固定类别标签，使系统可平稳扩展新角色/新模型，接口开销小。
4. **训练目标与决策结构匹配良好**：对组合式离散决策使用 GRPO 策略梯度；引入组内去均值的 advantage 且刻意省略标准差归一化并给出合理理由；所有组件在同一目标函数下联合优化。
5. **对成本建模较为审慎**：以参数规模为硬件无关的每 token 相对成本代理，并在附录用 FLOPs 与真实墙钟时间交叉验证，结果排序一致；同时明确承认成本代理的边界。
6. **门控行为有实证验证**：测试时写入率处于 (0,1) 区间、检索比例随记忆增长递减而非坍缩于全取或全弃，回答了"门控是否学到有意义行为"的关键质疑。
7. **消融干净利落地呈现了系统的"分工地图"**：不同模块对精度与成本的差异化贡献一目了然，使结论具有很强的可解释性。
8. **角色集鲁棒性验证**：将 26 个角色减半后重训，性能几乎不变，证明方法不强依赖于精心设计的角色集合。

1. **任务范围受限**：只用闭合领域、可自动验证答案的任务。开放文本生成需要奖励模型或人工评估，重要但尚未覆盖。
2. **骨干模型池时间窗口老**：只测试 Qwen2.5、Llama-3、Mistral Nemo 系（3B–32B），未涵盖更新的 Llama-4、Qwen3 等，外部效度（generalizability）随时间推移有限。
3. **算力与训练基础设施信息缺失**：相比 MASRouter / Puppeteer 的对比与路由开销、训练时间、完整 FLOPs 数据，论文**未报告 GPU 型号、卡数、训练时长**、具体超参敏感度等，复现成本较高。
4. **附录的实测（FLOPs/墙钟）只覆盖两个数据集**（HumanEval 和 MBPP），主文其余基准以端到端成本报告。

### 方法与评估方面的局限
5. **"冗余"判定的覆盖度有限**：写入门控的相似性基于句子嵌入（MiniLM），复杂的语义冗余（不同表述但同为错误推理）可能逃过过滤；检索门控的二元独立性决策也受嵌入质量上限约束。
6. **对单点基线公平性存疑**：三个训练种子只有三个方法运行；AFlow、MacNet 等一类方法只报告单次运行。
7. **GRPO 组均值 advantage 的偏差风险**：省略标准差归一化有理由，但 G=6 的组规模较小，对于困难或容易题的分布偏移仍存在组内方差估计器偏差的可能。
8. **MBPP 结果未全面占优**：MacNet-Chain-14B 在该数据集 pass@1 高于我们的方法 3 个点，论文解释是任务短且均匀，这提示自适应编排在短而直接的任务上收益有限。
9. **写入门控使用 MMR 风格的可学习相似性**，但作者没有单独验证学到的是否偏向相关而非新颖（或相反），其权重 λ 的行为仍可从门控综合统计中进一步拆解。

### 实际应用限制
10. **训练需要逐查询多 rollout 调用 LLM**，初始训练成本显著。
11. **有效性与训练目标强绑定**：本框架的性能锚定在"可自动计算二元成功奖励"的任务上，若未来扩展至开放场景需要新的奖励设计。
12. **所有方法均由 3B–32B 规模模型驱动**，未验证云 API（数百B级）场景下的泛化，路由决策空间与成本结构差异较大。
