## 摘要
自我进化智能体通过根据环境反馈优化其工具链——提示、技能、工具和执行逻辑——来推进自主性。然而，这一范式受到三个挑战的阻碍：\textit{信用分配失败}，即最终的成败反馈使得难以判断哪一步导致了错误；\textit{捷径学习}，即智能体记忆任务特定模式而非获得可泛化的能力；以及\textit{灾难性遗忘}，即不加防护的更新会降低先前获得的能力。在本文中，我们介绍了HarnessEvolve，一个从参考轨迹中学习以实现可靠智能体自我进化的自我进化框架。HarnessEvolve将执行智能体与进化流程解耦，将执行、评估、优化和门控分配给独立的智能体模块，从而实现可泛化且稳定的工具链改进。具体而言，HarnessEvolve通过生成参考轨迹（在给定正确答案时产生的执行路径）并将失败执行与其对齐以提取错误信号，从而克服了信用分配失败问题；这些错误信号经过聚类以揭示系统性的失败模式。为防止捷径学习和灾难性遗忘，候选工具链更新必须通过两道门：质量门，用于过滤数据泄漏和提示膨胀；以及性能门，仅在更新能改善当前批次且不降低最近批次性能时接受该更新，并在保留集上通过周期末验证选择表现最佳的被接受智能体快照。我们在涵盖开放领域和企业场景的多个基准上进行了广泛实验，使用了不同模型和智能体框架。结果表明，HarnessEvolve在所有基准和设置中均持续优于最先进的基线，证实了其在任务领域中的可靠性。

## Abstract
Self-evolving agents advance toward autonomy by optimizing their harness---prompts, skills, tools, and execution logic---based on environmental feedback. This paradigm, however, is hampered by three challenges: \textit{credit assignment failure}, where terminal success/failure feedback makes it ambiguous which step caused the error; \textit{shortcut learning}, where agents memorize task-specific patterns rather than acquire generalizable capabilities; and \textit{catastrophic forgetting}, where unguarded updates degrade previously acquired competence. In this paper, we introduce HarnessEvolve, a self-evolving framework that learns from reference trajectories to achieve reliable agent self-evolution. HarnessEvolve decouples the execution agent from the evolutionary pipeline, assigning execution, evaluation, optimization, and gating to independent agent modules, enabling generalizable and stable harness improvements. Specifically, HarnessEvolve overcomes credit assignment failure by generating reference trajectories (execution paths produced when given the ground-truth answers) and aligning failed executions against them to extract error signals, which are clustered to reveal systematic failure patterns. To prevent shortcut learning and catastrophic forgetting, candidate harness updates must pass two gates: a quality gate that filters data leakage and prompt bloat, and a performance gate that accepts each update if it improves on the current batch without degrading recent batches, with epoch-end validation on a held-out set selecting the best-performing accepted agent snapshot. We conduct extensive experiments on several benchmarks spanning open-domain and enterprise scenarios, using different models and agent frameworks. Results demonstrate that HarnessEvolve consistently outperforms state-of-the-art baselines across all benchmarks and settings, confirming reliability across task domains.

# HarnessEvolve 论文总结

## 1. 论文的核心问题与整体含义（研究动机与背景）

智能体（Agent）的发展正从依赖人类设计的静态流程，逐步向**自我进化（Self-Evolution）** 方向演进：智能体通过环境反馈自主优化其"harness"——即提示（prompts）、技能（skills）、工具（tools）与执行逻辑（execution logic）的集合。然而，作者指出当前自我进化范式在实际部署中面临三大核心挑战：

1. **信用分配失败（Credit Assignment Failure）**：在长程任务中，智能体只能获得终局的二元成败信号，无法精准定位到底是哪一步中间动作导致了失败。若仅对整个失败轨迹进行反思，容易误判错误的根本原因，导致优化方向失灵。
2. **捷径学习（Shortcut Learning）**：缺乏防护机制时，智能体倾向于将答案硬编码、或向 harness 中注入大量针对特定任务（甚至特定训练题）的上下文示例，造成数据泄漏（data leakage）和提示膨胀（prompt bloat），表面提升训练精度却无真实泛化能力增益，实则过拟合于评测实例。
3. **灾难性遗忘（Catastrophic Forgetting）**：每次 harness 更新只针对某一批轨迹数据优化，可能与先前已习得的能力冲突，经过多轮迭代后逐渐破坏原有能力。

这些挑战无法仅靠设计又一个迭代式提示优化算法来解决，而是需要一个**系统级的架构变革**——这正是论文提出 **HarnessEvolve** 的出发点。HarnessEvolve 的核心思路是：从**参考轨迹（reference trajectories）**——即给智能体提供正确答案后所产生的执行路径——中学习，使智能体自我进化过程具备可诊断、可筛选、防退化等可靠性保障。

## 2. 论文提出的方法论

### 2.1 核心思想：多智能体模块解耦

HarnessEvolve 将执行智能体与进化流程**解耦**，把完整的自我进化流水线划分为四个独立模块：

- **A_exec（执行智能体）**：被优化的目标对象，使用当前 harness 运行任务。
- **A_eval（评估智能体）**：在执行过程中评判任务准确率；在参考轨迹生成阶段验证轨迹的真实性（防止智能体利用已知答案"抄近路"）。
- **A_opt（优化智能体）**：对失败轨迹进行诊断、聚类错误、生成候选 harness 修改方案。
- **A_gate（门控智能体）**：对候选更新执行质量检查（数据泄漏与提示膨胀）与性能检查（防遗忘验证）。

四个智能体相互独立、串行协作，确保优化决策可审计且无法被执行智能体"钻空子"。

### 2.2 关键技术细节与算法流程

整个自进化流程以 epoch-batch 双层循环进行：

**(1) 参考轨迹生成（Execution，对应 Algorithm 1 中的前置步骤）**

在正式优化之前，赋予 A_exec 每个训练任务的问题**和其标准答案**，让它尝试生成能达到正确答案的执行轨迹；A_eval 验证该轨迹是否为真实、合规的推理链（如确实调用了合适工具、处理中间结果，而不是直接把答案说出来）。通过验证的轨迹被缓存为参考轨迹 τ⁺。任务最多尝试 T_att=5 次，若均未产生真实参考路径，则该任务无参考轨迹，优化时退化为单轨迹分析。

**(2) 轨迹对比诊断（Trajectory Comparison）**

在每个 batch B_j 中，A_exec 产生当前轨迹，A_eval 挑出失败轨迹（最终答案与标准答案不一致）构成失败集 F_j。对每条失败轨迹 τ⁻，A_opt 利用缓存中对应的参考轨迹 τ⁺，进行**逐层对比**，找出第一个分歧点 t*（即失败轨迹中最早偏离参考轨迹的动作），以此作为根因，而非把整个轨迹链条的后续错误都归咎为独立根因。每条失败轨迹产生结构化的错误信号 F_i = (显著性 s_i, 错误原因 m_i, 修复建议 h_i)。

**(3) 错误聚类（Error Clustering）**

各条失败样本的错误信号将按**错误原因（而非严重度标签）** 聚合，形成一组error groups P = {C₁, ..., C_K}。聚类遵循三个原则：
- 按根因分组，使每组的错误语义一致、能形成统一的修复策略；
- 优先把第一个分歧点的错误视为根因，避免将级联下游错误误判为根因；
- 保留长尾（单成员簇），防止罕见但关键的失败模式被淹没。

**(4) 候选生成与门控更新（Candidate Generation & Gated Update，对应 Algorithm 2）**

A_opt 根据聚类结果中错误的严重程度与影响范围，生成针对 harness 文件的候选修改集合 Δ_harness。该集合随后需通过两层门控才能被采纳：

- **质量门（Quality Gate）**：A_gate 检查候选修改是否存在数据泄漏（即把训练集问题及其答案直接塞进 harness，用 LLM-as-judge 打分，超过阈值 η_leak=0.8 则拒绝）和提示膨胀（统计注入的上下文示例数量，超过 η_blo=5 则拒绝）。被拒绝的更新带理由退回 A_opt 修改，最多修订 3 次，仍不过则放弃。
- **性能门（Performance Gate）**：通过的候选更新将构建候选智能体 A_candidate，它需满足两个条件——在当前批次 B_j 上的精度提升 ≥ 边际 δ=0.0，且对最近 R=2 个已执行批次精度的退化 ≤ 容忍度 ε=0.025。满足条件的候选更新被加入快照池 V 并立即成为新活跃智能体；不满足则被拒绝并累积连续拒绝计数，超过批次耐心 Pbatch=10 则提前终止该 epoch。

**(5) Epoch 末验证（Epoch-End Selection）**

每个 epoch 处理完所有 mini-batch 后，在验证集 T_val 上评估快照池 V 中所有历史快照，选出最佳精度的快照作为 A*。若验证精度连续 Pep=5 个 epoch 无提升，或达到最大 epoch 数 E=20，则整个流程终止，最终用测试集 T_test 评估 A*。

## 6. 论文的主要结论与发现

1. **HarnessEvolve 在所有数据集与设置上均超过全部基线。** 在 CloudCoreNetwork-QA 上（Qwen3.6-27B），达到 86.9% 的精度，比最强基线 GEPA（65.3%）高出 **21.6 个百分点**；在 Wireless-QA 上（DeepSeek-V4-Flash）达到 92.8%，超过 ACE（90.1%）。在开源数据集 SearchQA、OfficeQA、SpreadsheetBench 上同样全面领先。
2. **参考轨迹引导的诊断是精度提升最大的来源。** 消融实验显示去掉参考轨迹后精度从 86.9% 骤降至 57.8%（降幅 29.1 个百分点），验证了根因定位的不可替代作用。
3. **错误聚类贡献显著。** 去掉聚类后精度掉至 68.6%（降低 18.3 个百分点），说明实例级错误信号若不聚合会相互冲突、导致碎片化修改。
4. **质量门有一定必要但影响相对有限。** 去掉质量门后精度降至 80.1%（降低 6.8 分点），表明优化智能体在没有外部约束时确实存在一定程度的捷径学习倾向。
5. **跨框架迁移有效。** 优化得到的技能部署到 4 个不同框架上能带来稳定提升或不低于基线，证明优化产物没有严重绑定单一框架实现。
6. **门控机制在进化过程中过滤了大量低质量候选。** 自进化曲线显示大量更新被拒绝，保证快照池中的精度始终单调上升，最终 A* 为池内最优。

- **双层门控设计兼顾泛化与稳定性**：质量门防题面泄漏和提示膨胀、性能门防灾难性遗忘，且引入快照池+epoch-end 验证，具有"保证不差于池内最佳"的性质。
- **全 harness 的多组件协同优化**：不仅改提示，还覆盖技能、脚本、工具描述乃至执行逻辑（图 3 六类案例），突破了单一组件优化的局限。
- **企业 + 开源多基准验证**：实验覆盖多模型（微调与未微调）、多框架（LAMAgent / OpenClaw / Hermes / OpenCode / DeepSeek Harness），且跨框架迁移测试进一步支持方法落地价值。在分析中提到的三个挑战都有对应的消融分析，论证闭环完整。

## 8. 不足与局限

- **算力与成本缺乏报告**：未说明 GPU 规模、计算时数等资源开销。自我进化需频繁对大量轨迹、快照做验证集评估，推理开销明显，对实际部署的经济成本没有分析和讨论。
- **评估公平性问题不能完全排除**：三个企业数据集中使用了"后训练领域微调"的 Qwen 模型，参考轨迹本身就是由同一个待优化模型生成的，存在模型自我偏置与分布内过拟合的隐患；论文没有对完整系统做随机种子多次重复实验并报告置信区间，也未验证门控阈值（η_leak、η_blo、ε、R 等）的敏感性。
- **依赖 LLM-as-judge 的隐性误差**：A_eval 对参考轨迹"真实性"（是否应调用工具、是否有合法推理链）的判定、A_gate 对数据泄漏问题的判定都由 LLM 承担，但作者在文中并**没有单独评估这些 judge 模块本身的可靠性/误判率**。
- **参考轨迹获取的可行性限制**：方法需大量提供 ground-truth answer 的参考轨迹，复杂度与预算高；且对无法产生合规参考轨迹的方向会退化为单轨迹分析，此退化模式的效果只有主实验部分数字，缺少专门的失败模式剖析。
- **跨框架结论的边界**：迁移实验只迁移技能文件（skill.md + 技能内脚本等），而非完整的 harness（不含 prompt、工具、执行逻辑等），因此对标题宣称"harness 跨框架迁移"而言证据并不完全充分。
- **论文发表形态限制**：部分参考文献标注为 2026 年（多为预印本），这些数据集的广泛可用性、基线的复现性以及实验结果的第三方复现阶段暂未受到公开社区验证。
