## 摘要
代理系统通常由当前产生其行为的模型和框架来描述。这种边界对于单次执行是有用的，但对于一个可能更换模型、编排框架、交互会话和宿主服务器，同时保持单一身份、记忆和可执行代码谱系的长期代理来说，这种描述是不充分的。我们提出了一种用于持久代理的运行时无关架构。一个承载连续性的基底P_t=(I_t,M_t,B_t)包含架构身份表示、私有持久记忆和版本化软件体。一个可替换的部署绑定包括执行基底E_t=(R_t,H_t,D_t)，它提供推理器、框架和宿主，以及一组交互表面S_t，如聊天、API或用户界面绑定。一次部署执行是A_t=P_t▷(E_t,S_t)；当授权协议在受治理的部署边界内保持可归属谱系并转移连续权限时，更换任一可替换层是迁移，而非代理创建。我们定义了六个连续性不变量和一个静止-检查点-验证-绑定-再水化-恢复协议。Enoch将该设计实现为可重用体加上私有安装的身份、记忆、工作流状态和连续权限，其基础设施依赖位于版本化提供者合约之后。对冻结的公共提交的隔离运行通过了833项核心测试，以及从核心套件中单独执行的92项提供者和库测试；部署在保持承载连续性状态的同时，进行了推理器版本、交互表面和宿主机的替换演练。这一证据支持可机械替换性和授权系统连续性，而非行为不变性或穷尽式成对评估。下游的度量问题是，授权续接是否仍然能回忆、组合并执行其身份。

## Abstract
Agent systems are commonly described by the model and harness that currently produce their behavior. That boundary is useful for one execution but underspecifies a long-lived agent that may change models, orchestration harnesses, interaction sessions, and host servers while retaining one identity, memory, and executable code lineage. We present a runtime-independent architecture for persistent agents. A continuity-bearing substrate $P_t=(I_t,M_t,B_t)$ contains an architectural identity representation, private durable memory, and a versioned software body. A replaceable deployment binding comprises an execution substrate $E_t=(R_t,H_t,D_t)$, which supplies a reasoner, harness, and host, and a set of interaction surfaces $S_t$, such as chat, API, or user interface bindings. A deployed execution is $A_t=P_t\triangleright(E_t,S_t)$; changing either replaceable layer is migration, not agent creation, when an authorized protocol preserves attributable lineage and transfers continuation authority within a governed deployment boundary.   We define six continuity invariants and a quiesce--checkpoint--validate--bind--rehydrate--resume protocol. Enoch realizes the design as a reusable body plus private installed identity, memory, workflow state, and continuation authority, with infrastructure dependencies behind versioned provider contracts. A clean-room run of the frozen public commit passes 833 core tests and 92 provider and library tests executed separately from the core suite; deployments have exercised reasoner-version, interaction-surface, and host-machine substitutions while retaining continuity-bearing state. This evidence supports mechanical substitutability and authorized system continuity, not behavioral invariance or exhaustive pairwise evaluation. The downstream measurement question is whether an authorized continuation still recalls, composes, and enacts its identity.

# 运行时无关的持久代理：跨模型、框架和服务器的身份、记忆与代码保持

## 1. 论文的核心问题与整体含义（研究动机和背景）

- **核心问题**：现有代理系统通常以"当前产生行为的模型 + 编排框架（harness）"来定义代理边界。这种同步视角只对单次执行有效，无法回答以下**历时性问题（diachronic questions）**：
  - 当模型被替换，代理是"迁移"还是"死亡"了？
  - 当同一份记忆被复制到两个进程，两者都是同一个代理吗？
  - 当一个聊天会话被重置，是否意味着创建了一个新代理？
- **研究动机**：一个长期存续的个人代理，可能从一个聊天应用迁移到另一个、从笔记本电脑迁往服务器、更换底层推理模型、并跨不同 harness 恢复未完成的任务——但用户仍将其视为同一个代理。现有系统中存在大量零散机制（持久记忆、可恢复会话、provider 适配器、持久队列、版本化代码），却缺少统一、清晰的**代理边界定义**。
- **整体含义**：论文主张代理的核心不是模型、harness、服务器或聊天会话，而是一个"承载连续性的基底（continuity-bearing substrate）"——由**身份（Identity）、记忆（Memory）和版本化软件体（Body）**组成。模型/harness/服务器只是**可替换的执行绑定**，聊天/API/UI只是**可替换的交互表面**。更换可替换层应被视为"迁移"而非"创建新代理"。论文明确表示不讨论意识、人格或形而上的致种族持续性，仅处理**授权系统连续性（authorized system continuity）**这一架构与生命周期问题。

## 2. 论文提出的方法论

### 2.1 核心形式化架构

论文给出了以下形式化定义：

- **连续性承载基底（持久基板）**：\( P_t = (I_t, M_t, B_t) \)
  - \( I_t \)：代理的架构身份表征（身份记录、关系、价值观等）
  - \( M_t \)：私有持久化记忆与连续性相关的工作流状态
  - \( B_t \)：版本化可执行软件体（代码、提示词、工具、策略、测试、provider 合约与演化机制）
- **可替换执行基底**：\( E_t = (R_t, H_t, D_t) \)
  - \( R_t \)：语言模型或推理器
  - \( H_t \)：编排 harness（负责推理与工具执行）
  - \( D_t \)：宿主机、服务管理器与环境能力
- **交互表面**：\( S_t = \{s_{t,1}, ..., s_{t,n}\} \)（聊天会话、API、邮件、用户界面等）
- **整体部署执行**：\( A_t = P_t \triangleright (E_t, S_t) \)

其中 \( \triangleright \) 表示"实例化（instantiation）"而非"归属（ownership）"。

### 2.2 连续性不变量与迁移协议

- **六项连续性不变量**：
  - **I1 身份与谱系**：迁移必须保留安装身份版本与可归属谱系，身份更新需显式治理。
  - **I2 记忆**：记忆与工作流状态必须扩展或有效迁移其记录祖先，不得静默重置。
  - **I3 软件体**：除非另有声明治理的演化，目标必须执行同一 body 版本。
  - **I4 权威唯一性**：在受治理的部署边界内，最多只有一个协作执行体持有连续性权威（continuation authority）。
  - **I5 能力差异显式化**：环境能力差异必须可见，不得伪装为身份变更。
  - **I6 自我描述分离**：执行/进程/交互表面/部署标签属于环境元数据，不得覆盖安装身份。
- **六阶段迁移协议**（图 2）：
  1. **Quiesce（静止/关停）**：栅栏（fence）旧执行，停止接收新工作，推进权威纪元（authority epoch）。
  2. **Checkpoint（检查点）**：捕获身份版本、body 版本、记忆与工作流状态、待办任务、provider 游标与工件引用。
  3. **Validate（验证）**：在变更目标前验证 schema、哈希、声明谱系、支持的状态版本与能力需求。
  4. **Bind（绑定）**：根据 body 合约解析目标 provider 与凭据；provider 原生标识对目标本地有效。
  5. **Rehydrate（再水化）**：原子性安装或迁移私有状态，将 body 与自我标识作为独立启动输入，创建新的 harness 与交互会话。
  6. **Verify and resume（验证并恢复）**：运行健康与连续性检查，获取新权威纪元，协调歧义副作用，恢复持续任务。
- **失败语义**：验证完成前源端保持权威；目标激活失败则从检查点回滚，源端可恢复。迁移作为含单一晋升点的事务处理。
- **兼容非位级不可变性**：纯运行时迁移要求满足 \( v_I(t+1)=v_I(t) \)、\( v_M(t) \preceq v_M(t+1) \)、\( v_B(t+1)=v_B(t) \)（除非迁移事务同时包含经授权的记忆修复、body 演化或身份更新）。\(\preceq\) 表示可审计的延续而非相等。
- **权威 vs 标签**：论文指出，稳定的 UUID 等标识不足以表达延续——复制的目录可能包含相同标识，因此用**身份 + 可归属谱系 + 转换权威**来界定连续性，这与表 1 中的生命周期操作分类（重启、恢复、迁移、演化、身份更新、复制和分支/衍生）配套。

## 6. 论文的主要结论与发现

- 提出的运行时无关持久代理架构，**从架构上定义并实现了"代理可以跨模型、框架与宿主机迁移而不失身份"**这一能力边界：
  1. 身份是"功能性身份"，而非行为/感知层面身份。
  2. 迁移的正确语义被定义为"替换（E, S）层 + 保留（I, M, B）层 + 保持授权权威"，任何未经授权的更换都不是同一代理的延续。
  3. 用执行机制证据证明授权系统连续性和机械可替代性可实现：冻结快照通过 833 项核心 + 92 项 provider 测试，多 provider 替换场景均可工作。
  4. 权威唯一 + 栅栏 + 幂等/仲裁式外部效果处理的重要性被强调：复制记忆不复制权威，单一稳定 UUID/标签不足以代行连续性。
  5. 下行重点应放在行为身份保真度测度上——即一个已授权的延续体在替代推理器和/或 harness 后，能否真正再现并执行其身份、记忆与使命。

## 7. 优点

- **概念框架出色**：用连续承载基板/可替换执行基板/交互表面的三元划分处理纵向 agent 生命周期问题，准确区分了重启、恢复、迁移、演化、身份更新、复制、衍生等原本常被混淆的操作（表 1 在此非常有效）。
- **比类似工作更形式化**：定义连续性不变量和带明确失败语义的 6 阶段迁移协议，整体设计极具说服力。
- **工程实现扎实**：开源的 Enoch 从零实现上述模型，整体结构如下：
  - 身份与 body（self.json 与 body.yaml）分离加载；
  - 私有状态 sates 可在不曝光情况下的迁移（密钥可引用而非导出）；
  - 所有私有状态 schema受版本化清单管理，startup 快速拒绝损坏/未来版本状态，迁移回滚路径完整；
- **关注点全面**：结合了 authority epoch/fencing、幂等效果处理和 reconciliation（重放/失败关闭）等分布式系统语义，同时加入身份治理与人工托管边界。
- **诚实与克制**：清楚标注了证据边界（"支持可机械替代性和授权系统连续性，而非行为不变性或穷尽式成对评估"），并显著指明下游行为评测仍是未解决问题——这表明作者对证据解释非常审慎。
- **表述中立**：清晰声明不承诺意识或形而上的持续性。

## 8. 不足与局限

- **缺少全轴受控组合迁移实验**：论文只做了单轴替换（推理器版本、交互表面、宿主机各一次），未运行文末第 6 节所指定的完整跨模型/harness/host/交互面组合矩阵，因而不能回答"在迁移中多元素同时更换时是否仍能保持完整连续性"。
- **无行为层实证**：明确承认缺乏对行为连续性、延迟、成本与操作负担的测量；未运行任何 behavioral identity fidelity 基准（identity recall / composition / mission enactment 等）。行为身份是论文定义的最终度量问题，却尚未由作者解决。
