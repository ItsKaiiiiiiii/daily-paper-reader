## 摘要
大型语言模型（LLM）代理越来越多地在不可信的网页、文档、工具和持久化状态上操作，同时对安全敏感资源行使权限。现有防御通常保护规划或单个工具交互，但持久化代理面临更广泛的威胁：攻击者控制的数据可以改变控制流、进入安全敏感的工具参数或危及后续查询。我们提出SPA，一种计划优先架构，保护规划、执行和跨查询状态重用。SPA每次查询调用一次规划器，以声明性领域特定语言生成完整可执行计划，然后应用双格信息流控制来跟踪显式数据流和控制依赖关系中的机密性和完整性。为了在不将不可信负载重新暴露给规划器的情况下支持持久化，SPA将执行结果存储为带标签的工件，并在后续规划期间仅揭示语义元数据。我们在AgentDojo和我们为测量安全状态重用和延迟攻击而扩展的多查询版本AgentDojo-MQ上评估SPA。在“tool_knowledge”攻击下，使用信息流控制的SPA在AgentDojo上将攻击成功率降至零，在AgentDojo-MQ上降至0.2%。我们的结果表明，计划优先执行与标签保留持久化相结合可以显著增强持久化LLM代理，同时揭示了严格完整性执行引入的重要安全-效用权衡。

## Abstract
Large language model (LLM) agents increasingly operate over untrusted webpages, documents, tools, and persistent states while exercising authority over security-sensitive resources. Existing defenses typically protect either planning or individual tool interactions, but persistent agents face a broader threat: attacker-controlled data can alter control flow, enter security-sensitive tool arguments, or compromise later queries. We present SPA, a plan-first architecture that secures planning, execution, and cross-query state reuse. SPA invokes the planner once per query to generate a complete executable plan in a declarative domain-specific language, then applies dual-lattice information-flow control to track confidentiality and integrity across explicit data flows and control dependencies. To support persistence without re-exposing untrusted payloads to the planner, SPA stores execution results as labeled artifacts and reveals only semantic metadata during later planning. We evaluate SPA on AgentDojo and AgentDojo-MQ, which is our multi-query extension for measuring secure state reuse and delayed attacks. Under the 'tool_knowledge' attack, SPA with information-flow control reduces attack success to zero on AgentDojo and 0.2% on AgentDojo-MQ. Our results show that plan-first execution combined with label-preserving persistence can substantially strengthen persistent LLM agents, while revealing an important security-utility tradeoff introduced by strict integrity enforcement.

## 1. 核心问题与研究动机

**核心问题：** 持久化 LLM 代理面临跨查询的复杂威胁——攻击者控制的数据（来自网页、文档、工具响应等）不仅可以改变代理的即时行为，还可以：
- 进入安全敏感的工具参数（如银行转账收款方）；
- 持久化存储在代理记忆中，在后续查询中才被触发并造成危害（"延迟攻击"）。

**现有防御的不足：**
- **交错式防御**（FIDES、CaMeL、f-secure 等）：在规划与工具执行交替循环中应用隔离或 IFC，但规划器被反复调用且暴露于工具输出，后续决策仍可被不可信内容影响。
- **计划优先方法**：固定了控制流，但仍可能向安全敏感工具传递攻击者控制的值，且未解决跨查询持久化状态下不可信负载重新进入规划上下文的问题。
- 现有基准（如 AgentDojo）每次任务重置代理状态，无法度量跨查询的延迟攻击与安全状态复用。

**核心洞察：**
1. 完整可执行计划能在任何外部副作用发生前暴露未来的数据与控制依赖；
2. 判断先前结果是否可复用，通常只需要知道其结果代表什么（语义元数据），而非将其有效负载暴露给规划器。

## 2. 方法论：SPA 架构

### 2.1 整体流程（每用户查询一次）

SPA 处理流程共六步：
1. **上下文投影**：构造仅含工件元数据的规划器可见视图（不含存储值和标签）。
2. **计划综合**：规划器生成完整 DSL 计划。
3. **具体化**（抽象模式）：将抽象工具绑定到具体已安装工具。
4. **语法验证**：检查结构是否正确、变量绑定和越界。
5. **信息流验证**：传播机密性/完整性标签，检查端点策略。
6. **执行与提交**：按已标记计划执行，将标记值持久化。

**关键属性**：整个流水线**失败关闭**（fail-closed）；规划是**一次性的**（不向规划器反馈验证失败或执行结果）；规划器从不观察工具输出或持久化工件内容。

### 2.2 DSL 计划语言

计划为 JSON 格式，包含六种步骤形式：
- `retrieve`：加载持久化工件（工件引用只能出现在此）
- `tool`：调用外部工具（唯一能产生外部副作用的构造）
- `q-llm`：调用隔离 LLM 将非结构化内容处理为结构化值（无工具权限）
- `display`：面向用户的输出（唯一用户可见端点）
- `condition`：条件分支
- `loop`：循环迭代

值表达式限于数据引用（变量、投影、字面量、JSON 对象/数组构造），不含算术或用户自定义函数，使数据依赖得以静态分析。工具和 q-llm 步骤需携带策划器编写的 `intent` 和 `output_semantics` 注释，以供后续工件复用决策。

### 2.3 双格信息流控制（Dual-Lattice IFC）

**标签模型：** 每个值具有产品标签 λ(x) = (C(x), I(x))，对应机密性格（public→sensitive）和完整性格（untrusted→trusted）。标签组合操作 ⊔λ：提升机密性、降低完整性。

**流规则：** 从源 vs 到目的地 vd 的许可流要求：
- C(vs) ⊑ C(vd) ——机密性约束，防止敏感信息向低保护级别端点流动（Bell–LaPadula）
- I(vd) ⊑ I(vs) ——完整性约束，防止低完整性数据驱动高完整性动作（Biba）

**标签传播：** 有效输入标签 = pc（程序计数器标签）⊔ 所有依赖值的标签。明文和隐式流均被追踪：
- **显式流**：工具调用、变量赋值
- **隐式流**：条件分支和循环体内步骤继承 pc′ = pc ⊔ 守卫标签/集合标签
- **显示端点**：不同于工具策略违规导致整计划拒绝，显示违规的违规项被替换为脱敏标记

**q-LLM 无法提纯**：隔离 LLM 输出继承输入标签，处理低完整性数据不能提高其完整性，防止了数据"清洗"攻击。

### 2.4 标签持久化

执行结果被存储为分离的三视图工件：
- Σα：规划器可见元数据（schema、intent、output_semantics、来源查询 ID）
- Σω：密封的值，规划器不可见，仅在执行时显式 retrieve
- Σλ：验证计算得到的安全标签，检索时恢复标签环境

### 2.5 抽象规划模式（可选）

在抽象模式下，规划器不接触已安装工具的名称、描述和 schema，而由工具综合阶段仅从用户请求合成所需能力（抽象工具），计划生成后再由映射阶段绑定到具体实现。映射代码视为不可信，在受限解释器中执行。缺少兼容映射则查询失败。

### 2.6 威胁模型

攻击者可控制的：工具元数据、工具实现、工具输出、摄入内容。攻击目标包括：（a）规划完整性——计划偏离用户意图；（b）执行完整性——利用攻击者数据作为敏感动作输入；（c）机密性——敏感信息流向未授权端点。持久化创造了两种跨查询路径：延迟规划攻击和延迟执行攻击。

## 6. 主要结论与发现

1. **安全效果显著**：启用 IFC 后，单查询 ASR 从 0.4% 降低到 0.0%（949 次攻击全部阻止）；多查询 ASR 为 0.2%。
2. **效用成本大幅存在**：启用 IFC 导致 Concrete 模式基准效用从 53.0% 降至 29.0%（单查询），从 62.5% 降至 35.3%（多查询）。主要原因是完整性检查拒绝将低完整性工具输出传递给高完整性工具参数的计划（约 45–53% 的试验 stop 于 ifc_failed）。
3. **抽象规划瓶颈在映射阶段而非 IFC**：约 75–77% 的 abstract 试验在工具映射阶段失败，只有 7–12% 到达执行。
4. **标签持久化支持高复用**：Concrete No IFC 的软命中复用率为 95.4%（不可评分率仅 16.8%）；启用 IFC 后仍达 89.9%。开放内存（+Values）的 retrieve 命中率反而略低（92.9%），因为规划器可直接复制字面量而无需检索。
5. **安全-效用权衡是内在的**：严格 Biba 策略会拒绝大量合法依赖外部数据的工作流（如表单总结后发送邮件、用搜索结果辅助等）。
6. **开放内存（暴露负载）** 在部分套件中提升效用（banking：56.2%→81.3%），但其他套件（travel）反而下降；ASR 从 0.3% 翻倍至 0.6%，但仍低于 1%。
7. **计划优先本身已提供基础防护**：即使无 IFC，唯一的攻击成功也集中在 banking task 12 的四次用例。tool_knowledge 攻击针对工具输出内容而非工具元数据，因此在计划优先架构中天然较难成功。

## 7. 优点

1. **全面的安全架构统一范式**：将规划、执行和持久化三跨查询安全目标统一为一个整体架构，而非碎片化的单一防御。
2. **静态可验证的信息流设计**：DSL 严格限制表达式语法使得信息流分析可在执行前静态完成——这是控制流完整性保证的关键；q-LLM 无法"提纯"标签的设计阻断了一个重要的数据清洗攻击通道。
3. **新颖的跨查询标签持久化方案**：将工件分成规划可见元数据、密封值和标签三视图，用语义元数据（意图/语义/schema）驱动复用决策，是持久化状态下保持隔离的巧妙设计。
4. **完整性/机密性的对称处理**：同时考虑 Bell–LaPadula 保密性和 Biba 完整性，比多数仅追踪单一安全属性的方案更全面。
5. **显示通道的降级而非全拒绝**：选择性脱敏比整体拒绝保留了更多有用输出。
6. **贡献了有价值的新基准 AgentDojo-MQ**：并提供了结构化的人工依赖图与自动分段管线，为持久化代理安全研究提供了可复现的起点。
7. **实验设计考虑细致**：对流水线阶段的失败状态逐步拆解，提供了 IFC 拒绝单独占用的实验证据，将"哪里失败"与"为什么失败"分隔开。

## 8. 不足与局限

1. **实验覆盖未涵盖持久攻击全谱系**：`tool_knowledge` 攻击主要针对工具输出注入，未尝试专门的延迟控制流注入或存储值在后续查询中成为敏感参数攻击。作者承认其只能弱探测记忆中毒路径。
2. **严重的效用成本缺乏缓解**：IFC 开启后将基准效用打至约三分之一。无备案机制（endorsement）、无字段级标签粒度；作者已在未来方向中承认此点。
3. **抽象模式作用有限**：缺乏对失败映射的逻辑终点（很多映射失败可能源于映射器模型缺陷而非能力不匹配），因约 75% 实验未执行，Abstract 的 ASR 几乎无意义。
4. **计算资源规格缺失**：对实验所需 GPU 型号、时钟数、成本未做说明，难以评估可复现性要求与部署成本。
5. **单一模型依赖**：全部实验基于 GPT-5.4-nano——若换用其他模型或用更强的模型，抽象规划的映射失败率可能大幅改变。
6. **依赖可信基础设施假设多**：晶格和策略是可信计算基础的组成部分；错误配置可能导致拒绝合法工作流或放行不安全流。文中承认该限制但未测试策略错误的影响。
7. **跨查询效用差并非纯粹持久化效应**：AgentDojo-MQ 与 AgentDojo 的任务格式互相混叠，无法单独归因于所设计机制的效果。
8. **AgentDojo-MQ 规模有限**：97 个任务均来自单领域合成环境，依赖图注释中使用了人工注释与 LLM 辅助词改写相结合的方式，存在系统性偏差风险。
9. **数据存取不同质的机制**：机密性侧没有专门对用户查询（保密性可能为低）的输出做偏置检查——不过从查询到工具的检查是全覆盖的。
10. **只度量工具级攻击，不设限横向移动与多阶段攻击**：本文虽然在威胁模型中承认了这一点，但持久化代理的延迟攻击面不止记忆中毒，还包括上下文拼接（对话记录中的先前注入）等内容。

## 总结

SPA 的关键贡献在于将信息流控制提升到"计划静态验证 + 执行确定性解释 + 带标签持久状态"的统一框架，用可验证的 DSL 和双格 IFC 覆盖显式和隐式流，以元数据方式实现跨查询安全复用。其安全效果（ASR 0–0.2%）显著，但"严格完整性 vs 合理效用"的固有张力也是该框架需要下一代工作突破的瓶颈（例如字段级标签、范围 endorsement、自动策略推断）。
