## 摘要
企业数据智能体通过多次推理步骤中的大量工具调用来回答业务查询，每次会话通常会累积数十万条上下文令牌。现有的压缩策略通常分配保留预算，但不考虑删除单个工具输出所带来的下游后果。因此，激进的压缩可能会触发昂贵的工具重新调用，抵消初始节省。我们将此称为压缩-后果差距。为弥合这一差距，我们提出TRACER，将压缩形式化为一个序列化的逐工具决策问题。一个轻量级的REINFORCE策略，仅利用每次压缩事件时可用的信息，分配查询条件化的保留比率。其后果感知目标共同考虑任务成功、总令牌消耗和压缩后的工具重新调用。为改进信用分配，TRACER使用一个学习到的结果模型，将所选保留比率的预测后果与完全保留每个工具输出的后果进行比较。在三个压缩后端上针对未参与训练的生产查询，与保留所有上下文相比，TRACER将总令牌消耗减少了29-46%，同时保持可比或更高的任务成功率。与工具类型条件的静态策略相比，TRACER额外节省了15-18%的令牌。干预性回放显示，学习到的逐工具信用分数与测量的单工具后果相关。学习到的策略在跨智能体骨干和压缩器架构迁移时也产生正向节省，并在五个未参与训练的LOCA-bench环境中将令牌消耗减少18-25%。这些结果证明了后果感知、逐工具上下文保留对于提高长时程语言智能体效率的价值。

## Abstract
Enterprise data agents answer business queries by chaining many tool calls over multiple reasoning steps, routinely accumulating hundreds of thousands of context tokens per session. Existing compression strategies typically allocate retention budgets without accounting for the downstream consequences of removing individual tool outputs. Aggressive compression may therefore trigger costly tool re-invocations that offset the initial savings. We call this the compression--consequence gap. To close it, we propose TRACER, which formulates compression as a sequential per-tool decision problem. A lightweight REINFORCE policy assigns query-conditioned retention ratios using only information available at each compression event. Its consequence-aware objective jointly accounts for task success, total token consumption, and post-compression tool re-invocations. To improve credit assignment, TRACER uses a learned outcome model to compare the predicted consequences of the selected retention ratio with those of fully retaining each tool output. On held-out production queries across three compressor backends, TRACER reduces total token consumption by 29--46% relative to keeping all context while maintaining comparable or higher task success. Compared with a tool-type-conditional static policy, TRACER provides an additional 15--18% of token savings. Interventional rollouts show that the learned per-tool credit scores correlate with measured single-tool consequences. The learned policy also yields positive savings when transferred across agent backbones and compressor architectures, and reduces token consumption by 18--25% on five held-out LOCA-bench environments. These results demonstrate the value of consequence-aware, per-tool context retention for improving the efficiency of long-horizon language agents.

## 1. 核心问题与整体含义

- 企业级 LLM 数据智能体往往需要通过多步推理串联大量工具调用（SQL 查询、权限检查、知识检索等）来回答业务问题，导致上下文随会话单调累积至数十万 token，超过窗口限制、推高成本并稀释注意力。
- 现有上下文压缩方法（token 级剪枝、回合级摘要、步骤级删除）通常不加区分地对待所有内容，且只在孤立层面评估“压缩节省”，忽略了压缩后若智能体需要被删信息可能重新调用工具所带来的额外 token 成本；该代价甚至可能超过初始压缩节省，论文称其为“压缩–后果差距”（compression–consequence gap）。
- 核心问题：**如何为每个工具输出动态、差异化地决定保留多少上下文，并让这种决策感知下游重新调用代价，从而在长时程智能体推理中同时优化 token 效率与任务成功率。**

## 2. 方法论（TRACER）

### 核心思想
将每个压缩事件视为一个序列决策点。面对当前上下文中出现的 N 个工具输出实例，学习一个策略，为每个实例分配一个查询条件化的保留比率（retention ratio，0.05–1.0），再由固定压缩器按该比率截断/压缩内容，agent 继续运行。训练目标是“后果感知”的，显式惩罚因压缩导致的后续工具重调用。

### 关键技术细节
- **策略网络**：两层 MLP，输入 174 维状态（查询特征、各工具输出实例特征、上下文构成特征），输出每个工具实例的 Beta 分布均值；通过在实例中引入“槽位”来区分同一工具类型的重复调用，每个槽位独立决策。
- **动作空间**：保留比率限定在 [0.05, 1.0]；用 Beta 分布（浓度 κ0=8）参数化以自然匹配有界区间，训练时采样，评估时取确定性均值。
- **后果感知奖励**：\(R_{\mathrm{base}} = \text{success} - \lambda_{\mathrm{tok}} \operatorname{clamp}(T/T_{\mathrm{base}}, 0.2, 2)\)，并结合事件局部重调用惩罚 \(P_{\mathrm{recall},t} = \lambda_{\mathrm{recall}} \operatorname{clamp}((N_{\mathrm{post},t}-N_{\mathrm{pre},t})/N_{\mathrm{pre},t}, 0, 2)\)；总目标为二者的期望差。
- **两通道信用分配**：
  - 通道一（模型无关兜底）：将每个事件的局部惩罚均匀分配到该事件的活跃工具上，保证即使结果模型失效也存在正确但较粗糙的学习信号。
  - 通道二（基于结果模型的逐工具反事实归因）：训练一个轻量 Transformer 结果模型 \(f_\phi\)，预估重调用次数、token 总量与成功概率；对每个工具 \(i\)，计算“采取策略所选比率”与“将该工具完全保留（\(r_i:=1\)）”时的预测下游代价差，再结合即时 token 节省组成双向 credit：
    \[
    \mathrm{credit}^{\mathrm{attr}}_i = \lambda_{\mathrm{save}}(1-r_i)\frac{\mathrm{tok}_i}{T_{\mathrm{base}}} - \big(\hat C(s,a)-\hat C(s,a;\,r_i:=1)\big).
    \]
  - 通道融合：\(\mathrm{coeff}_{i,t} = \alpha A_t + \mathrm{credit}^{\mathrm{floor}}_i + \beta_t\,\mathrm{credit}^{\mathrm{attr}}_i\)，先用 20 episode warmup（β=0）再线性升温到 1，每 5 episode 拟合一次结果模型。
- **REINFORCE 更新**：策略梯度损失为 \( \mathcal L(\theta) = - \sum_{i\in\text{active}} \mathrm{coeff}_i \log \pi_\theta(a_i\mid s)\)；利用 Beta 分布 score function 的零均值性质，使任意与动作无关的基线天然无偏，单个槽的梯度可解释为credit与采样分数的协方差。

## 3. 实验设计

- **生产平台**：大规模电商企业的真实数据分析 agent；工具包括知识搜索、SQL 执行、权限检查、表查询、日期解析；主 backbone 为 Claude Sonnet 4.6（200K 窗口）。
- **数据/查询**：120 条生产日志查询，分为三档难度（25 简单查找、55 多步问题、40 多表权限连接），80/40 分层划分训练/测试，均有人工验证答案。
- **压缩后端（compressor backends）**：
  - 统一截断（truncation，无模型）；
  - Self-Info 子句级压缩（基于 Qwen-2.5-0.5B 自信息评分）；两者用于验证不同粒度和语义/位置压缩下 TRACER 的适用性
  - 摘要式压缩（基于 Qwen-3.7-Max）；
  - 另外的 AGORA 风格步骤级压缩器用于跨压缩器迁移测试。
- **对比基线**：Keep-all；Uniform-0.5（固定 0.5）；Recency（按远近线性递减）；Token-proportional（大输出更多压缩）；Tool-type-conditional（按工具类型的静态比率贪心搜索）。消融对比 RL-only（无结果模型的均匀 credit 赋分）。此外还做了跨 backbone（Qwen-3.7-Max、GPT-5.5）零样本迁移、以及公开 LOCA-bench 上 5 个任务环境的泛化测试。

## 4. 资源与算力

- 论文明文指出：策略与结果模型合计可训练参数 102,306，全部在 CPU 上运行；外部的 agent/压缩模型 API 调用才占主要 wall-clock 耗时。
- 生产实验环境为单台 Intel Xeon Platinum 8369B 服务器（32 核、128 GB RAM），无 GPU。
- 每轮 rollout 约 30–180 秒；每个 compressor 上的 100 episode × 5 seeds 训练约 25–42 小时。
- 整个实验活动估计约 400 compute-hours 和约 2800 美元 backbone API 费用。
- LOGO-bench 与具体部署资源细节未进一步展开。

## 5. 实验数量与充分性

- **主要对比**：3 个真实压缩后端 × 6 类策略，每类有成功率、token 比率、重调用率、每成功成本等指标；RL 训练用 5 个随机 seed，每 seed 100 episodes。
- **消融实验**：TRACER vs RL-only，在三种压缩后端上比较归因通道的作用，并报告 95% CI 与显著性检验（\(p=0.008\)）。
- **归因模型验证**：使用单工具干预回放（factual vs intervention rollout，3 个配对 seeds），验证预测后果与实际干预后果的相关性（Spearman、NMAE、Top-3 overlap、符号正确率）。
- **迁移实验**：向 Qwen-3.7-Max、GPT-5.5 迁移；向 AGORA 风格压缩器零样本迁移；在公开 LOCA-bench 上一共训练于 10 个任务环境、测试 5 个 held-out 环境，跨越 96K/128K/256K 窗口 × 5 seeds。
- **总体评价**：实验设计较为全面、统计规范（分层 bootstrap IQM、成对 Wilcoxon、iso-success token ratio 以避免成功与压缩混淆）。但论文核心数据来自单一企业私有环境，部分测试数据被省略/留空，外部复现性受限；LOCA-bench 任务并没有真实企业环境的长链生产性那么高。

## 6. 主要结论与发现

- TRACER 在三种压缩后端上相对 keep-all 节省 29%–46% 总 token，同时保持或略提升任务成功率；比工具类型条件静态策略额外节省 15–18%。
- 重调用率（precall）保持在 0.025 以下，说明节省不是通过高代价的“重新调用”换取。
- 摘要式压缩上收益最大（46% token 节省），Self-Info 上最小但也达 29%。
- 归因模块显著改善 RL-only：成功率在各压缩后端上提升 2.2–4.8 个百分点，并额外降低 3–5% 的等成功 token 比率，重调用风险下降约 13%。
- 反事实预测与实际单工具干预高度一致（聚合 Spearman 0.66、84% 方向一致率、82% 的 top-3 高后果工具命中率），说明 learned credit 具有方向信息价值。
- 策略能跨 agent backbone 和压缩后端迁移（保留 18–40% token 节省），且在 LOCA-bench 5 个未见任务上相对 keep-all 获得 18–25% 节省并提升成功率。

## 7. 优点

- 提出并形式化了此前被忽视的“压缩—重调用代价”权衡，并显式引入奖励，与实际系统开销契合。
- 将信用分配细化到“工具输出实例”级别，并通过单工具反事实结果模型缓解稀疏奖励下的 credit assignment 难题。
- 用 Beta 分布自然匹配有界动作空间，且从数学上保障基线无偏，为 REINFORCE 提供可解释的逐槽梯度。
- 策略只依赖工具级特征，不依赖具体模型内部状态，具有良好的可迁移性和模块化特点（可与现有压缩器、agent 解耦）。
- 实验方法较为严谨：用干预 rollout 验证归因模型、用 iso-success token ratio 分开“节省”与“失败导致的省 token”、多 seed + 统计显著性检验、有跨骨干/跨压缩器/公共 benchmark 的泛化测试。

## 8. 不足与局限

- **实验范围局限**：主要实验完全在单一电商生产数据上完成（80 条训练/40 条测试），数据规模偏小；虽然 LOCA-bench 作为公共泛化测试，但任务性质与真实生产数据差异较大。
- **复现性受限**：论文指出了很多实验相关的资源（训练 checkpoint、完整轨迹、原始生产查询与输出等）未开放，部分查询目标被“redacted”；因此外部难以完整地端到端复现论文所述结果。
- **成本与部署现实性**：训练虽是一次性，但论文明确指出合计需约 $2800 API 费用、跨多种后端 400 计算小时；且省钱估算只计入输入 token，未计入压缩器模型调用成本、输出 token、评分器成本、延迟和维护费用等，因此“训练后数周回本”的说法偏乐观。
- **因果验证强度有限**：结果模型取得的 Spearman 0.66/符号准确率 84%等仍非完美；在结构性较强且带噪的环境中，单调性正则化来自合成监督，未必有潜在收益保证。论文自身也说明 provenance upgrade 是“可选升级”而非已报告组件。
- **抗过拟合与长期漂移问题**：生产查询分布可能随时间变化，策略对工具类型偏好会因输入分布偏移而退化，论文没有报告长期动态部署中的鲁棒性。
- **对低容量压缩器/非语义压缩的后端**，收益相对较小，且对特定压缩策略的依赖需分别处理，并不能提供统一的“银弹”方案。
