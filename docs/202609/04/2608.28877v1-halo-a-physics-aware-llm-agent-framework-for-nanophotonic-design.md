## 摘要
语言模型最近已被应用于纳米光子设计，但它们能否可靠地将光学目标转化为可仿真的设计、执行电磁分析并根据数值反馈修正决策，目前仍不清楚。我们提出了HALO，一个物理感知框架，它将语言模型规划器与类型化设计规范、电磁仿真、诊断评估以及在迭代设计循环中可选复用先前失败轨迹相结合。我们还引入了HALO-Bench，这是一个包含52个任务的基准测试，涵盖源自实验室、源自论文和开放式的纳米光子设计任务，并采用统一的评估协议。我们比较了三种规划器配置：固定结构化工作流、使用相同仿真接口的自主结构化智能体，以及直接编写并执行仿真代码的自主编码智能体。固定结构化工作流在token使用上最高效，且未观察到代码或路径级故障，而自主编码在更强模型下可以实现更高的任务成功率，但代价是额外的操作失败。我们还研究了先前失败轨迹的复用。在有针对性的多轮任务中，检索到的失败反馈减少了首次成功的迭代次数和总token使用量。这些结果阐明了科学智能体中显式接口、自主执行和可复用设计经验之间的权衡。

## Abstract
Language models have recently been applied to nanophotonic design, but it remains unclear whether they can reliably translate optical objectives into simulation-ready designs, execute electromagnetic analysis, and revise decisions from numerical feedback. We introduce HALO, a physics-aware framework that couples language-model planners with typed design specifications, electromagnetic simulation, diagnostic evaluation, and optional reuse of prior failure trajectories in an iterative design loop. We further introduce HALO-Bench, a 52-task benchmark spanning lab-derived, paper-derived, and open-ended nanophotonic design tasks under a shared evaluation protocol. We compare three planner configurations: a Fixed Structured Workflow, an Autonomous Structured Agent using the same simulation interface, and an Autonomous Coding Agent that directly writes and executes simulation code. The Fixed Structured Workflow is the most token-efficient and exhibits no observed code- or path-level failures, while autonomous coding can achieve higher task success with stronger models at the cost of additional operational failures. We also study reuse of prior failed trajectories. On targeted multi-round tasks, retrieved failure feedback reduces both iterations to first success and total token use. These results clarify the tradeoffs between explicit interfaces, autonomous execution, and reusable design experience in scientific agents.

## 2. 方法论：核心思想、关键技术细节与流程
### 2.1 HALO框架整体思想
- 核心设计范式为 **"提出–执行–评估–修订"（propose–execute–evaluate–revise）** 的迭代闭环，将自然语言设计意图标准化为可执行、可审计的科学设计流程。
- **"物理感知"（physics-aware）** 的具体含义：规划器的每一步决策都通过电磁仿真和任务特定的物理指标来评估和修订——仿真器物理反馈是整个循环中不可分割的核心环节。

### 2.2 核心组件一：类型化设计模式（Design Schema）
- 每个候选器件用**类型化、机器可读的仿真规范**表示，显式定义以下字段：
  - 几何结构与非空间布局关系
  - 材料分配与层级结构
  - 光照条件和求解器配置
  - 设计变量/扫描变量
  - 评估目标与指标
- 该结构化表示使得设计决策可直接检查、可字段级验证，并在仿真反馈之前即可进行物理一致性预检。

### 2.3 核心组件二：三种规划器配置（核心变量）
为了研究"工作流结构"与"执行自由度"的影响，论文对比了三种配置，形成自主性递增的谱系：

| 配置 | 工作流编排 | 仿真访问方式 | 关键特征 |
|---|---|---|---|
| **固定结构化工作流（Fixed Structured Workflow）** | 预定义LangGraph流程，每轮一次规划器调用，无条件分支（仅按成功与否停止/继续） | 仅可通过HALO预定义的类型化仿真接口 | 无法自由读写文件、改流程或写仿真代码；Pydantic校验 |
| **自主结构化智能体（Autonomous Structured Agent）** | LangChain Deep Agent，自主编排，可读写文件、维护笔记、决策中间动作 | 保留相同的结构化仿真接口 | 编排更自主，但科学执行边界不变 |
| **自主编码智能体（Autonomous Coding Agent）** | 完全自主，可自行编写、执行、检查和修订Python RCWA仿真代码 | 直接代码级访问，不受schema约束 | 自由度最高，但降低可审计性，且引入代码/API/路径/产物等新失败模式 |

### 2.4 核心组件三：共享评估协议
- 三种配置共享**同一评估器生成协议**：评估器根据任务目标、设计产物和仿真结果，动态生成**可执行的、逐案定制的评估脚本**，将输出转化为数值指标和通过/失败决策；该脚本在后续迭代中固定复用。
- 评估器生成**人可读的诊断说明**（summary + 成功/失败原因），并经光学专家独立抽查其物理与逻辑一致性。

### 2.5 核心组件四：轨迹记忆与复用（可选）
- **运行内历史**（within-run trajectory history）：默认闭环实验中始终可用，含同一案例的先前迭代。
- **检索记忆**（retrieval memory）：仅在消融实验中启用；存储先前的失败轨迹，支持**模式辅助检索**——结合文本相似度与模式级相似度（几何、材料、光学设置、扫描变量），检索排名前三的失败轨迹，以加速当前案例的收敛。作为对照，还设计了**同任务Top-1失败记忆**控制条件。

## 6. 主要结论与发现
### 6.1 结构化设计理解（无反馈）
- 所有评估模型在受扰动的Lab-Derived任务上总体准确率均**超过93%**（Gemini 2.5 Pro达到97.2%，Claude Opus 4.8达到97.7%）。这证明**闭环失败不能仅归因于模型无法生成初始合理的结构化设计**，可靠性的瓶颈在执行、修订和反馈解释环节。

### 6.2 闭环成功率与token效率（核心发现）
- **最高成功率**为Claude Sonnet 4.6 + Autonomous Coding Agent的**79.8%宏平均**。
- **自主性并非普惠优势**：
  - 在Gemini 2.5 Flash / 2.5 Pro上，固定工作流优于两种自主配置。
  - 自主结构化智能体并不稳定优于固定工作流，说明在保留结构化仿真边界时增加编排自由度未必有益。
  - 更强的模型更能从代码生成自由中获益：Gemini系列下自主编码的成功率从Flash的32.3%提升到3.1 Pro Preview的68.8%。
- **token效率（Succ./M tokens）**：固定工作流在**每个模型块中均为最高**（Claude Sonnet 4.6时达2.327，是自主结构化智能体的约5倍、自主编码智能体的约4倍）。

### 6.3 失败轨迹复用的价值
- 在16个基线延迟成功案例中，**模式辅助Top-3检索将10例（62.5%）从多轮成功转化为首轮成功**：
  - 平均首次成功迭代：2.44 → **1.44**
  - 中位token消耗：1.67M → **0.34M**
  - 总token消耗：41.38M → 14.79M（**减少64.3%**）
- 同任务Top-1控制条件也有效（降至1.75轮，token减少50.0%），作为诊断性对照表明**失败经验本身即携带可加速收敛的有效信号**。

### 6.4 失败模式分布（归因）
- **固定结构化工作流**：无任何代码/工具/API或产物/路径错误；失败集中在仿真器/运行时错误（34.0%）和超时/未完成评估（29.0%）以及目标未达成（24.0%）上。
- **自主结构化智能体**：缺失/无效结果（28.6%）、超时（25.6%）和搭建/扫描管理错误（18.8%）最为突出。
- **自主编码智能体**：新增代码/工具/API错误（25.2%）和产物/路径错误（18.3%），"错误设定/扫描"类失败为0（因为自由度下不存在此类限制性失败）；但这类操作负担并未使其全面落后——有强模型时可获得最高成功率，不过需支付额外的软件与产物管理代价。

## 7. 优点（方法或实验设计的亮点）
- **系统级、端到端的统一评估**：从自然语言直接到仿真验证的全流程评估，三种配置共享任务输入、预算限制和评估协议，使"结构 vs. 自主性"的比较在受控条件下具备较好公平性。
- **基准设计兼具宽广度与区分度**：52个任务覆盖3个来源域和7种物理机制；三种配置间的成功率差异（0%到95%）证明基准具有足够判别力。
- **失败归因与透明度**：完整的轨迹日志（提示词、设计模式或代码、仿真输出、分数、评估说明）使每类失败模式可追溯、可分类，为理解系统瓶颈提供了深层依据。
- **物理一致性前置验证**：类型化schema能在仿真执行前进行字段级物理一致性校验，将"布局/绑定"类错误与仿真数值错误区分开，定位更精准。
- **显式关注token效率**：以"每百万token成功数"作为核心度量，引入了科学智能体中常被忽略的计算成本维度。
- **"失败经验复用"视角**：实验证明失败轨迹（而非仅成功轨迹）可作为有价值的设计资源，为后续科学智能体记忆研究提供了可复用的思路。

## 8. 不足与局限
- **单次运行缺乏统计涨落估计**：每种模型–配置–案例仅执行一次，无法估计方差，也无法对结论差异（如Gemini 3.1下三配置差异不大）进行统计显著性判断。
- **物理覆盖范围有限**：HALO-Bench主要覆盖周期性纳米光子结构（基于RCWA仿真），不涵盖非周期、三维自由形态或需全波FDTD等更高保真度求解的场景。
- **仿真精度局限**：所有设计均基于仿真验证，不等于实验制备和测量；作者也承认终版设计需经应用特定的更高保真度验证。
- **记忆检索实验的目标设定有明确边界**：其评估对象是"基线需多轮才能解决的案例"的收敛加速，而非基准整体成功率提升；且同任务Top-1对照条件无法代表真实首次部署场景。
- **文本与模式检索空间的局限**：虽然模式辅助优于纯文本的动机合理，但附录未在正文中给出直接对比（检索方法细节在补充材料）。
- **评估器/规划器同模型偏差风险**：由于评估器与规划器使用同一底层模型，失败评估本身可能继承相同的物理理解盲区（作者已作必要声明）。
- **模型版本非公开**：预印本中（Gemini 3.1 Pro Preview、Claude Opus 4.8 / Sonnet 4.6等）标注为2026年及未来版本，其结论对当前可用模型的即时参考价值有一定限制。
