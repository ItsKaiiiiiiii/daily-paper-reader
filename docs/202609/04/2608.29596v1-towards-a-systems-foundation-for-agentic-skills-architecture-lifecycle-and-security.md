## 摘要
自主大型语言模型（LLM）智能体在复杂、长周期任务上部署时，日益面临可靠性、上下文消耗和执行稳定性瓶颈。虽然整体式提示工程和无状态工具调用范式难以扩展，但该领域正迅速收敛于\emph{智能体技能}：一种模块化的过程抽象，将执行知识外部化为可重用、可执行且可移植的工件。本文为智能体技能生态系统建立了统一的系统基础和参考架构。我们将技能形式化为外部化的过程知识，连接高层认知规划与确定性执行环境，并系统性地跨越九个阶段的生命周期描述了其架构：自主发现、编写与表示格式、记忆存储、动态检索与路由、组合与编排、执行与修复、终身适应、经验评估和安全治理。我们进一步审视了市场动态、公共注册表以及新兴的对抗性威胁向量，同时探讨了运行时验证和防御机制。最后，我们跨软件工程、操作系统导航、具身机器人和科学发现类别对系统实现进行了分类，同时强调了持续学习和基准真实性方面的关键开放挑战。本文确立了智能体技能作为构建可扩展、稳健且可验证的自主语言智能体的基础范式。

## Abstract
Autonomous large language model (LLM) agents increasingly face reliability, context consumption, and execution stability bottlenecks when deployed on complex, long-horizon tasks. While monolithic prompt engineering and stateless tool-calling paradigms struggle to scale, the field is rapidly converging toward \emph{agentic skills}: modular procedural abstractions that externalize execution knowledge into reusable, executable, and portable artifacts. This paper establishes a unified systems foundation and reference architecture for the agentic skills ecosystem. We formalize skills as externalized procedural knowledge bridging high-level cognitive planning with deterministic execution environments, and systematically delineate the architecture across a nine-stage lifecycle: autonomous discovery, authoring and representation formats, memory storage, dynamic retrieval and routing, composition and orchestration, execution and repair, lifelong adaptation, empirical evaluation, and security governance. We further examine marketplace dynamics, public registries, and emerging adversarial threat vectors, alongside runtime verification and defense mechanisms. Finally, we categorize system implementations across software engineering, operating system navigation, embodied robotics, and scientific discovery, while highlighting critical open challenges in continual learning and benchmark realism. This work establishes agentic skills as a foundational paradigm for building scalable, robust, and verifiable autonomous language agents.

### 一、核心问题与整体含义（研究动机与背景）

**核心痛点：**
- 自主 LLM 智能体在长时程（long-horizon）、复杂任务上部署时面临三重瓶颈：
  1. **可靠性下降**：任务越长，性能衰减越严重；早期规划错误会级联放大，且智能体缺乏有效的"无恢复机制"（no-recovery regime），陷入死循环或递归耗尽。
  2. **上下文消耗**：整体式提示（monolithic prompting）将所有指令放入上下文窗口，token 成本随指令集增长，且无法按需加载。
  3. **经验无法累积**：过程性知识被锁在会话结束即丢弃的转录日志（transcripts）中，每次执行同一任务都从零重新推导。

**现有替代方案的不足：**
- **上下文注入**（把程序放入 prompt）→ 高 token 成本，无法按需加载。
- **微调**（把程序写入权重）→ 工具、API 和组织规范变动速度远超再训练周期。

**本文的核心主张：**
- 收敛到 **智能体技能（Agentic Skills）** 这一新范式：将执行过程性知识外部化为可重用、可移植、可执行的工件，在模型之外存储。
- 该范式的核心价值在于：
  - 将高层认知规划与确定性执行解耦；
  - 跨会话持久化；
  - 按需动态加载；
  - 无需重训练即可修订。
- 本文旨在为技能生态系统提供**统一的系统基础和参考架构**，覆盖架构、生命周期与安全三个维度。

### 二、方法论：核心思想、关键技术与公式

#### 2.1 形式化定义
- **技能六元组**：s = ( A, I, C, T, π, E )
  - A：激活条件（activation condition）
  - I：过程性指令（procedural instructions）
  - C：适用性约束与环境前置条件
  - T：可访问的工具与接口（tools/interfaces）
  - π：执行策略或过程控制流（execution policy/procedural control flow）
  - E：预期状态转移或后置条件效应（post-condition effects）

- **技能的三个核心系统级判据**：
  1. **封装模块性**：独立可版本化、可验证、可更新，不改变模型权重或全局 harness 代码。
  2. **晚绑定动态调用**：由激活条件 A(xt, g) → {0,1} 动态求值决定是否被加载，而非常驻上下文。
  3. **过程性状态变换**：编码可复用的可操作知识（如何执行、如何处理错误），而非声明性事实。

- **边界辨析**：与系统 prompt、原子工具、工作流/DAG、情景记忆等概念划清界限（表1）。

#### 2.2 核心定义与公式
- **定义1（技能）**：六元组，核心是"可复用的过程抽象"。

### 六、主要结论与发现

1. **技能形式的抽象统一是必要且可行的**：外部化的可执行过程技能可以同时实现持久化、模块化、运行时组合以及免训练修改——这是提示、工具、工作流和情景记忆无法同时提供的属性。

2. **技能实用效用与环境的反馈带宽成反比**：在高反馈、模式可验证的环境中（如 CLI 带 stderr 回溯），静态技能几乎没有帮助；这一"环境反馈带宽假设"界定了技能适用的边界。

3. **自然语言指令是"安全盲区"**：所有现有表示格式都未能对 I 和 A 做预执行验证；标记、注释、多模态层等文本通道可绕过静态扫描劫持智能体。

4. **开池检索噪声带来的技能"脆弱性"是严重问题**：在理想条件下（oracle 加载），技能很大；在自主检索条件下（34K 技能池）性能毁灭性下降。

5. **单智能体的容量相变**：超过临界技能数后，单智能体路由选择精度突然崩塌——推动分区架构的合理性。

6. **技能与记忆之间的并发学习关系仍需解决**：共同进化产生的漂移和技能漂移仍是开放挑战——不充分的验证导致越修越差。

7. **生命周期安全牵涉五个环节，不仅是执行阶段**：从准入（恶意准入）、检索（Sybil/路由劫持）、组合（良性组合攻击）、到运行时（动态载荷注入）和演化（协同进化投毒）均为攻击表面。

4. **注意到了工程实践盲点**：提出了"元数据-only 路由失明"、"容量相变"、"环境反馈带宽假说"等对系统建设者有直接借鉴意义的设计洞察。

5. **对安全的覆盖超越 token 级**：识别出技能生态特有的供应链和生命周期攻击面（描述-实现差距、良性组合攻击、依赖混淆安装等），其威胁分类映射到六元组组件的做法便于在蓝图层次开展防御。

6. **恰当地划出已知负面结果**："When skills don't help" 这类反直觉的实证结论对防止领域内盲目乐观很关键。

### 八、不足与局限

1. **缺少自有实证和消融**：没有实验数据支撑其设计选择（如九个阶段划分的合理性或比较优势）；引用其他系统的经验结论仍非对本文框架的直接验证。

2. **文献时效性与校验风险**：作者大量引用 2026 年的 arXiv 预印本（部分参考文献标记为 2026 年发布），这些工作可能未经同行评审，论文写作时间与其引用的文献存在很大时间重叠（预先反映），存在引用偏差风险。

3. **代表性局限**：
   - 代码和技能主要是 Python/JavaScript，以及英语语料库为本底；
   - 集中在软件、Web、OS 导航和数据；对具身/机器人讲得很简略，也明确说没有覆盖物理动力学/特定硬件时序限制；
   - 对市场平台内部私有部署细节（私有关键技术）没有观察渠道，分析公共注册表可能不反映业界全貌。

4. **跨系统和跨表可比性有待加强**：表格中系统性能数字来自不同的评估环境（例如类 PPO 门相对人评），很难推动去比较一个系统与另一个系统；仍需标准化基准。

5. **有些开放挑战指出方向但没有给出解决方案**：例如零信任安全架构和程序验证仍是一种建议，并未解决代码+自然语言混合验证的复杂度问题——对这些挑战，作者提出的方面性的方向仍属于工作量。

6. **技能的通用定义主要以"独立工件"为核心**，但对"技能系统中设计选择（如何切分技能、粒度选择）"的系统化研究较少展开，更多以描述系统状态呈现，无法从深层设计空间的角度回答"如何做决定"的问题。
