## 摘要
视觉-语言-动作（VLA）模型将视觉观察和语言指令直接映射为机器人动作，但长时程任务需要的不仅仅是动作预测。代理必须在物理状态演化过程中协调感知、规划、执行、进度验证与恢复。动作预测或模型生成的技能决策本身并不能保证提议的操作在当前状态下有效，也不能保证其结果会被验证。我们提出具身技能（EmbodiedSkills），这是一个统一框架，将每个技能决策视为执行提议：运行时在执行前检查其先决条件，并在执行后验证结果。一个共享的可执行技能接口将高层技能选择、受限的低层VLA执行以及动作后验证连接在单个代理循环中。由于该接口保持固定，低层VLA策略可以被替换或调整，而无需更改代理循环。该接口还将规划、执行、验证和恢复事件记录为结构化轨迹，为各组件提供监督，并在交互反馈可用时支持可选的在线适应。我们在RoboTwin 2.0和LIBERO上使用Qwen3-VL与OpenPI/pi0.5实例化了EmbodiedSkills。任务适配的低层VLA策略在50个RoboTwin 2.0任务中平均成功率达86.20%，在四个LIBERO套件中平均成功率达97.40%。这些结果确立了EmbodiedSkills中所用任务适配低层VLA策略的执行性能。在四个依赖记忆的RMBench任务上，相同的任务适配执行方法实现了12.5%的平均成功率。该框架提供了一个可训练且可检查的代理层，用于将这些策略转化为闭环具身系统。

## Abstract
Vision-language-action (VLA) models map visual observations and language instructions directly to robot actions, but long-horizon tasks require more than action prediction. An agent must coordinate perception, planning, execution, progress verification, and recovery as the physical state evolves. An action prediction or a model-generated skill decision does not, by itself, guarantee that the proposed operation is valid in the current state or that its outcome will be verified. We propose EmbodiedSkills, a unified framework that treats each skill decision as an execution proposal: the runtime checks its prerequisites before execution and verifies the outcome afterward. A shared executable-skill interface connects high-level skill selection, bounded low-level VLA execution, and post-action verification within a single agent loop. Because this interface remains fixed, low-level VLA policies can be replaced or adapted without changing the agent loop. The interface also records planning, execution, verification, and recovery events as structured trajectories, which provide supervision for individual components and can support optional online adaptation when interactive feedback is available. We instantiate EmbodiedSkills with Qwen3-VL and OpenPI/pi0.5 on RoboTwin 2.0 and LIBERO. Task-adapted low-level VLA policies achieve an average success rate of 86.20% across 50 RoboTwin 2.0 tasks and 97.40% across the four LIBERO suites. These results establish the execution performance of the task-adapted low-level VLA policies used in EmbodiedSkills. On four memory-dependent RMBench tasks, the same task-adapted execution approach achieves 12.5% average success. The framework provides a trainable and inspectable agent layer for turning these policies into closed-loop embodied systems.

### 研究动机
- **VLA 模型的局限**：VLA（Vision-Language-Action）模型擅长将视觉观察和语言指令直接映射为机器人动作，但在**长时程任务**（long-horizon tasks）中，仅靠“动作预测”是不够的。
- **闭环智能体能力缺失**：机器人执行如“将容器放在盘子上”这类任务时，还需要具备感知场景、识别目标物体、生成子目标、判断当前状态是否可执行、调用低层策略、验证执行结果以及失败恢复等能力。已有 VLA 策略和 LLM 机器人智能体只覆盖了这些环节的一部分：
  - 端到端 VLA 策略将中间任务决策隐式化，失败后难以诊断是物体定位、子目标选择、低层动作、验证还是恢复环节出现问题。
  - LLM 智能体虽然能显式输出工具调用和推理步骤，但“显式决策”不等于“物理上可执行”——提议的技能可能与当前阶段不兼容、依赖过期观测、缺少必要参数或执行后无法产生预期结果。
- **核心挑战**：如何在“模型层级决策”与“物理执行”之间建立桥梁，使提议的操作在执行前得到检查、执行后得到验证，并让证据反馈给后续决策和学习。

### 整体含义
论文提出 **EmbodiedSkills**，一个用于**编排（Orchestrating）、训练（Training）与部署（Deploying）** 的 VLA 智能体统一框架。核心思想是：将每个技能决策视为一个“执行提案”，由运行时系统在执行前检查其前置条件、在执行后验证其物理结果，避免模型生成的文本决策被盲目转换为物理动作。框架提供可训练、可检查的“智能体层”，帮助将低层 VLA 策略转化为可靠的闭环具身系统。

## 2. 论文提出的方法论

### 核心思想
- **技能即执行契约（Skill as Execution Contract）**：每个“具身技能”被定义为带有类型化输入输出、前置条件和后置条件的可执行单元，而非仅仅作为规划器的“词汇”。
- **策略与运行时分离（Policy–Runtime Separation）**：
  - 高层策略（如 VLM）只负责“提议”下一步技能决策；
  - 独立的守护运行时（Guarded Runtime）负责检查该决策的合法性（阶段兼容性、参数完整性、构件新鲜度、动作数值有效性、状态转移合法性），通过后才允许执行；
  - 执行后，验证器检查子目标是否达成，反馈结果作为下一轮决策依据。
- **统一接口**：固定不变的可执行技能接口连接高层技能选择、受限的低层 VLA 执行与动作后验证。低层 VLA 策略可以在不修改智能体循环的前提下替换或调整。
- **结构化的轨迹记录**：规划、执行、验证、恢复事件被记录为统一 schema 的结构化轨迹，作为组件训练监督来源，也可支持可选的在线策略优化。

### 关键技术细节
- **智能体状态与技能决策**：
  - 方法级状态为：\( s_t = (z_t, M_t, H_t) \)，其中 \( z_t \) 为当前阶段，\( M_t \) 为任务构件集合，\( H_t \) 为有序循环轨迹。
  - 高层策略从状态依赖的动作集中选择结构化决策：\( d_t \in \{\text{RunSkill}(k,q), \text{AdvanceStage}, \text{FinishRun}\} \)。
- **可执行技能契约**：
  - 形式为 \( k = (X_k, Y_k, \text{pre}_k, \text{exec}_k, \text{post}_k, \text{fail}_k) \)，覆盖输入模式、输出模式、前置条件、可执行操作、状态更新规则和失败映射。
  - 构件（artifact）携带来源和新鲜度信息，依赖关系变化时自动失效，防止陈旧预测授权新的物理动作。
- **六阶段结构化技能空间**：
  - 阶段序列为：Observe（观察）、Plan（规划）、Preflight（预检）、Execute（执行）、Verify（验证）、Recover（恢复）。
  - 并非固定单遍流水线，而是根据状态动态回访旧阶段（如重新观察、重新规划）。
- **守护运行时转移（Guarded Runtime Transition）**：
  - 技能提议需通过 \( G_{\text{skill}} \) 检查（阶段匹配、技能属于当前阶段集合、所有前置条件满足）；
  - 前向推进需通过 \( G_{\text{advance}} \)；
  - 终止由独立控制门 \( G_{\text{finish}} \) 控制；
  - 非法决策被记为“阻塞决策”并保留证据，而非静默执行。
- **受限的动作块执行（Bounded Action Execution）**：
  - 低层 VLA 策略将“活动子目标 + 当前观测 + 机器人状态 + 预检证据”映射到一个有界动作块（action chunk）；
  - 一个语义子目标可能需要多个动作块，执行后先获取新证据再决定是继续、推进还是恢复。
- **验证与恢复**：
  - 验证器仅针对当前活动子目标判断语义路径：Advance / Continue / Reobserve / Replan / Recover / Finish；
  - 总体任务成功由环境评估器定义，而非局部子目标判断。
- **模块化接口与训练**：
  - 规划器、选择器、验证器、低层 VLA 策略可独立进行监督微调（SFT），互不阻塞；
  - 训练样本采用与部署一致的输入边界（deployment-consistent），避免训练时出现测试时不存在的证据；
  - 可选在线优化：支持组相对策略优化（GRPO 风格），但论文将其定位为可选优化手段而非主要训练方式。

## 6. 论文的主要结论与发现

1. **低层执行性能**：
   - RoboTwin 2.0 50 个任务上，任务适配的 π0.5 策略达 **86.20%** 平均成功率，超过 LingBot-VA 报告的 π0.5 参考值 82.74%（+3.46 个百分点），且在 50 个任务中有 39 个任务高于参考值。
   - LIBERO 四个套件上平均成功率达 **97.40%**，超过官方 OpenPI 参考的 96.85%（+0.55 个百分点）；最大增益出现在 LIBERO-Long（92.4% → 93.6%），说明长序任务上优势更明显。
2. **消融发现三种机制的重要性和层次**：
   - 去除中间验证：成功率从 86.20% 跌至 48.2%（−38.0 点）；
   - 去除子目标条件化：进一步跌至 34.4%（−51.8 点 vs Full）；
   - 一个子目标仅限一个 32 步动作块：仅剩 19.5%，说明仅语义分解不够，许多有效子目标需要多个有界动作块。
   - 结论：`显式子目标 + 动作后验证 + 自适应延续` 是框架性能的核心来源。
3. **统一接口的跨 benchmark 有效性**：
   - 同一执行接口能同时支持 RoboTwin 2.0（双灵巧臂、域随机化）与 LIBERO（桌面单臂），说明该技能接口不与特定任务分类绑定。
4. **RMBench 记忆依赖任务仍不理想（12.5%）**：正确动作依赖先前交互历史的任务仍构成显著瓶颈。

## 7. 优点

- **思想清晰、定位准确**：准确识别了“VLA 模型的决策能力 ≠ 物理可执行性”这一关键缺口，将技能决策从“模型输出”经运行时验证后升级为“物理动作”，概念划分明确。
- **策略—运行时分离架构有工程价值**：低层策略可替换、高层组件可独立微调、接口固定，模块化程度高，既支持研究迭代又便于工程部署。
- **训练与部署一致性**：强调训练样本与部署时使用完全相同的上下文边界（不泄露未来信息），方法学严谨。
- **诊断性强**：结构化轨迹使失败可以被归因到“规划/验证/执行/恢复”具体环节，优于端到端黑盒策略。
- **受控消融设计较好**：通过固定预算、固定低层策略等设计，分别剥离验证机制、子目标条件化和多块执行各自的贡献，验证了 AgentLoop 的核心设计决策。
- **跨 benchmark 覆盖面较广**：覆盖 50 任务的 RoboTwin 2.0、4 个 LIBERO 套件、4 个 RMBench 任务，任务类型涵盖空间、物体、目标、长序、双臂、记忆依赖等维度。

## 8. 不足与局限

- **任务专家模型而非通用模型**：RoboTwin 2.0 上使用 50 个独立微调的任务专家策略，训练、存储和部署成本显著高于一个通用策略，限制了框架在实际场景中的经济性。
- **依赖底层组件质量**：守卫循环使失败显式化，但不能修正“模式合法但语义错误”的决策——错误的目标定位或子目标仍可通过模式检查并把执行引向错误物理状态。验证同样受遮挡、视觉歧义等影响。
- **延迟开销**：与单遍动作策略相比，额外 VLM 调用与动作后观测引入较大延迟。
- **无真实硬件验证**：所有结果均为仿真环境，未涉及真实机器人的部分可观测性、传感器噪声和接触不确定性。
- **无算力/资源报告**：缺少 GPU 数量、训练时长、单任务微调成本等关键信息，可复现性与成本评估不足。
- **RMBench 上的性能极低（12.5%）**：清楚表明当前任务适配执行方式对记忆依赖类任务的处理能力严重不足，但论文并未展开解释失败模式或提出针对性改进。
- **模块化带来的协调成本**：各模块各自适配时，其行为需在共享接口处保持兼容；长 episode 可能累积规划和执行小误差，导致观测和模型调用次数增加，整体资源消耗上升。
- **在线优化只是“可选”且未经实验验证**：论文虽给出公式化的在线学习目标，但主要结果全部来自离线组件级监督，在线适应部分缺少系统实验支撑。
