## 摘要
以用户为中心的多轮智能体必须根据不断演变的任务情境采取行动，这种情境由变化的用户意图、通过工具获取的事实、缺失的信息和执行约束共同塑造。现有的上下文管理方法改进了对过去交互历史的使用，但很少维护一个显式的情境状态，将已确认事实与任务状态判断分离开来。因此，智能体往往需要从对话痕迹中隐式地推断细粒度的属性、任务依赖关系和约束满足情况。我们提出了意图驱动情境状态（IDSS），这是一个无需训练的框架，在与对话并存的地方维护一个显式的情境状态。IDSS将工具返回值解析为具有来源感知的实体和属性，跟踪用户意图、所需变量、约束和执行状态，并将新事实传播到任务约束中，以更新动作的可执行性。这使智能体能够避免不可行的动作，推进依赖的目标，并重用相关信息，而无需重复搜索原始历史。在八个大语言模型上、三个交互基准上的实验表明，IDSS提高了任务完成率、偏好引导和交互效率，在涉及多实体协调、动态用户约束和约束感知重规划的任务上取得了明显改进。消融实验和错误分析表明，这些改进来自于事实持久化、以意图为中心的状态跟踪和约束建模之间的相互作用。这些结果表明，对于可靠的以用户为中心的多轮智能体，显式情境跟踪为以历史为中心的上下文管理提供了一种有效的替代方案。

## Abstract
User-centric multi-turn agents must act on an evolving task situation shaped by changing user intents, accumulated tool-grounded facts, missing information, and execution constraints. Existing context-management methods improve the use of past interaction history, but rarely maintain an explicit situation state that separates grounded facts from task-state judgments. As a result, agents often need to infer fine-grained attributes, task dependencies, and constraint satisfaction implicitly from dialogue traces. We propose Intent-Driven Situation States (IDSS), a training-free framework that maintains an explicit situation state alongside the dialogue. IDSS parses tool returns into provenance-aware entities and attributes, tracks user intents, required variables, constraints, and execution status, and propagates new facts to task constraints to update action executability. This allows agents to avoid infeasible actions, advance dependent goals, and reuse relevant information without repeatedly searching raw history. Experiments on three interactive benchmarks across eight LLMs show that IDSS improves task completion, preference elicitation, and interaction efficiency, with clear gains on tasks involving multi-entity coordination, evolving user constraints, and constraint-aware replanning. Ablations and error analyses show that these improvements come from the interaction between fact persistence, intent-centered state tracking, and constraint modeling. These results suggest that explicit situation tracking offers an effective alternative to history-centric context management for reliable user-centric multi-turn agents.

### 1. 核心问题与整体含义（研究动机与背景）

- **问题背景**：以用户为中心的多轮智能体（如客服、旅行规划、生活服务助手）需要根据不断演变的用户意图、累积的工具返回事实、缺失信息和执行约束来采取行动。与单轮指令执行或单目标长程规划不同，这类任务对状态维护提出了更高要求。
- **核心痛点**：
  - 用户会在一次对话中引入多个目标，目标之间可能存在依赖或冲突；
  - 偏好往往逐步披露而非一开始就完整给出；
  - 工具返回值可能修正先前的事实，新观察到的事实可能使原有行动路径不可行；
  - 现有方法（如外部记忆、上下文压缩、摘要折叠等）主要帮助减少上下文长度压力，但智能体仍需从压缩后的历史或记忆中隐式重建当前任务状态，事实与状态判断（如意图是否活跃、哪些变量缺失、约束是否满足）没有被显式分离。
- **研究意义**：作者提出显式情境状态跟踪，作为以历史为中心的上下文管理的替代方案，帮助多轮智能体在决策时有一个清晰的、面向行动的任务状态视图，从而避免事实遗漏、意图漂移、过早执行和约束违反。

### 2. 方法论：核心思想、技术细节与算法流程

- **核心思想**：提出 **Intent-Driven Situation States（IDSS）**，一个免训练（training-free）框架，在对话历史之外维护一个显式的情境状态 `Dt = (Ft, St)`，其中：
  - `Ft`（事实层）：存储从工具返回值中解析出的结构化实体和属性；
  - `St`（状态层）：跟踪用户意图、所需变量、约束及其执行状态。
- **公式化**：将传统的仅历史策略 `at = π(Ht, A)` 替换为情境增强策略 `at = π(Dt, Hcomp_t, A)`，其中 `Hcomp_t` 是移除状态已覆盖信息后的紧凑残差历史。
- **事实层（Fact Layer）**：
  - 定义 `Ft = {ei = (type_i, id_i, attrs_i, src_i)}`，其中 `src_i` 为来源（provenance）；
  - 通过确定性解析器将工具返回 `ot` 转换为原子操作序列 `Δt = [δ1, δ2, ...]`，增量更新 `Ft = Ft−1 ⊕ Δt`；
  - 支持 ADD、UPDATE、DELETE、MERGE 四种操作；冲突时按来源可信度解决，工具观测值优先于智能体推断值；同源中较新观测覆盖旧值。
- **状态层（State Layer）**：
  - `St = (It, Vt, Ct)`，分别对应意图集、变量集、约束集；
  - 意图状态为 ACTIVE / PENDING / COMPLETED / BLOCKED，意图依赖关系由任务语义和执行前置条件推断；
  - 变量标注为 askable（询问用户）、retrievable（调用工具）、derivable（从事实推断），并标记已知/未知；
  - 约束标记为 satisfied（满足）、unsatisfied（未验证）、violated（违反）。当约束违反时，关联意图被标记为 blocked，并记录事实依据和约束链。
  - 智能体在每次回复前添加 `<state>` 块来更新状态层，该块在用户可见前被移除，并在下一轮重新注入提示。
- **跨层约束传播**：当事实层更新时，确定性属性比较会重新评估约束；约束违反则阻止相关意图，同时激活可行的备选路径。例如，工具返回的 fare_class = basic_economy 违反修改航班的约束，则 blocking modify_flight 意图，激活 cancel_and_rebook 意图。
- **无需额外 LLM 调用**：事实层更新是确定性解析，状态层在生成回复过程中维护，不增加推理开销。

### 3. 实验设计：数据集、基准与对比方法

- **三个交互基准**：
  - **τ-bench**（Retail 和 Airline 两个领域）：评估工具调用、规则遵循和多轮任务完成，使用 Avg@4 和 pass@4 指标；
  - **VitaBench**（Delivery、In-store、OTA、Cross-domain 四个子任务）：生活服务场景，强调时空推理、多实体协调与跨域状态继承，使用基于 rubric 的 0–100 分制评分；
  - **UserBench**：评估未充分指定的用户请求下的偏好引导能力，使用 Score、CER（Correct Exist Rate）、PE（Preference Elicited）指标。
- **评估 LLM**： GPT-5.5、GPT-4.1、GPT-4o、Claude-4.5-Sonnet、Gemini-2.5-Pro、DeepSeek-V3.2、GPT-4.1-mini、Gemini-2.0-Flash 共 **8 个模型**。
- **用户模拟**：使用 GPT-4.1 作为用户模拟器，每个任务运行 4 次独立试验并取平均。
- **对比方法**：
  - ReAct（标准智能体范式，保留完整轨迹）；
  - StateAct（在每步生成 goal/state/thought/action，但未分离事实与状态判断）；
  - ReSum（周期性调用外部摘要器压缩历史）；
  - IterResearch（将工作区重构为演化的报告，丢弃原始交互痕迹）；
  - U-Fold（动态意图感知摘要 + 紧凑工具日志提取）。

### 6. 主要结论与发现

- IDSS 在三个基准、八个 LLM 上均取得最强或接近最强的整体性能，并一致优于 ReAct、U-Fold 等基线；
- 在 τ-bench Airline（约束密集、多转依赖强）上提升最明显，超过最强基线 U-Fold 平均 1.5 Avg@4 和 2.0 pass@4；
- VitaBench 的 OTA 和 Cross-domain 任务上优势最明显（多实体协调、跨服务组合和状态继承场景）；
- UserBench 上 IDSS 全面领先 Score 和 CER（相对提升约 4.6% 和 4.0%），表明更好的意图/变量/约束跟踪有助于更有针对性地澄清偏好；
- 消融实验显示：事实层对 τ-bench 贡献最大（去除后 Avg@4 下降 2.2 点），状态层对 UserBench 贡献最大（Score 下降 8.4%），VitaBench 同时依赖两个层，约束建模提供一致的小幅增益；

- 效率方面，IDSS 零额外 LLM 调用，以最少交互轮数（7.8）取得最高平均性能（50.5%）；
- 总体结论：显式情境跟踪为以用户为中心的多轮智能体提供了一种有效、通用的上下文管理替代方案。

### 7. 优点

- **方法创新**：将对话管理从“以历史为中心”转变为“以情境为中心”，显式分离了工具确认的事实与任务状态判断，这在现有工作中较少见；跨层约束传播机制能够自动阻止不可行的路径并激活替代方案，具有较好的可解释性（记录阻塞理由和证据链）；
- **免训练设计**：事实层采用确定性解析，状态层在回复生成中维护，不需要额外 LLM 调用、不需要微调，即插即用，跨域适配成本低；
- **实验严谨性较好**：覆盖 8 个 LLM、3 个基准、6 种对比方法，外加消融、错误分析、效率分析和案例研究，多维度验证了方法的有效性；
- **通用性强**：在不同模型（GPT 系列、Claude、Gemini、DeepSeek）上均一致提升，说明方法不依赖特定后端模型；
- **工程落地性好**：通过压缩历史（将工具返回替换为事实层引用）同时兼顾了信息保留度和上下文长度控制。

### 8. 不足与局限

- **应用范围有限**：IDSS 设计针对工具返回为可解析文本字段的交互任务，对多模态观测、非结构化输出或更复杂工具环境的适配未展开；
- **实验评估使用模拟用户**：GPT-4.1 作为用户模拟器虽便于可复现性和控制变量，但与真实用户的自然表达、纠正行为和偏好披露方式存在差异，结论的外部效度有待真实用户实验验证；
- **样本量偏小**：每个任务仅 4 次独立试验，缺少置信区间和显著性检验，对性能差异的统计可靠性存疑；
- **状态维护依赖模型指令遵循能力**：状态层由 LLM 在生成过程中更新，较弱的模型可能产生不完整或不一致的状态块，从两个较小模型（GPT-4.1-mini、Gemini-2.0-Flash）的较小提升幅度中可见端倪；
- **约束建模的确定性**：约束状态更新依赖确定性属性比较，当约束需要语义理解或涉及模糊条件时，可能无法准确评估；
- **未解决的错误类型**：约束违规错误率变化不大（5%–8%），表明部分违反规则源于模型自身的规则理解不足，而非状态缺失；
- **实际部署风险**：作者在伦理声明中指出，IDSS 不能消除工具错误输出、模型幻觉或高风险场景下不当部署的风险，需要人工监督和安全防护措施。
