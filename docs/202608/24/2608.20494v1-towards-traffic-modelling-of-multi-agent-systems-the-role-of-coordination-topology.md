## 摘要
多智能体LLM系统是一种新兴的网络化工作负载，其快速部署引发了对它们所产生流量模式的疑问。与传统应用相比，这些系统在内部生成请求：单个用户任务可触发一个结构化的模型调用序列，其时机由协调逻辑而非用户到达率决定。目前尚不清楚为人类驱动工作负载设计的经典流量模型是否适用于这一场景。我们提出了一种对LLM调用到达间隔时间分布的经验表征，覆盖顺序、星型和全网状智能体协调拓扑，使用多层测量框架，每种拓扑重复运行500次。我们发现，拓扑从根本上塑造了到达LLM后端的请求过程：扇出协调引入了顺序执行中不存在的结构双峰性，而推理阶段组件最适合用对数正态分布描述，泊松指数零模型在所有拓扑中均被断然拒绝。这些差异会传播到推理和网络层面的指标。该框架和分析流程已在 https://github.com/dlamagna/agentraffic 公开提供。

## Abstract
Multi-agent LLM systems are an emerging networked workload whose rapid deployment raises questions about the traffic patterns they generate. Compared to conventional applications, these systems generate requests internally: a single user task can induce a structured sequence of model calls whose timing is governed by coordination logic rather than by user arrival rate. It is not clear whether classical traffic models, designed for human-driven workloads, apply to this setting.   We present an empirical characterisation of LLM-call interarrival time distributions across sequential, star, and full-mesh agentic coordination topologies, using a multi-layer measurement framework over 500 repeated runs per topology. We find that topology fundamentally shapes the arrival process of requests to the LLM backend: fan-out coordination introduces a structural bimodality absent in sequential execution, and the reasoningphase component is best described by a log-normal distribution, with the Poisson exponential null model decisively rejected across all topologies. These differences propagate to inference and network level metrics. The framework and analysis pipeline are released openly at https://github.com/dlamagna/agentraffic.

## 论文总结：迈向多智能体系统的流量建模：协调拓扑的作用

### 1. 论文的核心问题与整体含义

- **研究背景**：多智能体 LLM（大语言模型）系统正在成为一种新兴的网络化工作负载。与传统的由人类用户请求驱动的应用不同，多智能体系统在内部主动生成请求——单个用户任务可触发一串结构化的模型调用，其时机由协调逻辑（如消息传递、并行分发、结果聚合）而非用户到达率决定。这一特性对经典流量模型（如泊松到达模型）是否依然适用提出了根本质疑。
- **核心研究问题**：**多智能体系统的协调拓扑（Coordination Topology）是否以及在多大程度上塑造了 LLM 调用到达过程（Arrival Process）的统计特征？** 具体而言，不同的拓扑结构是否会导致显著不同的请求到达间隔时间（Inter-Arrival Time, IAT）分布？
- **整体含义**：如果网络流量模型建立在错误的到达过程假设上，那么网络规划、容量设计、负载均衡、限流等基础设施决策都可能出现偏差。历史表明，Web 流量、数据中心流量等新工作负载都曾推翻旧有假设（如泊松分布、自相似性发现等）。本文延续这一实证传统，在智能体流量成为主导负载之前，对其流量特性进行早期刻画，为未来建模和网络设计提供基础。

### 2. 论文提出的方法论

- **核心思想**：采用**受控实验 + 多层级测量**的实证方法，将拓扑作为唯一的设计变量，观察其对 LLM 调用到达过程的影响。以 **LLM 调用的到达间隔时间（IAT）** 作为主要流量指标，同时收集 TCP 和底层包级别指标作为跨层验证。
- **测量框架架构（AgenTraffic）**：
  - 使用 **AgentVerse** 作为智能体工作流框架，将多智能体问题解决组织为结构化阶段（招募、讨论、共识、评估）。
  - 部署三个容器化服务：LLM 后端（vLLM AsyncLLMEngine + Llama-3.2-3B）、编排器（Orchestrator）、工作智能体，通过 Docker 桥接网络连接。
  - **四层同步观测**：应用层（调用延迟、IAT）、模型服务层（令牌吞吐、并发数）、容器层（CPU/内存/接口字节）、网络层（TCP 连接事件、包时序、字节率）。所有层共享同一时间轴和智能体标识，实现跨层关联分析。
  - 指标通过 Prometheus、Jaeger、cAdvisor、tcpdump 等工具采集。
- **三种协调拓扑**：
  1. **顺序（Sequential）**：智能体按固定顺序逐一调用。
  2. **星型（Star）**：指定求解者先发言，随后所有剩余智能体作为并行评审者同时被分发调用。
  3. **全连接（Full Mesh）**：每一轮中所有 N×(N-1) 个有向对等消息对并发提交。
- **统计分析方法**：
  - 对 IAT 数据使用 **3 × IQR 上尾栅栏**剔除极端异常值。
  - 为推理阶段分量（IAT > 50 ms）拟合三种候选分布：**指数分布**（泊松到达的零模型）、**Weibull 分布**、**对数正态分布**。
  - 使用 **AIC（赤池信息准则）** 和 **KS（Kolmogorov-Smirnov）统计量**进行模型选择与比较。
  - 通过子采样（n=50/100/200）在不同样本量下检验模型排名的稳健性。

### 6. 论文的主要结论与发现

1. **拓扑根本性塑造到达过程**：三种拓扑产生了截然不同的 IAT 分布。顺序拓扑呈均质的多秒级到达过程（均值 6.23 s，中位数 4.56 s）；星型拓扑呈**双峰分布**（中位数跌至 0.41 ms，但 p95 高达 20.74 s，53.3% 的间隙小于 50 ms）；全连接拓扑时间压缩更严重（均值 1.09 s，中位数 236 ms，38.2% 的到达间隙小于 50 ms）。
2. **结构双峰性是扇出协调的特征**：星型和全连接拓扑的 IAT 分布呈双峰结构，50 ms 低谷处可区分两个分量——扇出分量（IAT ≤ 50 ms，由并行分发调用引起）和推理阶段分量（IAT > 50 ms，反映模型生成时间与上下文累积）。
3. **推理阶段分量符合对数正态分布**：在所有三种拓扑中，对数正态分布取得最低 AIC；在顺序和星型拓扑中 KS 统计量也最小。指数分布（泊松零模型）在所有拓扑中被断然拒绝，说明推理阶段的到达过程**并非无记忆过程**。对全连接拓扑，Weibull 对峰拟更精确而 AIC 较高，但对数正态总体上更能描述完整分布。子采样稳健性测试确认该排名在较小样本量（n=50 起）下依然成立。
4. **拓扑效应跨层传播**：从应用层的 IAT 分布、中位延迟、突发比例，到推理层的并发程度、令牌吞吐，再到网络层的 TCP 字节率，均有系统性的差异（如星型比顺序的提示令牌吞吐提升 34%，全连接提升 344%）。
5. **单一参数族无法描述完整到达过程**：星型和全连接的实际到达过程是混合分布，需要对扇出和推理阶段分别建模。
