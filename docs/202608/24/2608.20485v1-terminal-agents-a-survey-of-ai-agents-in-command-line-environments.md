## 摘要
大型语言模型智能体日益通过终端进行操作，然而现有综述将终端介导的行为分散在软件工程、工具使用和计算机使用研究中。我们将终端智能体视为这样一种系统：其主导的、推动进展的行为—观察循环通过终端命令执行、文本反馈和状态化环境交互来介导。以终端介导执行为组织视角，本综述确立了工作负载层面的边界，并通过七维终端能力画像将系统架构、能力获取和评估联系起来。我们的综合研究表明，实际行为是由模型、接口、框架、运行时和环境共同塑造的。可执行轨迹将学习扎根于行动后果、验证和恢复，而主流评估则强调最终结果，并对过程质量、恢复和治理的覆盖不均衡。受限的固定条件诊断揭示了两个启示：基准测试家族暴露不同的过程信号，而匹配的系统比较揭示了依赖基准的性能以及组件归因的局限性。这些发现促使在可回放轨迹和过程级证据的支持下，明确报告系统和运行时条件。该框架为跨软件工程和新兴应用领域研究终端介导的智能体提供了统一基础。

## Abstract
Large language model agents increasingly act through terminals, yet existing surveys disperse terminal-mediated behavior across software engineering, tool use, and computer-use research. We regard terminal agents as systems whose dominant progress-bearing action--observation loop is mediated by terminal command execution, textual feedback, and stateful environment interaction. Using terminal-mediated execution as an organizing lens, this survey establishes workload-level boundaries and connects system architecture, competence acquisition, and evaluation through a seven-dimensional terminal competence profile. Our synthesis shows that realized behavior is jointly shaped by the model, interface, harness, runtime, and environment. Executable trajectories ground learning in action consequences, verification, and recovery, whereas prevailing evaluations emphasize final outcomes and expose process quality, recovery, and governance unevenly. Bounded fixed-condition diagnostics illustrate two implications: benchmark families expose different process signals, and matched system comparisons reveal benchmark-dependent performance and limits of component attribution. These findings motivate explicit reporting of system and runtime conditions, supported by replayable traces and process-level evidence. The framework provides a unified basis for studying terminal-mediated agency across software engineering and emerging application domains.

## 6. 主要结论与发现

### 6.1 关于行为塑造

- **终端智能体行为由模型、接口、工具架、运行时和环境联合塑造**，工具架外环设计（上下文管理、观察格式化、重试策略、权限策略）是影响性能的系统组件，而非中性的实现通道。

### 6.2 关于能力获取

- **可执行轨迹将学习扎根于行动后果、验证和恢复**，但当前获取过程集中在**成功的仓库修复工作流**，对环境管理、持久状态、恢复和治理的覆盖不足。
- 失败中心轨迹和恢复路径对于学习诊断和适应能力至关重要，但往往在成功轨迹过滤中被移除。

### 6.3 关于评估

- 主流评估强调**最终结果**，对过程质量、恢复和治理的暴露**不均衡**。
- 基准家族在过程暴露上存在显著差异：
  - P2（有用反馈使用率）在所有基准中均在76–82%范围内，说明局部反馈使用普遍较好。
  - P5（最终窗口验证率）差异大：BashArena 66.2% vs Terminal-Bench 29.5% / SetupBench 36.6% / LongCLI-Bench 23.8%，说明基准条件显著影响过程暴露。
  - SetupBench前置环境启动、LongCLI-Bench结合低结果与长时间交互需求、BashArena增加状态错误和治理相关行动的可见性。

### 6.4 匹配系统诊断

- **SWE-agent在所有基准×模型条件下解决率最高**，但差距幅度随基准变化：Claw-SWE-Bench Lite上差距最大21.25个百分点，SWE-bench Lite上最多7.00个百分点。
- **OpenHands和mini-SWE-agent的相对排序跨基准反转**：OpenHands在Claw-SWE-Bench Lite上较高，但在SWE-bench Lite上较低。
- **Flash与Pro模型变体**在所有配对比较中均无显著差异（所有Holm校正后p值≥0.4，所有Bootstrap区间含零），但Pro在5/6个系统—基准配对中有更高的平均wall-clock时间，且无输出增益，说明更强的模型推理并不自动转化为更好的终端智能体表现。

### 6.5 过程信号

- 规则匹配的调用失败率（P1）在固定配置下为0.0%，说明狭义的动作制定故障罕见；更广泛的问题通过语义/状态相关信号暴露。
- P7治理触发率在所有基准中低于5%，但高触发率并不一定意味着违规（如sanitize-git-repo案例中的授权搜索）。

## 7. 优点与亮点

### 7.1 方法框架亮点

- **统一的执行基底视角**：清晰区分了“终端作为访问表面”与“终端作为执行基底”，提供了可操作的工作负载边界测试，避免了表面CLI访问被误纳入。
- **七维终端能力画像**：提供了一个跨架构、获取和评估的公共分析语言，维度设计有清晰的构造逻辑（根据控制对象、所需证据和偏离反应分组）。
- **四层架构分析**：系统化了接口、运行时、控制/治理、工具架/上下文的责任分配，避免了将智能体简化为单个模型。

### 7.2 诊断实验亮点

- **有界固定条件设计**：通过固定模型、解码参数和任务身份，隔离了基准和系统配置对结果的影响。
- **确定性指标与LLM辅助指标的区分**：增加了透明度，并明确了辅助指标的局限性。
- **详尽的附录协议**：报告了完整的检索协议、编码模式、判定提示词、置信度过滤和人工审计流程，支持可复现性。
- **轨迹级案例分析**：连接了聚合结果与具体的执行机制，展示了诊断框架的定性解释力。

### 7.3 综述范围的优点

- **跨领域综合**：衔接了软件工程、运维、科学工作流、网络安全、数据工程等多个领域，并提供了TUA-Bench等跨领域基准的讨论。
- **对评估有效性的关注**：区分了“新鲜度”（temporal validity）这一评估有效性属性与行为观察属性，并讨论了污染控制、奖励破解等协议有效性问题。

## 8. 不足与局限

### 8.1 实验覆盖

- **单次运行限制**：每条件仅一次正式运行，无法评估随机变异性；统计检验主要基于配对差异设计而非重复测量方差。
- **模型覆盖窄**：仅DeepSeek-V4-Flash/Pro，未覆盖多模型族，对“模型族影响”的推断有限。
- **过程指标兼容性**：P2/P4/P6的LLM判断存在标签误差风险，LongCLI-Bench语义覆盖率仅68.7%、不确定性28.2%，其估计只能方向性解读。
- **跨基准不具可比性**：基准本身使用不同评估器和任务分布，作者明确指出结果只能在同一基准内解读。

### 8.2 偏差与归因风险

- **组件归因困难**：工具架优化带来的增益可能来自上下文管理、观察整形、重试策略或指令注入等，而非更强的模型推理。
- **领域集中**：综述的诊断和主要实验集中在软件工程相关基准，运维、数据科学等领域的证据碎片化，跨域结论有限。
- **LLM判断循环**：用DeepSeek-V4-Flash来判断DeepSeek-V4-Flash的执行轨迹，存在同源模型偏差，尽管有规则约束和置信度过滤缓解。
- **残留评审盲点**：即便有规则约束，P2/P4/P6的判定标准（如“helpful”“relevance”）仍需语义判断，不同读者可能对判定结果存在异议。

### 8.3 应用限制

- **环境/运行时条件影响未充分分解**：容器镜像、依赖缓存、网络访问、超时等被确认影响成败，但诊断实验未系统控制这些因素。
- **治理维度观察不足**：

治理维度观察不足：P7（治理审查触发率）普遍低于5%，但论文未系统分析高权限、高风险场景下的治理策略具体效果，也未比较不同治理机制（如沙箱强度、审批粒度）对成功率的调节作用；安全关键型任务的治理失败模式（如越权、资源泄漏）在现有基准中暴露有限。此外，云管理、多租户环境等治理敏感场景在实验基准中缺位，导致治理维度结论的外推性受限。

### 8.4 综述框架的自限性

- **定义边界仍存在灰色地带**：终端介导执行的三个边界测试在处理混合界面（如终端与GUI混用、终端与ACI混用）时可能产生误判；当任务核心逻辑由外部脚本或静态配置文件承载，而终端命令仅用于批量触发时，边界测试的判别力下降。
- **七维画像的维度独立性存疑**：七个维度在操作上有重叠，如“恢复与适应”与“运行时与环境管理”在依赖安装失败的修复路径上高度交织；诊断指标P1–P7并非严格一一映射到维度，而是多维复合信号，论文对维度间交互的理论化尚不充分。
- **对能力获取的综述偏向软件工程**：数据来源、学习方法章节中的示例大量来自SWE-bench、Terminal-Bench等代码仓库类任务，对科学计算、网络攻防等领域的能力获取路径描述较弱，可能使“终端智能体能力获取”的通用结论过于乐观。

## 9. 未来研究方向

- **构建理论化的终端能力形成模型**：在七维画像基础上，建立维度之间的依赖关系（如“恢复”依赖“反馈解释”和“状态追踪”），形成可验证的因果路径，避免仅停留在分类描述。
- **发展多模型、多随机种子、多运行次数的过程指标基准**：解决单次运行和单一模型族带来的统计与外部效度问题，形成可重复的终端过程诊断协议。
- **扩展终结端原生评估基准**：增加对长时程任务、环境漂移、部分可观测状态、高风险治理场景的覆盖，推动“过程质量”在评估中的权重。
- **研究终端介导执行下的学习算法**：探索状态化轨迹上的RL与验证器引导优化，如何显式建模恢复、验证和治理行为，而非仅优化最终解决率。
- **跨域迁移研究**：系统比较软件工程、运维、数据科学、安全等领域中终端智能体的能力迁移规律，识别领域特定的接口与治理约束。
- **构建终端智能体安全与治理的实证框架**：量化沙箱、审批、权限最小化等机制在不同威胁模型下的成本与收益，为部署提供依据。

## 10. 结论

本综述以**终端介导执行**为核心视点，提出了终端智能体的操作性定义、七维终端能力画像和四层系统架构分析框架，并将系统架构、能力获取与评估三个脉络统一到一个分析空间中。通过有界固定条件诊断实验，论文展示了基准家族、工具架配置和模型推理强度如何共同塑造终端智能体的行为表现：SWE-agent在匹配比较中领先，而更强的模型推理并未带来稳定的增益；不同基准在过程信号暴露上存在系统性差异，尤其是验证、环境管理和治理维度。论文的贡献在于提供了可复现的诊断协议、清晰的概念边界和丰富的轨迹案例，但其结论受限于单次运行、窄模型覆盖、LLM辅助指标偏差以及软件工程中心的任务选择。未来研究需要在过程级评估标准化、跨域能力模型和安全治理机制上补足，才能使终端智能体真正成为通用计算环境中可靠自主执行的研究与部署对象。
