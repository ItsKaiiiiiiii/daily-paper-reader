## 摘要
基于LLM的多智能体系统通过跨专业智能体交换消息来基于聚合信息做出决策。在智能体之间转发每一条生成的消息会增加应用层流量。然而，这为智能体处理引入了大量输入令牌，可能提高推理延迟和计算开销。现有方法试图通过剪枝智能体或丢弃冗余消息来解决上述问题。然而，这种智能体级或消息级优化导致最终决策的证据支持不足，或仍然包含冗余消息传输。为应对这些挑战，我们提出了BANDMAS，一种多智能体协作框架，将智能体间通信建模为面向任务流量，通过因果启发的回放评估实现高效传输。具体而言，我们通过分析消息的语义特征（如证据和请求）将其分解为多个数据包。系统仅在这些数据包的预测回放贡献超过其资源成本时传输它们。因此，BANDMAS能够在遵循带宽、延迟、截止时间和接收者上下文约束的同时，自适应地调度通信数据包。在冻结的Qwen3-4B流量上，跨越SciFact、HotpotQA和FanOutQA，我们的框架在选定上限下将应用层字节减少53.2%至77.3%，并在所有三个工作负载上取得受限方法中最高平均任务指标。

## Abstract
LLM-based multi-agent systems make decisions based on the aggregated information via exchanging messages across specialized agents. Forwarding every generated message among agents increases application-layer traffic. Yet, it introduces tremendous input tokens for agent processing, potentially raising inference latency and computational overhead. Existing approaches attempt to address the above issues by pruning agents or discarding redundant messages. Nevertheless, such agent-level or message-level optimization results in insufficient evidence supporting for final decisions or still containing redundant message transmissions. To address these challenges, we propose BANDMAS, a multi-agent collaboration framework that models inter-agent communications as task-oriented traffic, which enables efficient transmission via causality-inspired replay valuation. Specifically, we decompose messages into several data packets by analyzing their semantic features such as evidence and requests. The system only transmits these packets if their predicted replay-derived contribution exceeds their resource cost. Consequently, BANDMAS is able to adaptively schedule communication packets while adhering to bandwidth, latency, deadline, and receiver context constraints. On frozen Qwen3-4B traffic across SciFact, HotpotQA, and FanOutQA, our framework reduces application-layer bytes by 53.2\% to 77.3\% at selected caps and attains the highest mean task metric among constrained methods on all three workloads.

## 1. 论文的核心问题与整体含义（研究动机和背景）

- **背景**：基于 LLM 的多智能体系统通过多个角色专业化智能体之间的自然语言消息交换来聚合信息、协作决策。在证据密集型工作流中，各智能体（如读者/专家智能体）分别处理不同的文档或数据流，下游验证者或回答者综合多方发现产出最终结果。
- **核心问题**：全量转发所有生成的中间消息会带来三重代价：
  - **网络带宽浪费**：应用层流量膨胀；
  - **推理延迟与计算开销**：接收者上下文 token 激增，增加模型推理计算量和延迟；
  - **信息冗余**：并非所有消息内容都对最终决策有贡献，消息常包含重复解释、无关信息等。
- **现有方法的不足**：已有工作要么在**智能体层级**（剪枝智能体/边）、要么在**消息层级**（丢弃整条消息）或**token 层级**（压缩上下文）进行优化，但粒度太粗或会破坏语义依赖与可追溯性，无法在接收者生成结果之前判断"哪个内容片段真正对任务有用"。
- **核心矛盾**：消息长度衡量"传输了多少"，语义相似度衡量"内容多贴合任务"，但二者都无法回答"被传输的内容是否真正提升了任务效用"。
- **论文立场**：将智能体间生成的文本视为**具有不同任务价值的应用流量**而非不可分割的对话历史，在接收端引入精细的、可审计的通信控制边界。

## 2. 论文提出的方法论

### 2.1 核心思想

**BANDMAS** 是一个接收端通信控制框架。它在消息生成之后、接收者推理之前介入：
- 将生成的每条自然语言消息**分解为多个语义数据包**（semantic packets，应用层记录，非物理网络包）；
- 通过**离线因果启发的重放评估**（causality-inspired replay valuation）为每个包学习一个"预测决策贡献"分数；
- 在线调度时，**仅传输预测贡献超过资源成本的完整数据包**，同时满足带宽、延迟、截止时间与接收者上下文约束。

### 2.2 关键技术细节

**（1）数据包化（Semantic Packetization）**

- 读者智能体统一输出包含四个字段的受控 JSON 对象：**Claim**（结论）、**Evidence**（证据）、**Uncertainty**（不确定性）、**Request**（请求）。
- 确定性解析器将消息按类型字段切分为语义包；无标记时按句子回退；过短片段合并到前一个包。
- 每个包记录消息 ID、路由、时间戳、截止时间、语义类型、来源、分段顺序、依赖元数据等。
- 使用紧凑 UTF-8 JSONL 序列化器计算真实传输字节数（含包封装开销），而非简单相加有效载荷长度。

**（2）重放因果效应（Replay Causal Effect, RCE）**

对每个包 $p_i$，定义两个对比条件下的边际效用：

- **充分性（sufficiency）**：$\Delta_{suf}(p_i) = U(F_x(\{p_i\}), x) - U(F_x(\emptyset), x)$ —— 单独发送该包的效用增量；
- **必要性（necessity）**：$\Delta_{nec}(p_i) = U(F_x(P_x), x) - U(F_x(P_x \setminus \{p_i\}), x)$ —— 从完整上下文中移除该包的效用损失；
- 最终标签：$\Delta(p_i) = \frac{1}{2}(\Delta_{suf}(p_i) + \Delta_{nec}(p_i))$。

效用函数为任务指标与证据指标的平均（T 与 E 各占 0.5）。正/零/负值分别表示该包有益、冗余、有害。论文明确此标签是上下文依赖、因果启发的**排序目标**，而非无约束的真实因果效应或在线结果信号。

**（3）分裂安全（Split-safe）的预测器**

- 重放仅在 profile/validation 分区离线进行；Freeze 后才允许对 final-test 分区做在线调度。
- 在线决策只允许使用：已生成的数据包、冻结的预测器、已完成的资源观测；**禁止**使用 gold 标签、接收者答案、评测分数或 final-test 的 RCE 值。
- 特征集为：包类型、路由、词法标记、序列化大小、轮次位置等**pre-outcome 元数据**。
- 预测器采用经验贝叶斯式收缩估计：$\hat{\mu}_g = \frac{n_g}{n_g + \alpha}\bar{\Delta}_g + \frac{\alpha}{n_g + \alpha}\pi_g$，层级从全局均值依次细化到包类型-路由、词法标记、大小、轮次等单元，$\alpha = 6$。
- 提供两种评分策略：**causal**（直接用预测 RCE）和**hybrid**（预测 RCE 与词义先验的加权组合，$\lambda_1 = 0.75, \lambda_2 = 0.25$）。

**（4）调度算法（Algorithm 1）**

- 静态模式下：按预测分数排序，贪心逐包检查精确序列化后的批量字节是否超上限，超限则丢弃，不超限则录取；
- 自适应模式增加：截止时间可行性检查、接收者上下文限制检查、基于资源价格（$\lambda$）的净价值判断：
  - $g_t(p) = s_h(p) - \lambda_{b,t}\frac{c_{wire}(p)}{C_b} - \lambda_{\ell,t}\frac{c_{link,t}(p)}{C_\ell} - \lambda_{q,t}\frac{c_{ctx}(p)}{C_q}$
  - 价格按完成的流量/服务观测更新：$\lambda_{k,t+1} = \max(0, \lambda_{k,t} + \eta_k(\frac{u_{k,t}}{C_{k,t}} - 1))$；
- 排名复杂度 $O(n \log n)$，精确批量核算最坏 $O(n^2)$。

## 6. 论文的主要结论与发现

- **传输效率**：在选定上限下，BANDMAS 将应用层字节减少 **53.2%–77.3%**（SciFact 64.2%、HotpotQA 77.3%、FanOutQA 53.2%）。
- **任务效用**：在三个 benchmark 上，causal 调度的平均任务指标**均为所有受限方法中最高**（SciFact 0.679 vs Full 0.617；HotpotQA 0.290 vs Full 0.273；FanOutQA 0.234 vs Full 0.219），即在削减大部分流量的同时**超越不设限的全量传输**。
- **证据质量**：HotpotQA 和 FanOutQA 上 causal 相比语义相关性分别提升证据 F1 0.144 和 0.034（统计显著）；SciFact 证据 F1 与 Full 基本相同（0.398 vs 0.397），说明改善主要出现在互补证据分布场景。
- **因果评分优于语义相关性**：配对检验显示任务指标显著优于语义相关性（三个 benchmark 均 p < 0.001），证明了重放学到的贡献信号比纯词法相关更有价值。
- **包化粒度重要**：类型化语义字段的粒度高 于整消息与句子级别，兼具语义可解释性与组合灵活性。
- **自适应调度的价值在负载饱和后体现**：低负载下静态排序已足够；高负载下自适应价格机制可显著降低 p95 延迟，但以一定效用下降为代价；不保证在所有条件下同时改进延迟和效用。
- **字节节省不等比转化为推理加速**：接收者延迟下降幅度小于流量下降比例，通信效率与计算效率需分别考量。

## 7. 优点

- **问题定位精准**：识别出"智能体级/消息级优化过粗、token 级压缩破坏语义"的中间空白地带，提出"语义包"这一合适的控制粒度，同时保留来源可追溯性与审计能力。
- **因果启发的监督信号设计巧妙**：充分性+必要性的双重对比分别应对"单独有用"与"组合中不可替代"两种互补的失效模式；离线重放、在线冻结的设计将昂贵的反事实计算隔离在部署路径之外。
- **方法边界清晰且诚实**：明确限定 RCE 的因果作用范围、声明依赖闭包不作为强制约束、明确 no-outcome-leakage 边界，方法可信度高。
- **实验设计严谨**：冻结流量隔离了生成不确定性；统一协议匹配基线确保对比公平；任务级聚类推断 + Holm 校正避免了"以包为推断单元"的统计错误。
- **工程细节扎实**：精确序列化批量核算（含封装开销）而非简单加和，体现了通信系统实现层面的深度思考。

## 8. 不足与局限

- **因果估计的固有局限**：RCE 仅在声明的两种对比上下文（孤立发送/整体移除）下有效，无法捕获高阶交互效应；多个可替代包共存时必要性被低估、依赖组合才有用的包被充分性低估。该方法不适用于自适应智能体（如果智能体本身根据历史通信改变行为），可能引入未捕获的混杂因素。
- **实验覆盖有限**：仅 2 个模型代际（Qwen3-4B、Qwen2.5-7B）、3 个证据聚合类 benchmark、受控无损链路；未覆盖有损网络、真实多节点部署、其他模型家族或更复杂的协作拓扑。
- **统计功效不足**：3 个随机种子不足以支撑全部跨策略显著性结论；论文中多处仅以"排名"而非"统计显著差异"表述。
- **基线为复现而非原生执行**：AgentPrune 和 SafeSieve 被改写为适配统一评估协议，可能未完全保留原生方法的全部行为特征。
- **字节统计口径偏乐观**：仅统计应用层紧凑记录，未计入传输层头部、重传、加密开销；带宽节省不完全等同于端到端网络资源节省。
- **预测器能力有限**：经验贝叶斯收缩模型是轻量级元数据查找，Spearman 相关系数仅 0.48–0.54，有用包召回率约 0.52–0.58，说明预测信号仍有较大噪声，存在改进空间。
- **实际部署边界**：不处理拓扑自适应与依赖闭包强制；上下文限制被临时绕过（defer）而非全局优化；GPU 内存/KV-cache 复用等模型服务属性被排除在包级成本之外，延迟结论以 warmed 状态为准，不可直接推广到冷启动场景。
