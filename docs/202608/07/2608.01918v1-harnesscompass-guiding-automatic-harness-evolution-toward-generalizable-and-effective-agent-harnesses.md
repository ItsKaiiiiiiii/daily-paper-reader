## 摘要
工具集设计通过塑造大型语言模型（LLM）在可执行环境中感知、推理和行动的方式，对智能体性能起着关键作用。近期工作提出了自动工具集演化，即从智能体-环境交互中迭代改进工具集。然而，现有方法常常过度拟合演化任务，仅依赖轨迹派生信号，并联合优化工具集组件，导致组件间相互干扰。我们提出HarnessCompass，一种新颖的自动工具集演化框架，其核心为约束演化、主动反馈和组件级优化。HarnessCompass首先对演化施加全局约束，将修改限制为任务无关的工具集变更，从而泛化到演化任务之外。然后，它利用智能体对工具集使用的主动第一人称反馈来增强轨迹派生证据，为演化提供更丰富的信号。最后，它将不同工具集组件的优化解耦，再整合为统一工具集，在保留组件协同作用的同时减少跨组件干扰。在SWE-bench Verified上使用GPT-5.4，HarnessCompass仅用5次演化迭代即将Pass@1从54%提升至66%，在有效性和演化效率上均优于AHE。此外，演化出的工具集能有效迁移到保留任务及其他模型，展现出比先前自动工具集演化方法更强的泛化能力。

## Abstract
Harness design plays a critical role in agent performance by shaping how large language models (LLMs) perceive, reason over, and act within executable environments. Recent work has proposed automatic harness evolution, which iteratively improves the harness from agent--environment interactions. However, existing methods often overfit to the evolution tasks, rely exclusively on trajectory-derived signals, and optimize harness components jointly, causing interference across components. We propose HarnessCompass, a novel automatic harness evolution framework built around constrained evolution, proactive feedback, and component-wise optimization. HarnessCompass first enforces global constraints on evolution, restricting modifications to task-agnostic harness changes that generalize beyond the evolution tasks. It then augments trajectory-derived evidence with proactive first-person feedback from the agent about harness usage, yielding richer signals for evolution. Finally, it decouples the optimization of different harness components before consolidating them into a unified harness, reducing cross-component interference while preserving component synergy. On SWE-bench Verified with GPT-5.4, HarnessCompass improves Pass@1 from 54\% to 66\% in only 5 evolution iterations, outperforming AHE in both effectiveness and evolution efficiency. In addition, the evolved harness transfers effectively to held-out tasks and other models, demonstrating substantially stronger generalization than prior automatic harness evolution methods.

# HarnessCompass 论文总结

## 1. 核心问题与整体含义（研究动机与背景）

- **Harness 的定义与重要性**：Harness 是连接 LLM 与可执行环境的软件层，包含提示词、工具、中间件、记忆和验证例程，直接影响智能体如何感知状态、推理和行动。即使基础模型固定，harness 设计也能显著改变智能体性能。
- **现有自动 harness 演化的局限**：已有方法通过元智能体迭代修改 harness，但存在三个核心问题：
  - **过度拟合演化任务**：元智能体可自由修改 harness，容易记住任务级捷径，导致在保留任务上泛化差。
  - **仅依赖外部轨迹信号**：只能看到"任务失败、在哪里失败"，不知道智能体为何认为 harness 难用，容易错误归因。
  - **组件联合优化导致干扰**：同时修改提示、工具、中间件、记忆等，单个编辑带来的增益会被相互干扰抵消。
- **核心论点**：harness 演化的问题不在于搜索本身，而在于演化过程缺乏结构与约束。一个有效的 harness 应来自"有纪律"的演化：约束可改内容、提供更丰富证据、在合并前隔离修改。

## 2. 方法论

### 总体框架
- HarnessCompass 采用迭代闭环：评估当前 harness → 分析轨迹 → 改进 harness，但通过三个原则约束该循环。
- 所有角色（代码智能体、轨迹分析器、反馈智能体、元智能体）共享同一基础模型，确保增益来自 harness 演化而非更强的分析器。
- 初始化时使用极简 harness H0（仅一个 shell 命令工具和简短系统提示），确保后续出现的所有组件都是由演化循环自己引入和测量的。

### 原则一：约束演化（Constrained Evolution）
- 通过一个全局"泛化门"（Generalization Gate）限制每次候选编辑：
  - **内容要求**：禁止提及具体任务实例、测试函数、私有符号、任务特定关键词匹配；只允许"可迁移决策准则 + 适用条件"，必须能在未见任务上评估。
  - **放置要求**：将编辑分为能力编辑（新增可执行功能，如运行测试、安装依赖）和指南编辑（提供行为指令）。能力编辑必须放在中间件/工具/子智能体代码中；指南编辑必须放在系统提示或记忆中，禁止将指南编码为可执行逻辑。
- 作用：迫使演化学到可复用的设计原则而非任务特定捷径，同时提高演化效率。

### 原则二：主动反馈（Proactive Feedback）
- 在轨迹证据之外，增加智能体的第一人称反馈：
  1. **盲报告（Blind report）**：不透露验证结果，让代码智能体报告 harness 对执行的阻碍和缺失能力，避免事后偏差。
  2. **事后报告（Hindsight report）**：透露验证结果，让智能体将失败归因于 harness、自身推理、任务歧义或环境，用于筛除与 harness 无关的失败。
  3. **调和对账（Reconciliation）**：合并盲/事后报告，记录一致性。
  4. **轨迹锚定（Grounding）**：只有轨迹能支持的反馈才保留；对"新增能力"请求，需轨迹展示出该能力可解决的明确缺口。
  5. **聚合与使用**：按组件分组，依据报告间一致性、受影响任务数、盲/事后一致性计算置信度；作为元智能体的补充证据而非替代，且仍需通过泛化门和后续验证。
- 作用：提供轨迹无法直接捕捉的"为何 harness 难用"信息，同时避免不可靠自述污染演化。

### 原则三：组件级优化（Component-wise Optimization）
- 每轮并行运行两个变体，分别只编辑：
  - **结构组件**：中间件、工具实现、子智能体配置。
  - **指导组件**：系统提示、技能、工具描述、长期记忆。
- 两种变体编辑不重叠的组件空间，因此互不干扰；各自评估后选出 Pass@1 更高的胜者。
- **R³ 合并（Revision, Recombination, Refinement）**：
  - **Revision**：逐一审查败者编辑，只保留独立有益、不与胜者冲突的编辑。
  - **Recombination**：将保留的编辑应用到胜者基线上，文件级冲突时以胜者优先。
  - **Refinement**：删除冗余编辑，保留更确定性组件对应的修改。
- 作用：保留双轨互补收益，消除跨组件干扰和冗余。

### 算法流程（文字说明）
1. 初始化 H⋆ = H0。
2. 对 t = 1..N：
   - 用当前 H⋆ 在搜索任务上执行 k 次 rollout 得到轨迹 T。
   - 从轨迹蒸馏证据 E。
   - 通过 GroundSelfFeedback 获得第一人称证据 F。
   - 对结构轨道和指导轨道并行执行 GatedEvolve 得到两个变体，分别 rollout 得到 Pass@1。
   - 选择 Pass@1 更高的变体为胜者，另一个为败者。
   - 用 R³ 将败者中有用的编辑合并到胜者上，得到 Ht。
   - 若胜者 Pass@1 高于上一轮，则接受 Ht 作为新的 H⋆。

## 6. 主要结论与发现

- HarnessCompass 在 SWE-bench Verified 上，用 GPT-5.4 将 Pass@1 从 54.0% 提升至 66.0%，仅需 5 次演化迭代；AHE 达到 63.0% 需要约 20 次，HarnessCompass 在有效性和效率上均超越 AHE。
- 保留集上优势更大：HarnessCompass 60.4% vs AHE 54.7%，说明更强的泛化性。
- 消融证明三个原则各有贡献：泛化门提升迁移性、主动反馈扩展信号、R³ 在保持性能的同时恢复泛化并减少迭代次数。
- 冻结 harness 可迁移到 Claude-Sonnet-4.6，总 Pass@1 从 70.0% 提升到 73.8%，说明学到的是跨模型的工程改进而非模型特定记忆。
- 收益在仓库间广泛分布，且集中在 harness 敏感的仓库（如 sphinx、pytest、django）；这些模式在跨模型时也成立。
- 案例研究对比显示：不受约束的演化倾向于记忆任务特定配方（如 "django-13158 需要..."),而 HarnessCompass 沉淀的是带适用条件的通用决策准则，排除了"分数提升来自答案书式记忆"的替代解释。
