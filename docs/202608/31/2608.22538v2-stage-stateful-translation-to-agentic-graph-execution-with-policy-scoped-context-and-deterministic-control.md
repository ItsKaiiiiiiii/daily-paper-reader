## 摘要
受策略驱动的智能体必须解释案件证据，同时可靠地遵循授权程序。我们提出了 STAGE，一种可执行图框架，它将模型判断限制在策略范围节点内，同时将程序控制置于确定性代码中。我们在三个公共策略遵循基准和 Smart Dispute（一个专有银行基准）上评估了 STAGE。与整体式全策略执行相比，STAGE 提高了任务成功率和重复运行可靠性，并在更深的工作流上取得了最大的收益。在 $\tau^2$-bench Telecom 和 Smart Dispute 上，$\mathrm{Pass}^{3}$ 分别提升了高达 55.0 和 65.7 个百分点。这些结果证明了将局部策略推理与确定性程序控制相结合对于企业应用的价值。

## Abstract
Policy-governed agents must interpret case evidence while reliably following authorized procedures. We present STAGE, an executable-graph framework that confines model judgment to policy-scoped nodes while placing procedural control in deterministic code. We evaluate STAGE on three public policy-following benchmarks and Smart Dispute, a proprietary banking benchmark. Compared with monolithic full-policy execution, STAGE improves task success and repeated-run reliability, with its largest observed gains on the deeper workflows. On $τ^2$-bench Telecom and Smart Dispute, $\mathrm{Pass}^{3}$ improves by up to 55.0 and 65.7 percentage points, respectively. These results demonstrate the value of combining localized policy reasoning with deterministic procedural control for enterprise use.

# STAGE 论文总结

## 1. 核心问题与整体含义

**研究动机：**
- 大型语言模型（LLM）作为智能体在处理多轮、工具调用、工作流编排等任务时能力不断提升，但在**受监管场景**（银行、客服等）中，智能体必须同时满足"语义理解"和"程序合规"两个要求。
- 真实世界政策往往包含**长依赖、条件分支、非局部跳转、混合决策与动作步骤**，而传统的"整体式（monolithic）"全策略执行方式——即一个智能体同时承担语义推理和流程控制——在上下文增长时容易出现：步骤遗漏、路径误路由、规则冲突、未经验证的判断传播等问题。
- 核心挑战不仅是"正确推理"，更是"在上下文和流程复杂性增长时可靠地遵循授权程序"。

**整体含义：**
- 论文提出**"LLM 拥有局部语义，代码拥有控制权"**（the LLM owns local meaning, while code owns control）的设计哲学。
- STAGE 将流程控制外部化为**确定性可执行图**，将模型判断限制在**策略范围节点**内，从而提升策略执行的可靠性和可审计性。

## 2. 方法论

**核心思想：** 基于图结构的执行框架，将每项政策拆解为显式的动作节点和决策节点，由确定性协调器（coordinator）驱动执行，模型只在局部节点内做语义判断。

**关键技术细节：**

1. **可执行策略图（Executable Policy Graph）**
   - 离线构建，基于权威政策由 LLM 辅助分解为有界任务。
   - 为每个任务映射政策原文（source passages），生成节点和合法转换。
   - 图经过验证后**冻结**，运行期不再修改。
   - 若无法进行保真重构则停止并人工审查，避免生成虚构规则。

2. **合规携带节点（Compliance-Carrying Execution Nodes）**
   - 每个节点是一个"可执行契约"，包含：局部任务描述、允许的技能与工具、结果校验规则、失败行为（重试/上报/终止）。
   - 模型仅接收与当前节点任务相关的政策上下文（policy-scoped context），而非完整政策。

3. **协调器拥有的控制（Coordinator-Owned Control）**
   - 运行时组件跟踪当前节点和尝试次数。
   - 向模型提供节点契约 + 案件信息 + 记忆。
   - 模型返回**类型化结果**，协调器依据节点契约进行验证。
   - 验证失败则按声明策略执行：前进、重试、标记审查或终止，并受尝试次数限制。

4. **三个研究问题（RQ）**
   - RQ1：节点级 STAGE 相比整体式全策略执行是否提升任务成功率和重复运行可靠性？
   - RQ2：在固定图下，策略范围与路由归属各自对可靠性有何独立影响？
   - RQ3：STAGE 的性能优势和错误构成如何随执行链长度变化？

## 6. 主要结论与发现

**RQ1（总体有效性）：**
- STAGE 在绝大多数组合上优于基线。
- 增益随流程复杂性增大而增大：
  - Referral Abuse（浅）：Pass 1 最大 +5.3pp，Pass 3 最大 +9.5pp。
  - Retail（浅分支）：Pass 1 最大 +15.0pp，Pass 3 最大 +25.0pp。
  - Telecom（深）：Pass 1 最大 +46.7pp，Pass 3 最大 +55.0pp。
  - Smart Dispute（最深）：Pass 1 最大 +58.1pp，Pass 3 最大 +65.7pp。

**RQ2（组件消融）：**
- **策略局部化**：将节点局部策略替换为完整政策后，Pass 3 下降 5.7–34.3pp；同时平均总 token 消耗降低 37.8%–69.1%（相对全策略节点）。
- **路由归属**：LLM 自由路由相比协调器路由，Pass 3 下降 2.5–17.5pp。
- 两者独立贡献于 STAGE 的可靠性。

**RQ3（链长影响）：**
- STAGE 在每种链长分组中均优于基线。
- 中等链长增益最大（Haiku +73.3pp，Sonnet +66.7pp）。
- 长链成功率仍下降，但 STAGE 将链错误率控制在 6.7%（Haiku）和 3.3%（Sonnet）。
- 长链剩余失败以执行/终端错误为主。

**其他发现：**
- 跨论文基准对比中，STAGE 在 Telecom 上达到最高分（92.5%，Luna），但在 Retail 上低于部分系统——进一步支持"图执行在深流程中收益最大"的核心主张。

## 7. 优点

1. **设计优雅**：将"语义判断"与"程序控制"分离，直接针对策略遵循失败的根本原因（长上下文下的注意力稀释和程序状态追踪负担）。
2. **可审计性**：每个节点产生类型化结果、证据、注释和来源引用，失败易于定位，执行过程可复查。
3. **消融严谨**：固定图下只改变单一变量（策略范围或路由归属），因果归因清晰。
4. **工业验证**：在真实银行工作流中验证，增强了结果的外部效度。
5. **Token 效率**：策略局部化显著降低 token 消耗，同时提升可靠性，兼具性能与经济性双重优势。
6. **错误分类细致**：区分链错误和执行/终端错误，为后续改进提供明确方向。
7. **图构建有保真保障**：无法忠实重构时停止而非编造规则，保障了执行图与政策的一致性前提。

## 8. 不足与局限

**实验覆盖：**
- 仅 4 个工作流、4 个模型，可能不适用于其他策略类型、领域或分布偏移。
- 每个条件仅 3 次运行，置信区间本质上覆盖的是运行间波动而非任务级抽样的不确定性，不能作为统计显著性的正式证明。

**复现性：**
- Smart Dispute 基于专有银行政策和内部测试集，外部研究者无法独立复现。
- 政策到图的构建提示词、实现代码、内部状态模式均不公开。

**假设依赖：**
- STAGE 假设冻结图**忠实代表**权威政策；若图构建或验证出错，会系统性强制错误程序，且错误可能被"看似合规"的执行掩盖。

**语义与合规的间隙：**
- 程序合规 ≠ 语义正确。执行可以完全按图走完，却在某个节点上做出错误解释。

**运维成本：**
- 未量化图构建工作量、验证成本和政策变更时的维护成本。

**Token/效率分析局限：**
- 端到端 token 对比并非受控效率比较（STAGE 生成审计工件，基线不生成）。
- 未报告缓存读写，跨模型的 token 差异不能归因于缓存复用。
- 未测量端到端延迟。

**约束上限：**
- 长链完成仍是挑战——即使 STAGE 减少了链错误，长链任务成功率仍随链长下降。
