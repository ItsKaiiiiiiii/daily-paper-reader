## 摘要
近年来，由多模态大语言模型（MLLMs）驱动的智能体系统发展迅速，但现有的具身智能体基准仍缺乏对多智能体协调的细粒度诊断。大多数基准要么专注于单智能体任务完成，要么用整体任务成功率来概括多智能体行为，这可能会掩盖重复工作、违反顺序约束、资源竞争以及交接不同步等协调失败。在本文中，我们提出了CoCoBench，一个用于在可执行家务任务中评估多智能体具身协调的构造级基准。CoCoBench包含897个经oracle验证的实例，围绕四种常见的协调构造组织：任务分配、顺序排序、互斥和交接协调。除了任务成功率外，CoCoBench还提供构造级评分，用于衡量智能体是否有效协调。我们评估了11个领先的MLLMs在不同协调模式、观察输入和智能体数量下的表现。结果表明，协调能力具有高度的构造特异性：整体表现优异并不意味着在不同协调类型上具备均衡的能力。这些发现为设计有针对性的模型架构和提升多智能体协调能力指明了新方向。

## Abstract
Agent systems powered by multimodal large language models (MLLMs) have advanced rapidly in recent years, yet existing embodied-agent benchmarks still lack fine-grained diagnostics for multi-agent coordination. Most benchmarks either focus on single-agent task completion or summarize multi-agent behavior with overall task success rates, which can obscure coordination failures such as duplicated work, violations of ordering constraints, resource contention, and desynchronized handoffs. In this paper, we introduce CoCoBench, a construct-level benchmark for evaluating multi-agent embodied coordination in executable household tasks. CoCoBench contains 897 oracle-validated instances organized around four recurring coordination constructs: task allocation, sequential ordering, mutual exclusion, and handoff coordination. In addition to task success rate, CoCoBench provides construct-level scores that measure whether agents coordinate effectively. We evaluate 11 leading MLLMs across different coordination modes, observation inputs, and numbers of agents. The results show that coordination ability is highly construct-specific: strong overall performance does not imply balanced competence across different coordination types. These findings point to new directions for designing targeted model architectures and improving multi-agent coordination ability.

## 1. 核心问题与整体含义（研究动机与背景）

- **背景**：多模态大语言模型（MLLMs）正越来越多地被用作具身智能体的“大脑”，支撑高层规划、具身推理与控制。同时，具身智能体正从单智能体任务执行走向多智能体协作，家庭场景中的许多任务天然需要多个智能体协作完成。
- **核心问题**：现有具身多智能体基准的评估粒度严重不足，存在两类典型的“掩盖”问题：
  - 多数基准只关注**单智能体任务完成**，无法评估多智能体间的交互；
  - 少数多智能体基准只用**整体任务成功率**总结经验，这会掩盖重复劳动、顺序约束违反、资源竞争、交接不同步等具体协调失败。
- **关键洞察**：即使智能体具备正确的感知和有效的底层技能，团队仍可能因重复工作、过早关闭容器、争抢工具、交接空等而导致失败；即使最终状态成功，也可能隐藏着大量无效尝试、不必要等待和可避免的冲突。
- **论文主张**：具身协作不应只评估“目标是否达成”，还要评估“智能体**如何协调**地达成目标”，即需要区分任务完成与协调质量两个维度。

## 2. 方法论：核心思想、关键技术细节与公式

### 2.1 问题形式化

- 任务实例定义为：**x = (E, A, S, O, U, ∆, Φ, H, d)**，其中 E 为家庭场景，A 为 N 个具身智能体，S 为环境状态空间，O 为观测函数集合，U 为高层技能集合，∆ 为共享底层执行器，Φ 为目标谓词集合，H 为步数预算，d 为目标协调构念。
- 高层协调策略将观测历史映射为联合技能决策：**u_t = (u_1^t, ..., u_N^t) ∼ π(· | o_{≤t}^1, ..., o_{≤t}^N)**。
- 执行器在环境中执行技能并记录事件，产生轨迹 **τ = (s_0, o_0, u_0, e_0, s_1, ..., s_H)**，其中 e_t 概括模拟器落地事件（如无效技能、前提失败、资源冲突、冗余动作、等待）。
- 任务成功定义为：**Succ_x(τ) = 1[∀ϕ ∈ Φ, ϕ(s_H) = 1]**。
- **协调耦合的形式化定义**：若存在两个智能体 a_i ≠ a_j 及技能 u_i^t、u_j^{t'}，使得一个智能体的动作改变了另一个智能体动作的可行性、目标贡献或执行成本，则该任务具有协调耦合。
- 评估函数由两条互补轴组成：**Eval(π; x) = (Succ_x(τ), C_{d,x}(τ))**，即任务成功率 + 构念级协调分数。

### 2.2 四种协调构念与评分公式

| 构念 | 含义 | 评分公式 |
|------|------|----------|
| **D1 任务分配** | 智能体平行分担独立子任务 | CD1 = min(1, M*/M)，M 为实际完工时间，M* 为 oracle 参考完工时间 |
| **D2 顺序排序** | 智能体遵循因果前提顺序 | CD2 = p_legal × (1 − v/n)，n 为顺序相关操作数，v 为顺序违例数，p_legal 为合法性门（合法为1，否则0.5） |
| **D3 互斥** | 智能体避免对独占共享资源的冲突 | CD3 = (1 − c/a) × min(1, M*/L)，a 为资源访问次数，c 为冲突次数，L 为执行步数，M* 为参考完工时间 |
| **D4 交接协调** | 生产者-消费者模式通过中间缓冲区协作 | CD4 = 1 − min(1, (o+w)/h)，h 为成功交接次数，o 为溢出事件数，w 为空缓冲区等待事件数 |

- 构念分数的关键设计原则：**高 CD 不意味着任务成功**，两个指标需联合解读；轨迹信号不足（n=0、a=0 或 h=0）的实例会被排除。

### 2.3 基准构建流程

- 基于 **AI2-THOR** 模拟器，通过符号模板实例化生成任务，覆盖 10 个任务族、4 个房间类别、3 种团队规模（N ∈ {2, 3, 4}），共 **897 个经 oracle 验证的实例**。
- 实例生成需经过三重质量门控：
  1. **放置门控**：验证物体可用性、空间可行性和所需能力；
  2. **Oracle 门控**：用特权参考策略确认任务可解；
  3. **指标门控**：仅保留 oracle 轨迹在目标构念上达到接近上限分数的实例。
- 所有任务共享固定的高层技能接口（导航、等待、拾取、放置、开合容器、切片等），每个步骤只向智能体暴露与任务和状态相关的参数化技能，确保评估聚焦于团队级协调而非底层技能执行。

## 3. 实验设计

### 3.1 Benchmark 构成

- **全量集**：897 个实例，D1（任务分配）218 个、D2（顺序排序）225 个、D3（互斥）230 个、D4（交接）224 个；按团队规模分为 415 个双智能体、288 个三智能体、194 个四智能体实例。
- **分层子集**：240 个实例（每构念 60 个，每种构念×智能体数组合 20 个），用于受控消融实验，平衡构念与团队规模两个维度。
- **对比基准**：与 CoELA、RoCoBench、SMART-LLM、MAP-THOR、PARTNR、COOP²、MECoBench 等现有具身多智能体基准对比，CoCoBench 是首个同时覆盖四种协调维度、支持集中/分散模式、多模态观测、异构角色且提供轨迹级构念分数的基准。

### 3.2 评估协议

- **集中式协议（C0）**：单一 VLM 规划器聚合所有智能体的观测和历史，每次为一个智能体选择下一步动作。
- **分散式协议（D1）**：每个智能体由独立 VLM 调用控制，只看到自己的自我中心视图和私有历史。
- **分散式+通信协议**：在 D1 基础上增加广播信道，智能体可共享消息。
- **观测设置**：图像（自我中心视觉）vs. 盲（无图像，保留文本任务描述、动作菜单和执行历史）。
- **模型集合**：11 个 MLLM——闭源 API（GPT-5.6-sol、GPT-5.4-mini、Claude Opus 4.8、Claude Haiku 4.5、Qwen3.6-Plus、Kimi-K2.6）和开源权重模型（Qwen3.5-9B、Qwen3-VL-8B、Cosmos3-Nano-16B、RoboBrain2.5-8B、InternVL3.5-8B）。

## 6. 主要结论与发现

- **协调能力具有强构念特异性**：GPT-5.6-sol 综合最优（SR 84.8%、CS 0.90），但 Qwen3-VL-8B 在 D1（任务分配）上 SR 和 CS 均为最高，Claude Opus 4.8 在 D2（顺序排序）上领先，GPT-5.6-sol 在 D3 和 D4 上领先。**整体性能强不一定意味着各协调构念能力均衡**。
- **集中式状态聚合仍至关重要**：集中式规划平均 48.0% SR、0.69 CS；分散式+通信为 39.6% SR、0.65 CS；分散式无通信为 36.7% SR、0.63 CS。通信只能部分弥补集中式聚合的损失。
- **符号级团队协调是主要瓶颈**：在高层技能接口下，移除视觉观测并不降低性能（盲设置 42.3% SR/0.660 CS vs. 图像设置 40.6% SR/0.655 CS）。物体和可执行动作已被显式落地，核心瓶颈是符号级多智能体协调而非视觉识别。
- **团队规模增大会放大协调难度**：平均 SR 从双智能体的 48.8% 降至四智能体的 43.1%；强模型（GPT-5.6-sol、Claude Opus 4.8）较稳定，但弱开源模型下降明显（InternVL3.5-8B 从 16.9% 降至 7.7%）。
- **失败模式揭示模型间差异**：闭源模型协议失败几乎不存在（均值 1.0%）；开源模型平均协议失败 17.5%，预算耗尽高达 61%（InternVL3.5-8B）。
- **任务成功与合法协调会分歧**：Claude Opus 4.8 合法计划率 96.3% 但成功率仅 78.5%（合法但不成功）；Claude Haiku 4.5 成功率 63.1% 但合法率仅 47.2%（成功但可能通过非法捷径达成）。**仅看成功率会高估实际协调质量**。

## 7. 优点

- **细粒度的构念级诊断**：将多智能体协调分解为任务分配、顺序排序、互斥、交接四种可测量的构念，分别提供独立评分，突破了传统整体成功率单一指标的局限。
- **任务成功与协调质量解耦**：SR 与 CS 分别衡量“是否达成”与“如何协调达成”，能揭示成功轨迹中的非法或低效行为。
- **严格的基准构建流程**：三重质量控制门控（放置、oracle、指标）确保实例可执行、可解且具有诊断区分度，优先保证构念效度而非原始数据规模。
- **衡量效度验证**：通过交叉应用四种评分函数计算相关矩阵，证明四种构念非冗余，CS 确实捕捉了任务成功率之外的信息。
- **可控的评估协议设计**：固定底层执行器隔离高层协调差异；支持多种策略架构和观测形式对比；并发分散式评估采用确定性执行顺序保证可复现性。
- **丰富的诊断维度**：涵盖失败模式分解、合法性差距分析、团队规模扩展、计算成本统计等多角度分析。
- **代码开源**：代码已在 GitHub 公开，便于复现与扩展。

## 8. 不足与局限

- **环境泛化性有限**：仅在 AI2-THOR 单一模拟器中验证，未涉及真实机器人平台或其他模拟环境（如 Habitat、Minecraft），环境多样性不足。
- **高层技能接口假设较强**：基准假定固定且正确的高层技能执行器，未评估底层技能执行出错或多级技能层次下的协调问题，这限制了结论向真实物理世界的推广。
- **Oracle 最优性不完全保证**：作者只对 D1 的参考完工时间 M* 手动验证了抽象层下的最优性，D2–D4 的 oracle 轨迹未声称是全局最短的。
- **跨模型比较存在不可比因素**：墙钟时间受 API 延迟和自家硬件影响，闭源与开源模型之间的计算效率不可直接比较；分散式协议中模型可能无意识地依赖任务类型判断而非真实协作意图。
- **策略架构消融覆盖有限**：集中式/分散式对比只用了 4 个代表性模型（GPT-5.6-sol、GPT-5.4-mini、Qwen3.5-9B、Cosmos3-Nano），未覆盖全部 11 个模型。
- **并发评估简化真实异步性**：分散式场景中智能体从同一状态快照选择动作、按确定性顺序执行，与真实环境中智能体并发、异步执行的行为存在差距。
- **指标本身的局限**：构念分数依赖轨迹中提供的信号量，信号不足的轨迹会被排除；某些爬取模型可能通过大量预算逼近目标，从而在 SR 上占优但在协调质量上并不理想，这虽被 CS 暴露，但削弱了 SR 的解释力。

## 总结

CoCoBench 是首个对联合作业协调进行“构念级”诊断的具身多智能体基准。它将多智能体协调分解为任务分配、顺序排序、互斥和交接四种机制，以轨迹级分数补充传统的任务成功率，提供了一种可复现、可诊断的评估框架。通过对 11 种主流 MLLM 的系统评估，揭示了协调能力的构念特异性、集中式规划的优势，以及团队规模扩大带来的协调负担。这项工作的主要贡献在于提供了一面更精细的“显微镜”，帮助社区区分“任务达成”与“协调得当”之间的本质差异，但环境泛化、真实异步性和底层技能层次等问题仍需后续研究解决。
