## 摘要
一个工具调用可以完全有效，但仍可能使自主智能体无法确定下一步该做什么。例如，如果外部效果已提交但其响应丢失，则已提交和未提交状态对智能体而言可能变得无法区分，尽管它们需要不同的后续操作。我们研究了可调用性与可操作性之间的差距：即工具接口是否暴露了在操作不确定性下智能体安全继续所需的行动相关状态和语义。我们通过智能体优先工具设计（AFT）来操作化工具可操作性，这是一组接口机制，涵盖选择性能力发现、执行生命周期与恢复、显式外部效果语义、机器可读结果以及后条件验证。我们引入了AFT-Bench，一个受控接口干预框架，它在任务、后端、初始状态、注入故障、智能体和语言模型保持不变的情况下，仅改变暴露给智能体的接口。

## Abstract
A tool call can be perfectly valid yet still leave an autonomous agent unable to determine what to do next. For example, if an external effect commits but its response is lost, committed and uncommitted states may become indistinguishable to the agent even though they require different continuation actions. We study this gap between callability and operability: whether a tool interface exposes the action-relevant state and semantics needed for an agent to continue safely under operational uncertainty. We operationalize tool operability through Agent-First Tooling (AFT), a set of interface mechanisms spanning selective capability discovery, execution lifecycle and recovery, explicit external-effect semantics, machine-readable results, and postcondition verification. We introduce AFT-Bench, a controlled interface-intervention framework that holds the task, backend, initial state, injected failure, agent, and language model fixed while varying the interface exposed to the agent.

## 一、核心问题与整体含义

- **核心问题**：论文聚焦于“可调用性（callability）”与“可操作性（operability）”之间的重要区分。一个工具调用在语法上完全有效，但因其接口未能向智能体暴露足够的状态与语义信息，智能体可能无法确定下一步的安全操作。
- **典型困境**：当外部效果已提交但响应在传输中丢失时，智能体观察到超时，无法区分“已提交”与“未提交”两种底层状态。两种状态要求截然不同的安全后续动作（盲目重试可能产生重复副作用，拒绝重试则可能遗留未完成任务），但接口却向智能体呈现出不可区分的观察。
- **核心论断**：当操作状态在接口层不可区分时，单凭更强的模型推理能力无法保证正确决策。工具使用的可靠性是模型策略与接口语义共同决定的——接口决定了策略可用的操作区分度。
- **关键贡献**：作者提出 Agent-First Tooling（AFT）接口机制体系和 AFT-Bench 受控实验框架，通过保持任务、后端、模型、故障等一切条件不变、仅改变接口语义，以机制级证据证明“更强的工具”不是泛泛的改善——接口本身决定了哪些操作区分可供智能体决策使用。

## 二、方法论：核心思想、技术细节与关键公式

### 核心思想：接口作为可操作的语义层

AFT 认为接口应在工具使用的全生命周期中暴露“行动相关信息”，具体通过七类机制来消解不同类型的操作模糊性：

- **选择性能力发现**：以紧凑的元数据暴露能力表面，按需物化完整 schema，减少模型上下文负担而不牺牲能力召回率。
- **可观察执行与生命周期**：提供可查询的执行状态、顺序与版本信息，让智能体知道调用进行到哪一步。
- **可恢复调用与可恢复状态**：前者在瞬态中断后继续已有逻辑操作，后者在进程本地状态丢失后从持久化状态重建调用。
- **结构化输出**：以机器可读格式携带状态、对象引用、效果摘要、验证元数据等语义。
- **效果语义**：通过幂等性、前置条件、效果范围、提交点、权限、补偿等使外部延续操作在不确定效果状态下保持安全。
- **后条件验证**：提供权威证据检查终端声明是否与真实世界状态一致。

### 系统模型定义

系统模型以形式化方式描述：
- 后端环境 E=(S, U, P, ZE)，其中 S 为状态集合，U 为操作集合，P 为转移模型，ZE 为可达证据；
- 接口 I 经 ΓI 诱导出智能体可见观察 zt=ΓI(ht)；
- 任务 τ 包含后条件 φτ、策略接受谓词 ατ、轨迹安全谓词 ψτ 和预算 Bτ；
- 执行轨迹 ξ = Run(M, C, I, E, τ, ω)，其中 M 是模型、C 是控制器、ω 是故障调度；
- 目标达成 Ygoal 与策略正确性 Ycorrect 被分开度量，安全中止或拒绝按任务策略要求计为正确。

### 操作模糊性的定义

论文给出形式化判据：当两个历史 h 和 h′ 产生相同接口观察（ΓI(h)=ΓI(h′)），但安全延续动作集合无交集时，接口便诱导了“操作模糊性”。消解途径有两条：
- **区分状态**：暴露额外证据让不同历史产生不同观察；
- **稳定延续**：利用幂等性或受保护写入令同一延续动作在多种隐藏状态下均安全。

### 可操作性定义

AFT 将可操作性定义为多维概况 O(I;q)=(Rcapability, Precover, Seffect, Voutcome, −Ccontext)，即能力召回、执行恢复、效果安全、终端结果正确性和上下文成本的多维向量，而非单一单调分数——不同机制服务于不同失效模式。

## 三、实验设计：数据集、场景与基准

### 实验框架：AFT-Bench

AFT-Bench 的核心设计原则是**配对受控比较**：每个对比都保持任务、后端、初始状态、注入故障、控制器、模型和执行预算完全固定，仅改变针对目标机制的接口语义。

### 三层验证结构

- **第一层（确定性实验）**：使用确定性能力感知控制器，在受控故障下验证机制激活、操作检查、恢复路径与处理隔离，实验中证据在进入自适应模型阶段前正式冻结。
- **第二层（持久化后端复制）**：在持久化 SQLite 环境下重复效果安全关键发现，确认副作用安全结果在真实事务边界上依然成立。
- **第三层（自适应 LLM 验证）**：使用三个当代 API 后端模型——Qwen 3.7 Plus、DeepSeek V4 Pro 和 GPT-5.6 Sol——在六个规范工作负载上执行冻结基准，覆盖 3×6=18 个完整的模型-工作负载单元。

### 七个主要对比

| 对比 | 接口处理 | 工作负载与端点 |
|---|---|---|
| 发现上下文 | 选择性 vs 急切发现 | 大型能力目录；暴露的上下文 token |
| 发现召回 | 选择性 vs 急切发现 | 大型能力目录；能力召回（非劣效检验） |
| 恢复 | 完整 vs 移除可恢复调用 | 瞬态中断；恢复成功 |

| 终端验证 | 验证 vs 移除验证 | 不正确的终端报告；不正确终端声明 |

### 故障注入与结果语义

- 故障由测试框架在后端定义的执行边界处注入，而非通过自然语言提示产生；
- 标准序列：REQUEST_ACCEPTED → BACKEND_STARTED → EFFECT_COMMITTED → RESPONSE_GENERATED → RESPONSE_DROPPED；
- 分别记录传输重传、已有调用的延续、任务动作的逻辑重执行和基于权威状态的对账，因为两个接口在超时后都可能发出第二个请求，但只有其中一个保留原始逻辑效果；
- 结果标签源自持久后端状态与 oracle 轨迹，而非智能体最终消息文本；运行结果分为已完成、安全中止、安全拒绝、安全升级、不安全提交、不必要失败或未决。

## 六、主要结论与发现

- **选择性发现压缩上下文且不牺牲召回**：72 个配对中平均减少 4,013.17 个上下文 token（95% CI [1976.14, 6231.28]），同时召回差异仅为 0.0139（下界远超预定义非劣效界限 −0.10）——选择性发现能保留任务相关能力发现的同时大幅减少接口表面。
- **恢复依赖接口状态与失效模式的匹配**：瞬态中断下，移除可恢复调用使恢复率下降满 1.00 效用单位；进程本地状态丢失下，移除持久状态同样造成满 1.00 效用下降。两个机制在不同失效类别上各自决定性，且在全部三个模型族与所有留一模型分析中方向一致、效应全部为满量程——恢复机制主要体现为运行时性质。
- **效果语义防止重复与不安全延续**：提交后响应丢失场景中，效果感知接口将重复效果降低 56.94 个百分点；过期状态与权限漂移场景中，强效果语义将不安全提交降低 50.0 个百分点，且重要的正确结果往往是非动作（安全中止/拒绝）。
- **验证纠正错误的终端信念**：验证将不正确终端声明减少 27.78 个百分点（144 个配对，95% CI [0.1806, 0.3750]）；部分成功工作负载中提升达 51.85 个百分点。但该效应高度依赖模型：Qwen 0.3542、DeepSeek 0.4792、GPT 为 0——GPT 已在更保守的终端报告策略中规避了目标错误，表明模型策略与显式验证之间存在部分替代关系。
- **总体格局**：全部七个合并主对比在 Holm 多重性校正后均满足既定推断标准。恢复为稳健的运行时保障，效果与验证构成模型依赖的策略性机制。整体支持“工具可靠性由模型策略与接口语义共同决定”的核心论点。

## 七、优点

- **精准的问题构造**：将“可调用性≠可操作性”这一业界痛点形式化为“操作模糊性”，给出了可判定的判据（ΓI(h)=ΓI(h′)×安全延续集合无交集），并将消解路径划分为“区分状态”与“稳定延续”两类互补机制，理论结构清晰。
- **严格受控的方法论**：AFT-Bench 的核心对比“仅改接口、一切环境保持固定”——任务、后端、初始状态、故障、控制器、模型、执行预算全恒一致——使每项效应都能机制级归因，而非停留在“更好的工具帮助智能体”的笼统结论上。
- **三层验证架构**：确定性实验确认机制激活与操作完整 → SQLite 持久后端复制建立真实事务边界 → 三个自适应 LLM 模型族验证生态效应。证据分层清晰且冻结规则严格，保证结论不受事后调整污染。
- **多维正确性语义**：区分目标达成与策略正确性，将安全中止/拒绝计为正确而非失败；效果安全指标区分重复、未授权、非预期与残余效果；验证指标区分虚假成功与虚假失败——度量颗粒度明显优于一般端到端任务成功率。
- **对模型-接口交互的正面处理**：明确呈现模型间异质性（如 GPT 验证效应为 0），并有留一模型分析检验结论稳健性，避免了把模型无关的机制效应误当普适规律或反之。
- **审计与可复现性**：完整矩阵补全性和唯一性审计、无效历史证据排除、API 故障零捏造行、结构化输出与手稿数值自动一致化等要求，体现了较高的工程严谨性。

## 八、不足与局限

- **机制识别 vs 现实概率**：论文明确承认其设计用于机制识别而非估计生产中各类故障的真实发生频率。工作负载人为激活目标失效条件，报告效应是条件机制效应而非生产环境中的故障流行率，无法直接推断现实系统的期望收益。
- **环境覆盖面有限**：大多数机制实验采用可重置的合成环境，尽管 SQLite 复制证明了持久事务边界上的效果安全性，但结论尚无法推广到支付系统、工作流引擎、云服务、企业 API 等生产后端。操作语义可能随后端实现而变化。
- **模型覆盖面有限**：三个模型族虽足以揭示模型-接口异质性，但不代表全部当前或未来的 LLM 行为。验证机制的边际价值随模型保守性变化显著这一事实本身提示，对更强/更弱模型的推广需要格外谨慎。
- **部分机制证据较弱**：可观察执行与最小结构化输出虽有理论价值，但独立效力证据比发现、恢复、效果语义与验证弱，论文将其未来事件丢失和解析器修复实验作为未来工作而非当前头条结论。
