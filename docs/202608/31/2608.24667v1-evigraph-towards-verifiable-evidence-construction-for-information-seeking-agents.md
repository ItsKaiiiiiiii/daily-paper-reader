## 摘要
代理式网络搜索可以检索到相关信息，但未能确定所检索内容是否确实支持答案中使用的论断。现有代理通常将搜索和证据记录保存在线性交互轨迹中，并主要针对最终答案的正确性进行优化，对中间依据的监督有限。我们提出EviGraph，一个深度搜索框架，它将搜索执行与证据记录分离，同时为可训练角色使用共享策略。执行器规划简洁查询，冻结的证据验证器检查源页面并返回带有明确极性的逐字证据项，策略将这些证据项映射为添加/支持图的请求，由确定性结构验证器进行检查。生成的图既作为持久工作记忆，也作为密集过程奖励的来源，使强化学习能够直接监督证据构建，而不仅仅是最终答案。在BrowseComp-Plus上，一个Qwen3-8B EviGraph代理在匹配的交互预算下达到35.9%的准确率，而相同双角色架构没有强化学习时为26.9%，单体代理为2.7%，同时每次滚动生成更少的token。在BrowseComp、GAIA和XBench上的一致增益表明，明确结构化和奖励证据记录能够改进代理式搜索。

## Abstract
Agentic Web search can retrieve relevant information without establishing that the retrieved content actually supports the claims used in an answer. Existing agents typically keep search and evidence recording in a linear interaction trace and optimize primarily for final-answer correctness, providing limited supervision for intermediate grounding. We present EviGraph, a deep-search framework that separates search execution from evidence recording while using a shared policy for the trainable roles. An executor plans concise queries, a frozen evidence verifier inspects source pages and returns verbatim evidence items with an explicit polarity, and the policy maps those items to add/support graph requests that are checked by a deterministic structural validator. The resulting graph serves both as persistent working memory and as a source of dense process rewards, enabling reinforcement learning to directly supervise evidence construction rather than only the final answer. On BrowseComp-Plus, a Qwen3-8B EviGraph agent achieves 35.9% accuracy under a matched interaction budget, compared with 26.9% for the same dual-role architecture without reinforcement learning and 2.7% for a monolithic agent, while generating fewer tokens per rollout. Consistent gains on BrowseComp, GAIA, and XBench indicate that explicitly structuring and rewarding evidence recording improves agentic search

# EviGraph：面向信息寻求代理的可验证证据构建


## 1. 核心问题与研究动机

**核心问题：** 现有智能体（Agent）搜索系统虽然能检索到相关信息，却无法保证检索内容**真正支撑答案中的论断**。具体存在三个层面缺陷：

- **相关性 ≠ 证据支撑**：某页面可能提到正确实体，但上下文对应不同时间、地点、数值或语境，检索相关性无法替代证据效力。
- **答案级奖励诱导捷径行为**：仅以最终答案正确性为优化目标，会允许模型在证据缺失、矛盾或缺乏支撑的情况下得出正确答案。
- **引文无法揭示证据结构**：传统引文只标注来源，却不说明具体哪个源片段支撑哪个论断、该片段对应何种约束条件，以及多条证据如何联合构成最终结论。

**背景定位**：现有系统（Search-R1、R1-Searcher、StepSearch 等）大多在**线性交互轨迹**中处理搜索与证据，仅以最终答案正确性作为优化信号，缺少对中间证据构建过程的监督。在多约束网络研究任务（如同时满足出生地、职业、大使身份、采访者姓名等多个独立可搜索条件）中，单一页面往往只满足部分约束，需要系统显式构建跨来源的证据组合。

**论文的核心主张**：将智能体搜索重新定义为**证据构建（Evidence Construction）** 过程——通过一个类型化（typed）、基于原文片段（span-grounded）的论断—证据图（claim–evidence graph）来结构化记录和优化证据，使中间证据质量本身成为可监督、可奖励的对象。

## 2. 方法论：EviGraph 框架

### 2.1 核心思想

EviGraph 将搜索执行与证据记录解耦为两个角色，但共享同一个策略模型 πθ：

- **执行器（Executor）** ：仅基于图快照（graph snapshot）规划简洁搜索查询或决策是否作答，不直接查看原始页面，也不修改图。
- **证据提议角色（Evidence-Proposal）** ：将验证器输出的证据项映射为图编辑请求（add / support），决定"哪些证据应当写入图中"。
- **冻结验证器（Frozen Verifier）** ：检查搜索结果和页面，返回带**极性（polarity）** 的逐字证据项（候选者、约束标签、来源、原文跨度、相关性解释、支持/冲突极性），但绝不直接编辑图。
- **确定性结构验证器（Deterministic Validator）** ：仅检查结构化不变式（如跨度是否真实出现在观测中、是否形成环、是否匹配未消费的验证器条目等），不做语义蕴含判断，也不决定回答终止。

### 2.2 证据图模式

- **节点类型**：文档（Document）、原文跨度（Span）、候选-约束论断（Claim）、答案候选（Answer Candidate）。
- **边类型**：
  - `CONTAINS`：文档包含某原文跨度（VD → VS）
  - `Evidence`：跨度链接到论断，极性 ∈ {support, conflict}
- **关键性质**：所有被接受的论断均可沿有向证据路径回溯到真实观测来源（source-reachability invariant），从结构上杜绝虚构 URL 或循环自证。

### 2.3 关键奖励机制与公式

宏步（macro-step）信用分配中，执行器过程奖励：

**r_E_m = α·n_m + [γβ·c(G_{m+1}) − β·c(G_m)] − κ·s**

- n_m：检索新颖性（本次验证器报告中尚未覆盖的约束标签比例）
- c(G)：候选覆盖率（一个候选满足的约束标签数比例，取所有候选最大值）
- κ·s：搜索成本惩罚
- 覆盖率项采用基于势函数的奖励塑形（potential-based shaping），保证策略不变性。

证据提议的子步奖励：

**r_P_m,j = λ_v·v_m,j + [γΦ(G_m,j+1) − Φ(G_m,j)]**

其中图质量势函数：

**Φ(G) = λ_cov·c(G) − λ_u·U(G) − λ_o·O(G)**

- U(G)：未解决冲突率（既有支持又有冲突证据的论断比例）
- O(G)：离题惩罚（约束标签不在任务需求集合 T 中的节点比例）
- v_m,j：首次为某候选-标签-极性三元组记录证据时 +1，结构拒绝时 −1

### 2.4 角色条件化 GRPO 优化

- 同一策略模型通过不同角色 token 区分执行器和证据提议角色，共享参数。
- 在相同状态-角色组内对优势进行归一化，使用裁剪的 PPO 目标（clipped objective）。
- 联合损失：**L = ω_E·L_E + ω_P·L_P + β_KL·KL 惩罚**。
- 训练过程：先只用过程奖励（λ_f=0），后启用最终答案奖励（用冻结的 DeepSeek-V4-Flash 评分器判定答案等价性）。

### 2.5 防奖励作弊设计

- 规范证据签名（canonical signature）：完全重复转为零奖励 no-op
- 每个候选-标签-极性三元组最多一次接受奖励（bonus cap）
- 未解决冲突被惩罚但不禁止记录冲突，丢弃验证器条目反而触发拒绝惩罚
- 势差奖励防止全 episode 塌缩

## 6. 主要结论与发现

| 配置 | BrowseComp-Plus 准确率 | Token/rollout | 搜索次数 |
|---|---|---|---|
| 单体代理（Qwen3-8B ReAct） | 2.7%（内部基线）/ 8.2%（标准基线） | 3,245 | 3.7 |
| 双角色无 RL（EviGraph） | 26.9% | 1,878 | 12.9 |
| 双角色 + RL（EviGraph） | **35.9%** | **1,689** | 13.2 |
| EviGraph（Qwen3-32B，无RL） | 36.6% | — | — |

- **核心收益在架构而非参数**：将线性轨迹改为结构化证据图，使 8B 模型从 2.7% 跃升至 26.9%（约 10 倍提升）。
- **RL 进一步优化效率**：在相同搜索预算下带来 9.0 个百分点的增益，且生成 token 减少约 10%，表明 RL 学会用更紧凑的查询和图编辑完成更有效的搜索。
- **多模态扩展有效**：Qwen3-VL-8B + EviGraph 在 LiveVQA 达 78.0%，超过 Gemini-2.5-Pro（76.0%）和全部同规模开源模型，与 Vision-DeepResearch-30B-A3B（77.6%）持平（差距约 1 问）。
- **训练动态**：奖励约在 50 步后快速上升，生成长度收敛到 1,650–1,750 token，确认 RL 优化的是证据构建技能而非单纯搜索更多。

## 7. 优点

1. **问题定位精准**：明确指出"检索相关性 ≠ 证据支撑"这一被忽视的关键缺陷，将中间依据的可验证性置于核心地位。
2. **架构设计清晰解耦**：执行、验证、提议、结构校验四层职责分明，明确区分哪些是学得的（搜索+图编辑策略）与哪些是固定的（验证器+结构校验器），可解释性强。
3. **奖励设计理论扎实**：使用策略不变的势差塑形避免 reward hacking，多重防作弊机制（规范签名、三元组奖励上限、冲突惩罚设计）考虑周详。
4. **可控实验排除了混淆变量**：搜索次数（12.9 vs. 13.2）和 token 数被精确统计，证明 RL 增益来自质量而非更多检索。
5. **多模态迁移零成本验证**：同一推理循环可直接用于视觉搜索任务且无额外微调，说明框架的模态无关性设计有效。

## 8. 不足与局限

1. **计算资源信息披露不完整**：未报告训练的总时长、总 GPU 小时数或经费估算，难以评估复现成本。

3. **技术细节留白**：约束标签集合 T 的生成方式（由谁生成、是否训练、如何确保覆盖完整）未明确；验证器访问页面的具体访问机制（visit-first policy 的细节）描述不够充分。
