## 摘要
基于大语言模型（LLM）的智能体即使在任务和工具完全相同的情况下，也会表现出显著的逐次运行差异——这对于探索性使用尚可接受，但在金融和合规等受监管领域则不可接受。我们研究了编排工程：将智能体包裹在确定性执行层中（有限状态控制、强制工具选择、输出验证、有限重试和结构化规划），并衡量其对执行确定性和任务成功率的影响。在两个合成任务（金融和法律）和两个开放权重模型（Qwen-2.5-7B-Instruct、Gemma-3-27B）上，初步的编排产生了混合结果：它在四个模型-任务组合中的一组合中显著提高了可复现性，在两组合中显著降低了可复现性，在第四组合中没有效果。痕迹级诊断找到了原因：一旦工具序列、状态序列和输出已经高度一致，不受约束的自由文本规划步骤便成为剩余差异的主要来源。添加结构化规划——在任何工具调用之前根据固定模式验证计划——彻底消除了这一影响：四个组合中的三个在N=100时达到可复现率和确定性指数1.000，四个组合中的三个任务成功率升至100%。这种增益并非没有代价：每个组合的令牌成本都有所下降，但延迟显示出真实且对样本量稳健的模型差异——一个模型在约束下变快，另一个明显变慢。我们认为，编排工程是提升智能体可靠性的一种独特且有效的学科，但其成本依赖于模型，必须通过测量而非假设来确定。

## Abstract
Large Language Model (LLM) based agents exhibit substantial run-to-run execution variance even when given identical tasks and tools -- acceptable for exploratory use but unacceptable in regulated domains such as finance and compliance. We study harness engineering: wrapping an agent in a deterministic execution layer (finite-state control, forced tool selection, output validation, bounded retry, and structured planning) and measuring its effect on execution determinism and task success. Across two synthetic tasks (finance and legal) and two open-weight models (Qwen-2.5-7B-Instruct, Gemma-3-27B), a first-pass harness produces a mixed result: it significantly improves reproducibility in one of four model-task cells, significantly degrades it in two, and has no effect in the fourth. A trace-level diagnostic finds the cause: once tool sequence, state sequence, and output are already highly consistent, an unconstrained free-text planning step becomes the dominant remaining source of variance. Adding Structured Planning -- validating the plan against a fixed schema before any tool is invoked -- eliminates the effect entirely: three of four cells reach a Reproducibility Rate and Determinism Index of 1.000 at N=100, and task success rises to 100% in three of four cells. The gain is not free: token cost falls in every cell, but latency shows a genuine, sample-size-robust split by model -- one becomes faster under the constraint, the other markedly slower. We argue harness engineering is a distinct, effective discipline for agent reliability, but its cost is model-dependent and must be measured, not assumed.

## 1. 论文的核心问题与整体含义（研究动机和背景）

- **核心痛点**：基于大语言模型（LLM）的智能体即使在任务、工具、环境条件完全一致的情况下，其逐次执行结果仍存在显著方差（随机性），表现为规划不同、工具选择不同、步骤顺序变化、重试行为不一致等。这种不可复现性在探索性场景下尚可接受，但在金融风控、合规审计、临床决策、合同审查等受监管领域构成硬性部署障碍——利益相关方要求智能体遵循可预测、可审计的固定流程，而非“结果碰巧正确”。
- **既有研究的缺口**：已有工作（如Yagubyan 2026）仅测量了不一致性但未进行干预；另一条工作线（如R-LAM）虽然构建了受约束执行层，但评估规模极小（N≈5–10）、领域单一，且未分解到底*哪个*约束组件贡献了多少确定性，也未考察约束在某些任务上是否会失效甚至起反作用。
- **研究问题**：将智能体包裹在“确定性执行编排器”（harness）中，是否能在不牺牲任务成功率的前提下降低逐次运行方差？如果第一版编排器无法干净地做到这一点，还需要额外施加什么约束？代价是什么？
- **整体含义**：论文论证了“编排工程”（harness engineering）是一个独立于提示工程和模型微调的有效可靠性干预手段，但同时也表明其效果与成本强烈依赖底层模型，必须逐一实测而非假设。

## 2. 论文提出的方法论：核心思想、关键技术细节

- **核心思想**：不修改模型权重，而是在智能体与工具之间插入一个确定性的控制层，把执行行为从“模型自由发挥”变为“受固定状态机约束的受控流程”，并通过逐层分解来定位剩余方差来源。
- **五个可独立开关的编排器组件**：
  1. **有限状态执行**（Finite-state execution）：将任务分解为固定命名状态序列（如 LOAD DATA → VALIDATE DATA → CALCULATE → GENERATE REPORT），智能体只能沿预定义状态图迁移。
  2. **强制工具选择**（Forced tool selection）：每个状态绑定唯一授权工具，通过API层强制 `tool_choice="required"`，消除工具调用缺失或越权。
  3. **输出验证**（Output validation）：每个状态的工具输出须通过形状/类型校验，才能推进状态机。
  4. **有限重试与升级**（Bounded retry with escalation）：校验失败时在固定上限内重试，超过即终止运行，而非静默失败或无限重试。
  5. **结构化规划**（Structured Planning）：在任何工具调用之前，智能体必须先将规划输出为 JSON 数组 `{state, intended_tool}`，并经模式校验；不合格则触发有限次数重新提示（默认2次），且**在有效规划产生之前不调用任何工具**。成功后将经过模式校验的规范（state, tool）对（而非模型的原始自由文本）记入日志，从而在机制上消除规划措辞差异这一方差来源。
- **三种实验条件**：
  - **Baseline**：原生工具调用、无任何编排组件。
  - **Harness**：有限状态执行 + 强制工具选择 + 输出校验 + 有限重试（**不含**结构化规划）。
  - **Harness+SP**：完整编排器，含结构化规划。
- **确定性度量指标**：
  - **确定性指数（DI）**：由四个等权子分数组成——规划稳定性、工具路径一致性、状态迁移稳定性、输出一致性，均为两两运行间的平均相似度。
  - **可复现率（Reproducibility Rate）**：完整执行痕迹与群体模态痕迹完全一致的运行占比，比DI更严格——规划文本中一个字符的差异即可打破精确匹配。
  - **任务成功率（TSR）**：对照确定性正确答案衡量，与确定性分开报告。

## 3. 实验设计：数据集 / 场景 / Benchmark / 对比方法

- **模型**：Qwen-2.5-7B-Instruct（7B）和 Gemma-3-27B（27B），均通过 OpenRouter 访问。
- **对照方法**：Baseline 与 Harness、Harness+SP 三种条件在四个模型×任务单元（cell）内相互对比。
- **统计处理**：bootstrap 95%置信区间（10,000次重采样）、置换检验（10,000次置换，α=0.05）、Cohen's d 效应量。

## 6. 论文的主要结论与发现

1. **第一版编排器（不含结构化规划）效果混合**：四个单元中，仅一个（finance_ecl/Gemma：0.42→0.55，p=0.006）显著提升可复现率；两个（legal_clause/Qwen：0.79→0.68，p=0.038；legal_clause/Gemma：0.56→0.38，p<0.001）显著**降低**可复现率；一个（finance_ecl/Qwen：0.91→0.93）无显著变化。任务成功率在所有单元均保持0.97–1.00。
2. **诊断结论**：工具路径、状态迁移、输出一致性在Baseline和Harness下均已达或接近天花板；唯一的剩余方差轴是**自由文本规划措辞**（Gemma的规划稳定性低至0.33–0.55）。可复现率指标实际上在追踪“哪种措辞习惯碰巧主导了这一批100次运行”，而非真实的执行稳定性差异——这解释了Harness效果方向的不一致。
3. **结构化规划彻底关闭方差缺口**：三个单元达到完美可复现率和DI 1.000（p<0.001）；第四个（finance_ecl/Qwen）为0.980（因两次真实的工具调用失败，与规划文本方差无关），仍显著优于Baseline（p=0.019）。两个原始逆转全部修复；三个单元任务成功率升至100%。
4. **成本是模型依赖的**：
   - **Token成本**：全单元一致有利——Harness+SP相对Baseline下降15–17%，相对Harness仅增加2–5%的规划往返开销。
   - **延迟成本**：Qwen在Harness+SP下反而**变快**（相对基线−14%至−25%）；Gemma则**明显变慢**（相对Harness +15%至+24%，相对基线+41%至+47%），可能因为Gemma更频繁触发规划校验重试。该效应在样本量加倍后不缩反而扩大，判定为稳健真实效应。
5. **元结论**：编排工程是提升智能体可靠性的有效学科，但其“哪个约束起作用、代价落在哪个资源轴、因模型而异到什么程度”均须实证分解，不能假设。

## 7. 优点

- **诚实且有诊断价值的负面结果处理**：第一版Harness的混合结果本可被误读为“编排不可靠”，论文通过迹级分解找到真实原因，示范了“复合确定性指标必须分层汇报”的通用实践。
- **分层度量设计**：将单一可复现率分解为规划/工具路径/状态迁移/输出四个层面，使方差归因成为可能，而非黑箱比较。
- **成本与效果并报**：不满足于“确定性达到1.000”这一饱和指标，同时报告token和延迟，并区分全模型一致的成本项与模型依赖的成本项。
- **稳健性验证**：N=50 → N=100的扩展检验排除了小样本伪影，延迟分裂效应在更大样本下不消失而是增强，增强了结论可信度。
- **范围界定克制**：对线性任务、两个模型、第三方API基础设施等局限明确声明，不过度外推。

## 8. 不足与局限

- **任务覆盖窄**：仅两个合成任务、均为线性四状态流水线、答案确定。不涉及分支、数据依赖或需要判断的任务，无法回答“结构化规划在更复杂/开放的执行路径下是否仍充分”这一问题（论文明言需要“合法执行路径歧义”的更难任务族做后续验证）。
- **模型覆盖窄**：仅两个开放权重模型（7B/27B），不覆盖前沿专有模型或推理模型；模型依赖的延迟结论只能证明“这种依赖存在”，不能预测具体哪个模型会显现。
- **第三方基础设施噪音**：OpenRouter是第三方聚合层而非本地可控推理，延迟指标尤其暴露于共享基础设施噪音；论文的主要可复现性指标因为是结构性的而非基于时序，受影响较小。
- **机制解释缺失**：论文未能提供Gemma为何更频繁触发规划重试的机制性解释（未直接测量重试频率），留待未来工作。
- **指标饱和效应**：一旦DI和可复现率到达天花板，无法区分进一步约束的增益；此时成本指标成为唯一区分维度，但“确定性100% + 延迟+24%”的取舍是否值得，论文没有给出规范性判断。
- **外部效度未知**：结论建立在不超过27B的模型和百次运行的规模上，到生产级真实工作流（更长流程、更多工具、共享推理集群）的可迁移性尚未验证。
