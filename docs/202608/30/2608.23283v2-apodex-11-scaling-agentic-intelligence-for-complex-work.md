## 摘要
通用语言模型能够推理和综合知识，但复杂工作还需要与文件、信息源和可执行代码进行持续交互，同时需要状态维护、故障恢复和可验证的交付。我们称之为“工作能力”：朝着现实世界目标持续、可验证的进展。Apodex 1.1 沿着两个互补的维度发展这一能力。“环境扩展”扩大了可执行文件、搜索和代码环境的多样性与可验证性，而“智能体协调扩展”则训练智能体分解长期任务、委派并行工作、整合异步结果并重新规划。共享的执行框架和 AgentOS 在工具和智能体之间维护任务状态和来源，训练将环境轨迹和协调痕迹转化为可靠的行为。在复杂的专业工作、金融、科学研究、数学、编码和搜索中，尽管 Apodex 1.1 使用的模型远小于许多前沿系统，它仍然达到了领先的性能区间。35B 参数的 Apodex 1.1 Mini 进一步以本地可部署的形式保持了强大的工作能力。这些结果将智能体智能扎根于随时间完成的、有用的、可验证的工作中，并推进了我们构建“重型求解器”以应对雄心勃勃的长期任务的目标。

## Abstract
General-purpose language models can reason and synthesize knowledge, but complex work also requires sustained interaction with files, information sources, and executable code, together with state maintenance, failure recovery, and verifiable delivery. We call this \emph{working capability}: sustained, verifiable progress toward a real-world objective. Apodex 1.1 develops this capability along two complementary dimensions. \emph{Environment Scaling} expands the diversity and verifiability of executable file, search, and code environments, while \emph{Agentic Coordination Scaling} trains agents to decompose long-horizon tasks, delegate parallel work, integrate asynchronous results, and replan. A shared execution harness and AgentOS maintain task state and provenance across tools and agents, and training turns environment trajectories and coordination traces into reliable behavior. Across complex professional work, finance, scientific research, mathematics, coding, and search, Apodex 1.1 reaches the leading performance band despite using a substantially smaller model than many frontier systems. The 35B-parameter Apodex 1.1 Mini further retains strong working capability in a locally deployable form. These results ground agentic intelligence in useful, verifiable work completed over time and advance our goal of building a \emph{Heavy-Duty Solver} for ambitious, long-running tasks.

## 2. 论文提出的方法论

### 2.1 总体架构
Apodex 1.1 围绕两个互补的扩展维度组织：

- **环境扩展（Environment Scaling）**：扩大智能体学习和行动所依托的可执行文件、搜索和代码世界的多样性、保真度与可验证性。
- **智能体协调扩展（Agentic Coordination Scaling）**：训练智能体分解长期目标、委派并行工作、整合异步结果、修订共享计划并重新规划。
- **共享执行框架与 AgentOS**：连接上述两个维度，维护任务状态、工件来源（provenance）、分支状态、回放与验证钩子。

### 2.2 任务契约（Task Contract）形式化框架

论文引入统一的任务契约：

\[
E = (W, W_0, q, A, T, \Omega, B, D, V_D)
\]

- \(W\) 为工作区状态空间，\(W_0\) 为初始工作区；
- \(q\) 为标准化目标；\(A\) 为可用动作集；\(T\) 为状态转移算子；\(\Omega\) 为观察接口；
- \(B\) 为资源预算向量（回合数、工具调用数、token、墙钟时间、并发执行数等）；
- \(D\) 为交付契约；\(V_D\) 为任务级验证器。

执行轨迹定义为 \(\tau_H = (u_0, a_0, o_1, \ldots, u_{H-1}, a_{H-1}, o_H)\)，其中 \(u_t\) 表示异步用户干预。成功不仅要求有用的结果，还要求从输入到交付有**可辩护的路径**。

### 2.3 环境扩展的三个环境族

| 环境族 | 核心焦点 | 验证边界 |
|---|---|---|
| 文件世界 | 权威性与转换：在多格式、嵌套目录、历史版本、跨文件引用中定位权威内容并生成专业工件 | 代码派生值或记录在案的来源追溯 |
| 搜索世界 | 发现与证据对齐：查询构建、来源取舍、交叉验证、证据综合 | 来源可追溯 + 声明审查 |
| 代码世界 | 可执行转换与验证：修改仓库、依赖与进程，从可执行状态获得反馈 | 测试 + 工件检查 |

- 覆盖规模：文件世界当前覆盖 **33 个领域、318 个职业、1208 个交付簇**；代码世界结合了基于真实 pull request 的“收割”任务与合成任务。
- 难度校准：对获取密集型任务定义采集压力系数 \(\rho_{\text{acq}}(E) = (N_{\text{cand}} + N_{\text{hop}}) / B_{\text{tool}}\)；代码世界则使用依赖深度、状态转换深度、测试可观察性等坐标。
- 验证与隔离：每个 rollout 有不可变世界清单 + 全新可变沙箱；可回放条件包括世界种子、工具版本、动作/观察序列、文件增量、验证器版本等。

### 2.4 Agent Team 1.1：交互式自组织团队

相比 Apodex 1.0，新增四个能力：

1. **显式任务板**：主智能体将任务分解写入（任务板），条目记录目标、依赖、解决状态、分配智能体、返回的证据/工件。任务板是模型、运行时和用户之间的共享协调记录，也是最终化的运行时门控。
2. **异步人为干预**：任务执行中可接受新的用户消息，训练策略判断干预改变什么、什么仍然有效、持续工作如何继续。
3. **非对称验证（Asymmetric Verification）**：验证比生成更窄——每个验证器只攻击一条具体声明及其支撑证据，而不是重新生成完整方案，从而避免引入第二条无约束的错误链。
4. **自适应 Max Team Effort**：只在薄弱、有争议或承重声明上额外分配独立调查；分配在每次返回后重新评估。
5. **证据接地综合（Evidence-Grounded Synthesis）**：执行结束后，从任务板、子智能体报告、证据和工件构建声明—证据图，再交给 writer 智能体起草交付物；无法追溯到证据的声明被限定或省略。

### 2.5 AgentOS 执行框架

- 工作区状态形式化：
  \[
  W_t = (F_t, Q_t, C_t, I_t, G_t, K_t)
  \]
  分别为文件状态、检索证据、可执行状态与日志、工件索引、依赖图、运行时控制状态。
- 三个文件系统命名空间：`/inputs`（只读输入）、`/workspace`（中间工作）、`/outputs`（最终交付物收集根）；提供只读 `/shares` 挂载作为跨运行的持久文档库。
- **分层压缩**：由推理端点报告的 token 使用触发；先驱逐旧工具观察文本，不够时再用 LLM 总结轨迹中间部分。
- **预算管理**：软/硬双截止时间，接近软期限时观察者要求智能体整合发现，结束后有有界、无工具的 finalization 调用恢复有用部分结果。
- **受控工件交付**：单发布者租约 + 精确清单 + 作用域写入策略 + 基线快照对账，防止并发、未声明、过期或不完整的交付。

### 2.6 训练方法

- **统一 SFT**：混合通用推理、工具使用、搜索、文件交互、编码、数学、科学与金融推理、专业交付和多智能体协调；过滤行为无效轨迹；通过 model-soup 合并不同能力域的变体。
- **Agentic RL**：核心算法为 **PIVOT-RL**——通过事后（hindsight）轨迹定位识别“**枢纽点**”（consequential decision points），保留有用前缀并构造带短方向性提示的局部续接任务；提示不是预测目标且推理时不存在；对状态任务恢复对应可执行环境状态。这解决了长期轨迹中仅靠终端结果无法有效分配信用的核心问题。
- **异步优化**：完成的轨迹异步进入优化，无需等待较慢的回合，适应异构智能体工作负载。
- **受控开发循环**：故障→任务流水线→环境扩展/协调扩展→训练→评估→下一轮分配，属于受管理的工程循环而非无约束的自我修改。

  - GDPVal 外部结果均为 Apodex 框架下复现；APEX-Agents 的 Claude Opus 5 结果也由内部复现——需要进一步说明复现口径是否与官方一致。
  - Agent Team 使用了**额外的组织计算**，与 ReAct 和静态提示的基线相比计算预算不同。
  - BioMysteryBench 的 Claude 4.x 数值来自原始的 23 任务集，与 Apodex 的 17 任务 Human-difficult 集不完全可比（论文已注明，仅作历史参考）。
  - 在 FrontierResearchBench 上，高难度任务全部模型通过率都很低（最高 20.6%），反映任务难度很大，但也说明 Apodex 仍落后于前沿系统约 8 个百分点。

## 6. 论文的主要结论与发现

- **主要性能结论**：Apodex 1.1 Agent Team 在 FrontierFinance（54.3）和 FrontierScience-Research（63.3）上取得对比表中最强数值，并在 GDPVal（78.8）、APEX-Agents（38.5）、HLE（56.1）、DeepSearchQA（92.4 F1）、FrontierSearchBench（69.1）等基准上保持领先性能区间。
- **协调带来的系统级增益**：从 ReAct 到 Agent Team，各基准普遍提升约 4–8 个百分点（FrontierFinance +5.6、FrontierScience +8.3、GDPVal +9.3、BioMysteryBench +11.8），证明训练协调行为与额外组织计算能有效转化为完成工作的能力。
- **模型规模的效率**：35B 的 Apodex 1.1 mini 在 FrontierFinance（50.2）、FrontierScience-Research（51.7）、APEX-Agents（27.7）上显著超越 Apodex 1.0 mini，并接近或匹配若干前沿系统水平，表明两个扩展维度提升了紧凑模型规模下可获得的能力。
- **数学推理的跃升**：匹配 Agent Team 对比中，Apodex 1.1 在 IMO 2025 上从 1.0 的 12.5 提升至 36.5（参考阈值 35），IMO 2026 从 13.0 至 30.5（阈值 29），USAMO 2026 从 5.8 至 26.5（阈值 25）；IMO-ProofBench Advanced 从 20.0 提升至 63.3。
- **科研交付仍是瓶颈**：在 FrontierResearchBench 上 Apodex 通过率仅 12.4%，即使 GPT-5.6-Sol 也只达 20.6%——可靠完成完整科研流程并交付所有必需工件，对所有系统仍然困难。
- **过程质量提升**：HDS6 显示最大单项提升为“初始分解”（+1.3）和“最终验证”（+0.8），证据保真和假设管理各组成项也普遍改善，说明改进在过程层面可见。

## 7. 优点（续）

- **以“完成的工作”为能力单位**：将评估从“模型能否正确回答”转向“模型能否在开放、长时程环境中完成可验证交付”，这与真实世界中知识工作者的任务结构一致，是对传统单轮基准的重要补充。
- **任务契约的强形式化**：用 \((W, W_0, q, A, T, \Omega, B, D, V_D)\) 统一刻画不同环境的共同结构，使文件、搜索、代码三个环境族可以共享同一套训练与验证管线，也让“成功”的定义从模糊变得可审计。
- **协调扩展提供了可量化的独立增益**：通过 ReAct 与 Agent Team 的双层对比，论文清晰地将“模型底层能力”与“协调行为带来的系统级增益”分离，避免了将脚手架收益误归因于模型权重。
- **过程性评测（HDS6）是重要创新**：大多数基准只考查最终结果，而 HDS6 把初始分解、假设管理、证据保真、失败恢复、最终验证等过程能力纳入量化评估，使改进来源更加可解释（如“初始分解 +1.3”“最终验证 +0.8”）。
- **PIVOT-RL 针对长期信用分配问题提供了务实解法**：通过事后定位“枢纽点”并构造局部续接任务，在不必重放完整长轨迹的前提下实现了对早期关键决策的强化，工程上比全轨迹 Monte-Carlo 信用分配更可行。
- **验证与生成的成本不对称设计合理**：非对称验证让每个验证器只攻击单条声明，从设计上避免了“用第二条全量错误链去验证第一条链”的失控问题；证据接地综合则保证了交付物中每条声明都有可追溯来源。
- **训练数据的职业覆盖面广**：文件世界覆盖 33 个领域、318 个职业、1208 个交付簇，且训练数据来自经许可的真实人工工作流程，说明团队在数据许可与质量把控上投入较大。
- **开源了可本地部署的 Mini 模型**：35B 版本在多个基准上超越了同规格 Apodex 1.0 mini 并接近部分前沿闭源模型，为研究社区提供了可复现入口，增强了论文的可验证性。

## 8. 不足与局限性

- **算力与训练细节完全不透明**：论文未披露 GPU 型号/数量、总训练 token、训练墙钟时间或整体预算，外部研究者无法评估方法的数据效率与算力门槛，也难以判断性能提升中有多少来自规模红利。
- **部分外部对比缺乏统一复现口径**：FrontierFinance 等基准上部分外部模型结果为“报告参考值”而非统一脚手架下复现；GDPVal 与 APEX-Agents 上的部分外部结果由作者内部复现，但未说明复现脚手架是否与官方原始评估一致。这引入了不可忽略的比较误差。
- **Agent Team 与基线的计算预算不对称**：Agent Team 可以动态生成任意数量的子智能体并并行执行，其推理总 token 与墙钟时间远超 ReAct 或静态提示基线。论文未提供等单位算力（per-compute-budget）的对比，因此“协调增益”中混入了“更多算力”的贡献。
- **内部基准的独立可复现性存疑**：FrontierSearchBench（41 个任务）与 FrontierResearchBench（97 个任务）为内部构建，评估管线、答案构造与验证细则没有作为开源基准公开发布，外部研究者难以独立复现或审阅其难度与公正性。
- **HDS6 的过程评分存在主观性**：虽然定义了四个评分项，但对“初始分解质量”“假设管理”等维度的打分仍依赖人工评审判断，论文未报告评分者间信度（inter-annotator agreement），存在主观偏差风险。
- **科研交付任务的绝对水平仍很低**：Apodex 1.1 在 FrontierResearchBench 上仅 12.4%，即使最强外部系统也不超过 20.6%。论文将此归因于任务难度，但也意味着其“重型求解器”雄心在当前仍只是阶段性成果。
- **数学提升可能存在数据边界风险**：IMO/USAMO 2025–2026 的分数跃升令人印象深刻，但论文未详细分析训练数据与这些竞赛题在时间线上是否可能重叠，也无法完全排除基准污染的可能。
- **超长时程的稳定性证据有限**：展示的端到端案例最长约为 82 分钟；对于论文宣称的“数天甚至数周”工作目标，异步干预、状态崩溃恢复、长时间工件完整性等行为尚未有系统性的压力测试。
- **训练数据与职业覆盖的偏倚未被讨论**：文件世界虽覆盖 318 个职业，但主要来自特定许可数据源，其职业、地域、语言分布的偏向性（如是否偏向英语世界、白领知识工作）并未被讨论。
- **对未来自我改进闭环的边界说明不足**：论文提到“受控开发循环”而非无约束自我修改，但对于“故障→新任务→再训练”的循环中人工介入的程度、频率与成本没有量化，外部难以判断该循环的可扩展性。

## 9. 总体评价与启示

总体而言，Apodex 1.1 是一篇**工程规模宏大、评测体系严谨、目标定位清晰**的智能体系统论文。它的核心贡献不在于某一项算法突破，而在于提出并实践了一个完整的范式转变：**以“随时间完成的可验证工作”作为智能体能力的度量单位**，并通过“环境扩展 + 协调扩展”两条正交路径系统性地逼近这一目标。任务契约、AgentOS 执行框架、PIVOT-RL 与 HDS6 过程评测共同构成了一个自洽且可演进的闭环体系，其设计哲学（验证窄于生成、证据驱动综合、事后枢纽点信用分配）对后续智能体研究与工程实践都有较强的借鉴价值。

与此同时，论文在算力披露、外部对比口径、内部基准开放性、计算预算对称性等方面的不足，使其性能数字在独立复现之前只能被视为“受控条件下的参考值”。其科研任务的低通过率也提醒我们：真正可靠的长时程自主工作，仍是整个领域尚未解决的难题。

**一句话概括**：Apodex 1.1 用系统性工程与严谨评测，把“智能体能否干活”这个模糊问题变成了可量化、可扩展、可追溯的科研议程，是“工作能力”范式下一次有分量的领跑尝试，但其绝对能力上限与独立可复现性仍需后续工作检验。
