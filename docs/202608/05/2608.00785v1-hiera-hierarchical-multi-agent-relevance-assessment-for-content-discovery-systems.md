## Abstract
Content discovery systems depend on relevance judgment for search quality evaluation, but human annotation faces inter-annotator disagreement and scaling costs. While Large Language Models show promise as automated assessors, current approaches rely on flat aggregation strategies: single-step prompting, voting ensembles, or uncoordinated multi-agent pipelines that aggregate independent outputs without integration. We propose HIERA, a hierarchical multi-agent relevance assessment framework with four specialized agents: a Relevance Judge, Query Analyzer, Item Analyzer, and Relation Analyzer. The Judge determines when specialist analysis is needed; the Relation Analyzer then coordinates query and item analyses with external knowledge to establish relevance relationships for final judgment. Ablation studies show that the same agents and external knowledge without hierarchical coordination degrade performance, confirming that the coordination structure itself accounts for the improvement. Evaluation across five datasets (EVS, MSRD, ESCI, WANDS, Home Depot) shows improvements over 11 baselines: 10.2\% on Home Depot, 4.8\% on ESCI, and up to 38\% on EVS ($p < 0.05$). Hierarchical coordination yields 12.7\% improvement over uncoordinated collaboration using identical agents.

### 1. 核心问题与整体含义（研究动机和背景）

- **研究背景**：内容发现系统（如流媒体平台、电商市场）的搜索质量高度依赖相关性评估，即判断内容与用户意图的匹配程度。这类评估是计算 NDCG、MAP 等检索指标的基础，也为推荐模型提供训练数据。
- **核心挑战**：
  - **人工标注不可靠**：相关性具有内在主观性，不同标注者经常对同一查询-条目对产生分歧（inter-annotator disagreement）。
  - **人工标注成本高**：跨领域标注数千个查询-条目对在经济上不可行，导致系统只能基于有限的 ground truth 运行。
- **现有 LLM 评估方法的局限**：
  - **单步方法（Single-step）**：直接提示模型一次性评估相关性，将全部推理压缩进单次推断，无法分解复杂相关性关系。
  - **多步方法（Multi-step）**：采用顺序处理（如先二分类过滤再细粒度评分），但各阶段信息隔离，缺乏分析推理的传递与整合。
  - **集成方法（Ensemble）**：通过投票或混合融合多模型输出，但缺乏协调机制，也没有针对不同相关性维度的专门分析。
- **关键动机案例**：查询 “gray dresser” 匹配 “metallic mercury finish dresser” 的真实标注为相关，但所有现有方法均判定为部分相关。该案例需要同时解释颜色关系（metallic mercury 即灰色）、评估风格兼容性（装饰风格对比）以及验证功能匹配（存储需求），需要多维度协同推理。
- **论文提出的核心需求**：(1) 专门化分析（不同维度需要不同专家能力）；(2) 结构化协调（各分析之间需要相互参考、逐层递进）；(3) 证据整合（最终判断需综合多方视角与外部知识，而非简单的独立输出聚合）。

### 2. 方法论：核心思想、关键技术细节与算法流程

- **HIERA 框架**（HIErarchical Relevance Assessment）将相关性评估分解为专门化的、相互协调的组件，采用三层架构：

  - **决策层（Decision Layer）**：**Relevance Judge Agent (J)**
    - 检查查询-候选项证据，评估三个维度是否需要专家介入：
      - **Query Interpretability（查询可解释性）**：用户意图是否明确陈述，还是需要推断。
      - **Information Completeness（信息完整性）**：候选项可用信息是否足以支撑判断。
      - **Relational Transparency（关系透明度）**：查询与结果之间的语义连接是否直接可感知。
    - 若任一维度证据不足，J 委托给 Relation Analyzer（R）；若所有维度清晰，则直接输出判断。

  - **分析层（Analysis Layer）**：三个专职分析器
    - **Relation Analyzer Agent (R)**：负责连接分析与协调，作为层级协调者，根据已识别的信息缺口咨询 Query Analyzer（Q）、Item Analyzer（I）与外部知识（K），并将所有专家发现整合为一个结构化相关性论证，返回给 J。
    - **Query Analyzer Agent (Q)**：负责查询理解，将查询拆解为显式需求与隐式意图（如风格或功能偏好），必要时访问 K。
    - **Item Analyzer Agent (I)**：负责候选条目表征，提取显式特征与推断属性（如颜色外观、风格类别），必要时访问 K。
    - 该分离遵循**单一职责原则**：智能体专注于特定任务时比同时处理多种分析挑战更高效。

  - **信息层（Information Layer）**：**外部知识访问 (K)**
    - 为分析层智能体提供事实验证的外部知识（如 Web 搜索、结构化数据库）。
    - 智能体根据分析中识别的具体缺口构造定向查询，检索结果在智能体分析框架内被情境化整合。

- **协调协议（Coordination Protocol）**（用文字说明的算法流程）：
  1. J 判定需更多证据时，将指导信息（identified gaps）委托给 R。
  2. R 进行自身的连接分析，根据发现的缺口激活相关专家：Q 解释查询、I 表征候选条目、K 提供事实验证。
  3. 关键在于 **整合而非独立**：R 将各专家的发现综合成单一结构化论证后再返回 J。
  4. 形式化表达：
     - `Gaps = R(q, c, guidance_J)`：R 基于查询、候选与 J 的指导识别信息缺口。
     - `Active = {s ∈ {Q, I, K} : s 解决 Gaps}`：激活能解决相应缺口的专家。
     - `Result = integrate(∪ s(Gaps))`：所有主动专家的结果经 R 整合。
  - **与并行多智能体方法的本质区别**：所有专家发现先经过 R 再到达 J，最终论证反映查询意图、条目属性与外部证据之间的**交互关系**，而非将各信号视为独立证据。

### 6. 主要结论与发现

- **HIERA 在所有 5 个数据集上的一致且显著的性能提升**：
  - EVS：准确率较最佳基线（Zero-Shot）提升 38%（0.713 vs 0.517），κ 提升 70%（0.461 vs 0.271）。
  - Home Depot：较 Multi-Criteria 提升 10.2%（0.464 vs 0.421）。
  - ESCI：较 Self-Instruct 提升 4.8%（0.543 vs 0.518）。
  - WANDS：较 LLM-Blender 提升 4.3%（0.681 vs 0.654）。
  - MSRD：较 Self-Instruct 提升 2.4%（0.859 vs 0.839）。
- **层级协调结构本身是性能提升的来源**：
  - 相同智能体与外部知识在不经层级协调时，κ 下降 37%（0.524 vs 0.718）。
  - 协调结构带来 12.7% 的性能提升（相对于同智能体的非协调协作）。
  - 在 token 消耗几乎相同（2,917 vs 2,866）的情况下，协调结构仍大幅领先，证明增益来自拓扑结构而非算力投入。
- **外部知识的价值取决于集成方式**：
  - 相同 Web 搜索结果在 HIERA 中带来 +12.7%（MSRD）的改进，但直接拼接给大多数基线反而造成性能下降（如 Multi-Criteria 在 MSRD 上 -2.4%，Multi-Stage -5.6%，CollabEval 在 WANDS 上 -6.5%）。
  - 结论：知识需要被情境化整合到分析框架中，而非作为原始补充文本附加。
- **激活频率**：J 在 91.5% 的情况下会委托给完整层级，仅 8.5% 直接判断。价值在于协调协议本身，而非选择性激活。
- **核心结论**：对需要多维度推理的相关性评估任务，通过中央合成器（R）的结构化编排优于独立多智能体运行和平面聚合策略。构建多智能体评估系统时，投资于协调协议比增加智能体数量或使用更昂贵模型带来更大收益。

### 7. 优点（方法/实验设计亮点）

- **方法设计**：
  - 将单一职责原则引入相关性评估：查询意图、条目表征、关系分析各有专职智能体，避免多任务同时处理导致的能力稀释。
  - 三层架构清晰：决策层判断“是否需要”，分析层回答“具体是什么”，信息层提供“事实依据”，职责边界分明。
  - 协调协议是整合式的而非聚合式的：所有专家输出先经 R 合成，最终论证反映多维度交互而非独立信号拼接。
  - 智能体具备自适应性：可根据信息缺口动态激活所需专家（Q/I/K），而非固定流程；同时 J 可在证据充分时直接判断，避免不必要的计算开销。
  - 外部知识访问是有目标的：智能体基于具体分析缺口构造查询，检索结果在分析框架内被情境化整合。
- **实验设计**：
  - 消融设计精细且具有强说服力：通过控制 token 预算（2,917 与 2,866 仅差 1.8%），有效排除了“更多计算 = 更好性能”的替代解释。
  - 外部知识集成实验设计巧妙：向所有基线提供与 HIERA 完全相同的 Web 搜索结果，精确隔离了“信息可得性”与“集成策略”两个变量。
  - 使用 3 个互补指标（Accuracy、Macro F1、Cohen's κ），兼顾整体正确率、类别均衡性和偶然一致性校正。
  - 统计检验规范（McNemar + Bonferroni），提供 Bootstrap 置信区间，结果可信度高。
  - 案例研究深入：成功与失败案例的完整执行轨迹分析，揭示了多智能体协调的模式化行为特征与系统性局限。

- **应用限制**：
  - HIERA 延迟显著高于单步方法（35.6s vs 0.93–0.98s），不适用于在线实时评估场景，仅适用于离线评估等延迟容忍任务。

  - 资源消耗较高：多智能体协调产生显著 token 消耗与 API 调用成本。
