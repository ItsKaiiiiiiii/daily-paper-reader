## 摘要
大语言模型（LLM）智能体日益依赖外部工具来完成复杂的现实世界任务。然而，由于隐式推理的局限性以及现实世界执行环境的动态演变，可靠的工具使用规划仍然具有挑战性。现有的工具使用智能体通常依赖LLM从文本描述中推断工具组合，这可能导致在复杂任务中探索效率低下和执行不可靠。为应对这些挑战，我们在模式层面建模工具关系，并构建有向的工具-模式超图（Tool-Schema Hypergraph），其中工具被表示为从其所需输入模式节点到输出模式节点的超边。此外，我们提出了HyperAgent，一种由工具-模式超图引导的动态规划与执行框架。给定一个任务，HyperAgent首先提取任务相关的工具上下文图，并利用该图引导构建模式感知的任务DAG（有向无环图）。在执行过程中，HyperAgent通过基于缺陷导向扩展的、状态条件驱动的工具支持图构建来动态实现每个子任务，该图识别未解决的依赖需求，并根据当前智能体状态检索支持性的生产者工具。在AppWorld上的实验表明，与现有智能体基线相比，HyperAgent在提高任务完成性能的同时，减少了冗余API调用、LLM交互次数和Token消耗。

## Abstract
Large language model (LLM) agents increasingly rely on external tools to complete complex real-world tasks. However, reliable tool-use planning remains challenging due to the limitations of implicit reasoning and the evolving nature of real-world execution environments. Existing tool-use agents typically rely on LLMs to infer tool compositions from textual descriptions, which can lead to inefficient exploration and unreliable execution in complex tasks. To address these challenges, we model tool relations at the schema level and construct a directed Tool--Schema Hypergraph, in which tools are represented as hyperedges from their required input-schema nodes to their output-schema nodes. Furthermore, we propose HyperAgent, a Tool--Schema Hypergraph-guided framework for dynamic planning and execution. Given a task, HyperAgent first extracts a task-relevant tool context graph and uses it to guide the construction of a schema-aware Task DAG. During execution, HyperAgent dynamically realizes each subtask by constructing a state-conditioned tool support graph through deficit-oriented expansion, which identifies unresolved requirements and retrieves supporting producer tools according to the current agent state. Experiments on AppWorld demonstrate that HyperAgent improves task completion performance while reducing redundant API calls, LLM interactions, and token consumption compared with existing agent baselines.

### 1. 核心问题与整体含义（研究动机和背景）

- **研究背景**：大语言模型（LLM）智能体在复杂现实任务中越来越多地依赖外部工具（API、操作系统、软件服务）。但可靠的工具使用规划仍面临两大挑战：
  - **隐式推理不可靠**：现有方法依赖 LLM 从文本工具描述中推断工具组合，难以准确识别工具间的参数依赖（如上游工具的输出是否能满足下游工具的输入），尤其在工具文档规模庞大时容易出错。
  - **环境动态演化**：工具的可执行组合依赖于运行时状态（已有值、效果、错误等），静态规划的工具路径可能冗余或缺失，导致在线探索低效甚至执行失败。
- **现有方法局限**：
  - 早期方法（如 ReAct、PlanExec）依赖在线试错或静态任务分解，缺乏对工具依赖的显式建模。
  - 图增强方法（如 ToolNet、GTool、In-N-Out）虽显式建模工具关系，但存在两个关键缺陷：
    - 仅捕获粗粒度工具依赖，未指明上游哪个输出具体满足下游哪个输入，产生歧义。
    - 工具组合未考虑智能体状态（已获得的值、已实现的效果），静态规划无法适应动态执行。
- **论文核心含义**：主张在“模式（Schema）层”显式建模工具间细粒度依赖，并利用超图结构引导规划与执行，从而提升工具组合的可靠性与效率。

### 2. 论文提出的方法论：核心思想、关键技术细节、流程

#### 核心思想
- 构建**有向工具-模式超图（Tool-Schema Hypergraph, TSH）**，将每个工具表示为从输入模式节点集到输出/效果节点集的超边，并通过端口级依赖链接（输出模式→输入模式）刻画跨工具的数据流。
- 提出 **HyperAgent** 框架，分三阶段：离线构建超图 → 在线任务级规划（提取上下文图、生成任务 DAG）→ 在线执行（动态构建工具支持图、验证并更新状态）。

#### 关键技术细节
1. **超图构建与精化**：
   - 基于专家标注的 In-N-Out 参数级 API 图，将每个 API 工具转换为超边，保留输入/输出模式节点与跨工具依赖链接。
   - 从工具文档中提取“效果（effect）”和“前置条件（condition）”节点，补充状态类依赖；使用 GPT-4o 生成候选、专家验证、并标注强弱依赖。
   - 定义超图 $H=(V,E,D)$，$V$ 为输入/输出/效果节点，$E$ 为工具超边，$D$ 为端口级依赖权重。

2. **任务级规划**：
   - **任务解释**：LLM 将用户请求解析为操作语义 $d_t^{op}$ 和模式语义 $d_t^{sch}$，分别作为检索信号。
   - **种子锚定**：基于操作语义检索 Top-K 超边；基于模式语义锚定输入/输出侧节点。
   - **上下文图提取**：从种子节点和超边出发，执行有界反向扩展（依赖链接反向），结合依赖权重与语义相似度排序，提取紧凑的 **Tool Context Graph**，保留任务相关工具的依赖拓扑。
   - **任务分解**：将上下文图序列化后，LLM 生成 **Schema-level Task DAG**，每个子任务包含目标、输出模式/效果、候选终端工具集，边表示数据或效果依赖（由上下文中具体依赖链接支撑）。

3. **执行阶段**：
   - **拓扑执行**：按依赖拓扑选择就绪子任务，执行后用新获得的模式-值绑定和效果更新智能体状态 $S_\ell=(C_\ell,R_\ell,I_\ell)$，并据此精化剩余 DAG。
   - **子任务验证**：不仅检查 API 调用成功，还验证执行痕迹是否满足预期的输出、效果和约束，只有满足“契约”才标记完成。
   - **缺陷导向扩展（Deficit-Oriented Expansion, DOE）**：
     - 对每个候选终端工具，维护**缺陷集**（当前状态或已选工具输出不能提供的输入模式）。
     - 使用 beam search 迭代加入生产者超边，优先选择输出与缺陷集重叠度高的工具，更新缺陷集，直至缺陷集为空得到完整支持子图。
     - 选择支持子图作为该子任务的工具组合，执行并更新状态。

#### 公式与算法流程（文字说明）
- 工具-模式支持强度 $\rho(e,r) = \max_{o\in O(e)} W(o,r)$，预计算稀疏生产者矩阵 $A_{prod}$。
- 缺陷集 $M_{G_h}$ 编码为二元向量；扩展方向按 $\Omega(e,M_{G_h}) = \sum_{r\in M_{G_h}} \rho(e,r)$ 排序；每轮保留 Top-B 子图候选（按缺陷集大小排名）。
- 整体流程：TSH 构造 → 上下文图抽取 → Task DAG 生成 → 拓扑执行 + DOE 支持图构建 + 状态更新与 DAG 精化。

### 6. 主要结论与发现

- **性能提升**：HyperAgent 在 AppWorld Test-N 和 Test-C 上，TGC/SGC 均显著优于 ReAct、PlanExec、FullCodeRefl 等非微调框架（如 GPT-4o 下 Test-N TGC 67.1% vs ReAct 48.8%），且可与强 RL 方法（LOOP）竞争。
- **效率提升**：相比 ReAct，HyperAgent 大幅减少 LLM 交互轮次、API 调用数和 token 消耗（Test-C 中 API 调用从约 123 降至 57，token 从 180k 降至 68k）。
- **组件有效性**：去掉图上下文或工具支持子图均导致性能下降；增大扩展深度和 Top-K 可先提升性能，但过度扩展增加 token 成本而无明显收益。
- **上下文图质量**：HyperAgent 的上下文图比语义检索和 In-N-Out 图检索有更高的黄金工具召回率，能恢复语义不直接相关但操作上必需的先决工具。
- **动态适应性**：在相同子目标集下，HyperAgent 比 ReAct 实现更高子目标完成率（74% vs 64%）且平均 LLM 调用更少（2.5 vs 5.2）。

### 7. 优点

- **新颖性**：将超图引入工具-模式依赖建模，自然表达“多输入多输出”的联合约束，优于普通图的成对边。
- **细粒度依赖建模**：端口级模式依赖（哪个输出支持哪个输入）消除了工具间依赖的歧义，减少冗余调用。
- **状态条件化规划**：DOE 根据当前智能体状态动态补齐缺失生产者，避免静态计划失效。
- **两阶段规划与执行解耦**：任务级 DAG 负责全局规划，工具级支持子图负责局部实现，兼顾全局一致性与局部适应性。
- **效率显著**：通过减少 LLM 交互和 token 消耗，降低成本，同时改善性能。
- **模块化实现**：检索和扩展模块是确定性的，不频繁调用 LLM，工程上更可控。
