## 摘要
长时程工具使用智能体必须对用户目标、领域策略、工具调用、模拟器状态以及延迟的可验证奖励进行推理。强化学习（RL）天然适用于这一场景，但多轮on-policy展开会产生长上下文，而模型特定的注意力层可能需要自定义掩码和习得的汇合归一化。我们提出了SINKFLEX-RL，一个用于双控工具使用环境中强化学习的模块化训练系统。该系统结合了Gymnasium兼容的环境封装器、VERL风格的展开数据流、无需独立价值模型的组相对策略优化，以及一个sink感知的FlexAttention路径，旨在因果和滑动窗口掩码下保持模型特定的sink缩放。在Tau2Bench零售初步运行中，验证奖励（mean@1）从训练早期的0.25上升至观察训练窗口后期的0.44，同时训练得分和轨迹奖励代理也呈上升趋势。在固定配置的内存基准测试中，优化后的注意力路径在4096个token时将峰值VRAM从28.06GB降至22.52GB，减少了19.7%，并在8192个token配置下使用25.53GB运行，而eager基线则内存不足。这些结果展示了集成环境接口、RL数据流和注意力内核设计对于内存可行的长时程智能体训练的价值。

## Abstract
Long-horizon tool-using agents must reason over user goals, domain policies, tool calls, simulator state, and delayed verifiable rewards. Reinforcement learning (RL) is a natural fit for this setting, but multi-turn on-policy rollouts create long contexts, while model-specific attention layers may require custom masks and learned sink normalization. We present SINKFLEX-RL, a modular training system for RL in dual-control tool-use environments. The system combines a Gymnasium-compatible environment wrapper, a VERL-style rollout dataflow, group-relative policy optimization without a separate value model, and a sink-aware FlexAttention path designed to preserve model-specific sink scaling under causal and sliding-window masks. In a preliminary Tau2Bench retail run, validation reward (mean@1) rises from 0.25 early in training to $0.44$ later in the observed training window, while training-score and trajectory-reward proxies also trend upward. In a fixed-configuration memory benchmark, the optimized attention path reduces peak VRAM from 28.06GB to 22.52GB at 4096 tokens, a $19.7\%$ reduction, and runs the measured 8192-token configuration using $25.53$~GB where the eager baseline runs out of memory. These results illustrate the value of integrating environment interfaces, RL dataflow, and attention-kernel design for memory-feasible long-horizon agent training.

### 2. 论文提出的方法论：核心思想、关键技术细节、公式或算法流程

#### 核心思想
- 将工具使用 RL 训练拆分为可替换的模块组件，并统一通过 Gymnasium 兼容接口连接。
- 使用 GRPO 替代 PPO 的独立价值网络，减少模型参数量和内存占用。
- 通过数学等价将显式 sink token 替换为输出缩放操作，避免额外 token 的键值缓存和注意力计算。
- 利用 PyTorch FlexAttention 的可编程掩码与融合执行，在保持模型特定注意力语义的同时减少内存。

#### 关键技术细节

**环境封装与 rollout 数据流**
- 提供 `reset/step` 接口，将模型输出路由到自然语言回复、工具调用或终止三类动作。
- 环境内部处理用户模拟器、状态后端和奖励检查，训练器不依赖具体基准实现。
- Rollout worker 负责采样、格式化、解析动作，并收集 logits、动作掩码、轨迹奖励等元数据。

**GRPO 更新（无价值模型）**
- 对同组 G 个 rollout 的轨迹奖励做组归一化：
  - $\hat{A}_i = \frac{R_i - \mu(R_{1:G})}{\sigma(R_{1:G}) + \epsilon_A}$
- 使用重要性采样比率和裁剪后的损失：
  - $J_{i,t}(\theta) = \min \left( \rho_{i,t}(\theta)\hat{A}_i,\ \text{clip}(\rho_{i,t}(\theta), 1-\epsilon_c, 1+\epsilon_c)\hat{A}_i \right)$
- 最终损失包含对参考模型的 KL 正则项。

**零值 sink 等价**
- 若 sink 的 value 向量为零，则显式拼接 sink token 的注意力输出等于：
  - $O_{\text{sink}} = \sigma(\ell - s_\eta) \cdot O_{\text{std}}$
  - 其中 $\ell = \log\sum_i \exp(q\cdot k_i)$，即标准注意力的 log-sum-exp。
- 这避免了显式物化 sink token，只需在注意力输出上施加一个数据依赖的缩放因子。

**Sink-aware FlexAttention 路径**
- 掩码函数组合因果、滑动窗口、常显前缀：
  - $M_{b,h,q,k} = 1[k \le q] \land 1[q-k \le w \lor k < p]$
- 注意力调用返回输出 $z$ 和 log-sum-exp $\ell$，然后施加 $z' = z \odot \alpha_{\text{sink}}$，$\alpha_{\text{sink}} = f_\eta(\ell)$。
- 通过 `torch.compile` 和 AOTAutograd 自动生成前向/反向代码，避免物化 $O(n^2)$ 的 Jacobian。
- 掩码元数据跨 batch/head 共享，通过 kernel 侧广播避免重复存储。

### 7. 优点：方法或实验设计上的亮点

- **模块化设计**：环境、rollout、GRPO、注意力内核分离，便于扩展其他工具使用环境。
- **数学等价的零值 sink**：将显式 sink token 的注意力转化为输出缩放，既保留语义，又免除额外的缓存和计算。
- **FlexAttention 的可编程性**：允许自定义掩码和 score 修改，同时保留融合、块稀疏执行路径，兼顾模型兼容性与内存效率。
- **GRPO 省去价值模型**：在长上下文下减少一整套网络的显存占用和计算。
- **实验表述诚实**：明确指出训练实验是“初步”的、内存实验不测吞吐，没有夸大结论，这对学术可信度有积极意义。
