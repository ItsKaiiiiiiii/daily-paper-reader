## 摘要
自我进化智能体通常围绕预设的优化管线构建：框架决定如何收集证据、修订持久化工件、选择候选者以及何时停止。我们探究当前沿模型作为优化器时，这种特定任务的程序是否仍然必要。我们引入了开放式优化（OEO），它保持目标、允许的交互、资源预算、数据边界和评估固定，同时允许优化器在线组合改进过程。我们将OEO与两种互补的预设方法进行比较：SkillOpt（一种具有有界编辑的分阶段管线）和GEPA（一种反思性进化搜索）。在跨越8个基准-目标模型设置的14次直接比较中，由GPT-5.5驱动的OEO取得了12胜1平1负的微弱劣势（差距0.21个百分点）。其使用的目标交互令牌预算中位数为SkillOpt配置的34.3%。一次性、零交互的对照实验表明，这些收益并不能由单次先验驱动的重写来解释。然而，委派存在能力边界：SkillOpt在中等优化器下优于OEO，而弱优化器无法通过不变的OEO界面运行。在完全插桩的OEO-SkillOpt配对中，轨迹分析进一步表明，预设对优化过程的影响比对最终行为的影响更为一致。总体而言，这些发现将预设管线重新定义为依赖于能力的脚手架：必要的约束仍然外部化，但一个足够强大的优化器可以自行组合从可测量反馈到持续改进的路径。

## Abstract
Self-evolving agents are usually built around prescribed optimization pipelines: the framework decides how to gather evidence, revise a persistent artifact, select candidates, and stop. We ask whether this task-specific procedure remains necessary when a frontier model acts as the optimizer. We introduce Open-Ended Optimization (OEO), which keeps the objective, permitted interactions, resource budget, data boundary, and evaluation fixed while allowing the optimizer to compose the improvement process online. We compare OEO with two complementary prescribed approaches: SkillOpt, a staged pipeline with bounded edits, and GEPA, a reflective evolutionary search. Across 14 head-to-head comparisons over 8 benchmark-target-model settings, GPT-5.5-driven OEO records 12 wins, 1 tie, and 1 narrow loss of 0.21 percentage points. It uses a median 34.3 percent of SkillOpt's configured target-interaction token budget. A one-shot, zero-interaction control shows that the gains are not explained by a single prior-driven rewrite. However, delegation has a capability boundary: SkillOpt outperforms OEO with a medium optimizer, and a weak optimizer cannot operate through the unchanged OEO interface. In the fully instrumented OEO-SkillOpt pair, trajectory analysis further shows that prescription changes how optimization proceeds more consistently than it changes final behavior. Together, these findings recast prescribed pipelines as capability-dependent scaffolding: essential constraints remain external, but a sufficiently capable optimizer can compose the route from measurable feedback to persistent improvement.

### 2. 论文提出的方法论

**核心思想：Open-Ended Optimization（OEO，开放式优化）**

- OEO是论文提出的用于检验“元策略归属”的核心方案。它保持外部优化契约完全固定，但将任务特定的改进流程（证据收集、修订策略、候选选择、停止规则等）完全交由优化器在线自主组合。
- OEO并非无约束的“自由发挥”，而是**由执行器（runner）强制契约边界**的智能体循环：优化器只能通过允许的操作接口与任务交互，操作包括：INSPECT（检查证据）、RUN_TARGET（执行目标模型）、REVISE（修订技能）、SELECT（选择历史检查点作为输出）、STOP（终止）。

**OEO算法流程（文字描述）：**

```
初始化：当前技能 s ← s0，历史 H ← ∅，检查点 K ← [s0]，选定技能 ŝ ← ⊥
循环（预算允许）：
  1. 优化器观察 (s, H, K, 剩余预算)，选择一个允许的操作
  2. 执行器校验操作合法性及剩余资源
  3. 若为 REVISE(s′)：
     - 更新当前技能，加入检查点，记录提交
  4. 若为 SELECT(j)：
     - 设置选定技能为 K[j]，记录选择
  5. 若为 STOP：
     - 终止循环
  6. 否则（INSPECT / RUN_TARGET）：
     - 执行操作，将观察结果追加到历史 H
  7. 更新优化器和目标模型的资源计数
结束：返回 ŝ（若已选择），否则返回当前技能 s；在密封最终划分上评估一次
```

**对比的两种预设方法：**

| 维度 | SkillOpt | GEPA | OEO |
|------|----------|------|-----|
| 证据调度 | 固定批次rollout与反思 | 父代与minibatch选择 | 优化器自主决定 |
| 诊断方式 | 成功/失败分解 | 轨迹条件反思 | 优化器自主决定 |
| 修订空间 | 有界补丁算子 | 自由形式文本变异 | 优化器自主选择编辑或重写 |
| 候选保留 | 严格改进门控+拒绝记忆 | Pareto感知池更新 | 优化器从提交状态中选择 |
| 调度与停止 | 固定阶段和epoch | 预算化进化循环 | 预算内自适应终止 |
| 返回技能 | 验证集最佳 | 验证集最佳候选 | 优化器选定的提交状态 |

### 6. 论文的主要结论与发现

1. **前沿优化器可以在无预设管线的情况下实现竞争性自我改进：**
   - OEO 在所有8个设置中均改善了初始技能；SkillOpt改善7个；GEPA改善其6个确认设置中的5个
   - OEO在GPT-5.5目标LiveMath上领先SkillOpt 18.55个百分点，领先GEPA 28.23个百分点

2. **效率提升显著：**
   - OEO 使用 SkillOpt 配置目标交互token预算的**中位数34.3%**且在每个设置中均低于100%
   - 在GPT-5.5目标SpreadsheetBench上仅用6.1%预算即达到平局（0.7607）

3. **收益不是单次静态重写可以解释的：**
   - 一次性重写在SearchQA上有帮助（+2.07和+5.00个百分点），但仍低于OEO 6.14和3.57个百分点
   - 在LiveMath上，静态重写反而降低了两个初始分数，而OEO改善了34.68和29.84个百分点

4. **委派存在能力边界：**
   - 在中等优化器（Qwen3.5-27B）下，SkillOpt在两个任务上均反超OEO（LiveMath领先9.68个百分点，SearchQA领先3.50个百分点）
   - 弱优化器（Qwen3.5-4B）通过OEO界面产生无效动作，根本无法执行；而SkillOpt runner可以完成运行
   - OEO对优化器能力的敏感度远高于SkillOpt（能力从中等提升到前沿时，OEO提升16.13/7.07个百分点，SkillOpt仅提升2.42/0.64个百分点）

5. **预设流程改变“路径”多于改变“行为”：**
   - 在所有8个OEO–SkillOpt配对中，OEO的最大编辑更大、触及的章节更广、修订更频繁
   - 但两方法选中的技能在7/8设置中pass/fail一致性≥0.78，在5/8设置中correct-set Jaccard > 0.70
   - 技能文本距离与行为距离的相关性仅ρ=0.3095，说明路径、文本、行为应分别评估

**最终原则：** 能力自适应责任分配（capability-adaptive responsibility）——保持契约外部化，将任务特定处方视为设计选择而非默认项；仅将在线组合委托给能有效承担该责任的优化器。

### 7. 优点

- **概念框架清晰且有区分度：** 将“优化契约”（外部治理边界）与“优化元策略”（任务特定路径）分离，为后续研究提供了清晰的分析语言
- **对照设计严谨：** 选择两种结构互补的预设管线（分阶段管线 vs 进化搜索），覆盖面广；新增一次性静态重写对照，排除“先验知识”的竞争解释
- **多层次评估体系：** 不仅报告最终分数，还引入轨迹指标（最大编辑、章节广度、修订churn）和逐条行为重叠指标（pass/fail一致性、correct-set Jaccard、gain-set Jaccard），体现了“过程”与“功能”分离评估的先进方法论
- **诚实的边界发现：** 主动通过能力梯度实验揭示OEO的适用边界，不夸大结论适用范围；明确将post-hoc的SpreadsheetBench GEPA对比排除在确认性计数之外
- **效率证据具体且可验证：** 以token预算作为标准化参照，直接量化效率差距，并区分优化器token与目标交互token

### 8. 不足与局限

- **缺乏统计显著性检验：** 每个设置只报告单次运行结果，未报告多次运行的均值、方差或置信区间。在存在明显优势时（如LiveMath差距18-28个百分点）影响不大，但在接近的场景（如SearchQA差距0.07-0.21个百分点）中，结果可能是噪声
- **未来模型能力的参考性有限：** 实验依赖2026年的GPT-5.5和Qwen3.5系列，结论的长期适用性需随模型能力演变持续验证
- **GEPA对比覆盖不完整：** SpreadsheetBench的GEPA对比为post-hoc匹配，非GEPA原生选择流程；GEPA的轨迹诊断因缺乏插桩而不可得，部分对比结论仅基于OEO–SkillOpt配对
- **轨迹分析仅限一个预设方法：** 无法确认“处方改变路径多于改变行为”的结论是否对GEPA同样成立
- **资源/算力信息缺失：** 未报告GPU型号、数量、训练时间或实际运行耗时，难以评估方法的计算成本
- **弱优化器场景下OEO完全不可用：** 未尝试为弱优化器适配OEO界面（如更结构化动作空间或校验机制），这一局限性可能来自于界面设计而非开放式优化的本质缺陷
- **token预算的边界定义存在模糊性：** 模型调用是原子性的，一个在预算内开始但超出预算完成的调用可能产生轻微超支，论文承认这一点但未详细说明超支规模
