## 摘要
自主LLM智能体日益部署于复杂真实世界工作流中，但其仍易受运行时行为漂移影响，即对原始任务的静默偏离，可能导致对外部系统不可逆的副作用。现有方法在提示层面处理漂移，但缺乏步骤级检测、风险评估和恢复决策的结构化机制。由于主任务执行智能体通常是大规模且昂贵的模型，无法在每次部署中重新训练，本研究针对即插即用的恢复模块展开。该工作引入一种基于图的框架，其中单个小型语言模型通过强化学习训练，在恢复图的每个节点上专门化，独立于主智能体。每个节点具有精确角色：漂移分类、操作检测、风险评估或最终决策，模型学习生成适应该角色的结构化XML格式推理。训练结合基于规则的 structural 奖励与 LLM-as-judge 语义质量信号，使模型在回答方式（模式与长度）和内容上均获得评分。在公开的AppWorld基准上的实验表明，该方法通常利用疑似漂移发生信息，借助小型语言模型作出正确恢复决策。此外，经训练的小型语言模型可靠遵循指定输出模式，并根据其分配的节点角色在各字段中生成语义适当的内容。

## Abstract
Autonomous LLM agents are increasingly deployed in complex real-world workflows, yet they remain vulnerable to runtime behavioral drift, a silent deviation from the original task that can lead to irreversible side effects on external systems. Existing approaches address drift at the prompt level but lack structured mechanisms for step-level detection, risk assessment, and recovery decision. Because the main task-executing agent is often a large and expensive model that cannot be re-trained on every deployment, this work targets a plug-and-play recovery module instead. It introduces a graph-based framework in which a single small language model is trained via reinforcement learning to specialize at each node of a recovery graph, external to the main agent. Each node has a precise role\,: drift classification, operation detection, risk evaluation, or final decision and the model learns to produce structured XML-formatted reasoning adapted to that role. Training combines rule-based structural rewards with an LLM-as-judge semantic-quality signal, so that the model is graded both on how it answers (schema and length) and on what it says. Experiments on the public AppWorld benchmark show that the method generally exploits information about the suspected drift onset to issue correct recovery decisions using a small language model. In addition, the trained small language model reliably respects the prescribed output schema and produces semantically appropriate content in each field according to its assigned node role.

## 论文详细总结：基于图的强化学习框架用于自主 LLM 智能体的结构化漂移诊断与恢复

### 1. 核心问题与研究动机

- **问题背景**：自主 LLM 智能体（如 ReAct 模式）已从“回答问题”演进为“执行动作”——调用 API、发送邮件、转账、修改数据库。随着真实系统集成加深，每一步错误的成本急剧上升。
- **核心痛点**：智能体在执行过程中容易出现**行为漂移（Behavioral Drift）**——即“安静地偏离原始任务目标”。漂移不是崩溃，也不仅仅是幻觉回答；而是一个由幻觉或恶意注入（如网页/邮件中的 prompt injection）触发后，智能体在后续步骤中自信地执行越来越偏离目标的动作。
- **现有方法不足**：
  - 大多数防御集中在**输入端预防**（如隔离不可信内容、指令层级训练、工具边界防火墙），但漂移不可避免会发生。
  - 一旦发生漂移，已有的“回滚消息历史”并不能回滚外部环境状态（世界没有回滚）。
  - 缺乏对漂移后恢复的系统性方法：即在漂移发生后，需要（i）回溯轨迹定位漂移起点，（ii）列出漂移期间实际提交的写操作，（iii）判断操作是否可逆，（iv）在回滚与升级给人类之间做决策。
- **核心挑战**：主任务执行智能体往往是大规模、昂贵的模型，不能针对每次部署重新训练。因此本文目标是开发一个**即插即用的外部恢复模块**，无需重训主智能体。

### 2. 方法论：图基恢复框架与 GRPO 训练

#### 2.1 核心思想
将漂移恢复建模为一个小型状态机的路由遍历过程。一个**单一的**小语言模型（SLM）通过强化学习被专门化到恢复图中的**五个节点角色**，各节点间通过结构化 XML 格式传递信息。

#### 2.2 恢复图架构（五节点状态机）
| 节点 | 角色 | 输出 JSON 键 |
|---|---|---|
| n1 | 漂移分类：判断单步是否与任务对齐 | `{step, is_aligned, why}` |
| n2 | 操作检测：枚举漂移步骤中的写操作和离轨读操作 | `{write_operations, read_operations}` |
| n3 | 搜索 API：确定涉及的应用以获取文档 | `{apps_name}` |
| n4 | 风险评估：将写操作划分可逆/不可逆 | `{write_reversible, write_not_reversible}` |
| n5 | 汇总与决策：输出回滚或升级人类的最终动作 | `{action, arguments}` |

- **路由规则（Algorithm 1）**：
  - 从疑似漂移起点 k0 开始**向后遍历**；
  - n1 判定某步为漂移（N）→ 进入 n2 → n3 → n4 → 回到 n1；
  - n1 判定对齐（Y）→ 检查连续 K 个对齐步 → 若满足则终止回溯，进入 n5 决策；
  - 若 n2 检测到无写操作 → 直接返回 n1 继续回溯。
- **对齐连击（Aligned Streak）K**：单一对齐步不足以证明漂移结束，需要一个短的连续对齐串作为稳健的终止代理。

#### 2.3 结构化 XML 推理
每个节点强制输出一个 `<reasoning>` 块 + 一个 `<answer>` JSON 块。这种固定模式避免了自由式 CoT 的解析不确定性，使各节点输出成为下游节点可直接消费的“类型化消息”。

#### 2.4 GRPO 训练机制
- **训练框架**：GRPO（Group Relative Policy Optimization），取代 PPO 中的值网络，优势基于组内比较：
  \[
  \hat{A}_i = \frac{r_i - \bar{r}}{\text{std}(r) + \varepsilon}
  \]
- **目标函数**：
  \[
  J(\theta) = \mathbb{E}_{q,\{o_i\}} \left[ \min\left(\rho_i \hat{A}_i, \text{clip}(\rho_i, 1-\epsilon, 1+\epsilon) \hat{A}_i\right) - \beta D_{KL}(\pi_\theta \| \pi_{ref}) \right]
  \]
- **关键设计**：同一个策略模型通过**角色条件提示（node-tagged prompt）**在五个角色上联合训练，无需为每个节点训练独立策略。

#### 2.5 复合奖励函数
奖励由九部分组成（均为 [0,1] 非负）：
- **格式奖励（节点无关）**：`r_xml-count`（标签计数与尾随文本惩罚）、`r_strict`（严格标签顺序与间距）、`r_soft`（宽松标签顺序）；
- **长度与风格奖励（节点无关）**：`r_reas-len`（推理块简洁度）、`r_tot-len`（总输出紧凑度）；
- **JSON 有效性及节点模式（节点特定）**：`r_json-valid`（JSON 语法），`r_json-schema`（键集合精确匹配 + Jaccard 部分加分），`r_json-sanity`（各节点值域合法性检查，如 `is_aligned ∈ {Y,N}`）；
- **语义质量信号（LLM-as-judge）**：冻结的更强 LLM（14B 模型）根据角色特定 rubric 对 `<reasoning>` 的接地性、`<answer>` 内部一致性及角色合理性打分（1.0=具体/接地/正确，0.5=泛泛但不错误，0.0=空/幻觉/矛盾）。

#### 2.6 漂移分类学（Drift Taxonomy）
- **Type I（瞬时读漂移）**：漂移区无写操作，漂移源是瞬时的，回滚消息历史即可恢复。
- **Type II（持久读漂移）**：漂移区无写操作，但漂移源持久存在于环境（如中毒文档/邮件），需额外向重执行的智能体注入恢复记忆/警告。
- **Type III（写漂移）**：漂移区执行了写操作，环境状态已改变，回滚不足以恢复。需判断写操作的可逆性：可逆则用逆 API 调用修复（本文仅检测不执行），不可逆则升级人类。

本文端到端实验聚焦 Type I 和 Type II；Type III 仅通过 n4 的语义质量信号间接评估。

- **内置评估**：

  - 两模型的**每个**保留提示均获得正向增益（图 3 所示 ΔR 严格为正）；
  - 单一策略可通过角色条件提示成功专门化为五节点角色，无需每个节点独立策略。
- **端到端（Type I）**：训练后 Granite 恢复 27.5%（无漂移上界的 78%），接近 GPT-4o 恢复的 32.5%；未训练 Granite 完全失败（0%）。
- **端到端（Type II）**：GPT-4o 初始骨干下，Granite 恢复 35.0%，GPT-4o 恢复 45.0%；GPT-4o-mini 下两者分别降至 7.5% 和 12.5%。剩余差距集中在 n5 产生警告的语义丰富度。

- **组件分解**：主要增益来自模式组件（json_sch、json_san）和 judge 信号；tot_len 轻微回退（0.14→0.08），因更丰富的推理被 judge 奖励但超出长度目标。

### 7. 方法亮点

- **即插即用**：恢复模块完全独立于主智能体，无需重训大型模型——实用性和部署友好性出色；
- **单模型多角色**：用角色条件提示和统一 GRPO 目标将一个小策略同时驱动到五种不同诊断职能，避免了为每个节点训练独立策略的昂贵开销；
- **结构化格式纪律**：固定 `<reasoning>`+`<answer>` XML 模式使节点输出成为“类型化消息”，避免了自由 CoT 下游解析的不确定性；
- **混合奖励设计**：规则结构奖励（可验证、防作弊）+ LLM-as-judge 语义信号（内容接地性）相结合，GRPO 的组归一化自动吸收了两者之间的尺度差异，无需手工平衡；
- **向后走 + 对齐连击终止**：一种简单但稳健的回溯控制律，避免了“恰好一个对齐步就草率终止”的判断风险；
- **成本低**：单 GPU（约 28GB 显存），小模型可训练，训练开销可控；
- **完备的漂移形式化**：对理想执行集、漂移起点、不可逆操作和漂移类型进行了严格的数学定义，为后续研究奠定了清晰的理论框架。

- **实验覆盖不足**：

  - AppWorld 仅 40 个任务，规模偏小，且只有单一漂移注入模式；未涉及 AgentDojo 等更具对抗性的基准；
  - 漂移假设为单调（onset 后每步均离轨），实际上排除了一致段落与漂移段交错的真实模式（作者明确承认此假设）；
  - 未对超参数（K、奖励权重、LoRA 秩等）做敏感性分析；
- **偏差风险**：
  - Judge 模型未必是 AppWorld API 领域的专家，可能漏掉 n4 的细微幻觉（如杜撰的反向端点）或高估 n5 的浅层报告；存在**奖励黑客**风险——模型可能学到 judge 过度重视的“看起来合理”的冗长推理，而非真实事实准确性；
  - 框架高度依赖外部提供的疑似漂移起点 k0 的质量，若漂移检测器本身出错则恢复失败；
- **应用限制**：
  - 消息历史回滚不能修复环境写入（作者引用 Zheng [2025] 强调此局限）；
  - 模型在 n4_evaluate_risk 上的 judge 分数提升幅度最小（0.72→0.78），说明可逆性判断对事实性知识要求高，通用 judge 难以验证；
  - 未与真实世界具备“写操作执行后不可恢复”的系统进行部署级测试，实际效果仍需更多验证。
