## 摘要
随着编码智能体日益承担实现工作，核心挑战从构建单个智能体转向构建一个系统性改进它们的通用基础设施。当前方法要么优化智能体系统而不积累可迁移知识，要么积累知识但缺乏对其进行组合推理的能力，且缺乏一种机制让知识通过运行证据自我进化。MEGA（元评估落地适应）作为自进化基础设施解决了这些缺口：每个优化周期产生持久资产，对这些资产的组合推理指导后续优化，运行证据则同时改进积累的智慧及支配该智慧的推理。第1层通过行为模式聚类和经验性A/B验证，从智能体会话中提炼可复用智慧，将每个过程转化为持久资产。第2层将这些资产分解为类型化智慧图中的原子PCR（主因-情境-结果）单元，并执行演绎、溯因和归纳推理以扩展隐含关系；随后通过组合检索组装上下文特定的执行计划，该检索能够表面化仅靠嵌入相似性无法触及的桥接知识。第3层对异构智能体工作流（代码节点、LLM调用和使用工具的智能体）进行多智能体协作优化，通过消除数据方差的受控评估，将改进效果归因于特定策略变化。从第3层反馈的证据驱动了管理智慧组合的策展策略以及跨运行积累的优化轨迹的自我进化。最终结果是：优化智能体系统与进化指导优化的知识是同一个过程。

## Abstract
As coding agents increasingly handle implementation, the central challenge shifts from building individual agents to building an infrastructure that systematically improves them. Current approaches optimize agent systems without accumulating transferable knowledge, accumulate knowledge without compositional reasoning over it, and lack a mechanism for that knowledge to self-evolve through operational evidence. MEGA (Meta Evaluation-Grounded Adaptation) addresses these gaps as a self-evolving infrastructure: each optimization cycle produces durable assets, compositional reasoning over those assets guides subsequent optimization, and operational evidence refines both the accumulated wisdom and the reasoning that governs it. Layer 1 distills reusable wisdom from agent sessions through behavioral-pattern clustering and empirical A/B validation, transforming each process into a durable asset. Layer 2 decomposes these assets into atomic PCR (Primary-Context-Resultant) units within a typed Wisdom Graph and performs deductive, abductive, and inductive reasoning to expand implicit relations; it then assembles context-specific execution plans through compositional retrieval that surfaces bridging knowledge unreachable by embedding similarity alone. Layer 3 performs multi-agent collaborative optimization over heterogeneous agent workflows (code nodes, LLM calls, and tool-using agents), attributing improvement effects to specific strategy changes through controlled evaluation that eliminates data variance. Evidence fed back from Layer 3 drives the self-evolution of both the curation strategies that govern wisdom composition and the optimization trajectories accumulated across runs. The result is an infrastructure in which optimizing an agent system and evolving the knowledge that guides optimization are one and the same process.

### 1. 核心问题与研究动机

**背景**：随着编码智能体逐渐承担实际实现工作，开发者的核心问题从"如何构建单个智能体"转向"是否存在能系统性、反复改进智能体系统的通用平台/基础设施"。

**核心问题**：当前智能体开发自动化存在三大结构性局限——

- **优化不积累知识**：现有优化器（如 DSPy、GEPA、AFlow）能在单一项目内提升系统性能，但优化成功的原因（何种策略在何种条件下有效）没有被结构化为可跨项目迁移的知识，新项目仍需从头开始策略搜索。单纯的存储式记忆（如 Reflexion、ACE）无法解决该问题，因为问题的本质不是"缺少存储"而是"缺少对存储内容的组合推理"。
- **知识缺乏组合推理**：技能库（如 Voyager、AgentSkillOS、SkillNet）虽存储了可复用过程性知识，但无法推理"在何种条件下、以何种顺序、组合哪些技能"。组成的单位是"完整技能"而非原子化子单元，且不执行逻辑推理来发现隐含关系（即 Press et al. 提出的"组合性差距"——模型能解决子问题却无法组合它们）。
- **知识无法自我进化**：未经运行验证的知识无法随运营证据改进。缺乏反馈回路——优化产生证据、证据修正知识、修正后的知识指导优化——导致未经验证和过时的知识积累，检索质量逐渐下降。

**核心论点**：以上三种能力从未被统一到一个基础设施中。MEGA 的设计目标正是将三者统一为一个自进化闭环：优化系统与进化指导优化的知识是同一个过程。

### 2. 方法论：MEGA 三层架构

MEGA 的整体形式化描述为：

```
W(t) = L1(T(t) ∪ T3(t−1))
Π(t) = L2(W(t), E(t−1))
E(t), T3(t) = L3(Π(t))
```

其中 t 为外层自进化周期，T 为智能体会话轨迹，T3 为 Layer 3 优化循环产生的执行会话，E 为评估证据，W 为智慧资产，Π 为执行计划。

#### Layer 1：基于会话的智慧生成（Session-based Wisdom Generation）

- **隐私预处理**：所有数据在离开本地环境之前，先进行客户端的密钥掩码与路径匿名化过滤。
- **两阶段聚类**：
  - 阶段一（领域预聚类）：基于嵌入相似度进行贪婪分配，按数据驱动方式划分领域。
  - 阶段二（行为模式发现）：在各领域簇内应用 BIRCH 算法，以 CF（Clustering Feature）元组 CF = (N, LS, SS) 表示簇，通过 O(1) 的 CF 加法合并实现单遍 O(n) 处理；半径阈值 T 决定是否新建子簇，从而无需预设 k 值。
- **合成与结构化过滤**：LLM 将簇内行为模式综合为结构化智慧，经过（1）哈希精确去重、（2）LLM 冲突检测与消解、（3）跨运行嵌入相似度去重，防止知识库污染。
- **行为 A/B 验证**：每个候选智慧在其通过综合与过滤后，并行运行两组测试——处理组（注入智慧）与对照组（基线无智慧），通过可观察的绩效变化而非主观质量评分来评估，双轴指标为绩效提升（准确率增益）与 Token 效率（成本变化）。这是三层质量门控（结构过滤、自评估打分、行为 A/B 验证）中最关键的一环。

#### Layer 2：智慧推理与策展（Wisdom Reasoning and Curation）

- **安全筛选**：所有进入图库的资产先经安全门控，检查指令级威胁（如提示注入）和代码级威胁（如数据外泄逻辑）。
- **PCR 原子分解**：每个智慧资产被分解为原子三元组 ω = (vP, vC, vR, m)，其中 vP 为 Primary（核心动作）、vC 为 Context（应用条件）、vR 为 Resultant（预期结果）、m 为 Method（实现方法）。边带有基于 Pearl 因果演算的双轴得分 σ(e) = (S(e), N(e))——充分性与必然性。WG-DB 使用角色流动节点池（Role-Fluid），同一概念可在不同三元组中分别充当 P 或 C，从而自然生成跨技能连接。
- **三种逻辑推理**：
  - **演绎（Deduction）**：当存在 P→C 和 C→R 关系时，传递推断 P→R，采用乘法式分数衰减抑制远距离推断的假阳性。
  - **溯因（Abduction）**：当 P→R 和 C→R 共享同一结果 R 时，若 C→R 的必然性分数足够高，则反推隐含的 P→C 关系，发现从未被显式记录的"前置条件"。通过贝叶斯后验估计结合结果覆盖率、因果强度和语义相关性来评估候选关系置信度。
  - **归纳（Induction）**：当多个 P 节点同时连接到相同 C 和 R 时（Pn→C， Pn→R），使用超几何检验验证共现是否超过偶然水平，仅当统计显著时才推断 C→R 边。
  - 三种推理迭代应用直至固定点（无新边通过阈值即终止）；演绎有随目标入度对数上升的动态惩罚，溯因有贝叶斯后验界，归纳有超几何显著性检验。
- **PCST 组合检索**：将检索形式化为无向投影图上的 Prize-Collecting Steiner Tree（PCST）问题，目标函数为：
  ```
  T* = arg max [ Σ v∈V(T) π(v; q) − Σ e∈E(T) c(e) ]
  ```
  奖励 π 与查询相关性成正比，成本 c 与因果弱度成正比。PCST 解中的非种子节点（查询相似度低但在连接种子节点中不可或缺）即构成"桥接知识"——这超越了仅靠嵌入相似度无法触及的知识。PCST 同时组合全部四种智慧类型（技能、策略、策展模式、优化轨迹），而非仅技能。
- **ROI 驱动的自我进化**：预测效用 pi = τ(sim_i, stage_i) × η(ω_i)，其中 τ 是历史迁移率、η 是饱和型证据置信度；步骤级聚合 P_step = 1 − exp(−Σ pi) 体现冗余技能的边际效用递减；自适应门控在冷启动（宽松、探索优先）与热启动（保守、LCB 基准）间切换；四轴复合评分、组合级强化（达到频率-质量阈值的组合晋升为策展策略）和内容级进化（未消费修订建议超过阈值即进入进化候选队列）。

#### Layer 3：评估驱动的多智能体优化（Evaluation-Driven Multi-Agent Optimization）

- **异构工作流优化目标**：将工作流建模为有向图 A = (N, E)，节点包含三种异构类型——确定性代码节点、LLM 调用节点（由提示与解码参数化）、使用工具的多轮推理智能体节点。Layer 3 联合优化全部节点类型的提示、工具配置、代码逻辑和编排结构，而传统提示优化器仅优化 LLM 调用的提示组件。
- **Adapt 流水线**：资产扫描（Asset Scan）→ 自适应入口（Adaptive Entry）→ 条件性研究智能体（Research Agents）→ 逆向 PRD / 数据合成（Reverse PRD / Data Synthesis）→ 共享优化循环（Shared Optimization Loop）→ 元学习智能体（Meta-learning Agent）。
- **多智能体协作**：中央优化智能体（集中式决策）+ 科学家智能体（错误模式分析、根因与受害者区分、ROI 排序）、代码审查智能体（静态分析 + 干运行验证 + 反启发式执行）、重设计智能体（增量优化停滞时进行架构重构）。
- **数据感知优化**：在进入优化循环前，判断评估结构为离散检查器、基于评分规则或连续指标三种类型之一，对每个发现的评估维度评估其密度、多样性和基线表现，区分"数据缺口"与"工作流问题"——仅对真实的覆盖缺口进行有针对性的合成数据增强（合并比例上限 50%）。
- **Seed-Epoch 过拟合调节机制**：每个 epoch e 用固定种子 ξe 采样评估集 De，epoch 内所有迭代在同一 De 上评估：Δi = Acc(De, vi) − Acc(De, vi−1)。由于评估数据完全一致，数据方差被消除，Δi 的主要变异来源可归因于策略变化的效果。当连续 m 次迭代 |Δi| < ε 时判定当前 epoch 饱和，换新种子进入下一 epoch，自动泛化验证。动量触发式验证策略（基线、epoch 边界、动量事件）有选择地分配验证预算。
- **优化保障机制**：（1）反启发式强制——禁止内容感知模式（匹配特定答案格式的正则、条件分支、查找表），仅允许结构化变换（JSON 解析、编码规范化、类型转换、错误恢复）；（2）过拟合检测——train/validation 差距阈值触发仅限提示优化的限制；（3）基于可修复性的目标校准——根据基线错误分布计算实际可达的精度上限。
- **跨层复合循环**：优化循环中产生的每个判定（Verdict) (Δacc, Δlat, Δtok) 反馈到 Layer 2，更新 η(ω)（证据置信度）与 τ(·)（历史迁移率）。元学习智能体记录优化过程中发现的模式作为结构化优化轨迹，注册到 Layer 2，使新项目从已验证的路径起步。

**智慧图维护（Auto Graph Hygiene）**：PCR 去重（语义等价三元组合并并整合证据）、矛盾消解（极性分析检测同一 P、C 下相反 R 的矛盾对，保留强证据变体，为弱方添加排除条件）、证据触发的自动内容更新（负反馈累积超过阈值时，跨引用域相似知识 + 外部验证，打补丁更新同时保留 PCR 结构和证据历史）。

### 3. 实验设计

#### 实验一：智慧策展质量（Wisdom Curation Quality）

- **Benchmark**：SkillsBench，84 个任务、11 个领域，每个任务由确定性 pytest 断言在隔离 Docker 容器中验证，二元通过/失败判定。
- **设置**：GCP n2d-standard-128 VM，Gemini CLI + Gemini 3 Flash 作为智能体，每任务 5 次尝试，43 个并发 Docker 试验。技能池共 4,207 个资产（含 SkillsBench 的黄金技能）。所有实验使用相同智能体、技能池、任务、验证器和 Docker 环境，唯一变量是技能发现与编排方法。
- **对比方法**：
  - No Skills（无技能基线）
  - SkillNet（LLM 元数据匹配 + LLM 生成程序性指导）
  - AgentSkillOS（分层树搜索 + Quality-First DAG 计划生成）
  - MEGA (WG)（PCST 组合检索 + 角色差异化计划组装）
- **指标**：通过率（主指标）、每任务平均 Token 消耗、策展延迟（执行前发现与编排技能的耗时）、策展 ROI（每额外百万 token 的通过率提升）。

#### 实验二：优化性能（Optimization Performance）

- **Benchmark 与数据集**：来自 GEPA 评测套件的四个复合 AI 系统基准——HotpotQA（多跳检索，150/100/300）、IFBench（指令遵循，150/100/294）、HoVer（检索验证，150/100/300）、PUPA（隐私保留委派，111/111/221），三元组分别表示（训练/验证/测试）。MEGA 使用比 GEPA 原始划分更小的验证集（如 HotpotQA 100 vs 300）。
- **模型**：GPT-4.1 Mini（gpt-4.1-mini-2025-04-14）。
- **对比方法**：MIPROv2、TextGrad、GEPA（含 GEPA+Merge 取每基准最优）、Feedback Descent。基线分数分别引用自 GEPA [2] 和 Feedback Descent [14] 论文。所有基线使用真实评估数据，MEGA 使用相同评估数据以保证公平比较。所有方法共享受控的底层工作流（剥离 DSPy/GEPA 优化器依赖的纯多阶段 LLM 流水线）和完全相同的评估检查器与评分组件。

- **维度一（策展质量）**：在 SkillsBench 上对比了 4 种条件（No Skills、AgentSkillOS、SkillNet、MEGA），报告了通过率、Token 消耗、延迟、ROI 四类指标。
- **维度二（优化性能）**：在 4 个基准（HotpotQA、IFBench、HoVer、PUPA）上对比了 5-6 种方法（Baseline、MIPROv2、TextGrad、Feedback Descent、GEPA、MEGA）。

#### 充分性与客观性评估

**优点**：
- Seed-Epoch 机制确保评估数据集在同一 epoch 内完全一致，从而消除数据方差对性能增量的干扰，归因可靠。
- 在 SkillsBench 实验中严格控制了变量（相同智能体、技能池、验证器、Docker 环境），唯一变量为编排方法，且所有策展管道的 LLM 组件统一使用 Gemini 3 Flash，避免了更强模型带来的不公平优势。
- 优化实验使用与基线相同的评估检查器和评分标准，排除评分偏差。
- MEGA 使用更小的验证集仍然超越基线，间接证明其优化效率优势。

**不足**：
- 没有独立的消融实验来单独验证 Layer 1（行为 A/B 验证）、Layer 2（PCR 推理、PCST）和 Layer 3（Seed-Epoch、多智能体协作）各组件各自的贡献大小，论文也明确承认增益是集成基础设施的贡献而非单一组件。
- 优化实验的基线分数大量引用已发表论文（GEPA、Feedback Descent），缺少在同环境完全重跑的完全公平基准（虽然论文声称已尽量统一设置）。
- 缺少跨项目/跨域迁移的纵向实验验证（即 Wisdom Graph 随项目积累而冷启动改善的假设未被直接测试）。

### 6. 主要结论与发现

1. **技能策展并非自动有益，策展方法决定了性能上限**：AgentSkillOS 通过率 41.1%、SkillNet 41.7%、MEGA 46.5%。高 Token 成本和延迟未必带来更高性能（AgentSkillOS 以最高成本获得最低通过率），**如何选择和组合技能比是否提供技能更关键**。
2. **MEGA 在策展质量上全面领先**：在 SkillsBench 上以 46.5% 的通过率、0.566 score/Mtok 的效率超越所有基线，同时以 11.8 秒/任务的策展延迟（对比 SkillNet 37.8s、AgentSkillOS 403.4s）和 822k 的 Token 消耗（最低）展现出显著的效率和速度优势。PCST 图检索无需 LLM 调用即可完成检索，这是延迟优势的结构性来源。
3. **MEGA 在优化性能上显著超越现有优化器**：聚合分数 76.55，超出最强基线 GEPA（69.52）7.03 分，超出 Feedback Descent（66.56）9.99 分，且在所有四个基准上表现一致。
4. **HoVer 增益最大（+18.00 分）**：多跳检索受益于组合智慧链式跨跳检索策略的能力，印证了组合推理是关键价值来源。

5. **更少的验证数据即可收敛**：MEGA 使用比 GEPA 更小的验证集（如 HotpotQA 上 100 条而非 300 条）仍能以更少的评估样本完成收敛，并在测试集上取得更高的分数。这表明 MEGA 的性能优势并非来自对更大数据规模的拟合，而是源自智慧图提供的先验知识、组合检索与因果推理所赋予的归纳偏置。

6. **跨层知识反馈是持续改进的引擎**：Layer 3 优化过程中产生的每个判定（Verdict）和元学习智能体记录的结构化优化轨迹，都会反馈到 Layer 2，更新证据置信度与历史迁移率，并注册为新项目可复用的起点。这种“优化→知识→优化”的闭环使得系统能力随项目积累而持续增长，而非每次从零开始搜索最优策略。

7. **自动知识卫生机制保障知识库的可信度**：智慧图维护模块通过 PCR 去重、矛盾消解和证据触发的自动内容更新，能够在知识积累过程中主动清除过时与矛盾的知识，保留强证据变体并为弱方补充排除条件。这一机制保证了长期运行下知识库的一致性和检索质量，是知识可自我进化的关键支撑。

总体而言，MEGA 通过将智慧生成、因果推理与评估驱动优化统一在同一个自进化基础设施中，证明了跨项目知识积累和组合推理能够显著加速智能体系统的迭代优化，并在推理、检索、指令遵循和隐私保护等多个异构任务上取得了一致且领先的性能提升。
