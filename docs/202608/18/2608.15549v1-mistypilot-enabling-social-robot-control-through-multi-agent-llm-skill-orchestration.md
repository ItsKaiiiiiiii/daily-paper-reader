## 摘要
从自然语言指令编程小型社交机器人不仅仅是调用孤立的API。交互任务将反应性物理行为与有状态社交行为相结合，而现有接口通常要求开发者手动将API组合成技能、配置参数、将传感器事件绑定到技能，并在运行时管理任务状态。我们提出了MistyPilot，一个多智能体LLM框架，它解释高级自然语言指令，并在Misty社交机器人上编排相应的技能。任务路由器将每条指令分派给两个专门智能体之一：用于传感器触发机器人控制和直接技能调用的物理交互智能体，以及用于对话导向任务状态管理和上下文相关多模态响应生成的社交交互智能体。为了提高效率，社交交互智能体在适用时重用先前生成的结果，否则进行完整生成。我们在五个组件级套件上评估了MistyPilot，传感器绑定和技能调用在物理Misty机器人上执行，并进行了有12名参与者的初步用户研究。MistyPilot在路由、传感器-技能绑定、任务状态解析、结果重用以及技能扩展到100项方面取得了高准确率，且方差低于其他相同的单智能体基线，而参与者报告了正向的可用性和交互质量感知。代码将通过项目页面公开提供。

## Abstract
Programming small social robots from natural-language instructions requires more than invoking isolated APIs. Interactive tasks combine reactive physical behaviors with stateful social behaviors, while existing interfaces often require developers to manually compose APIs into skills, configure their parameters, bind sensor events to skills, and manage task states at runtime. We present MistyPilot, a multi-agent LLM framework that interprets high-level natural-language instructions and orchestrates the corresponding skills on the Misty social robot. A Task Router dispatches each instruction to one of two specialized agents: a Physically Interactive Agent for sensor-triggered robot control and direct skill invocation, and a Social Interaction Agent for dialogue-oriented task-state management and context-dependent multimodal response generation. To improve efficiency, the Social Interaction Agent reuses previously generated results when applicable and invokes full generation otherwise. We evaluate MistyPilot on five component-level suites, with sensor bindings and skill invocations executed on the physical Misty robot, and a preliminary user study with 12 participants. MistyPilot attains high accuracy on routing, sensor-skill binding, task-state parsing, result reuse, and skill extension up to 100 skills, and lower variance than an otherwise identical single-agent baseline, while participants report positive perceptions of usability and interaction quality. The code will be made publicly available via the project page.

## 1. 核心问题与研究动机

- 社交机器人的开放编程接口（如 Misty 的语音、视觉、头部/手臂运动、触觉等 API）要求开发者手动将 API 组合为技能、配置参数、绑定传感器事件，并在运行时管理任务状态，普通用户无法直接通过自然语言控制机器人。
- 现实用户请求灵活多样，且可在单次交互中动态变化，例如先要求“拍头时向我问好”，随后要求“讲睡前故事”并修改结尾或重复播放。这既需要“反应式物理交互”（传感器触发→技能调用），也需要“有状态社交交互”（依赖对话历史与任务进度的多轮管理）。
- 现有系统（如 AutoMisty）虽能用 LLM 生成单条技能代码，却不支持运行时技能发现、调用与编排；通用工具智能体未针对社交机器人特有的传感器绑定与交互状态进行适配。
- 论文旨在解决三个技术缺口：① 反应式物理交互中的传感器-技能持久绑定与运行时技能扩展；② 多轮对话中显式任务状态跟踪与修改；③ 社交响应的多模态生成效率与协调性。

## 2. 方法论

### 整体架构
- 采用多智能体 LLM 框架，基于“工具智能体”（tool agent）范式，在架构层面进行角色分离，而非仅靠 prompt 区分。
- 核心流程：`Task Router` 将用户自然语言指令分派到两个专用智能体之一：
  - **物理交互智能体（PIA）**：负责传感器触发式控制、直接技能调用、传感器-技能绑定及持久化。
  - **社交交互智能体（SIA）**：负责对话导向的任务状态管理、多模态响应生成与历史结果复用。

### 任务路由与形式化
- 任务空间 `T`：给定自然语言指令 `Ti`，路由器 `R` 输出目标智能体 `K* ∈ {PIA, SIA}`。
- 每个智能体将任务解析为有序的参数化函数调用序列：`Agent(Ti) = [f1(θ1), f2(θ2), ..., fN(θN)]`。

### 社交交互智能体（SIA）
- **Load Task and Model**：通过 schema 约束的 prompt 将用户指令映射为预定义动作：
  - `NEW`（新建任务）、`UPDATE`（更新细节）、`DELETE`（删除）、`UPGRADE/DOWNGRADE`（切换不同能力的 LLM）、`MEMORY`（持久化用户要求保存的内容）。
- **任务状态管理器（TSM）**：使用显式、可编辑的外部任务状态记忆，以“原子单元”（atomic units）存储细节。例如将“返回时间”作为一个独立单元，更新只修改该字段，避免 LLM 在长上下文迭代摘要中的事实漂移问题。
- **快速/慢速双通道（Fast & Slow Thinking）**：
  - 快速路径：将 `main_task` 编码为查询嵌入 `q`，与记忆库 `M` 中已存嵌入 `x` 计算余弦距离；若最小距离 `≤ τ`（阈值取 0.4）则直接复用已有结果；否则进入慢速路径。
  - 慢速路径：`Script Writer` 基于扩展 Ekman 情绪分类（8类）生成文本、动作与语音。文本由上下文感知推理生成；动作通过模板映射到 Misty 的手臂、头部、身体、LED 等；语音使用 OpenAI-TTS 并控制语速（按 arousal 分为 0.95/1.00/1.05）实现情绪同步。

### 物理交互智能体（PIA）
- **Load Task and Model**：将指令映射为命令集：
  - `BIND <s,k>`：将技能 `k` 绑定到传感器 `s`；`UPDATE` 重新绑定；`UNBIND` 清除绑定；`INVOKE` 直接执行单次技能。
  - 技能库在运行时扫描目录并解析 docstring，实现即插即用的技能扩展。
- **Sensor & Tool Manager（STM）**：通过 Central Scheduler 为每个传感器维护独立工作进程，记录进程表（传感器、PID、绑定技能、状态），并周期性检查、自动重启失效进程。
- **持久化**：在启动时扫描持久化进程表，恢复传感器-技能绑定，支持跨会话重启。

## 6. 主要结论与发现

- MistyPilot 在路由准确率上与单智能体基线相当或更高，尤其在 PIA-Hard 上取得 96.2%±5.66%（基线 90.4%±15.65%），方差明显更低。
- PIA 在 SensorBind40-Hard 上达到 100%±0%，优于基线的 81%±4.18%，体现角色分离对复杂多传感器绑定任务的可靠性。
- SIA 在 TaskParser256 上：Easy 99.29%±1.60%（基线 91.43%±13.27%），Hard 96.75%±1.15%（基线 93.50%±5.36%），准确率与稳定性均提升。
- 快速思考路径：使用解耦的 `main_task` 表示后，在三种嵌入模型上均达到 100% Top-1 检索准确率，且显著拉开正确项与次优项的距离；响应时间从 5.088±2.571s 降至 2.263±0.627s（降低 55.5%）。
- 技能扩展：在 30–100 技能规模下均能正确选择新技能，未观察到性能退化。
- 用户研究五维度评分均值均高于 4.4/5（最高 4.75，最低 4.42），参与者对自然度、情感表达、响应速度和整体满意度持正面评价。

## 7. 优点

- **架构级别角色分离**：将路由、物理交互、社交对话隔离到独立智能体，各有局部状态与技能空间，避免单智能体上下文过度拥挤，提高了可扩展性和稳定性。
- **显式任务状态管理**：TSM 使用原子更新的外部记忆，避免长对话中的 LLM 事实漂移，支持精确的局部修改。
- **快速/慢速双通道设计**：通过嵌入检索复用历史结果，显著降低延迟，并保留全生成兜底能力。
- **即插即用技能扩展**：仅凭 docstring 即可动态注入新技能，运行时扫描技能库，无需修改控制逻辑。
- **持久化传感器绑定**：STM 进程表 + 自动恢复机制，保证跨重启可用性。
- **情感多模态一致性**：从情绪标签统一驱动文本、动作、LED、面部表情与语音韵律，提升社交交互自然度。
- **真实机器人验证**：在物理 Misty 上执行绑定与技能调用，而非仅仿真，增强结果可信度。

## 8. 不足与局限

- **评估覆盖面有限**：五个套件只针对论文认为最关键的组件，未覆盖全部可能的交互模式，缺乏复合型长时任务（如跨多会话、多用户协作）的测试。
- **数据规模偏小**：各套件样例数不高，尤其 Hard 子集可能不够充分；路由和绑定实验的统计功效有限。
- **单智能体基线对比单一**：仅对比了相同主干压缩成的单智能体，未与现有通用工具智能体、AutoMisty 或其他社交机器人编程框架做直接比较。
- **用户研究样本小**：12 人、仅 30 分钟交互，未包含客观任务完成率测量、不同用户群体（如老年人、儿童、非英语口音者）的区分，且 ASR 对带口音语音的误识别导致部分失败，系统鲁棒性有待提升。
- **隐私问题**：传感器绑定和用户标记结果跨会话持久化，在共享机器人场景下可能造成隐私泄露；论文提未来将引入用户认证与隔离，但当前未实现。
- **算力与成本未报告**：缺少硬件配置、推理延迟的详细分解、费用分析，影响可重复性和实用性评估。

- **上限未探明**：技能扩展仅在 100 个技能内验证，更大规模的可扩展性仍是开放问题。
