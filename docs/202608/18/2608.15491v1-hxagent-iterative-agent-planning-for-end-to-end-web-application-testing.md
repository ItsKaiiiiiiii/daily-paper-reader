## 摘要
在自动化Web测试中，利用自然语言的功能描述生成测试用例并执行测试对于提高效率至关重要。这些任务要求测试智能体在目标应用上自主执行任务并生成测试。我们提出了HxAgent，一种基于LLM的迭代规划智能体，采用主动纠正策略。每一步之后，HxAgent会重新评估Web状态，以使用（1）当前观察、（2）过去动作的短期记忆以及（3）从过去（不）正确动作序列中提取的长期经验来确定下一个动作。HxAgent在MiniWoB++上达到97.4%的精确匹配准确率，与无需人类示范的最佳基线相当，并比最近的WALT高出10.5%。在一个包含350个Web任务的数据集上，它达到83.8%的精确匹配和91.8%的前缀匹配，超过WALT 13.4%。在OnlineMind2Web上，它进一步比WALT提高了4.6%。

## Abstract
In automated web testing, generating test cases and performing testing using functionality descriptions in natural-language is crucial for improving efficacy. These tasks require such a testing agent to carry out tasks on the target application and generating tests autonomously. We introduce HxAgent, an iterative LLM-based planning agent with a proactive correction strategy. After each step, HxAgent reassesses the web state to determine the next action using (1) current observations, (2) short-term memory of past actions, and (3) long-term experience extracted from past (in)correct sequences of actions. HxAgent achieves 97.4% Exact-Match accuracy on MiniWoB++, comparable to the best baselines without human demonstrations and surpassing the recent WALT by 10.5%. On a dataset of 350 web tasks, it attains 83.8% Exact-Match and 91.8% Prefix-Match, exceeding WALT by 13.4%. On OnlineMind2Web, it further improves over WALT by 4.6%.

## 2. 论文提出的方法论

**核心思想：**
HxAgent将Web测试任务建模为部分可观测马尔可夫决策过程（POMDP），构建了一个迭代式LLM规划智能体，将动作序列生成视为一个闭环反馈过程。其独特之处在于主动纠正策略——每一步之后重新评估状态并调整计划，而非在整条轨迹失败后才进行反思修复。

**四个关键设计理念：**

1. **迭代式LLM规划（Iterative LLM-based Agent Planning）**
   - 在反馈循环中生成可控的序列动作，将LLM的推理锚定在文本和视觉屏幕上下文中，避免无关或幻觉动作
   - 每一步动作由四个输入决定：当前页面状态、可行动作集合、先前状态-动作对的短期记忆、从历史（不）正确序列中提取的长期经验
   - 动作被显式表示为**操作、Web元素、可选输入值**的元组（`(op, e, v)`），而非坐标或文本描述

2. **序列动作记忆（Sequence Action Memory, SAM）——短期记忆**
   - 维护结构化的最近状态-动作对历史（记忆窗口大小为k），提供显式历史上下文
   - 帮助智能体避免重复过去的失败决策，跟踪网页状态演变

3. **经验强化（Experience Reinforcement）——长期经验记忆**
   - 采用**训练**和**评估**两阶段策略
   - 训练阶段：LLM收集带成功/失败反馈的状态-动作序列，并使用规则提取函数 ϕLLM 将其抽象为文本规则启发式（如“点击前验证标签”）
   - 规则与新发现的SoA共同构成经验记忆，在评估阶段作为少样本示例和策略规则引导决策

4. **视觉增强（Vision Enhancement）**
   - 针对HTML超出LLM上下文长度以及复杂布局（如日期选择器）导致的歧义问题
   - 利用LLM的多模态能力，在可操作元素之外同时提供当前网页的截图辅助决策

**核心公式：**

- 动作序列（SoA）：
  \[
  \tau_t = \{(s_0, a_0), (s_1, a_1), \ldots, (s_t, a_t)\}
  \]

- 动作接地（Action Grounding）：
  \[
  a_t \sim \pi(\cdot \mid o_t, A(o_t), \mathcal{M}_t, \mathcal{E})
  \]
  即LLM根据当前观察、可行动作集、短期记忆和经验记忆选择动作。

- 状态评估：
  \[
  \{success, stop\} \sim G(\tau_t, \mathcal{M}_t, \mathcal{E})
  \]
  每次状态转换后评估任务是否完成或是否需要提前终止。

**算法流程（简化）：**
1. 加载任务和起始URL，初始化空短期记忆
2. 内容提取器（Content Extractor）从当前状态提取状态表示和可行动作集
3. 状态评估器（State Evaluator）调用LLM判断任务是否完成或应提前终止
4. 动作接地（Action Grounding）调用LLM确定下一个动作；若存在重复动作，则利用截图进行视觉辅助判断
5. 如需输入，则调用LLM生成输入值
6. 更新短期记忆，执行动作，转换到新状态
7. 重复直到任务完成、提前终止或达到最大步骤数
8. 训练阶段将（不）正确序列存入经验记忆，并更新规则集

## 7. 优点

- **主动纠正而非被动反思**：与ReAct/Reflexion等反应式修复策略不同，HxAgent每步执行后立即重新评估并调整计划，能在错误累积前加以纠正
- **短期+长期记忆的有机结合**：SAM保留即时上下文，长期经验提供跨轨迹的抽象规则，两者互补显著提升决策质量
- **动作表示的可执行性**：动作以结构化元组（操作+元素+输入值）显式表示，而非坐标或自然语言，可直接生成可重放的回归测试脚本
- **视觉增强处理复杂UI**：对重复元素或上下文歧义（如日期选择器），利用截图辅助消歧，有效降低幻觉和误判
- **无需人类示范**：在无人工演示条件下达到或超越依赖大量示范的基线（如WebGUM 401K示范、CC-Net 2.4M示范），可扩展性强
- **经验提炼机制高效**：规则提取只吸收新增的、非冗余的启发式规则，避免重复存储，经验集随训练动态增长
- **消融分析全面**：量化了各组件的独立贡献，验证了架构设计的合理性

## 8. 不足与局限

- **评估范围仅限Web**：实验仅针对Web应用，虽从架构上论证了对移动（Android）和桌面（Accessibility Trees）平台的适用性，但缺乏实证验证
- **LLM幻觉风险**：温度虽设为0以缓解输出随机性，但LLM输出仍不保证完全一致；论文也承认幻觉问题无法完全消除
- **复杂UI组件仍具挑战**：日期时间选择器（如Expedia仅有32% Exact-Match）、输入后回车提交域、较大的可交互组件等仍易导致失败，大HTML可能超出LLM上下文限制
- **经验记忆缺乏主动整合**：未执行主动的规则合并或修剪；对更大规模的经验库，缺少基于效用或新旧度的淘汰机制，可能影响长期可扩展性
- **数据集外部有效性有限**：自行构建的Real-world数据集（7个网站）不能代表所有类型的Web应用和UI元素；OnlineMind2Web中有些复杂组件的集合也有限
- **测试脚本在动态环境中的可靠性**：真实网站的布局变化（LinkedIn的XPath不稳定）、网络延迟（Expedia加载时序问题）、动态请求限制（GitHub的429错误）会导致测试脚本回放失败
- **与部分SOTA方法缺少直接对比**：排除了输出坐标或文本描述的GUI智能体（UI-TARS、CogAgent、SeeClick等），虽然理由合理，但无法直接证明HxAgent在这些方法上的相对优势
- **输入值生成策略简单**：对表单填写任务的无效数据生成（如StackOverflow的stackoverflow-3任务），论文未提出专门的解决方案
