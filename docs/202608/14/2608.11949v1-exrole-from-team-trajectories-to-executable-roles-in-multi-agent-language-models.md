## 摘要
角色为组织语言模型智能体提供了可解释的接口，但大多数多智能体系统将它们视为手写的提示标签，与学习到的行为和参数更新脱节。我们认为，有用的角色应是一种可执行的控制变量：它应总结对未来效用具有预测性的行为，指导后续交互，并识别负责该行为的可训练能力。我们提出了ExRole，一个从轨迹到角色的框架，它从前缀局部团队轨迹中学习具有未来感知的角色原型，将其解析为可读指令和与token对齐的角色标记，并可选地通过回合对齐的信用来路由共享的LoRA秩槽。在MuSiQue和2WikiMultiHopQA上，ExRole相比单智能体搜索分别提升了15.0/14.4和13.5/16.1个EM/F1分数点。与最强的非ExRole对照组相比，相应的增益仍保持在11.5/11.6和7.7/9.7个分数点。在这两个基准上，受控结果一致地偏好轨迹诱导的角色条件，而非无角色、手动、随机和打乱顺序的替代方案。角色-智能体-回合干预进一步表明，诱导的角色捕获了超越固定智能体身份或回合位置的可迁移行为特化。

## Abstract
Roles provide an interpretable interface for organizing language-model agents, yet most multi-agent systems treat them as hand-written prompt labels disconnected from learned behavior and parameter updates. We argue that a useful role should instead be an executable control variable: it should summarize behavior predictive of future utility, guide subsequent interaction, and identify the trainable capacity responsible for that behavior. We introduce ExRole, a trajectory-to-role framework that learns future-aware role prototypes from prefix-local team traces, resolves them into readable instructions and token-aligned role markers, and optionally routes shared LoRA rank slots with turn-aligned credit. Across MuSiQue and 2WikiMultiHopQA, ExRole improves over single-agent search by 15.0/14.4 and 13.5/16.1 EM/F1 points, respectively. Against the strongest non-ExRole controls, the corresponding gains remain 11.5/11.6 and 7.7/9.7 points. Across both benchmarks, the controlled results consistently favor trajectory-induced role conditioning over role-free, manual, random, and shuffled alternatives. Role-Agent-Turn interventions further show that the induced roles capture transferable behavioral specialization beyond fixed agent identities or turn positions.

## 1. 论文的核心问题与整体含义（研究动机与背景）

多智能体语言模型（LM）系统常通过"角色"（role）来组织协作，但现有系统普遍将角色视为**执行前手工写死的提示标签**（如 CAMEL 的 inception prompting），存在三个核心缺陷：

- **行为脱节**：手工角色标签不基于团队实际协作行为，也不随策略学习而更新；论文 Figure 1 显示，在固定策略下改变角色标签并不能可靠提升答案质量或证据使用。
- **缺乏可执行性**：传统角色只是文本描述，不能作为控制变量指导后续交互，也无法在模型内部被识别和利用。
- **信用分配困难**：共享团队奖励难以定位是哪个角色、哪个回合、哪条容量路径产生了有用的文本动作，导致角色归纳、角色提示与策略优化三者相互割裂。

**核心论点**：一个有用的角色应被视作**可执行的控制变量**（executable control variable），它需要同时做到三点：
1. **总结对未来效用有预测性的行为**（未来感知）；
2. **指导后续交互**（可执行指令）；
3. **识别并绑定产生该行为的可训练模型能力**（参数路径）。

为此，论文提出 **ExRole** 框架，将角色从"静态标签"转变为"从协作轨迹中学习、可执行、可优化"的共享控制变量。

## 2. 论文提出的方法论

### 2.1 核心思想

ExRole 将角色学习建模为**轨迹条件角色归纳**（trajectory-conditioned role induction），核心流程为：

> 团队轨迹 → 未来感知聚类 → 角色原型库 → 解析为可执行身份（指令+标记） → 在交互层与参数层双重执行 → 回合对齐强化学习优化

### 2.2 四个核心组件

**组件一：未来感知角色归纳（Future-Aware Role Induction）**

- 对每条日志中的智能体回合，构造 **prefix-local 30 维行为特征向量** φᵗ_obs，包含：动作倾向（search/answer/invalid/message）、回合位置统计、团队上下文、证据使用、答案行为。
- 用**角色编码器** f_θe 映射为嵌入 ξₜ，同时预测三个目标：
  - 同智能体的**下一动作**（交叉熵）；
  - **未来证据效用**（二值交叉熵）；
  - **最终轨迹收益**（均方误差）。
- 关键约束：输入仅为当前前缀可得的统计量，未来信息只作为预测目标，**不泄漏 suffix 信息**。
- 对嵌入执行带多初始化的 K-means 聚类，产出角色原型 p_k = (ξ̄_k, φ̄_k, η_k)，其中 η_k 记录该簇的主导动作、阶段、证据与收益统计。
- 角色数量 K 由**分离度-稳定性准则** K* = argmax [Sil(K) + λ_stab · Stability(K)] 自动选取。
- 使用**确定性联合解析器**（无需额外角色标注 LM）将原型解析为可读指令 ψ_k 与 token 对齐角色标记 χ_k，角色类型从固定功能词表（Researcher / Coordinator / Verifier / Analyst）中通过贪心去重分配。

**组件二：可执行角色绑定（Executable Role Binding）**

- 从源角色库 P 中解析出至多 N 个可执行角色（N 为智能体数），并与智能体一一绑定。
- 角色同时作用于**提示层**和**模型内部**：
  - 活动智能体的观察中注入角色指令与标记；
  - 标记保留在 token 序列中，**每个 token 继承最近标记对应的角色**（seg(u) = max{q : u⁻_q ≤ u}），确保提示中的角色与模型侧路由器消费的角色完全一致。

**组件三：角色条件稀疏 LoRA 路由（Role-Conditioned Sparse Routing）**

- ExRole-Routed 变体在共享 LoRA 参数内部实现**秩槽级稀疏门控**：
  - 路由器将可执行角色特征 v_zq、离散角色 ID、语义前缀（token embedding 池化）三者融合；
  - 用 softmax 温度采样 + 硬 Top-S 掩码选定额外激活的秩槽；
  - 通过**中心化稀疏增量**（centered sparse-delta）保持共享更新的平衡，再做裁剪。
- ExRole-Shared 变体保留相同的角色库、交互协议与回合对齐信用，但使用统一共享 LoRA 路径，作为**隔离稀疏路由贡献的匹配对照组**。

**组件四：回合对齐优化（Turn-Aligned Optimization）**

- 在 GRPO 的组相对轨迹优势 Adv^(g) 之上，增加**折扣回合局部信用** U_turn,t = Σ λ^(t'−t) · r_t'，只对响应 token 生效：
  - gAdv_t,j = I_resp_t,j · [Adv^(g) + α_c · Û_t^(g)]
- 同一回合收益同时作为**detached 角色回合信用目标** c_q，供路由器学习预测（未来效用损失 + 信用损失）。
- 完整的训练目标为：
  - L_shared = −J_turn^GRPO + β_KL · L_KL
  - L_router = λ_future·L_future + λ_credit·L_credit + L_reg（含负载均衡、角色多样性、稀疏性、熵正则）
  - L_routed = L_shared + L_router

## 6. 论文的主要结论与发现

1. **主性能结论**：
   - MuSiQue 上，ExRole-Shared 达 31.5 EM / 43.2 F1，较单智能体搜索提升 15.0/14.4 点，较最强非 ExRole 对照提升 11.5/11.6 点。
   - 2WikiMultiHopQA 上，ExRole-Routed 达 50.0 EM / 59.7 F1，较单智能体搜索提升 13.5/16.1 点，较最强对照提升 7.7/9.7 点。
   - 受控比较一致支持：**轨迹诱导角色 > 无角色 > 手工角色/随机角色/洗牌角色**。

2. **角色机制发现**：
   - 诱导出的 Researcher / Analyst / Verifier 三类角色在搜索率、证据命中、作答时机上呈现显著分化（搜索率分别为 96.6%、85.8%、61.3%）。
   - 角色嵌入在 t-SNE 投影中形成分离区域，路由器对不同角色产生不同的标准化门控签名。

3. **可迁移性**：
   - 角色身份使 held-out 动作对数损失额外降低约 19%（在控制智能体身份与回合阶段后）；不同角色间的 JS 距离是同一角色跨智能体距离的 **48–60 倍**。
   - 角色行为模式可跨说话人顺序与智能体映射迁移，不依赖固定索引。

4. **路由效果**：
   - Routed 相对 Shared 的配对差异在 MuSiQue（−1.5 EM）和 2Wiki（+1.0 EM）上方向相反，置信区间均含 0，**无统计学显著一致增益**——路由的价值是任务依赖的。

5. **瓶颈定位**：
   - 约 73% 样本能检索到含答案证据、87% 能生成有依据的答案，但严格成功率仅约 30%——剩余错误集中在最终答案选择与精确生成环节。

6. **方法边界**：
   - 全 Wikipedia 检索压力测试（HotpotQA）中，诱导角色未超过最强无角色/提示角色对照，说明角色特殊化无法弥补检索与答案选择在该设置下的约束。

---

## 7. 优点

1. **概念创新**：将角色重新定义为"可执行控制变量"，统一了行为抽象（聚类）、交互控制（提示+标记）与参数学习（路由+信用），而非传统的静态标签。

2. **未来感知归纳**：在归纳过程中以"下一动作 + 未来证据 + 最终收益"为预测目标，使角色携带延迟效用信息，同时避免 suffix 泄漏——兼具前瞻性与因果正确性。

3. **无额外角色标注模型**：模板评分 + 确定性联合解析器即可生成可读指令与标记，工程成本低、可复现性强。

4. **实验设计严谨**：
   - 受控对比覆盖了角色来源的多个维度（无/手工/随机/错配）；
   - 配对 bootstrap 置信区间提供统计可信度；
   - 角色-智能体-回合三方解缠实验有效排除了固定索引混淆；
   - 提供完整的角色归纳隔离审计（训练/评估集零重叠验证）。

5. **架构公平性**：Shared 与 Routed 共享角色库、奖励、训练目标与回合对齐信用，唯一差异是路由路径，从而干净地隔离了稀疏路由的贡献。

6. **透明度高**：附录提供了完整符号表、伪代码、目标函数推导、路由梯度链式法则与训练/推理详细配置，便于复现。

7. **诚实报告局限**：明确报告了 HotpotQA 上的失败结果与路由无一致增益的事实，未选择性隐藏负面结果。

## 8. 不足与局限

1. **场景覆盖有限**：仅在支持文档集合的多跳问答上验证；软件工程、网页导航、更长的工具使用流程、更大团队规模均未测试，泛化性未知。

2. **HotpotQA 压力测试未通过**：在完整 Wikipedia 词法检索配置下，诱导角色未优于最强对照，说明角色特殊化无法补偿检索与答案选择约束——方法边界明确但未被解决。

3. **路由增益不稳定**：Routed 相对 Shared 在两个基准上方向相反且置信区间含零，**无一致统计显著收益**；作者虽将此归因于任务依赖，但"路由是否值得额外复杂度"的问题仍未获肯定回答。

4. **算力消耗未披露**：未报告 GPU 型号/数量/训练时长，阻碍成本评估与现实可行性判断。

5. **奖励权重人工设定**：回合级奖励的多个正项与惩罚项的权重为手工配置，存在调参偏差风险；角色库离线归纳假设任务分布相对稳定，面对分布漂移需重新归纳。

6. **单次训练稳定性**：除配对 bootstrap 与 HotpotQA 解码多种子外，多数主结果基于单次训练运行，未系统报告多次独立训练的方差。

7. **与外部最先进方法的差距**：ExRole 虽优于多数 MAS-RL 基线，但低于最强的搜索特化策略（R1-Searcher），论文未进一步解释或弥合该差距。

8. **外部基线公平性存疑**：Table 2 中外部参考行采用各自论文声明的协议，骨干、训练数据、评测细节均不同，仅作上下文参考，不能视为严格对比。
