## 摘要
新兴的智能体互联网使基于LLM的智能体能够跨组织边界发现对等体、调用工具并委派任务。现有协议越来越多地定义了智能体如何交换消息，但并未定义智能体如何证明其身份、授权、所宣称的能力或委派后的责任。我们提出InterSAGE，一种信任原生的协议套件，它在通信协议之外（而非取代通信协议）提供了这一缺失的安全基座。InterSAGE包含四个层次：持久身份、发现、信任协商和责任。其四个核心原语是：(1) 智能体身份卡，将开发者、代码包、操作者和部署上下文绑定在一起；(2) 使用绑定DID的可验证凭证清单进行能力感知发现；(3) 将单调能力衰减与两级访问控制相结合的信任协商；以及(4) 内核中介的加密审计轨迹，将使用、委派和执行痕迹绑定到智能体身份，而无需共识账本。InterSAGE旨在补充MCP、A2A、ANP和AG-UI，使通信协议能够独立演进，同时保持信任语义的显式、可移植和可验证。我们将InterSAGE与跨越智能体协议、去中心化身份、OAuth/OIDC扩展、零信任治理、委派和审计架构的50多项工作进行了比较。我们表明，没有先前的架构将持久身份、能力感知发现、信任协商和责任作为一个统一的安全智能体互操作的四层信任基座来联合实施。

## Abstract
The emerging Internet of Agents enables LLM-powered agents to discover peers, invoke tools, and delegate tasks across organizational boundaries. Existing protocols increasingly define how agents exchange messages, but not how an agent proves its identity, authorization, advertised capabilities, or accountability after delegation. We present InterSAGE, a trust-native protocol suite that supplies this missing security substrate alongside, rather than in place of, communication protocols. InterSAGE comprises four layers: Persistent Identity, Discovery, Trust Negotiation, and Accountability. Its four core primitives are: (1) Agent Identity Cards that bind developer, code package, operator, and deployment context; (2) capability-aware discovery using DID-bound Verifiable Credential manifests; (3) trust negotiation combining monotonic capability attenuation with two-tier access control; and (4) kernel-mediated cryptographic audit trails that bind usage, delegation, and execution traces to agent identity without a consensus ledger. InterSAGE is designed to complement MCP, A2A, ANP, and AG-UI, allowing communication protocols to evolve independently while keeping trust semantics explicit, portable, and verifiable. We compare InterSAGE with more than 50 efforts spanning agent protocols, decentralized identity, OAuth/OIDC extensions, zero-trust governance, delegation, and audit architectures. We show that no prior architecture jointly enforces persistent identity, capability-aware discovery, trust negotiation, and accountability as a unified four-layer trust substrate for secure agent interoperability.

## 2. 论文提出的方法论：核心思想、关键技术细节

### 2.1 总体架构

InterSAGE 是一个四层信任原生协议套件，位于现有通信协议（MCP、A2A、ANP、AG-UI）之下/之间，向协议消息中嵌入信任原语，而非取代任何通信协议：

- **L0 持久身份（Persistent Identity）**：Agent Identity Card（AIC），解决"智能体是谁"
- **L1 发现（Discovery）**：能力感知发现（Capability-Aware Discovery），解决"智能体能力是否可信"
- **L2 信任协商（Trust Negotiation）**：双向认证 + 委派 + 两级访问控制，解决"能否信任并协作"
- **L3 问责（Accountability）**：内核中介审计追踪 + 支付原语，解决"事后能否追溯与追究"

### 2.2 五项设计原则

| 原则 | 含义 |
|---|---|
| P1 信任是绑定层而非附加物 | 信任原语嵌入协议消息内部，而非代理/网关包裹 |
| P2 与现有互联网层互补 | 不替代 TCP/IP、HTTP、MCP/A2A |
| P3 通用密码学原语 | 基于 Ed25519、PKI 式 GAR，无区块链等基础设施绑定 |
| P4 默认拒绝、收敛于严格 | 能力只允许衰减、不允许放大（单调能力衰减） |
| P5 结构性保证优于策略保证 | 安全属性编码为签名不变量，而非依赖运行时策略引擎 |

### 2.3 四个核心原语（论文的主要技术贡献）

**原语一：Agent Identity Card（AIC，L0）**

核心公式：`AIC = Sign_GAR(DID_agent ‖ K_pub ‖ S_max)`

- **四维身份绑定**：开发者（Developer，构建时签名）、代码包（Code Package，SHA-256 摘要）、操作者（Operator，OIDC 验证的身份）、部署上下文（Operational Context，租户/环境）。四个维度由不同方控制、独立验证、联合签名。
- 由**全球智能体注册表（GAR）**签发，类比 CA 签发 X.509，但原生编码智能体语义（能力集、委派深度等）。
- **密钥保护三级**：OS 文件隔离（0o600）→ OS Keychain → TEE 飞地（SGX/Nitro）。核心不变量：私钥永不离开发行信任边界，应用逻辑只通过内核签名 API 操作。

**原语二：能力感知发现（L1）**

- 每个技能（Skill）和工具（Tool）均表示为绑定智能体 DID 的**可验证凭证（VC）清单**，由技能分发者/工具提供者签发，可附 GAR 背书。
- 发现结果需要经过**四步验证协议**：供应链验证（签发者签名/GAR背书）、主体绑定（credentialSubject.id 必须匹配展示者 DID）、权限对齐（所需权限必须是 AIC 能力边界 S_max 的子集）、新鲜度（未过期、未撤销）。
- 支持注册表中介发现和对等（P2P）发现两种模式，两种模式都收敛到同一验证流程。

**原语三：信任协商（L2）**

- **双向认证**：通过质询-响应（challenge-response）协议，双方内核各自签署新鲜随机数，会话能力边界取双方 S_max 的交集。
- **委派链**：父智能体可为子智能体签发 AIC，要求 S_child ⊆ S_parent，并施加深度绑定、租户隔离、级联撤销、有效期上限、环检测等六项结构性安全属性。
- **两级访问控制模型**：基础设施层（强制、内核强制、密码学验证）+ 应用层（可选、声明式策略），最终权限 `S_session = S_policy ∩ (S_max^A ∩ S_max^B)`，任意一层被攻破/配置错误都不能放大另一层的能力边界。这被称为 **单调能力衰减链**（Developer → Operator → GAR → Runtime），每级只能收窄、不能放宽。

**原语四：内核中介审计追踪（L3）**

- Token 用量记录绑定智能体身份、会话、委派链，实现按委派树追溯成本至人工操作者。
- 每个操作生成带签名和 `prev_hash` 的**哈希链追踪条目**，任何篡改都会被立即发现。
- 提供支付原语框架（价格广告 → 支付协商 → 带计量的服务交付 → 结算），与 Google AP2 互补。
- 与 BlockA2A 的区块链方案相比：InterSAGE 通过内核中介的密码学签名实现**去中心化非否认**，无需共识账本，可在断网/边缘/资源受限环境中部署。

## 6. 论文的主要结论与发现

1. **信任层是智能体互联网缺失的根基**：通信互操作≠安全互操作；现有协议栈在消息格式上趋于一致，但在信任语义上各自为政。
2. **InterSAGE 是首个联合覆盖四层信任基座的安全协议套件**：持久身份 + 能力感知发现 + 信任协商（单调衰减 + 两级访问控制）+ 问责（内核审计），在单一架构中整体实现。
3. **结构性保证优于策略性保证**：将能力边界编码为签发时的加密签名（而非依赖运行时策略引擎），使得 PDP 误配置、策略引擎被攻破等故障场景下能力边界仍然收窄而非放大。
4. **与现有协议互补而非竞争**：InterSAGE 定义的是 MCP/A2A/ANP/AG-UI 消息中可以携带的信任对象（AIC 能力边界、清单 VC、会话令牌、签名痕迹），通信协议可独立演进。这一分离使得协议可在云、边缘、断网环境中部署，不依赖特定运行时、策略引擎或分布式账本。
5. **四维身份绑定显著强于单维绑定**：SPIFFE/OAuth/DID 等仅绑定单一维度，InterSAGE 的四维绑定意味着单一维度泄露（如操作者凭据被窃）无法冒充另一开发者或替换代码包。

## 7. 优点

- **架构设计亮点**：
  - 分层清晰、职责分离：L0-L3 每层只解决一类安全问题，层间依赖为严格的向下单向依赖，组合安全性可推理。
  - 单调能力衰减实现"结构性最小权限"，授权边界由密码学强制而非策略正确性保证——这是相对于 AgentMesh、AIP 等的关键差异化优势。
  - 两级访问控制（基础设施级 + 应用级）的独立失效语义设计精妙：任意一级被攻破都不削弱另一级。
  - 支持三种部署拓扑（同位置、远程中介、直接 P2P），灵活覆盖从单机多智能体编排到跨组织开放协作场景。
- **与实际生态对接良好**：明确将 MCP/A2A/ANP 视为宿主协议，定义了信任原语如何嵌入其中（如图 1 所示），不要求改写现有协议。
- **继承了 BlockA2A 的安全意图但去除了区块链依赖**，大规模提高了可部署性，且保持了非否认和审计能力。
- **对比方法系统化**："共享目标 → 分歧 → 可观察后果"的三步对比范式使每一条区分声明都有机制层面的落脚点，而非泛泛而谈。

## 8. 不足与局限

- **定位为 positioning paper，实验证据缺失**：无形式化验证（TLA+/ProVerif）、无系统原型实现、无性能基准测试（延迟/吞吐）、无红队对抗评估。这限制了对其安全声明的可信度——例如"单调衰减保证即使 PDP 被攻破也成立"这一强声明，在缺乏形式化验证的情况下难以作为最终结论接受。
- **GAR 的信任锚风险**：GAR 作为集中式/联邦式信任锚与 CA 有相同的单点故障问题；GAR 根密钥泄露将是灾难性的。虽然提到可以用区块链或分布式账本备选，但这又引入了配套的延迟和治理复杂度。
- **采用启动问题（Chicken-and-egg）**：InterSAGE 的价值随生态采用数量增长；初始部署时可能只有少数智能体支持，难以形成网络效应。作者提出的分阶段采用路径（L0 独立起步）有一定合理性，但个体采用动机仍然存在。
- **语义标签治理**：L1 开放语义标签（如 legal-review）的碎片化/误导风险没有得到实质解决，仅寄望于"有机涌现"的领域本体。
- **隐私权衡未充分解决**：当前 L2 认证暴露请求者完整 AIC 属性，零知识证明（ZKP）扩展方案在 §10.2 中仅作为"未来方向"提出。对隐私敏感领域（医疗、金融）而言，这是一个实质空缺。
