## 摘要
智能体系统日益由异构的智能体、提示词、工具、模型、技能、复合子系统、策略和执行工作流组成，其配置在不同框架和运行时环境中不断演化。现有的LLMOps和AgentOps平台支持编排和可观测性，但并未提供一种通用的配置治理模型来表示和治理这些系统，使其成为一致、版本化的配置。本文介绍了智能体配置管理（ACM），一种面向异构智能体系统的框架无关的治理与配置参考模型。ACM结合了类型化且独立版本化的智能体配置项、不可变修订与基线、显式的配置-运行时分离、生命周期与保障语义、依赖感知的影响传播以及运行时来源信息。异构原生配置通过语义投影被归一化为规范配置图，通用治理语义在该图上运行。我们提供了一个Python参考实现，包含LangGraph、CrewAI和OpenAI Agents SDK的适配器。评估结合了27个治理场景和九个量化影响传播案例。对于所评估的配置，三个框架在投影后产生治理等价的ACM表示和可复现的治理结果。影响语义被形式化为有限格上的单调传播，从而确立了收敛性、终止性以及初始影响估值之上最小不动点的唯一性。这些结果提供了证据，表明在所评估的范围内，通用治理语义能够支持跨异构智能体执行抽象的可复现性、可审计性、依赖性分析和互操作性。

## Abstract
Agentic systems are increasingly composed of heterogeneous agents, prompts, tools, models, skills, composite subsystems, policies, and execution workflows whose configurations evolve across frameworks and runtime environments. Existing LLMOps and AgentOps platforms support orchestration and observability but do not provide a common configuration-governance model for representing and governing these systems as coherent, versioned configurations.   This paper introduces Agentic Configuration Management (ACM), a framework-independent governance and configuration reference model for heterogeneous agentic systems. ACM combines typed and independently versioned Agentic Configuration Items, immutable revisions and baselines, explicit configuration-runtime separation, lifecycle and assurance semantics, dependency-aware impact propagation, and runtime provenance. Heterogeneous native configurations are normalized through semantic projection into a canonical Configuration Graph on which common governance semantics operate.   We provide a Python reference implementation with adapters for LangGraph, CrewAI, and the OpenAI Agents SDK. The evaluation combines 27 governance scenarios with nine quantitative impact-propagation cases. For the evaluated configurations, the three frameworks yield governance-equivalent ACM representations and reproducible governance outcomes after projection. The impact semantics are formalized as monotone propagation over a finite lattice, establishing convergence, termination, and uniqueness of the least fixed point above the initial impact valuation. These results provide evidence that common governance semantics can support reproducibility, auditability, dependency analysis, and interoperability across heterogeneous agentic execution abstractions within the evaluated scope.

## 2. 论文提出的方法论

### 2.1 核心思想

ACM 以 **治理与执行分离** 为概念基石：

- **配置（Configuration）**：智能体系统的预期、已版本化、受治理的结构，独立于任何执行框架；
- **运行时（Runtime）**：该配置在特定操作条件下的某次具体执行。

ACM 治理前者，同时为后者提供语义解释机制，但两者永不混淆。

### 2.2 核心概念

- **Agentic Configuration Item (ACI)**：所有可配置工件（智能体、提示词、技能、工具、模型、策略、工作流等）统一表示为类型化、独立版本化的配置项。每个配置项由不可变修订构成，修改产生新修订而非覆盖旧版本。
- **四图分解**：`G_ACM = (GC, GE, GA, GR)`，即配置图（结构关系）、演化图（修订谱系）、保障图（策略与证据）、运行时图（执行观察），分别对应正交的治理关注点，并通过显式关系和修订级来源保持连通。
- **发布基线（Release Baseline）**：不可变的 ACI 修订集合，是系统在特定时点的完整、内部一致的可复现快照，也是审计、发布、合规评估的基本单元。
- **语义投影（Semantic Projection）**：框架特定适配器从原生配置中提取治理相关构造，投影为规范配置图 GC。框架特定解释被限制在投影边界之内，之后所有治理语义在归一化表示上运行。

### 2.3 治理语义的形式化

- **五维配置治理状态空间**：生命周期 `L = {Draft, Validated, Approved, Released, Deprecated, Archived}`（单调推进）、质量 `Q = {Undefined, Valid, Warning, Invalid}`、保障 `A = {Unassessed, Partial, Satisfied}`、影响 `I = {None, Local, Propagated}`（有限格）、资格 `E = {Blocked, Restricted, Eligible}`。运行时状态空间 `R` 单独定义于运行时实体。
- **传播策略** `P = {Blocking, Warning, Informational, None}`：声明式地决定影响在配置关系上的传递语义；策略由关系类型决定，多路径汇聚时按序 `Blocking > Warning > Informational > None` 确定性复合。
- **传播语义（固定点计算）**：局部传播方程 `F₍ᵥ₎(ι) = ι⁽⁰⁾(v) ⊔ ∨₍ᵤ,ᵥ₎∈E τ_Π(u,v)(ι(u))` 定义了全局传播算子 [Prop。从初始影响估值 ι⁽⁰⁾ 出发，迭代应用算子直至稳定，收敛至初始估值之上的**唯一最小不动点** ι*。论文通过 Knaster–Tarski 定理和单调递增链论证了单调性、收敛性、终止性与最小不动点的唯一性。
- **运行时语义**：运行时状态通过重放归一化事件序列重建，锚定于发布基线，不修改任何不可变配置修订，保证确定性重构。

## 3. 实验设计

实验采用两个互补战役，基于 Python 参考实现的原型系统：

### 3.1 Campaign A — 参考模型覆盖与语义一致性（RQ1–RQ3）

- **基准**：27 个受控治理场景，覆盖修订管理、依赖传播、资格评估、基线治理、运行时治理、动态智能体演化、语义投影等类别。这些场景是规范性的（规范预期结果已知），而非演示性的（即检测治理违规也属于成功）。
- **框架**：LangGraph（显式图、直接抽取）、CrewAI（混合重建）、OpenAI Agents SDK（委托/交接内省），三种互补的内省范式。
- **信息保持分析**：将投影结果与手工黄金表示对比，将每条治理相关属性分类为 `preserved` / `declared_by_adapter` / `approximated` / `unsupported`，并报告节点/关系/分支覆盖率。

### 3.2 Campaign B — 定量影响评估（RQ4）

- **案例**：3 个框架 × 3 类变更（局部、中间、全局）= 9 个实验案例，每个执行 5 次以验证确定性。
- **对比**：将 ACM 传递固定点传播与朴素一跳依赖检查基线对比；另设一个 13 项 18 关系的专用配置验证传递依赖（一跳仅恢复 6/9，ACM 恢复 9/9）。
- **指标**：影响集大小、影响深度、影响比、固定点收敛行为、可复现性、残余检查范围缩减。

## 6. 论文的主要结论与发现

- 异构原生配置经语义投影后可归一化为**治理等价**的 ACM 表示，而无需框架特定的治理逻辑（RQ3）。
- 参考实现与规定的生命周期、质量、保障、影响、资格、运行时和基线语义一致（RQ2）。
- 定量影响分析在三个框架间产生**相同的影响集、相同的影响比例、相同的收敛迭代数**，且具有确定性（RQ4）。
- 影响传播在 13 项/18 关系的配置上恢复了朴素一跳检查遗漏的 3 个传递影响项，且在局部变更下将残余检查范围缩减 84.6%（协议范围内）。
- 基于有限格的单调传播在数学上确立了收敛性、终止性和唯一最小不动点，为可复现治理提供了形式化基础。

## 7. 优点

- **框架无关的架构分离**：语义投影将框架特定提取限制在边界处，治理内核保持独立，可扩展至新框架而无需改变治理语义（插件式适配器设计）。
- **形式化的治理语义**：传播语义通过有限格上的 Knaster–Tarski 定理与单调递增链论证，提供了明确的数学保证（单调性、收敛性、终止性、不动点唯一性），而非仅凭实现断言。
- **配置-运行时分离**：运行时观察不会污染治理配置；治理评估的可复现性不依赖 LLM 概率输出，是设计层面的创新而非事后补救。
- **显式的"文档化损失"**：投影报告区分已保存/适配器声明/近似/不支持等状态，不静默丢弃不可表达的信息（如 CrewAI Flow 状态模式被报告为 unsupported），这一透明度在治理工具中极为可贵。
- **四图分解**：配置、演化、保障、运行时四个图的分离避免将静态配置与动态治理信息混淆，使各图可独立演化又保持可追溯。
- **评估协议严谨**：标准规范场景、确定性验证、注入测试保障（check via digest_verified）、版本控制来源确保 oracle 先于测试运行，且实验仪器与治理内核在架构上分离。

## 8. 不足与局限

- **覆盖范围有限**：仅评估三个框架（LangGraph、CrewAI、OpenAI Agents SDK），未涵盖分层委托、群集协调、流水线编排、大规模企业部署等智能体架构类别。结论明确限定于"评估的范围"内。
- **缺乏工业规模验证**：配置规模为 11–13 个 ACI，与可能的数千项生产系统差距明显；未评估长期运行、多团队协作、持续演化的现实场景。
- **无机器辅助验证**：数学证明为分析证明，未使用定理证明器或模型检查；完整 ACM 治理模型尚未经机器验证。
- **共享作者偏差风险**：场景、预期结果和参考实现由同一研究团队制定，可能引入共同假设偏差。论文承认这是"一致性证据而非独立实证验证"。
- **三个场景存在文档化偏差**：S14、S15、S16 以 `pass_with_deviation` 通过，偏差源于实现层面的设计决策（如分类细节位于一致性层而非引擎本身），论文将其视为合理设计而非缺陷。
- **Oracle 的独立性问题**：九个定量影响案例的 reference set 从原生定义建立但未独立裁决，内部一致性不能等同于外部准确性；传递依赖对比实验提供了部分补充证据。
- **应用限制**：ACM 有意将规划算法、推理策略、学习机制、通信协议等执行技术置于治理范围之外；自学习/自适应智能体的动态演化治理未涵盖。
- **综述性评估具有代表性而非穷尽性**：结论仅适用于所评估的三种内省范式，不构成对新兴智能体生态的普适性主张。
