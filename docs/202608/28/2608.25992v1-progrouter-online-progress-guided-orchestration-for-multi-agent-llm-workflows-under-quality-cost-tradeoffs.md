## 摘要
多智能体大语言模型（LLM）工作流已成为一种强大的范式，通过专业LLM智能体之间的协作推理来解决复杂、开放式的任务，但由于重复调用LLM和长期上下文积累，其运行成本高昂。现有的级联路由方法做出一次性、查询级别的决策，无法适应多步骤工作流的动态和状态依赖特性，在多步骤工作流中，每一步选择合适的LLM取决于不断演变的任务进度、剩余任务难度以及成本效率要求。我们提出了ProgRouter，一种在线进度引导的路由框架，它在工作流各步骤中自适应地选择LLM智能体，以在遵守时间和成本预算的同时保持任务解决质量。ProgRouter引入了一个多视图任务进度评分器，将粗略的工作流结果状态与子任务完成情况、进度趋势和工作流状态质量的细粒度信号相结合。然后，一个双路径任务进度预测器和一个自适应元门控机制估计每个候选路由LLM的进度增益。ProgRouter做出在线逐步路由决策，平衡进度增益、任务时间预算和长期运行成本效率。在HumanEval Plus、MBPP、MATH-500和ASQA上进行的实验，涵盖智能体代码生成、数学推理和检索增强的长文问答，表明ProgRouter在保持强劲任务解决性能的同时，相对于关键基线降低了运行成本。

## Abstract
Multi-agent large language model (LLM) workflows have emerged as a powerful paradigm for solving complex, open-ended tasks through collaborative reasoning among specialized LLM agents, but they incur substantial operating costs due to repeated LLM invocations and long-horizon context accumulation. Existing cascade routing methods make one-shot, query-level decisions and cannot adapt to the dynamic, state-dependent nature of multi-step workflows, in which the right LLM at each step depends on evolving task progress, remaining task difficulty, and cost-efficiency requirements. We present ProgRouter, an online progress-guided routing framework that adaptively selects LLM agents across workflow steps to preserve task-solving quality while adhering to time and cost budgets. ProgRouter introduces a multi-view task progress scorer that combines coarse workflow outcome regimes with fine-grained signals on subtask completion, progress trends, and workflow state quality. Then, a dual-path task progress predictor and an adaptive meta-gating mechanism estimate the progress gain for each candidate routed LLM. ProgRouter makes online step-wise routing decisions that balance progress gain, task time budgets, and long-term operating cost efficiency. Experiments on HumanEval Plus, MBPP, MATH-500, and ASQA, spanning agentic code generation, mathematical reasoning, and retrieval-augmented long-form question answering, demonstrate that ProgRouter reduces the operating cost relative to key baselines while maintaining strong task-solving performance.

## 1. 核心问题与研究动机

- **背景**：多智能体大语言模型（Multi-agent LLM）工作流通过多个专业化 LLM 智能体协作推理，可解决复杂开放式任务，但需要反复调用 LLM 并维护长程上下文，导致高昂的 token 消耗、计算量、能耗和延迟。
- **现有方法的不足**：级联路由（cascade routing）方法（如 CASCADIA、MasRouter）本质上是**一次性、查询级**的决策，无法适应多步骤工作流的动态特性——每一步"该用哪个 LLM"取决于不断演变的任务进度、剩余难度和成本效率要求。
- **核心研究问题**：如何在多智能体工作流中跨步骤动态路由 LLM 智能体，在满足运行成本预算的前提下保持任务求解质量？
- **关键挑战**：
  - 工作流开放、有状态，"合适"的智能体随状态变化，静态基准或离线偏好数据无法满足在线路由需求；
  - 中间状态噪声大、部分解决，进度估计困难，误判会浪费预算或导致不可逆的质量下降；
  - 未来步骤和子任务难度未知，贪心策略可能过早耗尽预算，保守策略则浪费强模型能力，需要 principled 的在线算法。

## 2. 方法论：ProgRouter

### 2.1 核心思想

ProgRouter 是一个**在线进度引导的路由框架**，在每步智能体调度时，基于当前工作流状态估计"若选用某个候选 LLM 能带来多少任务进度增益"，并据此在进度增益、时间预算和长期运行成本之间做权衡。整个框架在线学习、随工作流执行不断更新。

### 2.2 多视图任务进度评分器

将中间状态 $s_t$ 编码为归一化进度得分 $g(s_t) \in [0,1]$，从四个互补视角合成：

- **总体结果视图**：将状态分为 invalid / recoverable / partial success / complete 四种粗粒度状态，给出基准分 $b(c_t)$；
- **子任务完成视图**：计算已满足需求的比例 $r_t$；
- **进度趋势视图**：基于最近几步的进度增量判断改进/停滞/倒退，得 $d_t$；
- **状态质量视图**：评估最新状态迁移的语义与结构意义（如嵌入相似性、新解决子任务），得 $e_t$。

**聚合公式**：
$$g(s_t) = b(c_t) + \alpha_{c_t} r_t + \beta_{c_t} d_t + \gamma_{c_t} e_t$$

该评分器是**轻量级领域适配器**：新领域只需调整里程碑定义和粗粒度状态，下游路由算法保持领域无关。

### 2.3 双路径任务进度预测器

给定当前状态 $s_t$ 和候选 LLM $m_t$，预测进度增益 $\hat{y}_t = P_\Theta(s_t, m_t)$：

- **结构化路径**：利用表格特征（进度分、子任务状态、趋势、调度历史、候选模型），用树模型（随机森林/XGBoost）回归；
- **语义路径**：由协调器生成工作流状态的自然语言摘要，经轻量句嵌入（如 MiniLM）编码，再用树模型回归；
- **元门控机制**：用 XGBoost 作为元学习器，根据当前工作流状态在两条路径间自适应分配信任权重，合并得到最终估计 $\hat{y}_t$。

### 2.4 在线决策算法

基于 Lyapunov 漂移-惩罚框架：

- **虚拟队列** $Q_{w+1} = \max\{0, Q_w + \sum_{t} E(m_t) - \bar{E}\}$，跟踪长期平均成本约束的累积违约；
- **进度-缺口感知的价值项**：$\tilde{P}(m_t, s_t) = V \cdot (1 - g(s_t)) \cdot \hat{y}_t(m_t)$——当任务离完成还很远时，进度增益更有价值，从而激励选择强模型；
- **预算感知成本罚项**：$c^\Gamma_t$、$c^E_t$ 随累计时间/成本消耗接近预算而指数增长，促使保留预算余量；
- **最终路由分数**：
$$\text{score}(m_t) = \tilde{P}(m_t) - Q_w \cdot (E(m_t) - \bar{E}) - c^\Gamma_t \cdot \Gamma(m_t) - c^E_t \cdot E(m_t)$$
每步选择分数最高的 LLM；
- **在线学习**：ε-greedy 探索收集无偏训练样本，用实际进度增益 $y_t = g(s_{t+1}) - g(s_t)$ 作为标签更新预测器，ε 随样本积累逐渐衰减。

## 6. 主要结论与发现

- **固定单模型策略普遍违反成本约束**：小模型因反复失败重试累积高能耗，大模型因单次调用成本高也超预算，无论大小都无法同时满足质量与成本。
- **ProgRouter 在满足长期预算约束的方法中实现最优质量-成本权衡**：
  - HumanEval Plus：93.0% pass rate，比 MasRouter 高 2.1%、比 CASCADIA 高 8.2%；
  - MBPP：79.4% pass rate，同时能耗最低（3376 J）、延迟最短（10.3s），全面领先；
  - MATH-500：能耗（6112 J）和时间（19.0s）最优，pass rate 84.3% 仅比 CASCADIA 低 3.5%，但成本显著更低；
  - ASQA：引用精确率 92.1%，在满足预算的方法中最高，比两个基线高 2.3%；
- **基线的系统性失败模式**：Educated Guessing 收敛到任务无关的历史强模型（违反预算）；CASCADIA 在升级前浪费大量小模型调用；MasRouter 不随工作流状态调整，在 MATH-500 上违规、在 MBPP 上效果差、在 ASQA 上过度依赖单一小模型。
- **路由分布显示自适应专业化**：ProgRouter 将多数步骤分配给高效小模型（如 HumanEval Plus 84.3% 用 0.5B、MATH-500 91.0% 用 3B），仅在预测到显著进度增益时调用大模型，体现了进度-缺口项 $V(1-g(s_t))\hat{y}_t$ 的作用。

## 7. 优点

1. **问题定义清晰且有实践价值**：将 LLM 智能体选择形式化为带任务级和系统级约束的在线优化问题（Eq. 1a–1d），站位准确。

3. **理论支撑扎实**：引入 Lyapunov 虚拟队列处理长期平均成本约束，提供了 principled 的质量-成本权衡框架，而非纯启发式。
4. **轻量且领域可迁移**：进度评分器作为轻量领域适配器，下游算法领域无关；预测路径开销小，适合在线场景。

## 8. 不足与局限

1. **应用覆盖有限**：仅验证了代码生成、数学推理和 RAG 长文问答 4 个基准；未覆盖开放式网页导航、工具增强问答等更复杂的智能体场景，泛化性待验证。
2. **需人工领域适配**：多视图进度评分器的粗粒度状态和里程碑需要根据任务特征人工设计，尚未实现端到端自动学习进度表示。
3. **实验规模与统计性不足**：MBPP/MATH-500/ASQA 使用随机抽样子集，样本量小；未报告多次运行方差、置信区间或显著性检验；消融仅在 HumanEval Plus 上开展。
4. **在线学习细节有待明确**：预测器更新时间、ε 衰减曲线、训练缓冲大小等超参数未充分讨论；ε-greedy 探索在真实生产环境中的风险（如随机选弱模型导致低质量输出）未评估。
5. **隐含假设**：时间/成本预算 $E_w$、$\Gamma_w$ 和长期约束 $\bar{E}$ 需预先设定，实际部署中预算估计偏差对路由效果的影响未分析。
6. **伦理与安全考虑**：路由决策不改变模型能力，输出质量仍依赖所选模型；真实部署中工作流状态可能含用户隐私信息，需要数据保护措施；还需监控路由模式避免过度依赖特定模型。
7. **硬件依赖**：实验基于特定 GPU 工作站和 Ollama 服务，能耗数值（Joule）难以直接推广到云端 GPU 集群、不同架构或分布式部署场景。
