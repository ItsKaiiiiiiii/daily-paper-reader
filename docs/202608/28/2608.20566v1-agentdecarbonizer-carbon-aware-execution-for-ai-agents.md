## 摘要
AI代理将大型语言模型从单次提示-响应交互扩展为长时间运行、目标导向的工作流，这些工作流会发起多次模型调用、调用工具并与外部环境交互。这些工作流支持软件修复、数据分析和实验管理等任务，但重复的模型调用可能会产生大量碳排放。本文使用WildClawBench对OpenClaw代理工作负载的碳排放进行了特征化，并表明碳排放取决于令牌消耗、上下文缓存重用和电网的碳强度。我们的特征化将截止时间灵活性识别为碳感知执行的一个机会：代理任务可以等待碳强度较低的时段，或转移到碳强度较低的电网。然而，这样做需要处理时间转移时不确定的执行时间，以及空间转移时缓存上下文的重新计算。我们提出了AgentDecarbonizer，一个与OpenClaw并行的AI代理碳优化器。给定任务提示和用户指定的截止时间，AgentDecarbonizer保守估计任务持续时间，并选择截止时间可行的执行计划，同时考虑空间转移期间的缓存重计算开销。在WildClawBench工作负载上，对四个电网的60个代理任务进行评估，AgentDecarbonizer与碳无关基线相比，碳排放减少高达57.9%，与在任务开始时选择碳最优电网的基线相比，减少高达37.5%。

## Abstract
AI agents extend large language models from single prompt-response interactions to long-running, goaldirected workflows that issue many model calls, invoke tools, and interact with external environments. These workflows enable tasks such as software repair, data analysis, and experiment management, but their repeated model invocations can incur substantial carbon emissions. This paper characterizes the carbon emissions of OpenClaw agent workloads using WildClawBench, and shows that emissions depend on token consumption, context cache reuse, and the carbon intensity of the grid. Our characterization identifies deadline flexibility as an opportunity for carbon-aware execution: agent tasks can wait for lower-carbon-intensity periods or shift to lower-carbon grids. However, doing so requires handling uncertain execution time for temporal shifting and cached context recomputation during spatial shifting. We present AgentDecarbonizer, a carbon optimizer for AI agents that runs alongside OpenClaw. Given a task prompt and user-specified deadline, AgentDecarbonizer conservatively estimates task duration and selects deadline-feasible execution schedules, while accounting for cache recomputation overhead during spatial shifting. Evaluated on WildClawBench workloads with 60 agent tasks across four grids, AgentDecarbonizer reduces carbon emissions by up to 57.9 % compared with a carbon-agnostic baseline and by up to 37.5 % compared with a baseline that selects the carbon-optimal grid at task start time.

  1. **执行时间不确定**：后续步骤依赖前面的模型输出、工具结果及外部交互，且必须满足用户指定截止时间，不能无限期延迟。

### 2.2 关键技术组件

**① 执行时间估计器（Execution Time Estimator）**

  1. **特征提取**：从任务提示中提取类别、模态、复杂度、工具使用、批量数量等运行时相关特征；
  2. **阶段分解**：将任务拆分为执行阶段序列；
  3. **阶段级时长估计**：基于公开研究的启发式锚点（表4：各阶段典型步骤数，如外部检索7.3步、代码调试14.71步等），结合每步267.6个token和模型生成速度（GPT-5.4为74 tokens/s），给出每阶段的保守时长估计；
  4. **聚合**：汇总得到任务总保守时长 eT。
- **运行中更新**：根据已完成阶段、工具调用、Token生成量等执行进度信号，周期性修正剩余时长估计。

**② 碳强度预测器（Carbon Intensity Predictor）**
- 使用 EnsembleCI 预测各电网未来碳强度，粒度 Δt=15分钟，每小时刷新一次预测。

**③ 缓存感知碳模型（Cache-Aware Carbon Model）**
- 留在同一电网：假设可复用缓存上下文；
- 切换到其他电网：根据历史API调用的token统计和缓存token元数据，估计重新计算已缓存输入所需的prefill额外开销；
- 只有当预期碳减排超过缓存重计算开销时才进行空间迁移。

**④ 碳感知规划器（Carbon-Aware Planner）**
- 将任务分解为 K=⌈eT/Δt⌉ 个有序执行区间，在截止时间前选择 K 个最低碳、不重叠的候选区间；
- 用一个**动态规划**算法精确求解优化问题，其关键观察是：未来缓存成本仅取决于前一个执行位置（局部缓存重计算假设）。

**⑤ 执行控制器（Execution Controller）**
- 根据规划方案控制等待、恢复、跨网格迁移；收集token消耗、工具使用等运行时记录并反馈给规划器触发重规划。

### 2.3 数学形式化（公式说明）

优化目标为最小化预测碳排放与缓存重计算开销之和，满足截止时间和执行顺序约束：

- **目标函数**：min Σ [预测能量 × 预测碳强度 + 缓存重计算罚项]，其中缓存重计算罚项仅当相邻执行区间更换电网时产生。
- **DP 递推**：D(k)_r,t = 预测碳排放项 + min{保持同区域的最优前驱成本，切换区域的最优前驱成本 + 重计算罚项}。
- **定理7.1**：该DP算法可在 O(K|R|H) 时间内求出精确最优解（|R|为电网数，H为候选区间数，K为执行区间数）。
- **定理7.2**（截止时间保证）：若实际累计执行时间 ≤ 保守估计 eT，则调度保证在截止时间内完成任务。

- **碳排放特征化发现**：
  1. **多样性**：代理任务在执行时间、API调用数、token消耗上差异巨大（5.2万到840万token）。

## 7. 优点

- **问题新颖**：首次系统化研究AI代理工作负载的碳排放并定制优化方法，填补了该方向空白。
- **负载特征化扎实**：基于真实代理系统（OpenClaw）和真实基准（WildClawBench）的执行痕迹，识别出输入主导、缓存依赖、多样性三个关键特征，结论有据可依。
- **缓存感知的空间迁移**：突破了传统碳感知迁移中“只看碳强度”的局限，将缓存重计算代价显式纳入优化目标，更贴近LLM服务实际。
- **截止时间感知的保守估计**：结合初始保守估计与运行中动态更新，兼顾不确定性和用户期限，并给出严格的截止时间保证定理。
- **算法高效且可证明最优**：利用局部缓存假设设计DP算法，将复杂度从 O(K|R|²H²) 降到 O(K|R|H)，具备理论保障。
- **模型无关与模块化**：不改变OpenClaw代理行为，可适配不同后端模型；各组件可替换（如更精确的能耗模型、更先进的预测器）。

## 8. 不足与局限

- **能耗模型是估计而非实测**：每-token能耗从单次研究数据和价格比例推导（如输出/输入能耗比6:1、缓存/输入比10%），若实际服务商的能耗特征不同，绝对碳排放数字和优化决策可能偏差。
- **空间迁移未在真实系统验证**：由于GPT-5.4不提供用户可选服务区域的API，迁移机制仅在碳排放模拟器中实现，缺少端到端真实部署验证。
- **缓存假设简化**：假设缓存严格本地化（服务端本地），若服务商支持跨区域缓存传输（如CacheGen/LMCache），迁移罚项需下调，当前结果可能高估了缓存惩罚。
- **基准构造的局限**：使用同类别短任务拼接形成长时工作负载，可能无法完全代表真实长时代理任务的执行模式；跨任务缓存不复用的假设也可能与实际不符。
- **电网覆盖有限**：仅4个电网、1个月测试数据，结论对更多区域和季节的普适性存疑。
- **执行时间估计偏保守**：短任务上估计与实际执行间存在较大松弛（slack），说明估计器对短任务效率不高，可能错过更多低碳调度机会。
- **本地额外开销**：需要本地运行LLM估计器（约6.5GB内存、14.9W功率），对低端边缘设备有一定部署门槛。
