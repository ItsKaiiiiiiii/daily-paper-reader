## 摘要
科学LLM智能体在文献推理、工具使用和实验规划方面展现出潜力，但目前尚不清楚它们能否通过可执行代码修改和计算昂贵的验证来自主改进大型、紧密耦合的科研机器学习系统。我们在蛋白质折叠领域研究这一问题，该领域的进展需要协调的架构修改、多目标评估和领域感知解释。我们提出了AgentFold，一个多智能体框架，将折叠模型开发表述为对可执行代码变体的闭环搜索。从ESMFold出发，AgentFold提出假设、实现并调试代码级修改、评估模型变体、分析实验结果，并将成功和失败的干预措施存储在结构化记忆中。一种MCTS风格的策略将计算资源分配到高分的搜索分支上。在一个包含2000多行代码的工程级蛋白质折叠代码库上，AgentFold使用约5000个GPU小时和1.7亿个LLM标记探索了约80个模型变体。在匹配的计算预算下，AgentFold相比独立的Codex提议将最佳lDDT提高了7.5%，并优于随机搜索对照。除了模型改进之外，由此产生的干预轨迹揭示了反复出现的经验性设计模式：稳定的收益往往来自早期、柔和、可学习的先验和门控精化，而直接的几何扰动和几何条件反馈常常使训练不稳定。代码和实验资源公开可用，网址为https://github.com/lmqfly/AgentFold。

## Abstract
Scientific LLM agents have shown promise in literature reasoning, tool use, and experiment planning, but it remains unclear whether they can autonomously improve large, tightly coupled scientific machine-learning systems through executable code changes and computationally expensive validation. We study this question in protein folding, where progress requires coordinated architectural modifications, multi-objective evaluation, and domain-aware interpretation. We present AgentFold, a multi-agent framework that formulates folding-model development as a closed-loop search over executable code variants. Starting from ESMFold, AgentFold proposes hypotheses, implements and debugs code-level modifications, evaluates model variants, analyzes experimental outcomes, and stores both successful and failed interventions in structured memory. An MCTS-style policy allocates computational resources across high-scoring search branches. On an engineering-scale protein-folding codebase comprising more than 2,000 lines of code, AgentFold explores approximately 80 model variants using approximately 5,000 GPU-hours and 170 million LLM tokens. Under a matched computational budget, AgentFold improves the best lDDT by 7.5% over independent Codex proposals and outperforms a random-search control. Beyond model improvement, the resulting intervention traces reveal recurring empirical design patterns: stable gains tend to arise from early, soft, learnable priors and gated refinement, whereas direct geometric perturbations and geometry-conditioned feedback often destabilize training. The code and experimental resources are publicly available at https://github.com/lmqfly/AgentFold.

## 2. 论文提出的方法论

### 2.1 核心思想

**AgentFold** 将蛋白质折叠模型开发形式化为**对可执行代码变体的闭环搜索**。系统的核心产出包含两部分：
1. **改进的模型变体**（例如 lDDT、NWRS 等指标提升）
2. **累积的设计证据**——从干预-结果轨迹中提炼出的经验性设计模式

### 2.2 系统架构：双循环机制

AgentFold 采用 **MCTS 风格的树控制器**，对代码快照进行搜索，并包含两个循环：

- **内层探索循环（Inner Exploration Loop）**：持续执行以下四个阶段的循环——
  - **采样（Sampling）**：从经验池中选取高分化节点及多样参照节点，近似探索-利用权衡
  - **演化（Evolution）**：将总结的上下文转化为可执行代码，包括去重、统一规划与编码、交互式调试
  - **实验（Experiment）**：训练并评估候选变体
  - **分析（Analysis）**：将训练日志流式传给 Analyst 代理，生成结构化报告（归因、模式支持/反驳）
- **外层周期更新（Outer Periodic Update）**：每 10 次迭代进行一次批量更新，用复合评分函数更新搜索树中各节点的价值，并精化候选集，从而改进全局搜索策略。

### 2.3 关键技术细节

- **统一规划与编码（Unified Planning & Coding）**：同一智能体同时负责架构设计和代码实现，减少了设计与实现之间的接口不匹配。
- **交互式调试（Interactive Debugging）**：Debugger 代理实时监控训练过程，遇到错误或异常日志时，与 Unified Planner 自主互动直到训练成功启动。
- **去重（Deduplication）**：Deduplicator 代理在提出优化方向时对照历史数据进行筛选，避免重复实验，采用保守策略（倾向“不重复”判断以避免抑制潜在有效探索）。
- **归因与经验模式挖掘（Attribution & Pattern Mining）**：Analyst 代理将指标变化归因到具体干预，并对当前候选模式集 P 进行支持、反驳或限定更新。
- **结构化记忆**：数据库存储代码快照、代码差异、配置、日志和结构化归因，将失败与成功干预均保留为结构化证据。
- **混合评分机制**：总得分 $S_{total}(e) = S_L(e) + S_B(e) + S_A(e)$，其中 $S_L$ 为损失得分（自动提取）、$S_B$ 为基准得分（CAMEO2022 上自动评估）、$S_A$ 为 Critic 代理得分（评估干预理由与实现风险，仅用于排序而非最终改进声明）。

### 2.4 最重要的算法流程（文字概括）

1. **初始化**：从 ESMFold 基线出发，构建搜索树根节点。
2. **重复内层循环**：
   - 从搜索树中按 Top-k 策略采样父节点和参照节点
   - Summarizer 生成精炼的实验上下文简报
   - Deduplicator 筛选新颖方向 → Unified Planner 设计并编码 → Debugger 协助修复直至训练可运行
   - 训练并评估变体 → Analyst 生成归因报告 → Searcher 检索相关文献
3. **每 10 次迭代**：批量更新节点分数、修剪/深化搜索树、精化候选集。
4. **终止条件**：达到预定的评估预算（36 次评估用于控制对比）。

## 6. 论文的主要结论与发现

1. **闭环代码级搜索可行且有效**：AgentFold 在匹配预算下，最佳 lDDT 较独立 Codex 提议提升 7.5%，较随机控制提升约 9.6%，验证了“闭环搜索+结构化记忆+树策略”这一组合的有效性。

2. **改进主要集中局部结构精度**：各变体在 lDDT、loop lDDT、12-24 区间接触等局部/中程指标上有持续提升，但 TM-score 等全局指标基本不变。说明搜索策略倾向于发现“局部精化”型干预而非“全局折叠”型干预。

3. **反复出现的经验设计模式（P1-P3）**：
   - **P1（先偏好后几何）**：在坐标实例化前加入早期、柔和的**可学习先验**（如对 IPA logits 增加残基索引条件偏置）往往带来稳定增益；而直接对已耦合的刚性更新施加 frame 级偏移则常导致崩溃。
   - **P2（乘法精化）**：用 sigmoid/置信度相关的**门控**对 backbone 更新进行缩放，相比加法强制位移更稳定，可抑制不确定区域的过度更新。
   - **P3（避免几何到注意力的反馈）**：在初始几何不准确时将几何特征反馈到注意力或 frame 更新中，会放大后续精化步骤中的误差，导致训练崩溃或严重退化。
   - **失败案例**：`#60 diff-geom` 直接对序列特征计算曲率/挠率并反馈进 IPA 路径，lDDT=0.000、TM-score=0.091，为灾难性失败。

4. **参数效率**：最强变体 `esmfold_struct_enhanced_v4` 仅比 ESMFold 基线多约 1.1% 参数（22.606M → 22.856M），强变体 #47 增加不到 0.1% 参数即达第二名。增益更多来自**偏差放置和门控设计**而非模型容量。

## 7. 优点

- **问题定位精准**：选择蛋白质折叠这一“高难度、紧耦合、昂贵验证”的场景来检验科学智能体的能力上限，具有示范意义。
- **闭环而非单向生成**：完整包含 propose → implement → debug → evaluate → analyze → memorize 的闭环，而非仅生成代码建议。
- **失败模式被充分利用**：将失败干预也存入结构化记忆，作为后续避免重复的“负经验”，并通过失败案例反推设计规律（P3）。
- **MCTS 风格的算力分配**：外层周期性批量更新减少了昂贵训练评估对树更新的压力，内层 Top-k 采样实现探索-利用权衡。
- **目标指标分解分析**：将聚合增益分解到环区/物理/接触等具体方面，回答了“增益到底来自哪里”这一关键问题，而不满足于“总分提升了”。
- **消融与鲁棒性验证充分**：包含组件消融（IPA bias vs. BB gate）、不同 trunk 深度验证和重复运行误差条、以及具体案例可视化。
- **参数效率分析**：讨论了“改进是否只是容量效应”的反事实，增强了结论可信度。
- **促进可复现性**：代码与实验资源公开，并给出了详细的提示词模板。

## 8. 不足与局限

- **规模受限**：
  - 仅使用**单块折叠主干（one-block Folding Trunk）** 的紧凑 ESMFold 变体，未在完整 ESMFold、AlphaFold2/3、OpenFold 等更大模型上验证
  - 仅使用 **1,000 链训练子集**，远小于真实蛋白质折叠训练规模
  - 仅在 **CAMEO2022 开发基准**上评估，且该基准同时用于搜索排序，存在开发集“过拟合”风险；未在 CASP 或独立测试集上验证
- **泛化未验证**：转移至多链/复合物体系、更广的生物学场景（如抗体、膜蛋白、核酸复合物）仍未验证。
- **大规模部署成本**：约 5,000 GPU 小时 + 1.7 亿 LLM tokens 的搜索成本较高，一般实验室可能难以承担。
- **描述性证据而非因果证明**：论文明确承认模式集 P 是经验性、事后归纳的规律，而非理论定律；这些模式需要进一步受控实验验证其因果性。
- **GPU 细节缺失**：未报告 GPU 型号、数量及具体的能耗，影响可复现性和成本评估的精确性。
- **未消融系统组件**：未单独验证去重器、文献增强、Critic 代理等各组件对最终效果的独立贡献。
- **评估指标偏重局部结构**：由于改进集中在局部精度，未证明该方法能系统性改善全局折叠质量——而全局折叠质量对许多下游生物学应用至关重要。
- **基线对比范围有限**：仅对比 Codex 和随机控制，未与其他科学自动化的智能体框架（如 AI Scientist、MLAgentBench、FunSearch 等）直接对比。
