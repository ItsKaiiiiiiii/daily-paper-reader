## 摘要
空间高效的仓库布局通常包含仅容单智能体通过的通道和死胡同式工作站，在这些地方机器人几乎没有可等待而不阻塞他人的位置。在此类受限布局的多智能体取送货（MAPD）问题中，机器人必须接受在线取送货任务，同时保留称为避风港（Haven）的受保护等待位置。安全避风港撤退规划器（SHARP）引入了一种机制，为每个已承诺的任务路径扩展一条经过验证的撤退路径，通向该智能体专用的初始避风港；但固定避风港的承诺可能在交付后将智能体引向遥远的避风港。我们提出A-sharp（自适应SHARP），它在任务分配时改变智能体的撤退目标。一种简单的切换可能导致两个智能体依赖同一等待位置，或让另一条已承诺路径穿过仍被占用或预留的位置。A-sharp通过候选避风港的可用性测试和待释放规则（在智能体离开前保持先前避风港受保护）来防止这些失败。在显式避风港结构和安全区间路径规划（SIPP）假设下，我们证明了不变量保持和有限释放完备性：任何有限释放序列中的每个任务都能在有限时间内被交付。在四个地图上进行的72,000次运行（覆盖14,400个配对的智能体-地图-数量-速率-种子组合）中，SHARP和A-sharp均完成了各自的14,400次运行。就完工时间（最终交付时间）而言，在避风港数量多于智能体数量的全部138个配置中，预先指定的配对比较（采用Holm校正）发现A-sharp在107个配置中显著优于SHARP，且从未显著劣于SHARP；在测试的树形地图上，中位减少幅度为16.7%。

## Abstract
Space-efficient warehouse layouts often contain single-agent-width aisles and dead-end workstations where robots have few places to wait without blocking others. In Multi-Agent Pickup and Delivery (MAPD) on such constrained layouts, robots must accept online pickup-delivery tasks while preserving protected waiting locations called Havens. The Safe HAven Retreat Planner (SHARP) introduced a mechanism that extends each committed task path with a validated retreat to the agent's dedicated initial Haven, but fixed-Haven commitments can send agents toward distant Havens after deliveries. We present A-sharp (Adaptive SHARP), which changes an agent's retreat target at task assignment time. A naive switch can cause two agents to rely on the same waiting location or let another committed path pass through a location that is still occupied or reserved. A-sharp prevents these failures with an availability test for candidate Havens and a pending-release rule that keeps the previous Haven protected until the agent departs. Under explicit Haven-structure and Safe Interval Path Planning (SIPP) assumptions, we prove invariant preservation and finite-release completeness: every task in any finite release sequence is delivered in finite time. Across 72,000 runs on 14,400 paired map-agent-count-rate-seed cases over four maps, both SHARP and A-sharp complete their respective 14,400 runs. For makespan (final delivery time), a prespecified paired comparison with Holm correction over all 138 configurations with more Havens than agents finds A-sharp significantly better in 107 configurations and never significantly worse than SHARP; on the tested tree map, the median reduction is 16.7%.

# 论文总结：A-sharp（Adaptive SHARP）——受限仓库中的动态避风港选择

## 1. 核心问题与整体含义

- **背景与动机**：空间高效的仓库布局常包含仅容单智能体通过的窄通道、死胡同式工作站等受限结构，机器人在其中几乎找不到不会阻塞他人的等待位置。在多智能体取送货（MAPD）问题中，机器人需要在线接受任务并安全完成，而等待/返回/临时阻塞很容易造成死锁。
- **既有方案及其局限**：先前的 SHARP（Safe HAven Retreat Planner）通过为每个已承诺任务路径附加一条验证过的撤退路径，通向各智能体专用的初始避风港（Haven），从而保证安全性和任务完成性。但固定避风港的缺陷在于：交付后若撤退后缀仍生效，机器人可能被送回很远的初始位置，产生不必要的绕路。
- **研究问题**：能否在任务分配时动态改变撤退目标（Haven）？简单替换会带来新的协调困难——例如两个智能体可能依赖同一等待位置，或某条已承诺路径穿过仍被占用/预留给他人的位置。
- **整体含义**：论文提出 A-sharp（Adaptive SHARP），通过一套“可用性测试 + 待释放规则 + 原子状态更新”的所有权转移协议，使动态 Haven 切换在保持安全性和有限释放完备性的前提下可行，从而在受限仓库中提升任务效率。

## 2. 方法论

### 核心思想

- 在任务分配时刻，为每个可分配智能体选择一个**附近的可用 Haven**，并提交一条完整路径（当前位置 → 取货点 → 送货点 → 目标 Haven）。
- 关键不是简单换一个等待点，而是必须同时维护两类约束：
  1. **持久独占所有权**：Haven 作为受保护等待位置，在有限路径规划结束后仍须对其他智能体保持阻断；
  2. **有限时空调度预留**：已提交的未来路径在时间-空间上的占用必须与其他智能体不冲突。

### 关键技术细节

- **可用 Haven 定义**：一个候选 Haven `h` 对智能体 `a` 在时间 `t` 可用，当且仅当：
  1. `h` 不属于任何其他智能体的独占集合 `X_t(b)`；
  2. 没有其他智能体在任意 `t' >= t` 时刻对 `h` 有已提交的占用预留。
  - 该定义是“智能体相对”的：忽略自身独占集合和自身未来预留，因为自身未来预留会被原子的路径替换所覆盖。
- **待释放（pending-release）规则**：若智能体在分配新任务时仍位于旧 Haven，则旧 Haven 在智能体实际离开前继续保留在其独占集合中；直到智能体离开的那一刻，才在后续清理中释放。这避免了“所有权视图”与“物理占用视图”不一致造成的碰撞。
- **原子提交**：在成功验证后，一次性完成：
  - 保留当前时刻的顶点预留；
  - 删除自身未来时刻的旧预留；
  - 插入新完整路径的预留；
  - 更新当前 Haven 和独占集合；
  - 需要时设置待释放旧 Haven。
  - 从而避免陈旧预留导致的自我冲突，也避免其他智能体观察到“只有一半更新”的状态。
- **路径规划**：使用 SIPP（安全区间路径规划）分三段拼接完整路径：当前位 → 取货点、取货点 → 送货点、送货点 → 目标 Haven。规划时以其他智能体的独占集合为静态排除，以预留表为动态约束，并检查边交换冲突。规划器是“无副作用”的——任何一段失败都不改动状态。
- **算法流程（Algorithm 1）**：每个时间步先加入新释放任务；在待处理任务和非任务中（且无待释放旧 Haven）的智能体中循环；每个智能体选择最近取货任务，并在可用 Haven 中选择离送货点最近的；通过 SIPP 验证后，全局选择验证成功且取货距离最小的候选进行提交；然后重新评估所有候选，直到无任务或无候选可提交。随后执行一个时间步长的移动，并进行待释放清理。
- **理论保证**：
  - **不变量**：Haven 赋值单射、独占集合两两不相交、当前 Haven 必在独占集合中、每个非空闲智能体都有有限路径通向当前 Haven 等。
  - **有限释放完备性**：在 Haven 结构条件（核心子图 `G[F]` 连通、每个 Haven 至少与核心相邻、任务端点均在核心内）和 SIPP 段完备性假设下，证明了任意有限释放序列中的每个任务都在有限时间内被交付。证明思路是：若在最后一次成功提交后仍有未完成任务，则系统达到静止（quiescent）状态，此时 Lemma 2 保证任何空闲智能体都能为任何待处理任务规划成功路径，从而必然产生新的成功提交，产生矛盾。
