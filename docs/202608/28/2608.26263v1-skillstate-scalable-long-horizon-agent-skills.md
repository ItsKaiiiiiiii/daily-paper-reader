## 摘要
大型语言模型（LLMs）日益作为自主智能体执行复杂、长期运行的程序性技能。现有的智能体运行时通过不断将观察、动作和中间推理轨迹追加到不断增长对话历史中来维持执行，导致在长时间跨度下出现延迟退化和上下文中毒失败。我们提出SKILL.state，一种运行时架构，用显式的、可变的执行状态取代仅追加的对话历史。在每个执行步骤中，模型仅接收不可变的技能规范、当前结构化执行状态和最新观察。中间推理在产生经过验证的状态更新后立即丢弃，防止提示随执行历史增长。在多种数据集、模型和执行环境中，SKILL.state提高了任务准确性，同时大幅减少了累计token消耗。我们的结果表明，显式执行状态是一种有效且与架构无关的抽象，适用于可扩展的长时程智能体技能。

## Abstract
Large Language Models (LLMs) increasingly act as autonomous agents executing complex, long-running procedural skills. Existing agent runtimes maintain execution by continually appending observations, actions, and intermediate reasoning traces to an ever-growing conversation history, causing latency degradation and context-poisoning failures over long horizons. We present SKILL.state, a runtime architecture that replaces append-only conversational history with an explicit, mutable execution state. At each execution step, the model receives only the immutable skill specification, the current structured execution state, and the latest observation. Intermediate reasoning is discarded immediately after producing a validated state update, preventing prompt growth with execution history. Across diverse datasets, models, and execution environments, SKILL.state improves task accuracy while substantially reducing cumulative token consumption. Our results demonstrate that explicit execution state is an effective and architecture-agnostic abstraction for scalable long-horizon agent skills.

## 1. 论文的核心问题与整体含义

- **研究背景**：大型语言模型（LLMs）正从被动语言接口演变为能够执行长时程、程序性任务的自主智能体。现有智能体运行时几乎普遍采用"对话式执行模型"——在每一步，模型都需要接收原始技能规范以及不断增长的推理、动作、观察和工具输出记录。
- **核心问题**：这种仅追加式（append-only）对话历史设计在长时程任务中带来三大系统性缺陷：
  1. **提示规模随时间增长**：提示长度随执行步骤线性增长，导致token消耗和推理成本呈二次方（O(T²)）累积；
  2. **上下文污染**：过时观察和无关推理长期驻留在上下文中，模型被迫区分"当前事实"与"历史痕迹"；
  3. **信息重建负担**：每次决策都依赖于从海量文本历史中重建世界状态，而非直接获取当前执行状态，增加推理出错概率。
- **核心含义**：论文主张"执行本身是系统问题而非纯推理问题"，提出应从"管理对话历史"转向"维护显式执行状态"，从而为长时程智能体提供一种架构无关的可扩展方案。

## 2. 论文提出的方法论

  - Ot：最新环境观察。
- **关键技术细节**：

  3. **状态更新与丢弃机制**：状态更新经过确定性验证后合并：**Σt+1 = Σt ⊕ ΔΣt**（字典合并操作符，支持null删除语义）；推理轨迹Rt验证后**立即永久丢弃**，不进入后续任何提示。
  4. **复杂度保证**：提示大小与执行历史无关，稳定在O(1)有界范围内，累计token消耗为O(T)线性增长，而传统方法为O(T²)。

## 8. 不足与局限

- **基本假设限制**：论文的整个框架依赖于"当前状态可表示为未来执行的充分统计量"这一假设，即所有对后续决策有用的过去信息都能在出现时立即投影到结构化状态中。该假设在以下场景中失效：
  - 状态模式需在运行时动态发现时（规则未知的新领域）；
  - 某一历史观察的相关性在当时无法被识别、因而未写入状态时；
  - 任务目标本身定义在历史轨迹上（如审计、调试溯源、解释以往行为）。
- **模型能力依赖**：小型开放权重模型（Gemma-4-31B、Qwen-3-8B）在状态补丁生成方面错误率高，68%的错误源于过早状态覆盖/删除，显示出对模型结构化输出能力的依赖。论文承认需要约束解码来弥补。
- **多智能体缺失**：当前实现仅覆盖单智能体场景。多智能体并发写入需要确定性的冲突解决语义（⊕操作符的扩展），该部分未被实际验证。
- **算力信息不透明**：未披露GPU资源、训练/推理时间等关键资源指标，影响复现和成本评估。
- **真实长时程验证有限**：虽然Sierra τ-Bench等基准具有一定真实性，但仍属面向研究者的测试环境；缺乏对真实生产级系统（如数小时乃至数天的持续运行）验证。
