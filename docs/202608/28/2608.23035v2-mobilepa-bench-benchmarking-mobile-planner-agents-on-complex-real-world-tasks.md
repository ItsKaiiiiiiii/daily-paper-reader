## 摘要
随着端侧LLM智能体演变为个人副驾驶，移动操作系统已成为这一范式的关键测试平台，因此严格的能力评估至关重要。然而，现有基准测试分为两大阵营，各有其致命盲区：以GUI为中心的基准测试仅考察表面层面的屏幕操作，忽视了后台工具使用和长期规划；而静态函数调用基准测试则依赖离线API匹配，与真实运行时约束脱节。为弥合这一差距，我们提出了\textbf{MobilePA-Bench}，一个交互式、有状态且以工具为中心的基准测试，用于评估移动规划智能体的工具调用与规划能力。MobilePA-Bench运行于一个可执行沙箱中，该沙箱维护实时应用数据库并返回结构化反馈，覆盖$13$个功能域和$212$个真实移动工具。除基础工具使用外，它从三个高级维度评估中央规划智能体：\emph{(1)~子智能体协作}——分解复杂任务并将专业工作委派给有能力的子智能体；\emph{(2)~记忆使用}——回忆存储记忆、用户画像和过往偏好以解决隐含请求；\emph{(3)~技能使用}——调用预封装的复合技能而非从头规划每一步。大量实验表明，当前前沿LLM在移动场景中仍不可靠：在严格工具排序、权限限制和意外运行时错误下，性能急剧下降。通过将交互式函数调用沙箱与基于证据的验证相结合，MobilePA-Bench既可作为实用的诊断基准，也可作为智能体强化学习的交互基础——加速开发可靠的移动智能体。

## Abstract
As on-device LLM agents evolve into personal copilots, the mobile operating system has become a key testbed for this paradigm, making rigorous capability evaluation essential. Yet existing benchmarks fall into two camps, each with a critical blind spot: GUI-centric benchmarks test surface-level screen manipulation while overlooking background tool use and long-horizon planning, whereas static function-calling benchmarks rely on offline API matching that is detached from real runtime constraints. To close this gap, we present \textbf{MobilePA-Bench}, an interactive, stateful, and tool-centric benchmark for evaluating the tool-calling and planning abilities of mobile planning agents. MobilePA-Bench runs on an executable sandbox that maintains live application databases and returns structured feedback, spanning $13$ functional domains and $212$ realistic mobile tools. Beyond basic tool use, it evaluates a central planning agent along three advanced dimensions: \emph{(1)~Sub-agent Collaboration}---decomposing a complex task and delegating specialized work to capable sub-agents; \emph{(2)~Memory Usage}---recalling stored memories, user profiles, and past preferences to resolve implicit requests; and \emph{(3)~Skill Usage}---invoking pre-packaged composite skills instead of planning every step from scratch. Extensive experiments show that current frontier LLMs remain unreliable in mobile settings: performance drops sharply under strict tool ordering, permission limits, and unexpected runtime errors. By pairing an interactive function-calling sandbox with evidence-based verification, MobilePA-Bench serves as both a practical diagnostic benchmark and an interactive foundation for agentic reinforcement learning---accelerating the development of dependable mobile agents.

## 2. 论文提出的方法论：核心思想、关键技术细节

### 核心思想
- 将移动智能体定义为“中央规划器 + 模块化子智能体 + 状态化移动环境”的编排闭环：中央规划器负责任务分解与决策，直接调用结构化业务 API，查询记忆库，加载复合技能，并在必要时将 GUI 操作等任务委托给下游子智能体。
- 与 GUI 中心方法不同，MobilePA-Bench 将底层视觉解析与界面操作解耦，通过统一函数调用接口执行动作，以降低评估开销并精准诊断规划器的高层决策能力。

### 关键技术细节
- **统一动作空间**：所有操作（直接工具、子智能体路由、记忆搜索、技能加载）均以 JSON 函数 Schema 表示，包括函数名、描述和参数结构。
- **状态化模拟沙箱**：由三层构成——工具 Schema、工具执行代码、共享状态数据库。工具调用会实时更新数据库状态并写操作日志，返回结构化动态反馈（状态、错误类型、负载）。
- **环境摩擦注入**：通过在初始状态中注入缺失参数、权限受阻、实体歧义等障碍，迫使智能体根据反馈进行错误恢复与再规划。
- **任务公式**：定义任务为 $(q, S_0, H_0, A_0)$，智能体在每步选择动作 $a_t$，环境返回反馈 $f_t$ 并更新状态，直至 Finish 或达到最大步数。
- **证据对齐的任务验证（Query Bucket）**：根据任务完成语义划分为三类验证桶：
  - **Bucket 1 – Tool Call**：对确定性操作序列，严格匹配工具名、参数、顺序及副作用。
  - **Bucket 2 – State Change**：对路径等价任务，比较终态数据库增量 $D_T - D_0$ 与标注目标增量，拒绝破坏性或无关写操作。
  - **Bucket 3 – Agent Behavior**：对开放式/交互式任务，按规则评估是否路由到合适子智能体以及后续用户交互是否合理。
- **能力门控**：在基础验证之上，记忆使用需通过“黄金记忆 ID 全部被检索”的门控，技能使用需通过“给定任务加载了标注黄金技能”的门控。

### 四项核心评估维度
1. **Basic Tool Use（基础工具使用）**：工具与参数锚定、条件与依赖规划、引用与状态追踪、意图修订与任务管理、边界检测与错误恢复。
2. **Sub-agent Collaboration（子智能体协作）**：判断何时委托、选择正确子智能体路由并提供有效上下文交接。
3. **Memory Usage（记忆使用）**：通过检索用户画像与历史偏好解决隐含请求。
4. **Skill Usage（技能使用）**：调用预封装复合技能替代逐步骤规划。

## 3. 实验设计：数据集、基准与对比方法

- **数据集规模**：共 1,705 个真实用户任务，覆盖 13 个功能域（音频娱乐、应用存储、显示声音、系统设置、时间管理、AI 助手、通信、网络连接、出行生活、跨设备、输入交互、工具效率、安全隐私等）和 212 个移动工具。
- **任务分布**：

  - Sub-agent Collaboration：89 个任务

## 6. 论文的主要结论与发现

- **总体表现远未达到可靠部署水平**：最优模型 Claude-Opus-5 的综合加权得分仅 75.52%，13 个模型中有 7 个低于 70%。
- **各能力维度表现差异显著**：

- **错误跨能力边界级联放大**：真实任务往往同时涉及记忆、技能、工具和子智能体协作，单维度错误会叠加导致端到端成功率大幅下降。

## 7. 优点

- **填补现有基准空白**：同时覆盖 GUI 操作之外的结构化工具调用、记忆检索、技能复用和子智能体路由，形成统一评估框架。
- **状态化交互沙箱设计**：执行真实后端数据库读写并返回结构化反馈，能在不引入视觉渲染开销的情况下保留运行时真实约束，支持高吞吐评估与强化学习训练。
- **证据对齐的验证策略**：按照任务完成语义将验证分为“工具调用/状态变化/行为表现”三类，避免单一指标导致的过严或过松问题。
- **能力门控设计**：在任务成功判定中显式分离“是否检索了必需记忆”“是否加载了黄金技能”，能够精准定位失败原因。
- **完整开源基础设施**：1,705 个任务、数据集、沙箱环境全部开源，便于复现与后续研究。
- **稳定性验证充分**：报告了重复运行的统计波动，增强了评分可信度。
