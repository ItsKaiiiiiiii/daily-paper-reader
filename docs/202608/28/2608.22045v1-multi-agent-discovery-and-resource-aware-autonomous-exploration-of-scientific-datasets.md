## 摘要
现代科学设施和仪器生成的数据集规模之大，使得单个研究人员难以发现、访问和探索这些数据。尽管许多数据集是公开可用的，但使用它们通常需要熟悉存储库的组织结构、数据格式、多分辨率结构和可视化参数。我们提出了WebVisus，一个受约束且资源感知的多智能体系统，用于发现和自主探索远程的多分辨率科学数据集。给定一个自然语言研究问题，WebVisus识别用户的意图并启动一个自主探索智能体，该智能体检查切片、体积和时间步长，同时根据可用的客户端内存和计算资源调整数据分辨率和检索质量。这种设计支持渐进式探索，无需完整下载数据集或手动配置低层可视化参数，并使用自然语言。我们报告了系统架构、受约束的智能体协议、资源感知的访问机制，以及评估跨科学数据集的自主可视化探索和资源感知智能体访问的案例研究。

## Abstract
Modern scientific facilities and instruments generate datasets at scales that are difficult for individual researchers to discover, access, and explore. Although many datasets are publicly available, using them often requires familiarity with repository organization, data formats, multiresolution structures, and visualization parameters. We present WebVisus, a constrained and resource-aware multi-agent system for discovering and autonomously exploring remote, multiresolution scientific datasets. Given a natural-language research question, WebVisus identifies the user's intent and launches an autonomous exploration agent that examines slices, volumes, and timesteps while adapting data resolution and retrieval quality to available client memory and computational resources. This design supports progressive exploration without complete dataset downloads or manual configuration of low-level visualization parameters using natural languages. We report the system architecture, constrained agent protocol, resource-aware access mechanism, and case studies evaluating autonomous visual exploration and resource-aware agentic access across scientific datasets.

### 2. 论文提出的方法论

#### 2.1 整体架构：三层控制

- **浏览器客户端**：提供 Catalog（目录）和 Playground（可视化工作台）两种交互界面。
- **应用服务器**：维护数据目录索引、校验智能体动作、执行资源限制。
- **云端语言模型服务**：基于 Azure OpenAI（Microsoft Foundry）部署，支持 DeepSeek-V4-Flash、Grok-4.3、Kimi-K2.6、GPT-5.4-Pro、GPT-5.4、o3-mini 等多后端，部分模型支持多模态视觉输入。

数据保留在远程 Atlantis 服务端，系统只按需检索当前操作所需的特定分辨率、区域和时间步。

#### 2.2 三个专门化智能体

- **Orchestrator（编排器）**：解析用户目标并分解为结构化计划；不直接查询目录或发可视化命令，而是委派给下游智能体，并根据反馈修订计划。
- **Catalog Agent（目录智能体）**：调用固定工具集（目录统计、组列表、元数据搜索、数据集推荐、名称解析），返回最佳匹配及备选，并附元数据。
- **Executor（执行器）**：将计划转为类型化动作，管理数据集选择、访问模式、时间步设置、分辨率调整和可视化修改，并发出中间状态更新。

#### 2.3 约束动作协议

- 语言模型不能直接操作 DOM、调用 shell、访问操作系统或构造任意请求。
- 动作必须注册在固定命令词汇表中，经应用层解析和匹配后才能执行；不合法或违反资源/安全约束的命令会被确定性拒绝。
- 每次 Playground 请求附带紧凑的当前状态表示（数据集、访问模式、时间步、质量、可视化节点），多模态模式下还附渲染快照。成功/失败动作都写入交互记录，使智能体行为可观察、可审计。

#### 2.4 资源感知的渐进式访问

**内存感知分辨率选择**：数据以多分辨率布局存储，系统可在加载前估算候选表示的解码后内存占用。用细化字符串 s ∈ {0,1,2}* 表示各轴的细化操作（0/1/2 对应 X/Y/Z 维度），形状为：

```
R(s) = (2^n0(s), 2^n1(s), 2^n2(s))
```

对 b 字节/样本的数组，解码后内存足迹为：

```
M(s) = b · 2^(n0(s)+n1(s)+n2(s))
```

在一个具体示例中，原始细化串产生 (4096, 4096, 512) 的数组，float32 下需 32 GiB；通过减少细化（截短细化串），得到 (2048, 2048, 256)，恰好 4 GiB，满足指定内存预算。给定预算 B，WebVisus 选择满足 **M(s) ≤ B** 的最精细候选表示。

**智能体资源控制**：分辨率选择交由智能体决策。Executor 根据目标选定初始质量、空间范围和时间步，然后与活跃预算比较；超预算时降分辨率、缩小范围、降为切片或限制时间步。读取完成后，智能体收到最终形状、加载时长和可视化状态，可决定增加细节或减小请求。服务器端有双重检查：第一层限制加载到服务器内存的数据量，第二层限制传输到浏览器的数据量。

#### 2.5 可视化管线和自主探索循环

- 2D 数组用 Plotly.js 展示，3D 数组上传到基于 Three.js 的 WebGL 管线（ParaView 风格）。
- 切片位置、颜色映射、透明度、等值线范围、相机设置等操作基于缓存的纹理，无需重新检索数据；仅当数据集、分辨率、空间选择、访问模式或时间步变化时才发起新请求。
- 自主探索采用 **Observe-Plan-Act-Evaluate** 循环：观察状态（数组形状、统计量、参数、操作历史和渲染快照）→ 评估当前视图→ 提出动作集 → 资源策略审查 → 执行 → 等待加载和渲染完成 → 进入下一轮。客户端有退避机制，超时后自动降低检索设置。停止条件为目标完成、达到步数上限或用户命令。

### 3. 实验设计

论文包含三个实验部分：

#### 3.1 案例一：断层扫描数据的自主探索

- **数据集**：单时间步的断层扫描体数据，逻辑形状约 707×2048×2048，完全解码需约 11 GiB；数据集名称信息量有限，用户请求寻找“潜在有趣的内部结构”。
- **Benchmark**：无对比基线，目标单纯检验系统能否在固定资源预算内自主改善一个无信息量的初始渲染视图。
- **设置**：初始渐进表示约 45×64×64，限制 12 轮 Explore-Plan-Act-Evaluate 循环，用户不介入中间过程，默认模型 GPT-5.4。
- **结果**：最终视图暴露了圆柱形内部特征，整个流程耗时 172 秒，约 94,000 tokens。早期若干等值面调整因节点未创建而失败，但智能体恢复并完成了任务。

#### 3.2 案例二：大规模资源感知访问延迟测量

- **数据集**：6 个科学数据集，覆盖断层扫描、大气模拟、显微 CT、显微镜、农业和材料科学。
- **方法**：测量从 1 MB 到 2 GB 不同请求大小的云检索与本地加载延迟；无对比方法，属特性测量。
- **结果**：1 MB 请求约 0.1-0.2 秒；256 MB 约 10-47 秒；2 GB 最高约 387 秒（2kbit1 显微 CT），neurons 和 sandstone 也超 200 秒。表明中小尺寸渐进表示支持闭环迭代探索，大请求会阻塞自主执行。

#### 3.3 自主探索工作流（5 个任务）

- **数据集**：amlan-tomography-1、4D_micro_CT_sandstones、Tomography、2kbit1、NASA DYAMOND Data。
- **设置**：每个流程单条自然语言目标，最多 12 轮迭代，无中间用户操作，使用视觉快照。
- **基准**：无基线，成功标准为：数据集加载成功、预定义任务全部执行、生成非空摘要且无用户中断。
- **结果**：5/5 全部成功；平均使用 7.8/12 轮；平均端到端约 108 秒；共提出 203 个动作，成功 175 个（86.2%），拒绝 28 个（13.8%，多为在创建可视化节点前修改参数）；智能体在各种失败后均恢复并完成任务。

### 6. 论文的主要结论与发现

- WebVisus 能实现从自然语言目标到数据发现、渐进式访问、迭代可视化探索的**端到端闭环**，即在无需用户干预中间可视化参数的情况下，对约 11 GiB 的远程体数据完成自主探索，展示出初始渲染中不明显的内部结构。
- 渐进式多分辨率访问是实现自主探索的关键使能条件：MB 级表示响应在亚秒级，适合多轮观察；超大请求会显著阻塞自主执行（2 GB 最高约 387 秒），因此**数据访问必须纳入智能体推理**——智能体需要同时考虑“什么信息有用”和“什么表示可在预算内安全处理”。
- 注册动作协议有效约束了智能体行为（13.8% 动作被拒绝），交互记录使过程可审计、可中断、可覆盖。失败动作不导致任务失败，智能体表现出恢复能力。
- 在五类数据集上 WebVisus 都能自主完成探索任务（86.2% 动作成功率，100% 任务完成率），支持了这一范式的可行性。

### 7. 优点

- **端到端完整性**：连接了此前割裂的“数据发现”与“已加载数据探索”两个环节，是首个展示从科学目标到多分辨率远程数据自主探索闭环的系统。
- **资源感知的渐进式访问**：明确将内存足迹估算（M(s) ≤ B）纳入智能体决策，双重服务器端检查（服务端内存、浏览器传输）兼具理论和工程意义；使约 11 GiB 的数据用 <0.2 秒的 MB 级请求实现可探索。
- **内建安全约束**：确定性命令注册/校验、禁止直接系统访问、完整交互记录——在自主性和可控性之间取得合理平衡，符合“人类监督下的自主科学”理念。
- **多模型与多数据支持**：可接入多种大模型后端，支持约 1,400 个数据集的动态扩展，具备较好的可迁移性。
- **失败恢复能力**：虽然早期动作因先决条件不足而失败，智能体能调整策略继续任务，这一鲁棒性在真实使用中非常重要。

### 8. 不足与局限

- **无科学正确性验证**：系统产出的是“探索性观察和候选结构”，尚无定量测量、特征检测、统计验证。论文明确说明这些观察需领域专家进一步验证，系统目前无法替代科学分析。
- **统计严谨性不足**：单案例深度学习分析 + 5 个工作流，无重复试验、无固定分辨率基线和自适应策略的对比、无消融实验；无法评估运行间变异性、策略收益的显著性，或各组件（目录智能体、资源策略、多模态观察）的独立贡献。
- **动作失败率偏高**：13.8% 的动作因前置条件不足被拒绝（如等值面节点尚未创建），虽可恢复但暴露了缺乏命令前置条件自动校验的机制。
- **延迟瓶颈**：大尺度数据请求（≥256 MB）延迟可达数十至数百秒，限制了更高分辨率探索的实际可用性；当前系统更多依赖“小请求多轮迭代”策略，对大区域精细探索支持有限。
- **评估偏差风险**：5 个 `Autonomous Explore` 工作流结果由系统自身生成的摘要作为成功判据（非空摘要），存在自我报告型的乐观偏差；且未设置用户研究来评估真实科研人员的体验和产出质量。
- **应用范围有限**：系统限制为“探索性导航和可视化”，不包含数据分析任务（如求导、统计聚合、时间序列比较等）；对非体积类数据（表格、图结构、点云）的扩展未涉及。
