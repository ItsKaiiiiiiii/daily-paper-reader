## 摘要
大语言模型智能体能够进行推理、调用工具并自主执行多步操作，但其智能体技能——正确排序工具、在依赖关系下规划、判断不可信输入以及为生成的论证提供依据——很难仅通过准确率排行榜来衡量。我们提出了BekchiAI，它同时解决了两方面问题：一个用于测量智能体技能的基准测试，以及一个用于观察和控制实时智能体的平台。BekchiAI-Benchmark包含13个使用工具的ReAct智能体，覆盖7个任务类别（算术、结构化/SQL、安全检测、URL依据、规划、编排和工具策略），总计2,057个确定性、承诺性测试任务。每个任务都可验证：黄金答案通过针对真实数据库运行规范SQL、计算有向无环图（DAG）的精确调度或评估闭式lambda（包括对抗性安全样本，并配以故意不完美的签名扫描器）来计算，因此得分反映模型自身的判断，而非复制先知。我们定义了一小组超越准确率的行为指标——工具调用遵循度、URL幻觉与来源匹配、每模型令牌成本——并报告了四个模型（Qwen3.7-Max、gemma-4-31B-it、gemma4:26b、gpt-oss-120b）的对比，其差异体现在各系列内部的分布而非总体表现。基准测试运行使用提供的评估脚本执行。BekchiAI-Platform是一个补充的基于Web的可观察性与控制层，用于部署的智能体，提供完整的令牌和延迟遥测以及远程运行终止功能。该基准测试、评估工具和平台均已公开发布。

## Abstract
Large language model agents reason, call tools, and act autonomously over many steps, but their agentic skills-correctly sequencing tools, planning under dependencies, judging untrusted inputs, and grounding generated arguments-are hard to measure with accuracy-only leaderboards. We present BekchiAI, which addresses both sides: a benchmark for measuring agentic skill and a platform for observing and controlling live agents. The BekchiAI-Benchmark, a suite of 13 tool-using ReAct agents across 7 task categories (arithmetic, structured/SQL, security detection, URL grounding, planning, orchestration, and tool-policy), totalling 2,057 deterministic, committed test tasks. Every task is verifier-checkable gold answers are computed by running canonical SQL against a real database, computing the exact schedule of a directed acyclic graph (DAG), or evaluating closed-form lambdas including adversarial security samples paired with deliberately imperfect signature scanners so a score reflects the model's own judgment, not the copying of an oracle. We define a small set of behavioral metrics beyond accuracy-tool-call adherence, URL hallucination and source-match, and per-model token cost and report a four-model comparison (Qwen3.7-Max, gemma-4-31B-it, gemma4:26b, gpt-oss-120b) whose story is in the per-family spread, not the aggregate. The benchmark runs are executed using the provided evaluation scripts. BekchiAI-Platform is a complementary web-based observability and control layer for deployed agents, providing full token and latency telemetry as well as remote run termination. The benchmark, evaluation tools, and platform are publicly released.

## 论文总结：BekchiAI：一键测量、观察与控制LLM智能体

### 1. 核心问题与整体含义（研究动机与背景）

- **研究背景**：大语言模型（LLM）正从单轮文本生成器转向**智能体（Agent）**，即能交错执行模型调用、工具使用、记忆存取和多步规划以在有限人工监督下追求目标。在软件工程（如SWE-bench）、网页导航（如Mind2Web、WebArena）和科学实验等领域，智能体已承担实际后果性操作。
- **核心问题**：传统准确率榜单无法有效衡量智能体的**agentic技能**——是否正确选择与排序工具、在依赖约束下规划、对不可信输入做出安全判断、以及为生成的参数（如URL）提供真实依据。具体缺陷有三：
  - 单一准确率混合了多种异质技能，难以定位能力短板。
  - 许多任务容易被模式匹配攻破，或通过"先知工具"泄漏答案，导致高分并不反映真实能力。
  - 准确率不能体现成本（token消耗），也无法支持运行期的观察与控制。
- **论文立场**：智能体承担真实行动（写代码、转账、调用外部服务）时，评估重点应从"模型有多流畅"转向"其智能体技能有多可靠"；同时需要一种兼顾能力、成本与安全判断的可复现评估体系。

### 2. 方法论：核心思想、关键技术细节

- **整体架构**：BekchiAI同时提供两部分——**基准测试（BekchiAI-Benchmark）** 用于测量智能体技能；**平台（BekchiAI-Platform）** 用于对部署的智能体进行实时遥测与控制。二者共享同一套事件流，使能力与成本从单次运行中同时获得。
- **基准设计**：13个使用工具的ReAct智能体（严格JSON动作循环），覆盖7个任务类别、共2,057个确定性、承诺性测试任务。每个智能体每回合输出一个JSON动作——工具调用或最终答案——由测试框架执行工具并回传结果，直到模型作答或步数耗尽。
- **三条防游戏化设计原则（关键）**：
  1. **验证器计算金标准**：正确性由独立验证器判定——规范化SQL在真实SQLite数据库上执行；编排任务的黄金答案是依赖DAG的按ASAP（as-soon-as-possible）层划分；算术任务对闭合形式lambda求值。金标准不会漂移，并设数值公差仅吸收格式噪声。
  2. **手工编写的对抗样本**：规划与编排场景使用非对称连接DAG、长空闲跨度依赖和图中部死胡同干扰项，需按传递可达性剪枝；URL依据任务为每个问题搭配不同真实主机，ug_imposter还含同形字/错拼域名陷阱（如examp1e.com）。
  3. **故意不完美的安全工具**：三个安全类别提供签名启发式扫描器，与真实标签的吻合率仅约40%–55%——既漏报混淆攻击，也对良性类此内容误报。模型盲目信任或反向推断都只能得到接近随机的分数，正确行为是读取工件内容并自行判断。这把本可能成为"先知"的工具转成真正的判断力测试。
- **共享工具库**：所有智能体调用同一个预构建工具库（算术、SQL、安全扫描、网页/URL、客户/财务、故障转移、记录创建），保证工具行为一致且可独立测试。
- **行为指标**：在准确率之外定义一组规范化指标——工具调用遵循度、URL幻觉率与来源匹配率、安全违规率/过度拒绝率、每模型的LLM调用数与token成本（精确度用Wilson 95%置信区间评估）。

### 3. 实验设计：数据集、Benchmark 与对比方法

- **数据构成**：13个任务族共2,057个承诺测试任务，以JSONL文件提交，内容确定性可完整复现。任务族规模从150到196个不等，具体如下：
  - 算术类：ar_math（154）、ar_multistep（152）——多步计算与常量查表+计算
  - 结构化/SQL：sql_analytics（157）——SQL联接与分组分析
  - 安全类：sec_sqli（154）、sec_context_poison（154）、sec_guard（151）——SQL注入判断、提示注入判断、LLM安全风险门控
  - URL依据类：ug_fetch（155）、ug_imposter（150）——参数生成与同形字抵抗
  - 规划类：dependency_planning（180）、multi_tool_planning（152）——依赖解析与多工具编排
  - 编排类：orchestrator（196）——DAG的最早可能调度
  - 工具策略类：tool_error_recovery（150）、tool_arguments（152）——故障转移策略与参数构造
- **对比模型**：四个模型在相同2,057个任务上评估——Qwen3.7-Max、gemma-4-31B-it、gemma4:26b、gpt-oss-120b。
- **无关设置**：任务约定（如SQL金额以整数分存、排除取消订单）在提示中给出，确保衡量的是底层技能而非猜测能力。

### 4. 资源与算力

- **论文未说明GPU型号、数量或训练时长**——因为该工作为评估而非训练，不涉及模型训练过程。
- **提供了运行期成本数据**：全部四个模型在2,057任务套件上各发出约7k–8k次LLM调用；token消耗差异明显：gemma-4-31B共10.12M（输入8.32M + 输出1.80M），gpt-oss-120b共8.81M，Qwen3.7-Max共5.83M，gemma4:26b最省（5.43M，其中输出仅0.82M）。
- **无需专门训练资源**：基准可作为现成脚本直接对商品化LLM API运行；平台以轻量SDK接入。

### 5. 实验数量与充分性

- **实验数量**：4个模型 × 13个任务族 × 2,057个任务 = 每个模型全套件一次完整评估，共产生四个完整能力画像；每个结果附带Wilson置信区间；另外从平台侧记录相同运行的调用与token统计。
- **任务覆盖**：7个类别各有150–196个测试，总样本量在不同家族间均匀；对二项比例而言，每族约150个样本足以给出有意义的置信区间（论文明确采用Wilson区间以处理小样本）。
- **充分性评估**：
  - **优点**：覆盖了能力（逐族准确率）、行为（工具遵循、URL依据）与成本（token）三个维度；每族样本均等，四个模型放在同一测试集上，公平性较好。
  - **不足**：每模型只跑一次、无多次运行取均值或方差报告；无温度/解码参数说明；无消融实验（如去掉对抗样本或换成完美扫描器的影响）；四个模型覆盖有限，缺乏更大规模模型家族的系统对比。

### 6. 主要结论与发现

- **排序信号应看族内分布而非总分**：整体为 Qwen3.7-Max（0.88）> gemma-4-31B（0.86）> gemma4:26b（0.82）> gpt-oss-120b（0.71），但前两名差距仅2个百分点，且无模型在所有族占优。
- **gpt-oss-120b 是反转型离群点**：它在两个URL依据族均排第一（ug_fetch 0.78，其他模型0.43–0.53；ug_imposter 0.89），但在结构化/多步工具族严重塌陷（sql_analytics 0.24、tool_error_recovery 0.25、multi_tool_planning 0.44）——总分完全掩盖了这一画像。
- **工具/结构化族分辨力最强**：sql_analytics 跨模型跨度 0.24–0.87、tool_error_recovery 0.25–0.76、multi_tool_planning 0.44–0.96，单一族可将四个模型拉开超过60个百分点。
- **部分族已饱和**：sec_sqli 0.94–0.99，主要起健全性校验作用而非排序信号。
- **能力与成本需同时权衡**：gemma-4-31B 与 gpt-oss-120b 消耗最多token却未领先准确率；gemma4:26b 最省；gpt-oss-120b 用8.8M token换取最低准确率。最准的模型不是最省的。

### 7. 优点

- **防游戏化的金标准设计**：验证器（真SQL执行、DAG调度、闭式lambda）使答案可精确复算、不可漂移；这是与多数依赖人工标注或易泄漏榜单的显著区别。
- **安全族的创新设计**：用"故意不完美扫描器"取代完美oracle，将测试从"模型能否复述工具结论"转为"模型能否独立判断"——是方法论上的亮点。
- **手工编写的对抗样本**：同形字URL、深度依赖DAG、图中部干扰项等由人工逐一编写，非模板生成，提高了基准的难度真实度。
- **单流读出能力与成本**：平台在基准运行中即插即用，token/延迟/能力指标出自同一次运行，无需额外实验。
- **行为指标维度丰富**：准确率之外加入工具遵循、URL幻觉与来源匹配、过度拒绝率等，反映实际部署关注点。
- **平台提供运行期控制**：停止/暂停/恢复/撤销的远程开关、策略强制执行、grounding与计划vs实际一致性分析，是多数基准不具备的应用层能力。
- **可复现性**：测试集、工具库、评估脚本与平台全部公开。

### 8. 不足与局限

- **模型覆盖面有限**：仅4个模型，且无同一系列的规模扫描（如不同参数量版），难以推断扩展规律；更无开源权重模型在本地环境中的验证。
- **无多次运行与方差报告**：每模型每族仅单次运行，未报告温度、重复运行方差或解码策略，结果的稳定性缺乏保障。
- **缺少数值消融**：未实验"完美扫描器vs不完美扫描器""有对抗样本vs无对抗样本"等消融对比，难以量化各设计要素的贡献。
- **任务粒度单一**：基准为单回合任务，未覆盖长时程多回合交互、状态持续型智能体或真实环境反馈循环——论文自己在结论中亦承认此点。
- **平台控制为协作式**：若智能体无法访问控制通道（网络故障、恶意劫持），远程终止将失效；平台不能防御离线或拒绝通信的智能体。
- **成本与延迟数据与API绑定**：token成本按模型API给出，随供应商定价变化，基准本身不计算货币成本，横向比较可能随时间失真。
- **安全扫描器数据未公开细节**：40%–55%吻合率的具体判定规则未详述，第三方难以审计扫描器行为是否引入对特定模型的偏见。
