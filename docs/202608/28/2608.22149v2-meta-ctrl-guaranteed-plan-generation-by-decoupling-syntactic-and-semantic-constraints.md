## 摘要
大型语言模型（LLM）能为机器人生成流畅的计划，但常常违反执行时必须满足的句法和语义约束，而现有的补救措施在形式化保证与计划质量之间进行权衡：软性方法（如可行性评分、接地解码）不提供任何保证，而符号规划器（如LLM+P）则丢弃了语言模型的常识。我们提出了Meta-Ctrl，一种约束解码框架，它在保证编码约束的同时保持基础语言模型的计划质量。Meta-Ctrl引入了元令牌（meta-tokens）——一个紧凑的基础动作词汇表——在令牌级别强制执行句法，在动作级别强制执行语义（前提条件、目标、顺序），这种精确分解将约束解码的内存从超过107TB削减到2GB以下。借助该框架，一个小的开放权重语言模型在原本排名垫底的场景中变得具有竞争力：在LoTa-Bench协议下的WAH-NL任务中，它达到了报告的最高子目标成功率，超过了GPT-4，并在具身智能体接口（Embodied Agent Interface）上获得一致的提升。我们还在真实的桌面机器人上进行了进一步演示，其中每个生成的计划都通过构造满足其前提条件和目标。

## Abstract
LLMs generate fluent plans for robots but routinely violate the syntactic and se8mantic constraints they must satisfy to execute, and existing remedies trade formal guarantees against plan quality: soft methods (affordance scoring, grounded decoding) give no guarantee, while symbolic planners (LLM+P) discard the LM's commonsense. We propose \textbf{Meta-Ctrl}, a constrained-decoding framework that guarantees the encoded constraints while preserving the base LM's plan quality. Meta-Ctrl introduces \emph{meta-tokens}---a compact vocabulary of grounded actions---enforcing syntax at the token level and semantics (preconditions, goals, ordering) at the action level, an exact factorization that cuts the memory of constrained decoding from over 107TB to under 2GB. With it, a small open-weight LM becomes competitive where it otherwise sits at the bottom of the leaderboard: on WAH-NL under the LoTa-Bench protocol it reaches the highest reported subgoal success rate, exceeding GPT-4's, with consistent gains across the Embodied Agent Interface. We further demonstrate it on a real tabletop robot, where every generated plan satisfies its preconditions and goals by construction.

## 1. 核心问题与研究动机

- **背景**：LLM 在为机器人生成自然语言指令对应的动作计划时，虽然输出流畅，却频繁违反执行所必需的**句法约束**（动作名字非法、参数结构错误、格式错误）和**语义约束**（行为物理不可行或违反目标，如未抓取就放置、跳过必要前置条件、容器未打开就放入）。
- **现有方法的权衡困境**：
  - **软性方法**（affordance scoring、grounded decoding、replanning）：通过可行性分数重塑 LLM 输出分布，但指导是"软"的，无法保证不产生不可行输出；重规划无终止保证且成本累积。
  - **符号规划器**（如 LLM+P）：将规划交给 PDDL 求解器，可保证有效性，但放弃 LLM 的常识与灵活性，需要完整领域规范。
  - **文法约束解码（GCD）**：通过逐 token 掩码保证语法，但掩码是局部的，可能严重扭曲 LM 分布，产生"合法但不自然"的输出；且难以扩展到语义约束（依赖演化中的世界状态）。
- **核心研究问题**：能否同时获得**形式化约束保证**与**高质量（保持 LM 常识）的计划**，且计算开销可承受？

## 2. 方法论：Meta-Ctrl

### 核心思想
通过引入**元令牌（meta-tokens）**将约束强制执行**分解到两个粒度**：
- **token 级**：句法约束（合法动作名、参数结构、JSON 格式）；
- **动作级**：语义约束（前提条件、目标达成、时序顺序）。

这种分解是**精确的**，将联合约束分解为两个独立的子问题，避免了在 token 级构造联合 DFA 所产生的乘积状态爆炸。

### 关键技术细节
1. **基础框架 Ctrl-G**：约束解码被建模为概率推理——`p(xt | x<t, α) ∝ pLM(xt | x<t) · pHMM(α | x≤t)`，其中 `pHMM(α | x≤t)` 是用 HMM 后向动态规划可解的前瞻项，保证约束满足（不满足则概率为 0），同时用概率而非硬掩码保留自然性。

2. **两层分解**：
   - **Level 1（token 级语法）**：用 token 级 DFA `Dγ` 直接应用 Ctrl-G，消除畸形输出。
   - **Level 2（动作级语义）**：定义元令牌词汇表 `W`（每个元令牌是一个接地动作，如 `OPEN(dishwasher)`），用解析器 `τ` 将 token 序列投影到动作序列；语义约束 `β` 定义为元令牌上的 DFA，追踪世界状态（哪些动作已发生、前提是否成立、目标是否已达成）。

3. **精确分解公式**（假设 `τ` 在语法支持集上是双射）：
   `p(α | x≤t) = Σ_al p(al | x≤t) · p(γ | x≤t, al) · pmeta(β | a≤l)`
   三个因子分别对应：**桥接项**（当前部分 token 序列到候选动作的映射）、**句法项**（token 级）、**语义项**（动作级）。分解无额外假设，是精确的。

4. **效率收益**：联合 DFA 状态数 ~3.5 亿（350M），需 107 TB 内存；两层级分解后状态数 ~5.7 万（57K），内存降至 1.6 GB。计算加速 ~1,900 倍，内存降低 ~67,000 倍。

5. **HMM 训练**：token 级 HMM 每个基础 LM 一个（共享）；元令牌 HMM 每个模块类型一个（如 Action Sequencing 共享 132 符号的 HMM，Subgoal Decomposition 共享 123 符号的 HMM）。训练数据来自无约束基础 LM 生成（与评估实例不重叠），最多 100 万条/对，温度 0.1 / top-p 0.95 / 长度上限 2048，解析失败则丢弃。

## 6. 主要结论与发现

1. **约束解码能同时实现保证与质量**：Meta-Ctrl 在保证所有输出满足编码约束的前提下，将 Llama 3 8B 从 EAI 排行榜末尾（VH AS 21.3%）提升至榜首水平（90.4%），超过 GPT-4o、Claude 3.5 Sonnet、o1-preview 等大一个数量级的模型。

2. **语义控制是关键增益来源**：WAH-NL 上，仅语法控制将 SSR 提高 1.5 个点、Exec 不变（0.010）；添加语义控制后 SSR 再提升 66.8 个点、Exec 达到 1.000，任务成功率 0 → 0.47。

3. **执行成功率与任务成功率的分离**：Meta-Ctrl 将执行率提升至接近 100%（如 VH AS 97.7%，BEH AS 89%），但 BEHAVIOR 任务成功率受限于提示词中可编码前提条件的比例（VH 82% vs BEH 24%），说明方法收益取决于约束能否从提示词中显式化。

4. **硬掩码会崩溃**：仅语法掩码 + 贪婪解码导致任务成功率崩至 1.4%（VH AS），因 LM 倾向最短合法续写；概率前瞻（而非可达性掩码）是质量来源。

5. **LM 与自动机都承担负载**：无 LM 的自动机搜索已达 83.8%（VH AS）；LM 额外贡献 +6.9 点（VH AS）和 +16 点（VH SD），且经典规划器（信息更全）在 BEH AS 仅 13/37，说明"约束编码"优于"世界建模"的优雅降级。

6. **跨模型零训练迁移成立**：新 tokenizer 模型（Qwen3-8B、Gemma-3-12B-it）在 VH AS 上复现完全相同的任务/执行成功率（90.7/97.7）。

## 7. 优点与亮点

- **方法创新**：将约束解码从"token 级单粒度"提升为"token/动作双粒度精确分解"，使语义约束变得可负担——这是将 Ctrl-G 从语法扩展到语义的关键桥梁。
- **可证明的保证**：句法与语义均为 DFA 可表达时，保证是构造性的（by construction），且 LM-fault 错误率在所有模块上为零（附录 H 逐模块验证）。
- **高效**：1,900 倍计算加速、67,000 倍内存缩减，解码速度与无约束生成持平，实用性强。
- **系统化消融**：逐层剥离（约束 / 掩码 / 均匀 / 训练代理 / 无 LM 搜索 / 完整 PDDL 规划器），清晰归因各组件贡献，并诚实报告训练代理的偏差。
- **多维度验证**：仿真（两个模拟器 × 两个模块）、跨基准（WAH-NL）、真实机器人、跨 tokenizer 迁移、近期模型扩展对比，覆盖全面。
- **诚实与透明度**：明确报告 benchmark-side 评估器缺陷导致的残差、BEHAVIOR 先验拒绝 17% 黄金计划的过度约束，以及 HMM 语料对稀有动作的覆盖缺陷。

## 8. 不足与局限

- **DFA 表达性限制**：约束必须是 DFA 可表达的；需要无界记忆的约束（如连续量的任意算术）不适用。语义 DFA 针对任务族手工构建，需要结构化规范（模拟器谓词 + BEHAVIOR 公共 BDDL 分类）。
- **提示词内容决定上限**：BEHAVIOR 任务提示不暴露对象可操作性，DFA 只能编码 24% 前提条件，导致任务成功率提升有限——方法增益高度依赖规范的可获得性。
- **过度约束风险**：固定先验拒绝 17% 黄金 BEHAVIOR 计划，不可行任务只能回退到仅语法解码，这为可达到的任务成功率设定了独立于基础 LM 的上限。
- **真实系统保证的相对性**：自动机从感知估计状态初始化，保证是相对于"机器人相信的状态"而非真实状态；规划保证不覆盖感知与抓取失败（真实机器人端到端成功率受限于下游）。
- **训练代理偏差**：对训练语料中罕见的必要动作（SLEEP、PLUG IN）赋予近零质量，可能惩罚约束本应强制执行的步骤；uniform 代理无此问题但损失了部分执行率。
- **算力报告不完整**：未报告 HMM 训练的具体 GPU 配置与时长，难以完整评估端到端训练成本。
- **HMM 共享粒度有限**：目前按模块类型各训练一个元令牌 HMM，跨模块类型与跨基础模型的单一代理仍留作未来工作。
