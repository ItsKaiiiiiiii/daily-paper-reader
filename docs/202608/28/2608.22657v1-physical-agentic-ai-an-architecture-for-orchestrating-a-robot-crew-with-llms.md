## 摘要
智能体AI框架解读开放式任务目标并将其分解为多步计划。关于具身特定能力、物理前置条件和跨机器人协调的更丰富信息改善了接地性，但并未消除不可行、时机不当或不安全的物理动作。因此，物理机器人团队需要在语义规划与执行之间设置一个明确的架构接口，在该接口中，每个规划动作在驱动前都必须针对机器人能力、系统状态和工作流约束进行验证。本文提出了物理智能体AI（Physical Agentic AI），一种基于技能接地的机器人智能体编排框架，其中每个机器人暴露一个可执行技能的类型化库，而基础模型规划器将任务分解为多个阶段，并将每个阶段分配给一个机器人-技能对。机器人编排层（Robot Orchestration layer）将技能库、机器人状态、命名位置和工作流契约暴露给非驱动式任务规划器（Mission Planner），而确定性机器人编排器（Robot Orchestrator）每次验证并授权一个技能。我们在无人机-地面机器人搜索与派遣任务上进行了评估，其中每种条件下的每个任务都在Gazebo中实时执行，并在人形-四足运输任务上使用了硬件等效技能接口以及Unitree G1和Go2上的两次物理试验。我们独立改变规划器知识和运行时强制执行，发现检索将技能接地率从51%提升到96%，但仍使知情规划器派发了23-29%的故障步骤。每次派发强制执行将错误派发降至0%，且没有错误阻塞，并且保留计划消融证实了门控而非规划变化是原因。实时执行使差异具体化：没有强制执行时，所有八个注入故障都越过了编排边界，其中六个产生了机器人运动；有强制执行时，所有八个在运动前被拒绝。

## Abstract
Agentic AI frameworks interpret open-ended task goals and decompose them into multi-step plans. Richer information about embodiment-specific capabilities, physical preconditions, and cross-robot coordination improves grounding, but does not eliminate infeasible, mistimed, or unsafe physical actions. Physical robot crews therefore require an explicit architectural interface between semantic planning and execution, where every planned action is verified against robot capabilities, system state, and workflow constraints before actuation. This paper introduces Physical Agentic AI, a framework for skill-grounded robot agent orchestration, in which each robot exposes a typed library of executable skills while a foundation model planner decomposes a task into phases and assigns each phase to a robot-skill pair. A Robot Orchestration layer exposes the skill library, robot state, named locations, and workflow contracts to a non-actuating Mission Planner, while a deterministic Robot Orchestrator validates and authorizes one skill at a time. We evaluate on a drone-UGV search-and-dispatch mission, where every mission in every condition is executed live in Gazebo, and on a humanoid-quadruped transportation task using hardware-equivalent skill interfaces plus two physical trials on a Unitree G1 and Go2. Varying planner knowledge and runtime enforcement independently, we find that retrieval raises skill grounding from 51% to 96% yet leaves informed planners dispatching 23-29% of faulted steps. Per-dispatch enforcement reduces false dispatch to 0% with no false blocks, and a held-plan ablation confirms that the gate, not plan variation, is responsible. Live execution makes the difference physical: without enforcement all eight injected faults crossed the orchestration boundary and six produced robot motion; with enforcement all eight were refused before motion.

## 2. 方法论体系

### 2.1 核心设计原则

- **推理与执行分离**：基础模型负责自然语言理解与任务分解；确定性运行时负责物理执行授权，二者权力完全分开。
- **技能接地规划（Skill-grounded Planning）**：规划器只能基于机器人暴露的已实现技能库推理，不能生成任意动作或低级控制指令。
- **契约中介协调（Contract-mediated Coordination）**：多机器人工作流用可声明、可执行的工作流契约编码排序约束、同步点和资源依赖，独立于语言模型。
- **执行时验证（Execution-time Verification）**：每个技能在执行前必须通过工作流契约与当前机器人状态的即时验证。

### 2.2 四大架构组件

| 组件 | 角色 | 关键特性 |
|------|------|----------|
| **机器人技能库** | 每个机器人暴露类型化的可执行技能集合 | 技能包含参数、前置条件、预期效果、成本、同步需求 |
| **Mission Planner** | 非驱动式基础模型规划器 | 将任务分解为阶段，选择机器人-技能对；不直接连接任何机器人控制器 |
| **工作流契约** | 声明式协调约束规范 | 规定角色、技能、有序约束、参数有效性规则、运行时绑定值 |
| **Robot Orchestrator (RO)** | 确定性过程式运行时 | 持有唯一驱动权威，逐动作检查并授权 |

### 2.3 规划与执行协议

- 规划器产出结构化计划：**π = {(ϕ₁, r₁, κ₁), ..., (ϕ_T, r_T, κ_T)}**，每个步骤将阶段ϕ与机器人r及其技能κ配对。
- 执行流程五阶段：检索上下文 → LLM规划 → 全局验证（失败允许一次replan）→ 逐动作授权执行 → 终止与失败上报。
- 每次派发前RO的**五项检查**：
  1. 技能在目标机器人上是否存在；
  2. 参数是否有效且满足**请求包含性（request containment）**——不允许把用户指定的目标偷偷替换为其他已注册值来"凑合"；
  3. 该步骤是否为工作流契约中下一步合法转换；
  4. 当前机器人状态是否满足技能与契约前置条件；
  5. **运行时绑定值**（如另一台机器人在执行中产生的目标坐标）是否已就绪且有效。

### 2.4 对动态信息的处理（核心技术细节）

- 某些执行关键事实在规划时**尚不存在**（如无人机的探测结果），不能靠检索解决，必须作为**有状态绑定值**在执行时解析。
- 例如：`navigate_to(target="victim")`——"victim"是一个符号绑定，RO派发时查询状态接口获取实际坐标；若无有效发布值则拒绝派发（`no_target_fix`）。

## 6. 主要结论与发现

- **结论一：接地与安全是可分离的机制**——技能接地是**检索问题**，派发安全是**执行强制问题**，二者不可互相替代。
  - 检索将接地率从51%提升至96%；但一旦知识饱和，非强制臂仍有23%的故障步骤被实际派发，且对故障注入的拦截率（recall）为0%。
  - RO将错误派发降至0%（p=5.0×10⁻⁴），故障拦截率100%、精确率100%、无误拦。
- **结论二：感知类故障必须由运行时状态接口拦截**——传送NaN损坏坐标时，未强制的LLM会"脑补"出合理坐标并危险地派发地面车；RO通过状态接口绑定解析，拒绝不可解析目标，关闭了**结构化通道旁路**。
- **结论三：检索会引发替换式失败（retrieval-induced substitution）**——上下文越丰富，规划器的失败模式从可检测的幻觉（发明不存在的技能）转变为"看似合理但错误的位置替换"，后者能通过静态名级检查但违反用户意图。RO通过**请求包含性检查**拦截此类错误。
- **实时执行的意义**：无强制时所有8个注入故障越过了编排边界，其中6个实际产生了机器人运动；有强制时8个全部在运动发生前被拒绝。
- **最终主张**：语言模型可以改善计划质量，但**不应持有执行权威**——该权威必须属于运行时系统。

## 7. 优点

- **架构设计清晰有力**：将"知识"与"权力"分离是洞见性的——不是简单强调约束的重要性，而是用受控实验证明"给模型更多信息"与"限制模型权力"是两种不可替代的机制。
- **实验分离度极高**：四条件设计在保证其他因素完全一致的前提下精确隔离变量；且全部实时执行使"错误派发"是真实的物理/仿真动作而非字符串判定，可信度远高于仅做静态计划验证的同类工作。
- **同一架构跨仿真与真实硬件复用**：从Gazebo到G1/Go2仅替换技能库、契约与适配器，规划器和契约层完全不变，验证了架构在异构团队中的可迁移性。
- **识别了新颖的失败模式**：检索诱导替换（substitution）是现有文献较少系统性讨论的现象，对评测和防护设计有参考价值。
- **对感知故障的处理有启发性**：将运行时才存在的信息建模为"有状态绑定值"，由确定性层而非LLM解析，是应对跨机器人感知依赖的正确思路。
- **诚信度高**：对硬件试验结论的统计力度自认局限，避免过度声称。

- **硬件验证样本量极小**：仅2次真实试验，且是定性演示性质，无法支撑关于物理世界泛化的强结论；作者也自认此局限。
