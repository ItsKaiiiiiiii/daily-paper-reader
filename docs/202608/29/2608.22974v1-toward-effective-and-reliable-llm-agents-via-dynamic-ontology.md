## 摘要
大型语言模型（LLM）智能体严重依赖模型参数中编码的知识或作为非结构化上下文呈现的知识。在特定领域任务中，这导致重要的语义连接隐含化，常常造成证据使用不完整和多步决策脆弱。本体提供了一种将领域概念和关系外部化为机器可解释结构的方法，但传统上构建任务可用的本体需要领域专家的大量投入，且难以扩展。自动构建也面临挑战：看似语义合理的本体可能不包含实际决策所需的关系结构。我们提出OaK，一个以本体为核心框架的框架，为LLM智能体动态构建和细化面向任务的本体。给定任务需求和训练数据，OaK构建本体及其知识图谱，生成用于图推理的任务自适应函数，并使用评判反馈迭代优化两者。通过使相关概念和关系显式化，本体为知识检索和多步决策提供基础。我们在TravelPlanner、CRMArenaPro和ToolQA上评估OaK。结果表明，OaK改进了标准LLM智能体，增强了证据基础，并提高了多步推理的可靠性。

## Abstract
Large language model (LLM) agents rely heavily on knowledge encoded in model parameters or presented as unstructured context. In domain-specific tasks, this leaves important semantic connections implicit. This often results in incomplete evidence use and brittle multi-step decisions. Ontologies offer a way to externalize domain concepts and relations as machine-interpretable structures, but constructing task-usable ontologies traditionally requires substantial effort from domain experts and is difficult to scale. Automatic construction is also challenging: an ontology that appears semantically plausible may not contain the relational structures needed for actual decision making. We present OaK, an ontology-as-a-kernel framework that dynamically constructs and refines task-oriented ontologies for LLM agents. Given task requirements and training data, OaK constructs an ontology and its knowledge graph, generates task-adaptation functions for graph reasoning, and uses judge feedback to iteratively refine both. By making relevant concepts and relations explicit, the ontology grounds knowledge retrieval and multi-step decision making. We evaluate OaK on TravelPlanner, CRMArenaPro, and ToolQA. Results show that OaK improves standard LLM agents, strengthens evidence grounding, and boosts the reliability of multi-step reasoning.

## 2. 论文提出的方法论

**核心思想：**
- OaK 将本体定义为二元组 **K = (S, F)**：
  - **S**：任务导向的 schema，定义领域概念（实体类型）、属性、关系及其约束。
  - **F**：类型化推理函数集合，定义如何通过可执行过程（检索、过滤、遍历、投影、聚合、多步推理）使用 schema 中的类型化元素。
- 给定 schema S 后，OaK 从任务数据中实例化一个 schema 约束的知识图谱 G，作为函数执行所依据的证据底物。

**关键技术细节——两阶段流程：**

1. **构建阶段（Construction Stage）**：在训练数据上运行一个四步循环：
   - **Step 1：Schema 构建**。分为需求分析（LLM 读取任务描述与采样数据产生需求规格 R）、Schema 起草（基于 R 与上一轮反馈生成 schema）、形式化验证（将轻量级 YAML/JSON schema 编码为 OWL 本体并使用 HermiT 推理机检查一致性和可满足性，涵盖不交性、限制、属性逻辑、全局一致性、不可满足类五类逻辑有效性检查）。
   - **Step 2：知识图谱实例化**。基于当前 schema，对参考语料做 chunk–map–merge 流水线抽取，得到知识图谱。合并操作依赖 schema 声明的主键签名 κ(e) = (τ(e), πpk(e)) 来消解跨 chunk 的重复实体。
   - **Step 3：知识推理（函数组合）**。从通用算子库 O 中组合出任务适配的推理函数集合 F。函数通过对多个算子的流水线组合、算子特化或参数重解释、轻量预处理/后处理三种方式实现，并在图上做可执行性验证。
   - **Step 4：本体评估**。先用数据集的官方评估协议打分，再用评判模型对所有产物（schema、图、函数、轨迹、分数）给出结构化修复建议 ψt（包含 add/delete/modify 动作及诊断原因），分别反馈到下一轮的 schema 或函数构建中。循环最多 5 轮。

2. **推理阶段（Inference Stage）**：
   - 冻结最终 schema S* 和函数集 F*，对每条测试查询 q 构建其专属推理图 Gq = Build(S*, Cq)，再让 ReAct 智能体调用 F* 作为工具求解答案。
   - 该内核是智能体接触数据的唯一通道——它不能引用内核未声明的概念或调用未声明的计算。

## 3. 实验设计

**数据集 / Benchmark（共 3 个，覆盖互补任务类型）：**
- **TravelPlanner**：多日行程规划，要求同时协调交通、餐饮、景点、住宿和预算。评估指标包括常识约束（CS）和硬约束（HC）的 Micro/Macro 通过率，Final 通过率要求 CS 与 HC 全满足。
- **CRMArenaPro**：CRM 工作流执行，覆盖 B2B 和 B2C 两类组织。包含 Workflow、Policy、Text、Database 四类子任务，采用精确匹配与 token-level F1。
- **ToolQA**：跨异构语料的组合式工具使用，涉及 Flight、Coffee、Airbnb、DBLP、Yelp 五个子集，使用归一化精确匹配。

**对比方法：**
- **ReAct**（基础范式）
- **AFlow**（自动智能体工作流搜索）
- **MemP**（可复用程序性记忆）
- **ReCode**（递归程序化计划与行动）
- **AgentSquare**（模块化设计空间的自动搜索）
- **OaK**（本文方法，完整版及消融变体）

**实现要点：**
- 两个 LLM 骨干：DeepSeek-v4-flash 和 gpt-4o-mini。
- 本体评估器固定为 claude-sonnet-4.6。
- 每轮构建从训练集随机抽取 20% 样本，循环最多 5 轮；ReAct 智能体每查询最多 20 步。

**消融实验：**
- w/o Function Composition：移除函数组合，直接暴露通用算子库给智能体。
- w/o Function Module：移除整个函数集，让 LLM 直接在完整图上推理。
- w/o Iterative Refinement：只执行第一轮构建，不做后续迭代。
