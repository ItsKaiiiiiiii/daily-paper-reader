## 摘要
长时程网络代理往往在最终失败之前就已经偏离轨道：即使在当前状态、复用技能或计划假设不再支持用户指令的情况下，轨迹仍可能保持局部合理。现有代理能够进行规划、反思或复用经验，但其计划很少明确说明在何种证据下活动步骤仍应被信任。我们提出FCPAgent，一种用于鲁棒长时程网络代理的可证伪承诺规划框架。FCPAgent将每个计划步骤表示为一个可证伪承诺单元（FCU）：一个基于可复用技能的子目标，同时包含确认证据、证伪证据和置信度得分。执行过程组织为计划-测试-修复循环。混合承诺测试模块在候选动作修改浏览器之前对其进行检查，并在执行后检查观察结果；为提高效率，它结合了轻量级证据匹配与基于LLM的诊断验证。当证据证伪承诺时，范围感知修复将矛盾定位到执行、技能或规划层面，并修正最小的充分部分。在WebArena上，FCPAgent相比最强基线实现了平均成功率13.8%的相对提升，在长时程任务上尤其取得了大幅增益。

## Abstract
Long-horizon web agents often go off track before final failure: a trajectory can remain locally plausible even after the current state, reused skill, or plan assumption no longer supports the user instruction. Existing agents can plan, reflect, or reuse experience, but their plans rarely specify the evidence under which an active step should still be trusted. We propose FCPAgent, a falsifiable commitment planning framework for robust long-horizon web agents. FCPAgent represents each plan step as a Falsifiable Commitment Unit (FCU): a subgoal grounded in a reusable skill, together with confirming evidence, falsifying evidence, and a confidence score. Execution is organized as a plan-test-repair loop. The hybrid commitment testing module checks candidate actions before they modify the browser and checks observations after execution; for efficiency, it combines lightweight evidence matching with LLM-based diagnostic verification. When evidence falsifies a commitment, scope-aware repair localizes the contradiction to the execution, skill, or planning level and revises the smallest adequate part. On WebArena, FCPAgent achieves a 13.8% relative improvement in average success over the strongest baseline, with especially large gains on long-horizon tasks.

### 1. 核心问题与整体含义（研究动机与背景）

- **问题背景**：长时程（Long-horizon）网络代理在真实 Web 任务中面临一个关键挑战——**偏离轨道（off-track）执行**。代理在执行过程中，即使当前状态、复用技能或计划假设已不再支持用户指令，其轨迹在局部上仍可能看起来合理（例如，点击的页面标签与任务语义相关），从而持续在错误的路径上推进，直到最终失败才暴露问题。
- **核心矛盾**：最终任务反馈（success validator）是延迟且稀疏的，代理缺少一种**运行时的中间有效边界**，无法区分"可接受的执行偏差"与"有意义的轨迹漂移"。
- **现有方法不足**：已有方法（如 ReAct、Reflexion、WebDART、ColorBrowserAgent、SkillTracer 等）虽具备规划、反思、动态重规划或技能复用能力，但其计划步骤通常**未被构造成可测试的对象**，缺乏显式的有效性条件——即未指明"什么证据表明步骤仍然有效"以及"什么观察结果应使代理停止信任当前路径"。
- **核心主张**：稳定的长时程 Web 代理需要"知道自己何时出错"的计划。受认知科学中目标导向行为理论（TOTE：Test–Operate–Test–Exit）启发，论文提出将每个计划步骤视为一种**可证伪承诺（Falsifiable Commitment）**——一个关于"计划仍然有效、执行仍在任务支持路径上前进"的假设，并对其进行在线测试与修正。

### 2. 提出的方法论：核心思想、关键技术细节

**（1）核心概念：可证伪承诺单元（Falsifiable Commitment Unit, FCU）**

- 每个计划步骤被形式化为一个四元组：**cᵢ = (gᵢ, sᵢ, E⁺ᵢ, E⁻ᵢ, κᵢ)**
  - **gᵢ**：当前子目标（subgoal）
  - **sᵢ**：可选的链接可复用技能（linked skill）
  - **E⁺ᵢ**：确认证据（confirming evidence），按阶段组织为前置条件证据、进展证据、完成证据
  - **E⁻ᵢ**：证伪证据（falsifying evidence），按层级组织为执行级、技能级、规划级证伪条件
  - **κᵢ**：承诺置信度（confidence score），用于校准测试灵敏度
- 一个 FCU 表示一个**临时性、可测试的断言**：在当前执行阶段，追求 gᵢ（可选地通过技能 sᵢ）仍然适当。运行原则为：证据支持则继续（proceed），证据证伪则修复（repair）。

**（2）框架总体流程：计划-测试-修复（Plan-Test-Repair）循环**

- **可证伪承诺生成（Falsifiable Commitment Generation）**：
  - 从成功训练轨迹蒸馏出**技能库（skill library）S**，从失败/修复轨迹蒸馏出**失败-修复库（failure-repair library）F**，二者离线构建、测试期固定。
  - 给定任务查询 q 和初始观察 o₀，检索相关技能 S_q ⊆ S 和失败记忆 F_q ⊆ F，由 Planner LLM 生成紧凑的承诺序列 C = (c₁, ..., c_m)。
  - 技能提供"应如何工作"的程序性先验；失败记忆提供"什么会使承诺可疑"的已知风险护栏。
- **运行时混合承诺测试（Runtime Commitment Testing）**：
  - **轻量级动作级与状态级测试（Fast Tester）**：基于规则异常检查 + 双模态证据匹配分数 α±ₜ = λ·NLI(Tₜ, E±ᵢ) + (1−λ)·ITM(Iₜ, E±ᵢ)，其中 λ 平衡文本蕴含（nli-deberta-v3-base）与图像-文本匹配（SigLIP2）。根据阈值路由为 continue / complete / risk / verify。
  - **LLM 诊断验证（Slow Verifier）**：仅在完成类、高风险或模糊状态被路由时调用。结合任务、活动 FCU、近期轨迹和轻量测试信号，返回决策 dₜ ∈ {continue, advance, repair} 及诊断 uₜ（含证伪模式与范围）。
- **范围感知承诺修复（Scope-Aware Commitment Repair）**：
  - 根据诊断 uₜ 确定修复范围：执行级（保留 cᵢ，修正即时动作或路径）、技能级（保留 gᵢ，替换 sᵢ并更新证据）、规划级（重写 cᵢ 及受影响后缀）。
  - 检索失败-修复库中的相关案例作为软指导，保留未受影响的已完成前缀。
  - 修复范围由诊断的证伪者类型决定，恢复深度由状态严重性（是否回溯到安全状态）决定。

**（3）效率设计**：轻量测试器仅占运行总成本 2.4%，慢速 LLM 验证占 43.1%；混合测试相比纯慢速验证在 Shopping 和 Admin 上将每任务 LLM 调用时间从 464.5s 降至 374.0s（降低 19.5%），同时不牺牲成功率。

### 6. 主要结论与发现

- **主结果**：FCPAgent 在 WebArena 上将平均成功率从最强基线（ColorBrowserAgent）的 57.4% 提升至 65.3%，相对提升 13.8%；在各域均有增益（Cross 域相对提升达 23.0%，GitLab 达 19.1%）。
- **零样本泛化**：在 WebChoreArena 上，FCPAgent 在全部 4 个域均排名第一，加权平均 31.7% vs 基线 28.9%（相对提升 9.6%），验证了跨基准的迁移能力。
- **长时程价值**：任务越长增益越大——Shopping 域 11 步以上任务相对提升 161%，GitLab 长任务提升 87%（远高于中长度任务的 13%）。这直接支持"可证伪承诺在长时程中最有价值"的核心假设。
- **组件互补性**：消融显示可证伪规划（去除后平均降 6.2 个百分点）、承诺测试（降 3.2）、承诺修复（降 2.0）三组件各有不可替代的贡献。
- **证伪证据最关键**：细粒度消融中，去除证伪证据导致最大降幅（68.2%→63.2%），验证了显式指定"何时应停止信任当前路径"的核心价值。
- **状态级测试比动作级测试更具召回率**：状态级慢速调用中 10-17% 诊断为漂移，而动作级仅 6-8%；但二者互补——状态级提供高召回，动作级提供预防性护栏。
- **经验可扩展性**：随训练经验量增加，成功率稳步提升；失败-修复库提供了技能库之外的互补性负经验。

### 7. 优点

- **概念创新性强**：将"计划步骤应附带可测试的有效性条件"这一思想形式化为 FCU，为高层规划与低层执行之间建立了**运行时有效性接口**。相比传统"指令-执行"模式或事后反思模式，这是对计划本体论的一次重新定义。
- **多范围故障归因与指导性修复**：诊断能区分执行级、技能级、规划级失效，并选择最小充分修复范围（局部修复 55% vs 重规划 33% 的分布证明了分级设计的必要性），避免了"一刀切"式重规划的资源浪费。
- **效率设计务实合理**：混合测试架构（轻量匹配 + LLM 诊断）在保持成功率的同时显著降低 LLM 调用成本；路由阈值随信心 κᵢ 自适应调节，设计细致。
- **负经验的价值被充分挖掘**：大多数方法只从成功中学习，FCPAgent 显式利用失败-修复记忆来生成更尖锐的证伪器，这在经验扩展实验中验证了其独立贡献。
- **实验严谨性较高**：三次运行取均值、统一的离线训练/测试划分、可复现的 OpenStreetMap 配置、人工标注验证漂移检测精度、模块级成本分析等，方法在多个维度上均有对应证据支撑。

### 8. 不足与局限

- **对生成证据质量的依赖**：论文自认主要局限性——过宽的证伪器会触发不必要修复（增加延迟与偏离风险），过窄的证伪器可能漏检真实漂移。证据质量本质上取决于 LLM 生成能力和任务理解深度，降低了框架的下限保证（F1 为 80.0%，尚有改进空间）。
- **算力与成本信息缺失**：未报告 GPU 型号/数量/总训练或测试成本，也未讨论 API 调用总费用；仅报告了 LLM 调用时间的相对减少，读者难以评估实际部署成本。
- **基准覆盖仍然有限**：仅使用 WebArena 和 WebChoreArena 两个基准，虽覆盖 6-10 个域，但均为英文网页环境和"工单式"任务分布，未涉及移动端界面、动态 JS 重度页面、多标签协同、真实用户登录状态等更复杂的生产场景。
- **基线覆盖不完整**：论文提到了 SkillTracer 和 ContractSkill 两方法与自身高度相关，但因实现不可用而省略数值对比；其声称的"多范围归因 + 归因指导恢复"优势缺乏与最直接竞品的实证对照。
- **长时程分析的代理性问题**：Figure 3 使用最强基线的轨迹长度作为任务时长的代理，而非 oracle 交互长度，可能引入偏差（基线路径长可能既反映任务难度也反映基线效率低下）。
- **置信度 κᵢ 的生成机制**：文中仅说明由 Planner LLM 生成，未提供校准方法或验证，置信度偏差会直接影响路由阈值和修复决策质量。
- **修复成功率上的域差异**：Admin 和 GitLab 的修复条件成功率仅 40-45%，表明复杂有状态操作域中的恢复仍然困难，框架在"检测到漂移后能否有效恢复"方面存在瓶颈。
