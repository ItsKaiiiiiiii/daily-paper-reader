## 摘要
理解大型代码库对于大语言模型（LLM）智能体而言是一项长程任务：回答单个问题可能需要构建并运行软件、跨文件追踪执行流程，并在数十分钟内综合证据。在SWE-Atlas QnA（一个针对生产环境代码库的长程问题基准测试）上，单个Claude Code智能体（Opus 4.6）仅能解决32.3%的任务。在干净上下文中划分工作给多个智能体能缓解这一局限。然而，代码理解的子任务之间相互依赖。一个智能体的发现可能改写另一个智能体的任务，因此智能体必须在执行过程中进行协调，而不仅仅是在阶段边界处。现有的多智能体系统仅在阶段之间通过分阶段交接或同步轮次支持此类交换。通信与工作仍然相互排斥。执行过程中途的发现只能等到下一个边界才能共享。我们提出AgentRadio，一个异步消息传递层，为编码智能体框架提供三种原语：线程、消息以及等待被提及。最后一种作为后台任务运行，在不打断前台工作的情况下呈现队友的消息，从而让每个智能体对其同伴保持被动感知，并将新发现纳入其正在进行的任务。在五阶段分工与协商协议下，由AgentRadio组织的四个智能体解决了62.1%的任务，比单个智能体高出29.8个百分点，也高于使用更新版Opus 4.8的Claude Code（57.2%）。按评分标准进行的分析显示，增益随任务难度增加而增长，与将中途修正作为潜在机制的解释一致。我们的代码可在 https://github.com/Coral-Protocol/AgentRadio 获取。

## Abstract
Understanding large codebases is a long-horizon task for Large Language Model (LLM) agents: answering a single question can require building and running the software, tracing execution across files, and synthesizing evidence over tens of minutes. On SWE-Atlas QnA, a benchmark of long-horizon questions over production repositories, a single Claude Code agent (Opus 4.6) resolves only 32.3% of tasks. Dividing the work among agents with clean contexts mitigates this limitation. However, the subtasks of code comprehension are interdependent. One agent's findings can rewrite another's task, so agents must coordinate during execution, not only at phase boundaries. Existing multi-agent systems support such exchange only between phases, through staged handoffs or synchronized rounds. Communication and work remain mutually exclusive. A discovery made mid-execution cannot be shared until the next boundary. We present AgentRadio, an asynchronous message-passing layer that equips coding-agent harnesses with three primitives: threads, messages, and waiting for mentions. The last runs as a background task, surfacing teammates' messages without interrupting foreground work, so each agent remains passively aware of its peers and folds new findings into its ongoing task. Under a five-phase protocol of division of labor and negotiation, four agents organized by AgentRadio resolve 62.1% of tasks, 29.8 points above a single agent and above Claude Code with the newer Opus 4.8 (57.2%). Rubric-level analysis shows the gain growing with task difficulty, consistent with mid-course correction as the underlying mechanism. Our code is available at https://github.com/Coral-Protocol/AgentRadio.

# AgentRadio 论文深度总结

## 1. 核心问题与研究动机

- **背景**：LLM 智能体面临的任务日趋长程化（从单步问答、网站导航、完整电脑操作，到跨天专业工作乃至复现研究论文）。代码库理解（Codebase QnA）是其中的极端场景——回答单个问题需要构建运行软件、跨文件追踪执行、综合多方证据，耗时可达数十分钟。
- **核心问题**：单智能体在超长时程任务中表现严重退化。在 SWE-Atlas QnA 基准上，单个 Claude Code 智能体（Opus 4.6）仅解决 **32.3%** 的任务（公共榜单最强单智能体 Claude Code + Opus 4.8 也只有 57.2%）。根本原因在于智能体的有效注意力随上下文长度和交互轮次增加而显著下降。
- **现有方案的缺陷**：并行划分给多个智能体（各自干净上下文）虽有帮助，但代码理解的子任务高度相互依赖——一个智能体的发现可能改写队友的任务。然而，对 1,400+ 篇多智能体论文的调研表明，异步性"典型缺失"，仅有 22 篇涉及。既有系统要么并行但隔离、要么并行但按轮次同步，通信与工作严格互斥：执行中途的发现必须等到阶段边界才能传达。

## 2. 方法论

### 核心思想
AgentRadio 是一个异步消息传递层，让正在工作的智能体"边工作边收听"，实现**被动感知（Passive Awareness）**——类似于司机双手不离开方向盘时仍能收听广播。

### 三个通信原语
- **create_thread(name, participants)**：在消息服务器上创建命名会话线程。
- **send_message(thread, content, mentions)**：非阻塞地追加消息，可 @提及特定智能体，立即返回。
- **wait_for_mention(timeout)**：阻塞直到收到提及自己的消息，返回消息及所有线程的完整快照（无需二次读取重建上下文）。

### 关键创新：后台监听
`wait_for_mention` 的部署位置是唯一区分两种通信模式的自由度：
- **前台运行（阻塞接收）**：智能体必须停止工作来聆听，每条消息都消耗一个工作步骤的价值。
- **后台任务（被动感知）**：监听作为操作系统级后台进程运行，消息在步骤边界自然浮现，零额外 LLM 调用（只是 OS 进程而非智能体步骤），通信与工作不再互斥。

### 五阶段协议（Algorithm 1）
- **P1 Explore**：每个智能体启动后台 watcher，独立探索仓库，起草各自视角的子问题。
- **P2 Divide**：assembler（agent-1）开设规划线程，团队协商子问题划分直至全员批准。
- **P3 Execute**：各自执行子任务；在被动感知模式下，一旦有发现（影响队友、与计划冲突、障碍、死路），**立即发布**到 worklog，并在下一步折叠进自身任务。
- **P4 Review**：发布带证据的结论，互相审查（冲突、证据不足、遗漏观察），必要时退回 P3。
- **P5 Submit**：assembler 汇总终稿，经过最后一轮全员批准后提交。

### 实现细节
- 消息服务器为独立进程（存储线程/消息/提及）。
- 每个智能体通过三个薄 shell 脚本访问服务器。
- 对 harness 的要求仅为其原生支持的"后台运行 shell 命令"，harness 本身零修改。
- 从阻塞到被动接收的切换只改了通信原语的使用方式和一个阶段提示词。

## 3. 实验设计

### 基准
- **SWE-Atlas QnA**：124 个专家撰写的长程代码理解问题，覆盖 11 个生产代码库、4 种语言（架构 44 题、根因分析 37 题、代码上手 28 题、安全 11 题、API 集成 4 题）。
- 严格评估：每任务平均 12.3 个 rubrics（共 **1,306** 个），全部通过才算任务解决；修改源文件自动判失败；LLM 评分器固定为 Claude Opus 4.5。

### 五种配置递进消融（Ladder）
| 配置 | 说明 | 变动 |
|---|---|---|
| B0 | 单 Claude Code 智能体 | 基线 |
| B1 | 6 次独立单智能体运行取最优（best-of-6） | 增加算力、无协调 |
| L1 | 4 智能体 + 分工（division） | 增加并行分工 |
| L2 | L1 + 协商（negotiation，五阶段协议，阻塞接收） | 增加阶段间交流 |
| L3 | L2 + 被动感知（AgentRadio 完整版） | **仅改通信模式** |

### 对比方法
- 两种模型：Claude Opus 4.6 与开源 DeepSeek V4 Pro（同一 harness）。
- 额外对照：最强公共榜单单智能体（Claude Code + Opus 4.8，57.2%）。
- 所有配置温度 0、thinking effort high，每次任务相同设置，**逐任务配对比较**。

## 6. 主要结论

- **主结果**：4 个 Opus 4.6 智能体经 AgentRadio 组织后解决率从 32.3% 升至 **62.1%**（+29.8 点，相对提升 92%），且超过采用更新模型 Opus 4.8 的单智能体（57.2%）；DeepSeek V4 Pro 从 29.0% 升至 **50.8%**。
- **消融阶梯**：分工 +7.2（Opus）/ +2.4（DeepSeek）；协商再 +12.1 / +8.1；被动感知再 **+10.5 / +11.3**，经配对显著性检验。
- **结构 > 算力**：计算匹配的 best-of-6 仅为 37.9%（Opus）/ 31.4%（DeepSeek），远低于完整栈（62.1% / 50.8%），证明增益来自协调结构而非预算。
- **规模-难度关联**：被动感知增益随任务难度增大而增大（miss 1-3 组每任务 +0.3~0.5 rubrics，miss 4 组 +1.2，miss 5 组 +2.0），与"中途修正"机制一致。
- **机制验证**：MinIO 案例展示执行中发现→即时广播→团队共享证据→5 个 logging rubrics 全翻的完整链条；Grafana 案例表明被动感知只能传播智能体已形成的发现，无法凭空创造新概念。

## 7. 优点

- **单比特消融设计**：将"被动感知"这个抽象概念精确定位为 wait_for_mention 的前台/后台部署差异，是论文最优雅的设计点——一切其他因素均保持固定，因此增量效应归因清晰。
- **多层证据链**：从宏观准确率、中观类别分项、微观 rubric 级瀑布图（+84/−59、+100/−33、+47/−23），到难度分层和案例研究，证据层层递进、相互印证。
- **严密的统计严谨性**：配对 McNemar 检验、3 次独立运行的方差估计、成本-效果的显式定价（对比 B1 排除"钱多即好"的替代解释）。
- **双模型验证**：闭源与开源模型同一 ladder 重复，增强结论普适性。
- **工程侵入性极低**：不改 harness、不加 LLM 轮次、纯 OS 级后台进程，成本增量极小。
- **诚实呈现边界**：明确报告净损失 rubrics（消息漂移效应）和零增益案例（Grafana），未过度声称。

## 8. 不足与局限

- **基准单一性**：仅在 SWE-Atlas QnA 一个基准上评估，领域限于代码理解；缺乏其他长程任务（如研究、数据分析、通用 agentic 任务）的验证，泛化性存疑。
- **重复次数有限**：主实验每配置仅运行 1 次/任务（方差分析仅在 30 任务子集上做了 3 次），且每任务成本较高（L3 约 $19.45），大规模重复实验的经济门槛高。
- **Opus 4.8 对比不规范**：与最强单智能体的比较不是同环境平行运行，而是引用公共榜单数据，严格意义上不属于受控对比。
- **消息干扰风险**：被动感知净增 24 rubrics 但代价是丢失 23 个——中途消息会吸引智能体偏离本可通过的证据线，此机制在实盘中的可靠边界未被充分刻画。
- **协议依赖**：五阶段协议（包括 assembler 角色、全员批准门控）是预置的，AgentRadio 本身不解决"协议设计"问题；若换成不同协作协议，被动感知的增益是否保持未知。
- **概念天花板**：Grafana 案例证明被动感知不能创造任何智能体未形成的洞见，其增益上限受限于单智能体的初始认知多样性。
- **模型代际依赖**：被动感知增益在两种模型上都显著，但未测试更强/更弱的模型（如 40% 以上单智能体准确率区间）下是否仍为正——相关文献提示高能力单智能体可能削弱多智能体收益。
- **成本不成比例增长**：完整栈成本约为单智能体 6 倍，虽然 B1 对照证明结构而非算力生效，但实际部署时 $19.45/任务的经济可持续性问题未被充分讨论。
