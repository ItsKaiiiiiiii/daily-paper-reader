## 摘要
个性化AI代理通常可配置，但用户无法控制决定其未来行为的工件。我们提出OurArk，一种以代理自有软件身体为核心的持久个人代理架构：该身体是一个承载身份、可检查、有版本控制的工件，由人类保管。身体包含行为定义代码、提示、工具、技能、策略、测试和进化机制。记忆和凭证保持为私有实例状态，而模型推理则被视为可替换的外部服务。OurArk定义了在同一身体上的受治理自我进化与递归继承。自我进化产生隔离的候选变更，在人类控制下进行验证、审查和合并，从而实现人类与代理共同开发代理的软件身体。继承创建一个具有独立身份、使命、历史和全新私有状态边界的独立版本后代；兼容的后代自身也可以进一步派生。分歧后，可以直接父级变更和同级技能进行检查，以进行选择性局部适应。我们在开源Genesis创建引擎和Enoch参考代理中实现了该架构。一个四代理、三继承的线性谱系和可执行的回归测试证明了递归创建、继承的验证契约、隔离的身体变更、受人类控制的审查以及失败更新的恢复。OurArk为人们可以拥有、治理、专业化和随时间进化的个人代理提供了具体基础。

## Abstract
Personalized AI agents are often configurable without giving users control over the artifacts that determine their future behavior. We present OurArk, an architecture for persistent personal agents centered on an agent-owned software body: an identity-bearing, inspectable, and versioned artifact under human custody. The body contains behavior-defining code, prompts, tools, skills, policies, tests, and evolution mechanisms. Memories and credentials remain private instance state, while model inference is treated as a replaceable external service. OurArk defines governed self-evolution and recursive descent over the same body. Self-evolution produces isolated candidate changes that are validated, reviewed, and merged under human control, enabling human-agent co-development of the agent's software body. Descent creates an independently versioned descendant with a distinct identity, mission, history, and fresh private-state boundary; compatible descendants can themselves source further descent. After divergence, direct-parent changes and peer skills can be inspected for selective local adaptation. We implement the architecture in the open-source Genesis creation engine and Enoch reference agent. A four-agent, three-descent linear lineage and executable regression tests demonstrate recursive creation, inherited validation contracts, isolated body changes, human-controlled review, and failed-update recovery. OurArk provides a concrete substrate for personal agents that people can possess, govern, specialize, and evolve over time.

## 1. 论文的核心问题与整体含义

- **研究动机**：现有个性化 AI 代理虽然可配置，但用户往往无法掌控决定其未来行为的工件。代理的组件通常由平台组装和修改，用户只能做表层定制，无法真正"拥有"决定代理如何演化的制品，也难以让代理长期、稳定地服务于个人价值观与需求。
- **核心问题**：如何构建一种可被用户真正拥有、检查、治理并长期演化的持久个人代理？如何让代理在人类监督下自主修改自身行为工件，并在此基础上实现递归的血缘继承与专业分化？
- **整体含义**：论文主张一个持久个人代理应当有一个"承载身份的软件身体"（identity-bearing software body），由人类保管，代理与用户共同持续修改。这一身体作为连续性、继承、专业化、迁移与治理的具体单元，让代理不仅能被配置，更能被拥有和演化。

## 2. 提出的方法论

- **核心思想**：将代理实例抽象为四元组（body, private state, external reasoner, human custodian）：
  - **身体（Body）**：包含身份、代码、提示、工具、技能、策略、测试与进化机制的版本化仓库，是跨重启与继承的耐久载体。
  - **私有状态（Private State）**：凭证、记忆、日志、队列等，仅属于单个实例，不随继承传递。
  - **外部推理器（Reasoner）**：可替换的模型推理服务，不承担身份载体角色。
  - **人类保管者（Custodian）**：拥有身体与状态，掌握合并与晋升的最终权威。
- **三个核心操作**：
  - `evolve(B, c) → B'`：从上下文或压力源产生候选身体变更，需经过验证与人类批准才成为权威版本。
  - `descend(B, m) → (B_d, S_d)`：以现有身体为源，创建具有独立身份、使命、版本历史与全新私有状态边界的新代理。
  - `transfer(B_p, B_d, Δ) → B'_d`：后代可检查并选择性地将父级或同级的某一变更适配到自身身体，而不放弃独立历史。
- **六项设计原则**：保管与连续性、身体级个性化、可复现继承、独立专业化、可问责变更、人类治理。
- **实现机制**：
  - 身体以独立 Git 仓库形式存在，包含身份声明、运行时接口、推理适配器、技能/策略、测试及进化代码。
  - 继承由 Genesis 创建引擎执行：验证源仓库清洁、记录完整提交 ID、转换身份相关文本、初始化独立仓库、运行继承测试套件，验证通过后才创建出生提交。

## 6. 主要结论与发现

- **代理拥有的软件身体是可行的连续性单元**：一个身份承载、可检查、版本化的仓库，可以作为代理跨重启、跨世代的耐久载体。
- **同一身体上可统一实现进化与继承**：evolution 修改现有身体，descent 从身体物化独立后代，二者共用同一套验证与治理机制。
- **递归继承成立**：兼容后代可以继续产生下一代，种子代理可以成为专门化家族树的根，而不需要特权根模板。
- **人类治理与代理自主可以共存**：代理协助提议、实现与验证，人类保留合并权；失败的更新可以回滚，权威身体保持不变。
- **分歧后选择性迁移优于强制同步**：后代不需要持续镜像父级基线，而是按需拉取父级变更或同级技能，通过自身测试与审查流程适配。

## 7. 优点

- **清晰的理论边界划分**：将"身体、私有状态、外部推理器、人类保管者"四者分开，给出了实用的可拥有/不可拥有边界。
- **统一演化与继承模型**：同一身体既支持自我修改又支持后代继承，概念简洁，实现一致。
- **递归兼容性而非中心模板**：任何兼容的 Genesis 后代都能作为新世代的源，避免对根模板的依赖。
- **真实的人类-代理共同演化案例**：四条代际的能力累积路线（存在→操作/继承→工作→进化）本身即是共同演化的紧凑案例研究。
- **可复现性较强**：使用不可变提交 ID、版本化发布（Genesis v0.1.1、Enoch v0.3.1）并给出可重跑的验证命令。
- **诚实标注验证程度**：明确区分"已验证"与"部分验证"，未夸大机制覆盖范围。
- **相关工作总结系统**：用统一对比维度（演化对象、连续性单元、分支/继承方式、验收机制）梳理了 15 个相关工作，定位清晰。

## 8. 不足与局限

- **实验规模有限**：单一开发团队的一个线性血缘，无兄弟分支、无群体规模统计评估；无法推断在多样化用户群体或更大血缘树中的表现。
- **机制验证而非语义保证**：测试多基于 mock 服务，未评估长时运行可靠性、提案质量、专业化质量、人类审查负担或语义安全性。
- **行为连续性未测量**：更换推理器前后的行为连续性没有量化验证。
- **文本转换的语义风险**：Genesis 使用边界感知的字符串替换而非语言感知解析器，无法保证每个转换后的文件语义正确。
- **血缘记录不完整**：历史 Lucy–Enoch 血缘早于新溯源格式，只有新后代记录了完整的父辈出生与后代出生提交。
- **分歧后迁移未做端到端验证**：从发现到适配再到采纳的完整流程未在受控实验中走通。
- **权威边界有限**：写权限执行器的文件系统权限宽于生产级变更沙箱应有的范围；任务/进化/血缘记录不具备防篡改性；受保护作用域的检查是程序性的而非语义保证。
- **部署假设**：血缘发现与跨代理技能查找仍依赖托管仓库与 OurArk 命名约定；部分限制使结论仅限定于架构、已实现机制与回归证据层面。
