## 摘要
现代智能体在管理工具、上下文和控制流的智能体框架（agent harness）内运行，使得该框架成为智能体系统的关键部分。我们最初的Agent Lightning引入了一种解耦架构，通过LLM端点代理将任意智能体连接到强化学习训练，这种方法后来被verl Uni-Agent、AReaL 2.0、slime和Polar等框架所采用。我们将这种范式称为受控智能体强化学习（harnessed agentic RL），其中部署时的框架直接参与模型的后训练。受控智能体强化学习与传统智能体强化学习有根本不同：是框架而非训练引擎拥有环境交互循环，而训练器仅观察LLM请求-响应对的序列。这引入了重新分词、样本合并、优势计算、损失归一化和后端调度等方面的挑战，这些可能会显著影响训练的稳定性和有效性。我们提出了Agent Lightning v1.0，这是一个用约3500行代码实现的轻量级受控智能体强化学习框架。它支持任意智能体框架，并作为研究这些挑战的实用测试平台。我们在指令遵循、搜索和编码智能体上对其进行了评估，并提供了完整的可复现编码智能体强化学习流水线。仅使用6K训练示例和适度的计算量，强化学习将Qwen3.5-9B在SWE-bench Verified上的性能从41.8%提升到56.4%，绝对提升了14.6个百分点。我们发布了完整的工作流程和训练脚本，以促进受控智能体强化学习的可复现研究。

## Abstract
Modern agents operate inside agent harnesses that manage tools, context, and control flow, making the harness a critical part of the agent system. Our original Agent Lightning introduced a disaggregated architecture that connects arbitrary agents to RL training through an LLM endpoint proxy, an approach later adopted by frameworks such as verl Uni-Agent, AReaL 2.0, slime, and Polar. We refer to this paradigm as harnessed agentic RL, where the deploy-time harness directly participates in model post-training. Harnessed agentic RL differs fundamentally from traditional agentic RL: the harness, rather than the training engine, owns the environment interaction loop, while the trainer observes only sequences of LLM request-response pairs. This introduces challenges in retokenization, sample merging, advantage calculation, loss normalization, and backend scheduling, which can substantially affect training stability and effectiveness. We present Agent Lightning v1.0, a lightweight framework for harnessed agentic RL implemented in approximately 3,500 lines of code. It supports arbitrary agent harnesses and serves as a practical testbed for studying these challenges. We evaluate it on instruction-following, search, and coding agents, and provide a complete reproducible pipeline for coding-agent RL. Using only 6K training examples and modest compute, RL improves Qwen3.5-9B on SWE-bench Verified from 41.8% to 56.4%, a 14.6-point absolute gain. We release the complete workflow and training scripts to facilitate reproducible research on harnessed agentic RL.

### 1. 论文的核心问题与整体含义（研究动机与背景）

- **核心问题**：现代智能体（agent）并非独立的 LLM，而是在智能体框架（agent harness）中运行——框架负责管理工具、上下文、控制流与环境交互。这使得框架本身成为智能体能力的关键组成部分。然而，传统智能体强化学习（agentic RL）框架（如 verl、AReaL、slime）要求用户在训练框架内部直接实现智能体循环，导致部署时使用的成熟框架（如 mini-SWE-agent、OpenHands、Claude Code 等）难以被直接复用，造成**训练与部署不一致**。
- **动机**：作者最初提出的 Agent Lightning 采用解耦架构，通过 LLM 端点代理将任意智能体连接到 RL 训练；该代理式方法随后被 verl Uni-Agent、AReaL 2.0、slime v0.3.0、Polar 等框架采用。本文将这种范式正式命名为**受控智能体强化学习（harnessed agentic RL）**——即部署时的框架直接参与模型后训练，从而弥合训练与实际部署之间的鸿沟。
- **核心差异**：在传统 agentic RL 中，训练引擎拥有环境交互循环，策略模型看到的是持续扩展的 token 历史（一个线性轨迹）；而在受控 agentic RL 中，框架拥有该循环，训练引擎只能通过服务边界观察到一系列 LLM 请求-响应对。这种根本性差异引入了诸多新挑战。

### 2. 方法论

#### 核心思想
提出了一套解耦式系统架构：训练器与智能体框架分离，通过 LLM 端点代理连接，使任意智能体框架无需重新实现即可接入 RL 训练。系统仅约 3,500 行代码，以简洁性为第一原则。

#### 识别的四大挑战及设计选择

1. **重新分词与样本合并（Retokenization & Sample Merging）**：
   - 问题根源：框架与模型 API 通常通过文本消息通信，而 RL 训练基于精确 token ID。即使文本内容未变，重分词后 token 边界可能改变（如 "having" 从 `h`+`aving` 变为 `hav`+`ing`），导致 `(ptok_i, atok_i) ⪯ ptok_{i+1}` 的 token 级前缀条件不成立。三大诱因：聊天模板非组合性（如 Qwen 模板可能移除 `<think>` 标记）、解码-重分词漂移、推理时输出变换。
   - 缓解策略对比：AReaL/verl Uni-Agent 采用缓冲 token 替换（可能引入离策略偏差）；others 直接训练每个调用；树状训练需要复杂后端支持。**Agent Lightning v1.0 选择"尽力合并"（best-effort merging）**：仅当相邻调用的 token ID 严格满足前缀关系时合并，否则关闭当前序列并开启新序列，在保证 token 级正确性与计算效率间取得平衡。
2. **优势计算（Advantage Calculation）**：一个 rollout 可能因重分词、子智能体生成、上下文压缩等因素产生动态数量的训练样本。示例：Rollout 1（奖励 1）产生 3 个样本，Rollout 2（奖励 0）产生 1 个样本——rollout 级基线为 (1+0)/2 = 1/2，而样本级基线为 (1+1+1+0)/4 = 3/4。**作者认为 rollout 级优势计算更合理**，因为样本数往往是偶然因素造成，不应影响组基线。verl Uni-Agent 和 Polar 采用 rollout 级，slime 和 AReaL 采用样本级。
3. **损失归一化（Loss Normalization）**：对比三种方式——token-mean loss（DAPO，式 14）、seq-mean-token-mean loss（GRPO，式 15）、rollout-level token-mean loss（式 16）。**作者认为 seq-mean 会赋予产生更多样本的 rollout 过多权重，理论上 token-mean 和 rollout-mean 更合理；实践中 token-mean 对长序列敏感易不稳定，因此最终选择 rollout 级 token-mean loss**。
4. **训练后端调度**：rollout 批次的样本数量与长度在执行后才能确定，而 GPU 数量与并行配置固定。后端需将动态工作负载映射到固定 worker，同时保留 rollout 的统计来源（rollout 标识、prompt 组标识），且同一 rollout 的序列必须留在同一次优化更新中。

#### 系统架构（三个组件）
- **API Gateway**：有状态服务，存储 rollout、模型与事件；提供 rollout API 和代理 API（OpenAI 兼容转发）；所有端点幂等，支持网络失败重试。
- **Rollout Controller**：基于 Kubernetes（或本地进程池）管理智能体执行，采用声明式 reconciliation 循环，将 Kubernetes 作为可替换的执行后端。
- **Customized Trainer**：基于 VERL 构建，注册 rollout、等待完成、组装训练样本；包含样本适配器（实现上述三条设计选择）与轨迹监控系统。
- **Collocated Async RL**（同址异步强化学习）：让 rollout 与权重更新时分共享同一 GPU 池，避免同步 RL 等待最慢 rollout 的 GPU 空闲问题，同时比纯异步 RL 所需 GPU 更少，约比同步 RL 快 2 倍。
- **防奖励黑客**：对编码智能体禁用 Git 命令、隐藏 .git 目录，通过 Kubernetes 网络策略阻断非白名单外网访问。

### 6. 主要结论与发现

- **范式正确性**：受控智能体强化学习（harnessed agentic RL）是一种可行且有效的范式，允许部署时框架直接参与后训练，弥合训练与部署差距。
- **挑战的实质性**：重分词、样本合并、优势计算、损失归一化与后端调度若不妥善处理，会导致训练无效或不稳定；rollout 级优势计算与 rollout 级损失归一化是更合理的选择，能提升稳定性并改善最终性能。
- **样本动态性显著**：在编码智能体训练中，平均仅 36% 的 rollout 保持为单一训练样本，平均每个 rollout 产生 2.41 个训练样本，说明挑战具有实际普遍性。
- **编码智能体 RL 的可行性**：仅用 6K 样本和适中算力，RL 单独即可使 Qwen3.5-9B 在 SWE-bench Verified 上从 41.8% 提升到 56.4%（+14.6 绝对值），且提供了完整可复现的数据清洗流水线与训练脚本，填补了现有框架在编码智能体 RL 支持上的空白。

### 8. 缺点与局限性

- **实验对照不充分**：搜索与指令遵循场景各仅一条训练曲线，缺乏与传统 agentic RL 基线（如直接在框架内实现训练循环）、SFT 基线或多组随机种子的对比，难以判断解耦架构本身对性能的净影响；编码场景的消融也未在 SWE-bench Verified 上报告全部三组的成绩，只给出最优变体，削弱了消融结论的外部效度。
- **评测规模过小**：搜索场景各数据集仅 50 条测试样本，方差较大，+16.6% 的绝对提升缺乏置信区间或显著性检验支撑；指令遵循仅使用同源数据验证集，存在过拟合风险。
- **理论分析深度有限**：关于"为何 rollout 级优势更合理""token-mean 与 rollout-level token-mean 的偏好取舍"的论证主要依赖直觉性示例和推理，缺乏形式化证明或系统性仿真实验；对重分词的三种诱因（聊天模板、解码漂移、推理时变换）也仅作描述性说明，未量化各自出现频率。
- **对对齐副作用的讨论不足**：受控智能体 RL 训练出的模型只在训练所用框架的上下文中表现良好，未讨论当该模型部署到其他框架（无同样工具/格式约束）时是否出现能力退化或安全行为的迁移问题；奖励黑客的防御仅针对编码场景，未系统探讨其他场景的奖励漏洞。
- **可扩展性证据缺乏**：所有实验仅使用 3B–9B 的小规模模型，未验证架构在 30B 以上模型、大规模多节点分布式训练场景下的可行性；同址异步 RL 的加速结论也仅有一个粗略的 2 倍估计，缺少逐步分解的基准测试（如分别测 rollout 时间、更新时间的流水线开销）。

### 9. 改进建议与未来方向

- **补强实验矩阵**：在搜索与指令遵循场景加入 (a) 直接 agentic RL 基线、(b) SFT 后 RL 对照、(c) 3 个以上随机种子，并报告均值±标准差；编码消融应补全 SWE-bench Verified 上全部三组设置的结果。
- **扩大评测规模与多样性**：搜索评测可扩展到全量 HotpotQA 测试集或加入多跳问答更广的标准集（如 IIRC、WebQuestions）；增加一个零样本跨框架部署评测（训练框架 vs. 部署框架不一致）以检验鲁棒性。
- **严格化理论论证**：对"模型输出序列 + 重新分词"的随机过程建模，推导使 token 级前缀约束成立的充分条件与失败率上界；对三种损失归一化在异质序列长度分布下的梯度方差给出定量估计。
- **深化可扩展性研究**：在更大的模型规模（如 30B/70B）和多节点集群上报告吞吐量、GPU 利用率与同步/异步模式下的端到端效率对比曲线；补充动态批次映射算法的复杂度分析。
- **扩展安全与对齐分析**：研究受控智能体 RL 对模型一般能力（如通用问答、指令遵循脱离工具后）的影响；建立针对不同场景（搜索、编码、多模态）的奖励黑客分类及其防御策略。

### 10. 综合结论与启示

总体而言，本文是一篇工程与算法结合紧密的高质量系统论文。其核心贡献不在于某个新算法或新模型，而在于**为"训练引擎与部署框架解耦"这一新范式提供了系统性的命名、形式化的问题描述、一套轻量可复现的实现以及初步的实证证据**。论文清楚地展示了：在受控智能体强化学习中，那些由框架分层引入的"次要工程细节"（重分词、动态样本数、损失归一化）实际上对训练正确性与稳定性有决定性影响，这为后续框架设计树立了重要的"坑位清单"。

同时，其局限也反映了该方向仍处于早期：实验覆盖窄、理论刻画浅、规模证据不足。对读者（尤其是有意采用该范式的研究者与工程师）而言，本文最直接的参考价值是：(1) 设计解耦式 RL 训练系统时应优先采用 rollout 级优势计算与 rollout 级归一化；(2) 在接入现有 agentic 框架前须先验证模板与重分词的 token 级保真性；(3) 编码智能体 RL 在数据量适中（约 6K）且框架适当时，可获得十余个点的 SWE-bench 提升，是一条值得跟进的低成本路线。论文整体写作清晰、代码开放，是该领域目前最可借鉴的起点之一。
