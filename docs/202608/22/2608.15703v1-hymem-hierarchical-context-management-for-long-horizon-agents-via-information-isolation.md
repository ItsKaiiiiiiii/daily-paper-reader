## 摘要
大型语言模型（LLM）智能体在复杂的长期任务中往往表现不佳，因为其上下文随着时间推移变得日益混乱。随着交互的积累，详细的执行轨迹和中间输出占据了上下文的主导地位，使模型难以保留和使用高层规划信息。大多数现有方法通过对单一扁平上下文应用压缩或检索来解决此问题，但这种方法无法清晰区分不同类型的上下文信息，且常常导致推理性能下降。为应对这一挑战，我们提出了HyMem，一种分层框架，将智能体的上下文明确划分为不同的功能层。HyMem按功能组织上下文，将高层规划与执行及复杂分析分离。其隔离推理模块处理复杂子任务，而无需将中间推理痕迹添加到持久规划上下文中；同时，其记忆管理模块通过结构化摘要在上下文刷新时保留任务进度。这些组件减少了冗余上下文的积累，保留了任务关键信息，并支持在有限上下文窗口内进行连贯的长期推理。在GAIA和Browsecomp-plus上的实验表明，使用DeepSeek-V4，HyMem的平均Pass@1得分分别达到66.7%和61.3%，比最强基线高出6.1和4.7个百分点。进一步分析表明，HyMem有效控制了推理上下文的增长，使模型能够在复杂的长期任务中保持专注和准确性。

## Abstract
Large language model (LLM) agents often perform poorly on complex, long-horizon tasks because their context becomes increasingly cluttered over time. As interactions accumulate, detailed execution traces and intermediate outputs dominate the context, making it difficult for the model to retain and use high-level planning information. Most existing methods address this issue through compression or retrieval applied to a single, flat context, which does not clearly separate different types of context information and often leads to degraded reasoning. To address this challenge, we propose HyMem, a hierarchical framework that explicitly separates the agent's context into distinct functional layers. HyMem organizes context by function to separate high-level planning from execution and complex analysis. Its isolated reasoning module handles complex subtasks without adding intermediate reasoning traces to the persistent planning context, while its memory management module preserves task progress across context refreshes through structured summaries. These components reduce redundant context accumulation, retain task-critical information, and support coherent long-horizon reasoning within a limited context window. Experiments on GAIA and Browsecomp-plus show that, with DeepSeek-V4, HyMem achieves average Pass@1 scores of 66.7% and 61.3%, outperforming the strongest baseline by 6.1 and 4.7 percentage points, respectively. Further analysis indicates that HyMem effectively controls the growth of the reasoning context, allowing the model to maintain focus and accuracy across complex, long-horizon tasks.

### 2. 方法论

#### 核心思想：分级上下文隔离

HyMem 是一个 **训练免费（training-free）的推理期控制器**，其核心设计原则是：规划、工具执行、子任务推理与记忆整合各自处于独立的上下文空间，只有**受模式约束的消息**允许跨越边界，原始执行痕迹与中间推理token不得直接追加到主规划上下文。

#### 框架组件

**(a) Planner 层（规划器）**
- 维护贯穿全程的决策上下文：
  ```
  C(p)_t = <P(p), q, M_epi_t, M_wm_t, M_tool_t, H(p)_t>
  ```
  其中M_epi为情节记忆、M_wm为工作记忆、M_tool为工具记忆、H(p)存储先前子会话的**类型化返回结果**。
- Planner 只能发出四类动作：`<TASK>(d)`（委派执行）、`<ISO_REASON>(d)`（委派隔离推理）、`<FOLD>`（触发记忆压缩）、`<ANSWER>(ŷ)`（输出最终答案）。

**(b) Executor 层（执行器）**
- 收到工具使用指令后，创建**临时执行上下文**，执行有界工具调用循环。
- 关键操作：原始观测不直接返回，而是先经**相关性条件蒸馏算子** ϕ（去除导航文本、重复段落、格式噪声、工具错误样板，同时保留实体、日期、数值、来源标识等），再合成结构化返回：
  ```
  R(e)_t = <RESULTS>[findings, evidence, sources, status, gaps]</RESULTS>
  ```
- 执行上下文与原始观测在返回后被直接丢弃。

**(c) 隔离推理模块（Isolated Reasoning）**
- 对需要多跳分析、假设检验或证据调和的子任务，Planner 发出 `<ISO_REASON>(d)`，创建独立的推理上下文，继承部分记忆与近期规划状态。
- 中间推理轨迹保持私有，最终返回结构化结论：
  ```
  R(iso)_t = <RETURN>[conclusion, supporting facts, sources, confidence κ, assumptions]</RETURN>
  ```
- 返回后隔离上下文被丢弃。

**(d) 记忆管理模块（Memory Management）**
- 维护三种可重写记忆：
  - **情节记忆**（Episodic）：已完成里程碑、已核实事实、重要决策
  - **工作记忆**（Working）：当前目标、未解决缺口、下一步计划
  - **工具记忆**（Tool）：有效工具使用模式、失败查询、工具注意事项
- 折叠操作符 Φ 对全部历史与记忆进行联合重写；采用**非对称记忆注入**：Planner 和隔离推理接收全部三种记忆，Executor 仅接收工具记忆的精简程序性摘要。

#### 触发机制

折叠（FOLD）在以下条件之一满足时被触发：
- Planner 上下文 token 利用率 > 0.99
- 自上次折叠后执行器调用 ≥ 5 次
- 连续执行失败 ≥ 3 次
- Planner 轮次 ≥ 8 次
- 工具调用 ≥ 10 次

#### 理论表述

论文将问题形式化为条件互信息约束：`I(C(p)_t+1; X_t | R_t) ≈ 0`，即**给定结构化返回后，规划者状态与原始执行信息近似条件独立**。这一约束通过接口设计强制执行而非可微优化目标。

### 6. 主要结论与发现

#### 核心结果（DeepSeek-V4 骨干）

| 基准 | HyMem | 最强基线 | 提升幅度 |
|------|-------|----------|----------|
| GAIA 平均 Pass@1 | **66.7%** | ReSum 60.6% | +6.1 pp |
| Browsecomp-plus 平均 Pass@1 | **61.3%** | ReAct 56.6% | +4.7 pp |
| Browsecomp-plus Hard | **30.0%** | ReAct 14.0% | +16.0 pp |

#### 关键发现

1. **难度越高，收益越大**：HyMem 在 Browsecomp-plus Hard 上将 Pass@1 翻倍以上，在 GAIA Level 3 上相对 ReAct 提升最大，证明隔离机制在处理复杂多步任务时的核心价值。

2. **跨骨干鲁棒性不均匀**：Qwen3-32B 在 GAIA 上从 11.8%（ReAct）提升至 33.0%，但在 Browsecomp-plus 上未超越 ReAct——说明 HyMem 的收益依赖模型遵循类型化控制指令和输出可靠结构化结果的能力。

3. **资源效率可接受**：HyMem 在提升性能的同时，token 消耗和工具调用次数与基线相当，性能提升并非靠资源堆砌。

4. **机制验证（图4）**：HyMem-Total 与 HyMem-Planner 的上下文曲线分离明显，证明执行细节被隔离在临时上下文中，规划器上下文增长缓慢、保持聚焦。

5. **消融验证双组件缺一不可**：
   - 去掉隔离推理：GAIA 上 Pass@1 下降 18.6pp，Browsecomp-plus 下降 5.0pp
   - 去掉记忆管理：GAIA 上下降 18.6pp，Browsecomp-plus 下降 9.0pp
   - 两个组件都影响规划器置信度，说明"隔离推理保护规划器免受噪音干扰"与"记忆管理维持跨刷新连续性"协同作用。

### 7. 优点

1. **问题诊断精准**：将"上下文稀释"形式化为信息密度失配，为长期智能体性能退化提供清晰的理论刻画。

2. **结构创新性强**：以类型化上下文隔离作为核心设计原则，从源头阻断执行噪声进入决策空间，而非在混合后做信息压缩——范式上优于现有方法。

3. **训练免费、即插即用**：无需任何训练即可应用于现有骨干模型，工程部署成本低。

4. **机制透明、可验证**：通过上下文增长曲线和关键信息密度分析，直接实证了所设计的隔离机制确实起作用，而非简单的"黑盒性能提升"。

5. **错误模式分析深入**：通过辅助指标（置信度下降）解释失败模式——无记忆管理时模型即使能执行工具也因失去任务状态而信心下降。

6. **案例研究直观**：多跳推理案例完整展示从实体识别→约束验证→属性检索→策略调整→记忆压缩→最终答案的全流程，具有教学价值。

7. **非对称记忆注入设计精巧**：执行器仅接收工具记忆的精简摘要，避免原始工具日志污染执行决策。

### 8. 不足与局限

1. **对骨干模型能力依赖强**：HyMem 依赖模型遵循类型化控制指令（`<TASK>`、`<ISO_REASON>`、`<FOLD>`等）和输出结构化返回的能力。Qwen3-32B 在 Browsecomp-plus 上未获益即为明证——较弱的模型可能无法稳定遵守格式约束。

2. **评估覆盖有限**：
   - GAIA 仅限文本问题，未测试多模态能力。
   - Browsecomp-plus 仅采样150题，样本量较小。
   - 未覆盖 GUI 操作、真实网页交互、多轮用户对话等场景。

3. **辅助LLM成本未充分讨论**：摘要、蒸馏、记忆压缩均调用辅助LLM（DeepSeek-V4），虽然token消耗相近，但多次独立调用的推理延迟可能影响实际应用效率。

4. **无理论保证**：条件互信息的表述是概念性的，论文明确承认并非可优化目标；`πZ`、`πX` 为概念性选择器，未给出具体实现。

5. **记忆折叠策略固定**：触发条件（轮次超过8、工具调用超过10等）为手工设定，可能在不同任务类型上非最优；论文承认未来应研究自适应折叠策略。

6. **跨骨干泛化性不均**：在 Qwen3-32B 上的不一致结果说明方法并非对所有模型普适，需要更强的基础指令遵循能力。

7. **长期任务之外的适用性存疑**：对短任务或单轮推理，隔离机制带来的格式开销可能超过收益（实验中 easy 问题上表现略逊于 ReAct 即为佐证）。
