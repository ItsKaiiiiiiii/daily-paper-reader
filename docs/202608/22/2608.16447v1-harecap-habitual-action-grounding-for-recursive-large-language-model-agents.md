## 摘要
长时程具身任务要求大语言模型（LLM）智能体迭代地分解高层目标，根据环境反馈修订计划，并将叶子级子目标落地为有效可执行动作。ReCAP等递归上下文管理方法通过多级任务分解和父节点细化提高了规划稳定性，但仍需在叶子节点反复调用LLM，将原子子任务落地为精确有效的动作。我们将这最后的落地步骤称为“最后一英里的落地冗余”，它在长时程执行过程中累积成大量的LLM调用和令牌开销。为缓解这一问题，我们提出HaReCAP（习惯性动作落地的ReCAP），一种针对ReCAP的低侵入性叶子落地扩展。HaReCAP从成功轨迹中提取频繁出现的叶子决策，并离线编译成可审计且可弃权的一步叶子反射规则。在运行时，仅当规则能在当前有效动作集合中唯一确定一个合法动作时，才跳过叶子LLM调用；否则，回退到原始ReCAP。这种设计避免了在常规叶子动作落地时反复将完整递归上下文带入LLM，同时保留了原始递归控制流。我们以Qwen3.5-27B作为主模型，在Robotouille和ALFWorld上评估了HaReCAP。在ReCAP和HaReCAP都解决的任务上，HaReCAP在Robotouille同步、Robotouille异步和ALFWorld上分别减少了14.67%、17.93%和20.08%的令牌消耗。结果表明，HaReCAP可以作为ReCAP风格递归上下文管理框架的低侵入性扩展，在常见成功轨迹上减少跨环境和跨模型的最后一英里落地冗余。

## Abstract
Long-horizon embodied tasks require LLM agents to iteratively decompose high-level goals, revise plans in response to environmental feedback, and ground leaf-level subgoals into valid executable actions. Recursive context-management methods such as ReCAP improve planning stability through multi-level task decomposition and parent-node refinement, but still repeatedly invoke the LLM at leaf nodes to ground atomic subtasks into exact valid actions. We refer to this final grounding step as last-mile grounding redundancy, which accumulates into substantial LLM-call and token overhead during long-horizon execution. To mitigate this issue, we propose HaReCAP (Habitual-action Grounded ReCAP), a low-intrusion leaf grounding extension for ReCAP. HaReCAP extracts frequent leaf decisions from successful trajectories and compiles them offline into auditable and abstainable one-step leaf-reflex rules. At runtime, it skips the leaf LLM call only when a rule can uniquely determine a legal action in the current valid-action set; otherwise, it falls back to the original ReCAP. This design avoids repeatedly carrying the full recursive context into the LLM for routine leaf action grounding, while preserving the original recursive control flow. We evaluate HaReCAP on Robotouille and ALFWorld with Qwen3.5-27B as the main model. On tasks solved by both ReCAP and HaReCAP, HaReCAP reduces token consumption by 14.67%, 17.93%, and 20.08% on Robotouille synchronous, Robotouille asynchronous, and ALFWorld, respectively. The results show that HaReCAP can serve as a low-intrusion extension to ReCAP-style recursive context-management frameworks, reducing last-mile grounding redundancy across environments and models on commonly successful trajectories.

- **与宏技能方案的区别**：直接学习“从炸锅拿洋葱到砧板”的中间宏技能虽也能减少调用，但会引入对象绑定、前置条件判断、技能终止估计和方向敏感动作（如“A 叠在 B 上”与“B 叠在 A 上”）等风险，可能破坏 ReCAP 既有的回溯、细化和错误处理逻辑。因此本文选择只压缩叶子层的最后一步动作接地，而非取代递归规划本身。

## 2. 方法论：HaReCAP

### 2.1 核心思想

- 保留 ReCAP 的递归任务树、回溯和父节点细化机制；
- 在叶子级动作接地之前插入一个**可弃权（abstainable）的一步式习惯性动作接地模块**；
- 从成功轨迹中离线提取高频叶子决策，编译成“叶子反射规则库”（leaf-reflex library）；
- 运行时仅当规则能在当前合法动作集合中**唯一确定**一个合法动作时才直接执行，否则完全回退到原 ReCAP。

### 2.2 关键定义

- **leaf-reflex rule（叶子反射规则）**：一个从规范化叶子任务到规范化动作模板的一步映射 `s = (kτ, ka)`。
- **宏技能（macro skill）**：中间节点上的多步子程序（如持续执行拿取-移动-放置），HaReCAP 刻意避免这种粗粒度技能接管。
- **习惯性动作接地（habitual-action grounding）**：运行时从规则库检索规则，并基于当前合法动作集合唯一实例化一个合法动作的过程。

### 2.3 规则提取与离线构建

- 只保留**成功 ReCAP 轨迹**中已验证的“叶子任务→执行动作”映射，不保存完整轨迹或多动作窗口。
- 采用**动作类型无关的规范化（canonicalization）**：将对象 ID 归一化为类型占位符，如 `bread12 → bread#`，以提升不同物体 ID 和局部布局间的复用。
- 过滤条件：规范化后键非空、叶子任务必须显式包含对象 ID、且这些 ID 必须被执行动作覆盖：`ids(τ) ≠ ∅, ids(τ) ⊆ ids(a)`。
- 支持度 `ns` 在任务级去重后计数：同一任务内重复出现的相同 `(τi, ai)` 只记一次，避免循环带来的虚高。

### 2.4 运行时触发机制

- 仅在叶子 LLM 调用前触发，输入仅限当前叶子任务、当前合法动作集合、冻结的规则库和支持度阈值。
- 触发条件：
  - 叶子任务规范化键非空且含对象 ID；
  - 规则任务键与当前任务匹配；
  - 支持度 `ns ≥ m`；
  - 候选规则对应的动作键能在当前合法动作集合中**唯一实例化**，且覆盖叶子任务的对象 ID。
- 冲突处理：若多个规则命中并映射到不同合法动作，采用支持度评分 `ρ(s) = 1.6·ns/(ns+2) + (1/10)·min(ns, 10)`（单调递增）作弱排序；若最高分与次高分差距小于 1，则视为歧义窗口，系统弃权并回退 ReCAP。
- 安全性：规则对应多个合法动作时视为状态歧义，直接拒绝；返回 `⊥` 时完全回退到原始 ReCAP 叶子 LLM 调用。

### 2.5 执行写回与回退

- 规则命中后只替换动作的**来源**，ReCAP 的递归状态转移、父节点细化、失败回退机制全部保持不变。
- 回退时若 LLM 输出仍不匹配合法动作，依旧沿用 ReCAP 的失败处理和回溯逻辑。

## 6. 主要结论与发现

- 在 ReCAP 与 HaReCAP 都成功的任务上，HaReCAP 在 Robotouille 同步、Robotouille 异步、ALFWorld 分别降低 token 消耗 **14.67%、17.93%、20.08%**，同时 LLM 调用次数也有类似降幅。
- 端到端成功率保持与 ReCAP 相近，甚至在部分设置下略有提升（如 Qwen3.5-9B 在 Robotouille 同步上从 32% 提升到 44%，Gemma4-26B 在 ALFWorld 上从 66.42% 提升到 75.37%）。
- 支持度阈值 s=2 是默认最优：s=1 覆盖面大但包含低频经验，s=4 更保守但触发率下降。
- 最后的叶子动作接地是 ReCAP 风格递归智能体中的一项**独立可优化推理开销**，将其蒸馏为可弃权的一步规则不会破坏高层递归控制。
- 收益具有跨环境、跨模型的普适性，不局限于特定厨房场景或模型规模。

## 7. 优点与亮点

- **低侵入性设计**：完全保留 ReCAP 的递归控制流，不改变分解、回溯、失败处理逻辑，降低集成风险。
- **可审计、可弃权**：规则是透明的离线编译产物，运行时严格受合法动作集合约束；不确定时主动回退，保证安全性。
- **粒度选择合理**：只压缩叶子层一步接地，避免宏技能带来的对象绑定、前置条件、方向敏感等副作用；与宏观技能库方法相比更保守、更可控。
- **成本口径更公平**：采用 both-success 任务对比，避免因失败模式不同导致的 token 比较偏差。
- **跨越模型和环境验证**：在 2 个环境、3 个不同规模的模型上都获得一致的效率提升，增强了泛化性结论。
