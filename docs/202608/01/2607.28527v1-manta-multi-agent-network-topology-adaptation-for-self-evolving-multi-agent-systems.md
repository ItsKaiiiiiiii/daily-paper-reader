## 摘要
基于大语言模型的多智能体系统通过任务分解、智能体专业化、信息交换和中间验证来提升复杂问题求解能力。然而，现有系统通常将通信拓扑视为固定的设计选择或离线优化目标。我们提出了MANTA，一个多智能体网络拓扑自适应框架，使通信结构能够在推理时自进化。在执行前，MANTA从先前的结构经验中初始化一个任务条件化的拓扑。在部署期间，它监控协作轨迹，并在当前组织变得不足时应用有界结构更新。这些更新可以修改智能体角色、通信链路、执行顺序、信息可见性和验证路径，同时保留任务接口和智能体预算。我们在五个基准上对MANTA与代表性的单智能体和多智能体基线进行了评估，涵盖信息检索、工具使用、规划、工作流执行和数学推理。MANTA取得了74.0的最高平均分，比最强基线高出5.8个百分点，并在PlanCraft上获得了最佳结果。这些结果表明，推理时的自我改进可以扩展到协作本身的结构。

## Abstract
Large language model-based multi-agent systems improve complex problem solving through task decomposition, agent specialization, information exchange, and intermediate validation. However, existing systems typically treat communication topology as a fixed design choice or an offline optimization target. We introduce MANTA, a framework for Multi-Agent Network Topology Adaptation that enables communication structures to self-evolve at inference time. Before execution, MANTA initializes a task-conditioned topology from prior structural experience. During deployment, it monitors collaboration traces and applies bounded structural updates when the current organization becomes insufficient. These updates can modify agent roles, communication links, execution order, information visibility, and validation pathways while preserving the task interface and agent budget. We evaluate MANTA against representative single-agent and multi-agent baselines on five benchmarks spanning information seeking, tool use, planning, workflow execution, and mathematical reasoning. MANTA achieves the highest average score of 74.0, outperforming the strongest baseline by 5.8 percentage points and obtaining the best result on PlanCraft. These results show that inference-time self-improvement can extend to the architecture of collaboration itself.

# 2. 方法论

## 2.1 核心思想

- MANTA 在任务执行前根据积累的结构经验初始化一个“任务条件化”拓扑；
- 在执行过程中监控协作轨迹（trace），当当前组织明显不足时，施加**有界结构突变**；
- 通过跨运行记忆（long-term playbook）持续积累可复用的拓扑选择与修复经验，不更新模型权重、不进行离线搜索。

## 2.2 系统架构与流程

- 系统分为两层：
  - **目标多智能体系统**：负责实际的推理、工具调用、消息交换；
  - **编排层**：负责规划、审计、控制与记忆。
- 关键组件：
  - **Topology Planner**：根据任务和长期经验生成初始拓扑；在修复时生成有界突变；
  - **Trace Auditor**：扫描执行轨迹，标记过程性异常（不判断答案正确性）；
  - **Controller**：决定是终止并输出答案，还是允许一次修复；
  - **Finalizer**：综合证据、投票、生成最终答案；
  - **Skill Reflector**：每隔 N 次运行重写长期经验，仅使用过程信号，不接触基准标签。

## 2.3 拓扑表示与有界突变算符

- 拓扑规范包含智能体的结构角色（协调者、工作者、验证者、辩论者、投票者）、阶段角色（生产/批判）、领域人格、工具白名单、模式分组（star、chain、debate、voting、singleton）、上下文可见性策略。
- 确定性代码负责校验合法性（成员资格、循环、角色、预算），保证任务接口和智能体预算不被破坏。
- 突变操作符（每次至多 3 个操作）：
  - `add_agent`：增加一个智能体；
  - `expand_agent_to_group`：将智能体扩展为子群组中心；
  - `set_group_pattern`：改变群组交互模式；
  - `add_edge` / `remove_edge`：增删通信链路；
  - `set_context_policy`：调整信息可见性。
- 另有针对检索密集型任务的“确定性收缩”修复，不经过 Planner 的突变语言。

## 2.4 双时间尺度记忆

- **短期 playbook**：记录当前运行各轮拓扑、审计标志、修复建议与决策；
- **长期 playbook**：由 Reflector 根据过程信号周期性重写，映射任务特征和过程风险到拓扑选择；
- 学习过程完全基于过程信号，如“过程清洁”和“决策级共识”，不依赖基准正确性。

## 3.1 数据集与基准

  - 信息检索与工具使用：**BrowseComp**、**StableToolBench**；
  - 规划与工作流执行：**PlanCraft**、**WorkBench**；
  - 数学推理：**MATH**（用于检验协调改进是否能泛化到纯推理）。

# 6. 主要结论与发现

- **MANTA 平均得分 74.0**，超过最强基线 5.8 个百分点，并在 PlanCraft 上取得最佳成绩；在信息检索、工具使用、规划、工作流、推理等所有类别上均优于 Single Agent。
- **消融结果**：去掉初始拓扑规划降幅最大（71.7→57.5）；去掉拓扑修复降至 60.8；冻结或删除长期 playbook 也有较小但一致的下降。
- **突变预算**：预算从 0 增加到 3 可提高所有基准的成功率，首个突变机会增益最大。
- **跨域迁移**：MANTA 的长期 playbook 在同一域和跨域迁移中均带来正向收益（平均 +3.3），而基线（ADAS、AgentSquare、MASS）迁移效果为中性或显著为负。
- **Token 效率**：MANTA 是评估的多智能体系统中总 token 消耗最低的；元层开销仅占约 12%。
- **修复模式**：拓扑演化不仅是增加智能体——更多情况下是重连通信、改变执行顺序、插入验证角色；统计显示 162 次操作中仅 9.3% 是新增智能体，最常用的是确定性检索收缩（42%）、改变群组模式（27.2%）、分支扩展（20.4%）。
- **审计信号**：无修复标志的运行有 83.2% 正确，有标志的为 62.5%；但审计只是可靠性信号，不能保证正确性，且不同基准差异大（WorkBench F1 0.78，PlanCraft/MATH 很低）。

# 7. 优点

- **问题定义新颖**：首次系统性地把拓扑视为推理时可自改进的对象，提出“拓扑级自我改进”。
- **方法设计模块化且可解释**：规划、审计、修复、记忆各自独立，确定性代码与 LLM 组件分离，便于验证和调试。
- **过程信号驱动**：审计只关注协作过程中的可观察异常，不依赖基准答案，避免了“作弊”风险，也更容易迁移到新任务。
- **有界突变机制**：每次运行至多一次修复，每次修复至多 3 个操作，且必须通过结构校验，保持系统稳定。
- **记忆可迁移**：长期 playbook 不绑定具体任务，能在同域和跨域复用，相比固定 workflow 的优化方法更具泛化性。
- **实验分析深入**：不仅报告主结果，还做了消融、预算影响、迁移、token 用量、案例审计、统计关联等多维度分析。
- **Token 效率好**：自适应拓扑并未增加计算开销，反而比静态多智能体系统节省 token。

# 8. 不足与局限

- **基准规模较小**：每个基准仅 30 题、3 次运行，统计功效有限，部分标准差不小。
- **单一骨干模型**：只验证了 Gemma 4 31B，未测试其他规模或厂商模型，泛化性存疑。
- **审计评估依赖代理指标**：没有人工标注真实过程缺陷，精度/召回指标只能反映“与答案错误的相关性”而非真实检测能力。
- **修复策略受限**：每次运行只允许一次拓扑突变，对于需要多阶段动态调整的复杂任务可能不足；突变预算实验显示后续突变仍有增益，但当前设计上限为一。
- **跨域迁移实验范围窄**：只在 PlanCraft 和 WorkBench 两个规划/工作流基准之间进行，未涵盖检索或推理类基准的跨域。
- **未报告硬件算力细节**：缺乏 GPU 配置、时间成本等，影响可复现性和成本评估。
- **潜在偏差风险**：审计器生成的修复建议基于 LLM，可能因 prompt 或模型偏差产生不合理的结构变更；论文没有对修复建议的语义正确性做人工验证。
- **可行性限制**：需要一个可靠的 LLM 审计器来识别过程异常，若审计器本身不准确，修复可能无效甚至有害。
