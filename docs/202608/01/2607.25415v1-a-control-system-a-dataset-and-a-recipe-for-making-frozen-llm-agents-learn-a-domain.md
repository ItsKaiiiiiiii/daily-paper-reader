## 摘要
生产环境中的LLM智能体越来越多地由一个冻结模型加上封装组件构成：提示模板、工具集、记忆/检索层、规划策略和验证策略。2026年的两个系统Meta-Harness（Lee等，2026）和HyperAgents（Meta AI，2026）表明，这个封装本身可以被一个智能体提议者优化甚至自我重写——但代价是要么使用昂贵的代码搜索循环，要么使用不受约束的自修改代码，这两者都不可审计，也无法与完全黑盒的模型API一起使用。我们采取一个更狭窄、更受限的立场：将封装视为一个小型、固定、人类可读的动作空间，并使用经典样本高效的强化学习（ε-贪心上下文赌博机和REINFORCE）在线学习策略，根据多目标奖励（任务成功、验证器分数、策略合规性、成本、延迟以及无依据主张惩罚）进行评分。我们使用DSPy（Khattab等，2024）实例化这个控制系统，DSPy既充当上下文组装器，也作为最强非自适应基线（DSPy BootstrapFewShot静态提示）的来源，并在三个可验证任务领域——工具使用工作流、代码生成（HumanEval）和多跳检索问答（HotpotQA）——以及两家模型提供商（本地Ollama模型和AWS Bedrock）上进行了评估。我们发布了封装控制系统代码、跨领域可验证任务套件、训练过程中的完整轨迹/奖励分解日志，以及一套与提供商无关的部署方法，用于将其应用到新组织的领域和验证设置中。

## Abstract
Production LLM agents are increasingly assembled from a frozen model wrapped in a harness: a prompt template, a tool set, a memory/retrieval layer, a planning strategy, and a verification policy. Two 2026 systems, Meta-Harness (Lee et al., 2026) and HyperAgents (Meta AI, 2026), show that this harness can itself be optimized or even self-rewritten by an agentic proposer -- at the cost of either an expensive code-search loop or unconstrained self-modifying code, neither of which is auditable or usable with a fully black-box model API. We take a narrower, more constrained position: treat the harness as a small, fixed, human-legible action space and learn a policy over it online with classic sample-efficient reinforcement learning (an $ε$-greedy contextual bandit and REINFORCE), scored against a multi-objective reward (task success, verifier score, policy compliance, cost, latency, and an unsupported-claim penalty). We instantiate this control system with DSPy (Khattab et al., 2024) as both the context assembler and the source of the strongest non-adaptive baseline (a DSPy BootstrapFewShot static prompt), and evaluate it across three verifiable task domains -- tool-use workflows, code generation (HumanEval), and multi-hop retrieval QA (HotpotQA) -- and two model providers (a local Ollama model and AWS Bedrock). We release the harness-control-system code, the cross-domain verifiable task suite, the full trajectory/reward-decomposition logs from training, and a provider-agnostic deployment recipe for applying this to a new organization's domain and verification setup.

### 1. 论文的核心问题与整体含义（研究动机和背景）

- **背景**：生产环境中的LLM智能体并非只是一个模型，而是“模型 + 封装（harness）”的复合体——包括提示模板、工具集、记忆/检索层、规划策略和验证策略。2026年的多项研究（如Zhang等）指出，**封装本身往往比底层模型更能决定智能体的性能表现**。
- **现有方法的不足**：2026年的两个代表性系统——Meta-Harness和HyperAgents——虽然证明了封装可以被优化甚至自我重写，但它们允许LLM生成或改写任意封装代码，带来三个关键问题：
  - **成本高昂**：需要额外的智能体提议者循环或自编辑元智能体，每次候选都消耗额外的模型调用；
  - **难以审计**：回归是一个针对任意先验程序的diff，无法准确定位到某个具名杠杆；
  - **场景受限**：要求具备可自我编辑执行环境的编码能力，排除了防火墙后普通聊天补全API这一常见生产场景。
- **本文的核心立场**：对于一大类实际部署场景，更优的做法是**将封装定义为一个小型、固定、可枚举的动作空间，并用经典的、廉价的强化学习在线学习策略**。这带来了Meta-Harness和HyperAgents不优化的三个特性：可审计性（每个决策都是少量预先审查的具名配置之一）、黑盒兼容性（控制器无需代码执行权限）、多目标奖励（将合规性和无依据主张率作为一等信号，而非单一的任务准确率）。

### 2. 论文提出的方法论：核心思想、关键技术细节、算法流程

#### 核心思想
将“封装（harness）”视为被控制的变量——一个离散、可枚举的动作空间，通过在线强化学习（而非LLM代码生成）来学习最优控制策略。

#### 动作空间定义
- 封装被分解为**六个离散杠杆**，共构成 **3⁵ × 3 = 729种配置**：
  - **提示风格** ∈ {直接，结构化，反思性}
  - **工具策略** ∈ {从不，需要时，始终}（按领域重新解释，如检索强度）
  - **记忆策略** ∈ {无，类似成功案例，成功与失败案例}
  - **规划策略** ∈ {无，简要计划，计划与修订}
  - **验证策略** ∈ {无，最终检查，逐步验证}
  - **最大步数** ∈ {2，4，6}

#### DSPy作为上下文组装器
- 对于给定的任务和所选配置，构建一个DSPy签名（Signature）和模块（Predict、ChainOfThought或两遍草稿-修订模块），由各项策略决定指令、少样本示例、工具/段落暴露以及是否添加第二次廉价自检调用。
- 同一组装器同时用于在线控制器和静态基线，保证了比较的公平性。

#### 奖励函数
公式：R = wₛ·success + wᵥ·verifier score + w_c·compliance − wᵤ·unsupported claims − w_$·tokens/1000 − w_ℓ·latency/1000

各领域使用确定性验证器定义“正确”：编码用单元测试执行、工具使用用模拟后端的状态差异、检索用精确匹配（token-F1作为更软的验证器得分信号）。

#### 控制器
- **随机搜索**：在729种配置上均匀随机，作为下界。
- **ε-贪心上下文赌博机**：对任务特征向量做线性值估计，采用乐观初始化避免冷启动（未初始化赌博机的argmax确定性平局偏向动作0的陷阱）。
- **REINFORCE**：729个动作上的softmax策略，线性特征logits、熵正则化、移动平均基线。
- **DSPy静态基线**：固定配置（结构化提示、需要时工具、简要计划、最终检查），示范来自BootstrapFewShot一次运行——这是最强的非自适应提示，也是在线控制器必须击败的标杆。

### 6. 论文的主要结论与发现

- **头条结果（出乎研究者意料）**：在所有领域、所有模型（包括更强的Bedrock Sonnet）上，**DSPy优化的静态基线都匹配或击败了在线的自适应赌博机和REINFORCE控制器**，且通常token成本大幅更低（例如Bedrock Haiku工具使用：DSPy静态96%成功@285 tokens/episode vs. REINFORCE 62%@680 tokens）。
- **原因分析——样本效率差距，而非天花板**：这与Majumdar [2026]的发现一致——稠密策略在大型离散动作空间上需要Ω(M)量级的样本；主矩阵仅给在线控制器25–60 episodes，远低于M=729。专项的300-episode实验显示，即使预算放大5–12倍，两种控制器仍仅爬升至0.61–0.65，远低于DSPy-static的0.96——证据指向低平台期而非即将收敛。
- **实践指导**：这意味着在线控制器应从DSPy优化的静态基线引导启动，而非从均匀先验冷启动——这种顺序是“承重墙”而非“锦上添花”。
- **发现的三个关键陷阱及修复**：
  - **冷启动陷阱**：全零Q值下numpy.argmax向动作0确定性平局，导致工具策略=从不的配置被锁定。修复：乐观初始化+随机平局打破。
  - **崩溃隔离缺陷**：强模型Sonnet上“计划与修订”在编码领域偶发崩溃，一个格式错误的无提示词耗尽了token预算，导致同一作业中其他39个episodes全灭。修复：每episode独立try/except，解析失败视为普通失败episode（奖励0）。
  - **测量陷阱**：DSPy的LM磁盘缓存命中时返回空usage字典，导致token/成本被静默低估（尤其对高度复用的DSPy-static基线）。修复：用字符长度回退估计，并重跑全矩阵。

### 7. 优点

- **高度可审计的设计**：将封装控制在729个具名配置的受限动作空间内，回归可直接归因于某个杠杆，而非任意代码diff，这在生产环境极具价值。
- **黑盒友好**：控制器不需要代码执行权限，适用于任何聊天补全API，突破了Meta-Harness/HyperAgents的使用边界。
- **多目标奖励设计**：将合规性和无依据主张率作为一等信号纳入奖励，而非单一准确率，更贴近真实生产诉求。

### 8. 不足与局限

- **实验覆盖有限**：最多3个种子、729动作空间上仅25–60 episodes/轮（主矩阵），样本效率专项实验300 episodes仍不充分；OpenAI API key不可用导致模型覆盖不全。
- **领域真实性局限**：工具使用领域为合成的模拟CRM后端，非真实生产系统；无依据主张指标仅用于检索领域，且是词法重叠启发式，非通用幻觉检测器。
