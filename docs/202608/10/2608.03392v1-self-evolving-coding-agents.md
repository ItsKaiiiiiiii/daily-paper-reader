## 摘要
大型语言模型正越来越多地嵌入到软件工程工作流中，作为能够检查代码仓库、调用工具、执行测试、调试失败并生成补丁的编码代理。然而，尽管软件开发是一个动态、反馈丰富的过程，其中代码仓库不断演化、依赖关系变化、测试失败，修复尝试会留下可复用的经验，但大多数现有代理在部署后仍然基本保持静态。这种矛盾促使了关于自进化编码代理的研究日益增多，在这类代理中，代理通过根据先前的编码交互更新其框架、记忆、技能、工具、模型或协作结构来改进其未来行为。在本综述中，我们对这一新兴领域进行了系统性的综合。我们首先定义了自进化编码代理，并将其与传统编码代理和通用自进化代理区分开来。然后，我们建立了一个以对象为中心的分类法来表征这些系统中进化的内容，并辅以两个正交视角：进化何时发生，以及哪些软件特定的证据驱动了进化。在现有文献中，我们发现可执行反馈、仓库级上下文和编码轨迹使得软件工程作为一个自然领域在代理自进化中具有独特作用，但也引入了反馈可靠性、基准过拟合、安全性、可维护性、成本和泛化方面的新挑战。通过围绕这些维度组织现有工作，本综述旨在澄清自进化编码代理的概念边界，并为设计更具适应性、可靠性和软件感知能力的代理系统提供基础。我们收集的论文可在 https://github.com/zhouhao1024/Awesome-Self-Evolving-Coding-Agents 找到。

## Abstract
Large language models are increasingly embedded in software engineering workflows as coding agents that can inspect repositories, invoke tools, execute tests, debug failures, and generate patches. Yet most existing agents remain largely static after deployment, even though software development is a dynamic, feedback-rich process in which repositories evolve, dependencies change, tests fail, and repair attempts leave reusable experience. This tension has motivated a growing body of work on self-evolving coding agents, where the agent improves its future behavior by updating its framework, memory, skills, tools, models, or collaboration structures from prior coding interactions. In this survey, we provide a systematic synthesis of this emerging area. We first define self-evolving coding agents and distinguish them from conventional coding agents and general self-evolving agents. We then develop an object-centered taxonomy that characterizes what evolves in these systems, and complement it with two orthogonal perspectives: when evolution occurs and what software-specific evidence drives it. Across the literature, we find that executable feedback, repository-level context, and coding trajectories give software engineering a distinctive role as a natural domain for agent self-evolution, but also introduce new challenges in feedback reliability, benchmark overfitting, safety, maintainability, cost, and generalization. By organizing existing work around these dimensions, this survey aims to clarify the conceptual boundaries of self-evolving coding agents and provide a foundation for designing more adaptive, reliable, and software-aware agentic systems. The papers we collect can be found at https://github.com/zhouhao1024/Awesome-Self-Evolving-Coding-Agents.

### 2.2 对象中心分类法（五类演化对象）

| 类别 | 核心思想 | 代表性系统 |
|------|---------|-----------|
| **代理框架自演化** | 将编码代理本身视为可修改的软件工件，代理能检查、编辑、验证自己的实现代码 | SICA、SIFT、STOP、Darwin Gödel Machine、Mendel Gödel Machine、Huxley Gödel Machine |
| **记忆自演化** | 持续构建、精炼和复用以存储软件经验（问题解决轨迹、仓库历史、补丁成败、测试结果等）的记忆组件 | SWE-Exp、EvoCoder、Subtask-Level Memory、EvoRepair、Repository Memory、SAGE |
| **技能与工具自演化** | 将软件工程经验转化为可复用的操作能力（技能），或由代理自主创建/改进工具 | CODESKILL、GSkill、Socratic-SWE、EffiSkill、Live-SWE-Agent |
| **模型自演化** | 更新模型侧组件（基座模型、适配器、代理策略、奖励模型、验证器），通过自生成轨迹和可执行反馈进行训练 | Self-play SWE-RL、Agent-RLVR、ReVeal、CURE、ZeroCoder、Sol-Ver、ACE |
| **工作流与拓扑自演化** | 让工作流、代理角色和通信拓扑结构随任务难度、执行反馈和验证需求自适应调整 | SEW、AFlow、EvoAgentX、SEMAG、EvoMAC、AgentConductor |

### 2.3 演化时间维度

- **任务内演化（Task-time）**：在解决当前编码任务的过程中即时调整，如测试失败或编译错误导致立即修改当前补丁、工具使用或工作流。
- **任务后演化（Post-task）**：任务结束后，将完整轨迹抽象为记忆、技能、仓库知识或修复经验，供后续任务复用。
- **阶段式演化（Stage-wise）**：积累大批量软件交互证据后，进行更持久的模型策略更新，如自博弈训练、基于验证结果的策略更新等。

### 2.4 演化证据维度

- **结果证据（Outcome Evidence）**：如基准解决率、测试通过率、验证器评分等，用于选择/淘汰候选演化变体，提供选择压力。
- **环境反馈（Environmental Feedback）**：如编译诊断、运行时异常、失败测试日志、工具输出等，指导正在进行中的任务内调整。
- **轨迹衍生证据（Trajectory-Derived Evidence）**：完整代理行为记录，用于构建经验库、仓库记忆、技能库等长期知识资产。

## 6. 论文的主要结论与发现

- **核心发现 1**：可执行反馈（单元测试、编译错误、运行轨迹、CI 结果）、仓库级上下文和编码轨迹，使软件工程成为代理自演化的**独特天然场景**，但也带来独特的可靠性挑战。
- **核心发现 2**：自进化编码代理不能被视为单一技术，而应被理解为一族**基于可执行软件工件与仓库级上下文的适应过程**。
- **核心发现 3**：现有方法沿“代理框架、记忆、技能与工具、模型、工作流与拓扑”五个对象方向演化，且不同对象可同时演化，分类之间存在交叉。
- **核心发现 4**：演化时间（任务内/任务后/阶段式）与演化证据（结果/环境/轨迹）共同决定演化的**持久性、成本和可靠性**。
- **核心发现 5**：当前评估体系在衡量功能正确性与基准成功方面较强，但在**长期可维护性、鲁棒性、安全性**以及从不完整/误导性软件反馈中学习可靠行为的能力方面仍较薄弱。
- **核心发现 6**：自进化带来的核心挑战不是“让代理演化”，而是**让演化可信**——需要验证反馈、修订过期记忆、审计学习到的技能、约束自我改造，并评估超越即时任务成功的长期软件质量。
