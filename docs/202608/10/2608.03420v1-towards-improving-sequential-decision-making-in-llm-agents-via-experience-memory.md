## 摘要
大型语言模型在单次推理任务上取得了显著进步，但它们在序贯决策中的表现尚未得到充分理解。我们在完全可观测的双人零和博弈中研究这一问题，这类博弈提供了真实评估：结果由规则决定，单个棋步的最优性可以被计算或近似，而无需依赖裁判模型。在不同级别的模型中，LLM在井字棋或四子棋等简单游戏中表现出次优水平，并且输给MCTS对手。一些混淆操作保留了博弈树但改写了其表面形式，性能基本不变，这表明这一差距并不能完全用记忆策略的召回来解释。受这一性能差距的启发，我们引入了一个代理框架，该框架增强了为序贯设置设计的经验记忆，并解决了序贯决策中的常见挑战，如信用分配。我们证明，赛后反思和规则提取在不修改模型权重的情况下，能在井字棋上带来可衡量的改进。

## Abstract
Large language models have improved substantially on single-shot reasoning tasks, but their performance in sequential decision-making is less well understood. We study this on fully-observable two-player zero-sum games, which provide ground-truth evaluation: outcomes are determined by the rules, and optimality of individual moves can be computed or approximated, without relying on a judge model. Across model tiers, LLMs play suboptimally in simple games such as tic-tac-toe or Connect Four, and lose to MCTS opponents. Obfuscations that preserve the game tree but rewrite its surface form leave performance largely unchanged, indicating the gap is not fully explained by recall of memorized strategies. Motivated by this performance gap, we introduce an agentic framework enhanced with an experience memory designed for the sequential setting and addressing common challenges of sequential decision-making such as credit assignment. We show that post-game reflection and rule extraction yield measurable improvements on tic-tac-toe without modifying the model weights.

## 方法论

**核心思想**

REAPER 保留了 LLM 作为主要推理器，通过构建结构化的**经验记忆系统**，在决策时向模型提供来自过去博弈的检索案例和提炼出的策略规则。其核心创意在于将**案例推理**适配到序贯决策环境，解决两个关键结构性挑战：**延迟奖励下的信用分配**和**从已知状态到未知状态的泛化**。

**关键技术细节**

1. **架构基础**：REAPER 采用 planner-executor 循环架构，通过结构化 JSON schema 确保组件间通信的健壮性。规划器输出计划或最终答案，执行器逐步执行子任务，循环最多 3 次迭代。

2. **游戏缓冲与逐回合反思（Self-Reflector）**：每步决策存入游戏缓冲，终局后由反思器在一次遍历中分析完整轨迹，沿两个独立维度对每步打分——**局部质量**（该步在当时状态下是否合理）和**结果贡献**（该步对终局的影响）。这取代了将终局奖励均匀分配到所有步的粗糙策略，使得输局中的局部最优步不被错误惩罚。

3. **规则提取器（Rule Extractor）**：每固定局数后，将新积累的带有反思的案例与现有规则集合并，提炼出约 20 条**位置无关**的通用战略原则。规则集的周期性重建使其具有自纠正能力，能合并重叠规则、移除被新证据反驳的规则。

4. **检索机制**：以状态观测的 SimCSE 句子嵌入为键，用余弦相似度检索 k=8 个最相似案例。采用**分层抽样**，从正面和非正面案例中各取约一半，避免检索邻域被单一结果主导。

5. **状态描述器（辅助组件）**：将原始状态观测转换为自然语言描述后再嵌入检索，旨在解耦检索与表面形式；消融实验显示该组件反而降低性能（描述同一状态的文本嵌入彼此不够接近），故未纳入主配置。

**工作流程**：在线决策循环中，每步检索相似案例 + 当前规则 → 组合注入 planner 提示 → 执行动作；每局结束后运行反思器，每 N 局后运行规则提取器。

## 实验设计

**博弈场景与基准**

- **井字棋**（Tic-tac-toe）：小博弈树，最优结果为平局，测试避免失败的能力；
- **尼姆**（Nim）：初始局面 {1,3,5,7}，先手必败，测试基于 Nim-sum 的符号推理能力；
- **四子棋**（Connect Four）：大博弈树，先手必胜，测试长视距规划和多重威胁构建能力。

**评估框架与对手**

作者开发了 **PlyBench** 框架，基于 OpenSpiel 引擎，通过接口适配器和 LLM 适配器统一不同类型玩家（LLM、MCTS、Optimal、Random）。对手设置：

- **Random**：均匀随机动作；
- **MCTS**：模拟预算 n=1000（井字棋/尼姆）或 n=5000（四子棋）；
- **Optimal**：Minimax 最优解，平局时均匀随机打破。

**评估模型**

按能力分三个层级：

- **Efficient**：GPT-5 nano、Gemini 3.1 Flash Lite、GPT-OSS 120B；
- **Intermediate**：GPT-5 mini、Gemini 3 Flash、Qwen 3.5 122B；
- **Frontier**：GPT-5.4、Gemini 3.1 Pro、GLM-5.2。

**对比方法**

- 单次调用参考（直接 LLM 推理）；
- Original（Memento 直接移植）；
- Baseline（工程化改造的案例推理变体，含结构化输出、去重、分层检索）；
- REAPER（反射+规则）、反射单独变体等。

**评估指标**

井字棋和尼姆报告**每步最优率**（排除所有动作均最优的状态），四子棋报告胜率和平均步数；REAPER 实验以**平局率**为主要指标（对 Optimal 对手最优可达结果），并报告每步输出 token 数作为推理成本度量。

## 主要结论与发现

1. **序贯决策差距真实且普遍**：Efficient 和 Intermediate 级模型在井字棋上每 100 步错 4~12 步，部分模型无法输出合法动作；Frontier 级模型在四子棋中对 MCTS 对手全部落败，平均仅支撑 10.3 步（远短于双优完备博弈所需的 20+ 步）。
2. **差距并非记忆问题**：表面形式混淆后性能基本不变，模型经常能从规则本身识别出隐藏博弈；即使识别率骤降（如 M.Sq+5 上 Gemini 3.1 FL 仅 25.6% 识别但最优率仍 99.1%），性能也不随之下降，指向决策时推理瓶颈。
3. **REAPER 有效改进了序贯决策**：相比之下，直接移植 Memento（Original）完全无法工作（平局率为 0）；工程化 Baseline 达到 81.8% 平局率；REAPER 进一步达到 86.8%，两两差异均统计显著（p=0.018），每步最优率 97.0%。
4. **效率与性能并不冲突**：REAPER 在提升性能的同时，输出 token 数在训练过程中持续下降，最终低于 Baseline 和单次调用参考，说明改进来自更有效的决策上下文而非更长的推理链。
5. **推理努力与性能呈正相关但成本高昂**：从 low 到 high effort，GPT-5 nano 最优率提升约 15 个百分点，但输出 token 增加 7 倍。

## 优点

- **评估设置严谨且可验证**：选择完全可观测零和博弈，每步最优性可由 Minimax 精确判定，无需 LLM 裁判，消除评估中的主观偏差。
- **混淆实验设计精巧**：通过保持博弈树同构的表面改写隔离记忆与推理的解释力，为同类研究提供了范式参考。
- **方法不修改权重、通用性强**：REAPER 在保持 LLM 完全不变的前提下通过外部经验记忆提升性能，避开了权重微调的成本和风险。
- **消融设计系统清晰**：逐步从 Memento 移植到工程化 Baseline 再到 REAPER，明确分离每个组件的独立贡献。
- **统计报告规范**：提供置信区间、单侧 Welch t 检验，多次独立运行。
- **框架模块化程度高**：PlyBench 可通过适配器接口加入任意博弈和玩家，REAPER 的各组件以独立开关暴露，便于后续扩展。

## 不足与局限

- **验证范围有限**：REAPER 仅在井字棋上做完整验证，未在尼姆或四子棋上测试，无法确认方法在长视距、大博弈树任务中的有效性；四子棋的评估局数过少（10 局/模型），结论的统计效力有限。
- **单一模型验证**：REAPER 实验只用了 GPT-5 nano，未检验在 Gemini、Qwen、GLM 等其他模型上的可迁移性。
- **案例检索依赖表面状态**：附录 D.4 显示以自然语言描述为检索键会降低检索成功率，说明经验记忆对状态表示的规范化和一致性有较强依赖。
- **计算资源未披露**：无 GPU/API 调用总量等成本信息，复现和横向比较存在困难。
- **混淆实验的局限**：模型可能识别出混淆背后的原始博弈（如表 5 中 Hid 和 M.Sq 的识别率很高），一旦识别就可调用记忆策略，因此无法彻底分离推理与记忆。
- **方法放大性问题**：检索和反思依赖 LLM 的自我判断，若模型本身存在系统性盲点（如对某类棋形持续误判），反思也可能将错误模式编码进记忆。
- **博弈类型的限制**：研究中均为完全可观测、确定性、回合制零和博弈，方法在部分可观测、随机性、非零和等更复杂环境中的表现未知，作者也在结论中承认了这一局限。

## 与既有工作的衔接关系

值得补充的是，REAPER 并非凭空提出的新范式，而是对 **Memento**（一种基于长期记忆单元的 RAG 变体）向序贯决策场景的系统性工程重述。作者在方法论中明确指出了 Memento 直接移植失败的结构性原因：其记忆检索以静态问答任务为设计假设，缺少对**延迟奖励**的处理，也缺少对**检索邻域中结果分布失衡**的干预。REAPER 的三个核心组件（逐回合反思、规则提取、分层抽样检索）恰好逐一回应了这些缺口。这种"从现有方法出发、诊断其失效根因、再针对性改进"的研究路径，比全新提出一个无渊源的方法具有更强的可解释性和可积累性，也使得消融对比（Original → Baseline → REAPER）在逻辑上更加自洽——每一级提升都可以归因于一个具体的设计决策。

## 研究定位与贡献层次

纵观全文，论文的价值可以拆分为两个层级：

- **诊断性贡献**：通过精心控制的博弈环境，首次以严格地面真值（Minimax 可验证的最优步）量化了从 Efficient 到 Frontier 各层级 LLM 在序贯决策上的系统性能差距，并借助混淆实验将"记忆不足"从解释空间中排除，将问题锚定为"决策时推理瓶颈"。这一诊断本身对 LLM 能力评估研究具有独立参考价值，甚至先于 REAPER 方法本身而成立。
- **方法性贡献**：REAPER 证明了在不修改权重的前提下，通过外部经验记忆的合理组织和检索，可以显著缓解这一瓶颈，且成本（输出 token）不升反降。这为后续工作在"测试时计算（test-time compute）"方向上提供了一个轻量级、模块化的基线参照。

两者叠加，使得论文在"问题发现"和"问题缓解"两个层面都有所建树，而非仅仅完成其中一项。

## 适用读者与潜在应用

从读者视角，这篇论文适合以下人群：

- **LLM 能力评估研究者**：PlyBench 框架和混淆实验设计可直接迁移到其他博弈或推理任务上，用于区分"知识缺失"与"推理失败"；
- **智能体/RL 研究者**：REAPER 的"反思 + 规则提取 + 分层检索"管道可作为无权重更新的策略改善模块，与现有 RL 微调方法叠加使用；
- **推理成本敏感的应用开发者**：论文证明了"更聪明的记忆组织"可以替代"更长的推理链"，这对实时交互系统中控制 token 成本具有直接借鉴意义。

潜在应用场景包括但不限于：棋类对弈辅助、多轮策略对话、需要长视距规划的具身智能任务，以及任何具备可观测状态和延迟奖励的决策环境。

## 最终评价

总体而言，这是一篇**诊断价值高于方法效能**、**实验严谨性高于方法新颖性**的实证型论文。它没有提出复杂的算法，但通过清晰的实验设计和对统计细节的认真对待，揭示了一个此前被 LLM 裁判式评估所掩盖的真实能力缺口，并给出了一个朴素但有效的缓解方案。论文的短板——验证范围狭窄、单一模型支撑结论——与其说是作者的疏忽，不如视为研究阶段性的诚实体现：作者明确承认了这些边界，没有过度声称方法的普适性。对于关注 LLM 智能体决策能力边界和 RAG 类经验增强技术的读者，这是一篇值得精读的扎实工作。
