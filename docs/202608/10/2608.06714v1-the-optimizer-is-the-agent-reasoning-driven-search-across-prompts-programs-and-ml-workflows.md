## 摘要
近期用于优化提示、程序和机器学习工作流的系统通常依赖显式外层循环控制器，如进化搜索、多臂老虎机或文本梯度方法。我们提出了一个根本不同的问题：这种搜索策略在多大程度上可以被一个使用工具的智能体内化？我们提出了ReASearch，一个统一的推理驱动优化框架，其中智能体自主决定评估什么、如何诊断失败、进行哪些修改以及何时验证或重启。智能体不仅仅是由手工设计的启发式规则引导的提案生成器，还主动分析结果、分配预算，并通过持久记忆在长时间跨度内细化其策略。通过共享的智能体循环和领域特定工具，ReASearch以完全相同的脚手架来优化提示、程序和机器学习工作流。在14个多样化的任务中，它与专门的优化系统相比具有竞争力，且大多优于后者，在强领域特定基线上实现了2%到40%的提升，在某些情况下发现了改进此前人类已知最优结果的解决方案。至关重要的是，我们观察到通常由显式控制器实现的复杂搜索行为，会从智能体的推理过程中自然涌现。

## Abstract
Recent systems for optimizing prompts, programs, and ML workflows typically rely on explicit outer-loop controllers such as evolutionary search, bandits, or textual-gradient methods. We ask a fundamentally different question: how much of this search policy can be internalized by a single tool-using agent? We present ReASearch, a unified framework for reasoning-driven optimization in which the agent autonomously decides what to evaluate, how to diagnose failures, which edits to make, and when to verify or restart. Rather than serving only as a proposal generator guided by hand-designed heuristics, the agent actively analyzes outcomes, allocates budget, and refines its strategy over long horizons through persistent memory. With a shared agent loop and domain-specific tools, ReASearch instantiates the exact same scaffold to optimize prompts, programs, and ML workflows. Across 14 diverse tasks, it is competitive with and mostly better than specialized optimization systems, achieving gains of 2% to 40% over strong domain-specific baselines, and in some cases discovering solutions that improve on prior human best-known results. Crucially, we observe that complex search behaviors, which are typically implemented by explicit controllers, emerge naturally from the agent's reasoning process.

### 核心思想

- 提出 **ReASearch**（Reasoning-driven Agentic Search）：一个**无外部控制器**的统一智能体框架。

  - 评估什么候选
  - 如何诊断失败原因
  - 做哪些编辑

## 六、主要结论与发现

1. **统一框架有效性**：单一 ReASearch 脚手架同时在 3 个领域 14 个任务上达到或超越领域专用优化系统，**提升幅度 2%~40%**。
2. **超越人类已知最优**：在 Circle Packing（如 n=30 时 2.843 vs. 已知 2.842；n=32 时 2.940 vs. 2.939）和 Heilbronn（多个 n 值达到/接近已知最优）等任务中发现接近或超越此前人类已知最佳的解。
3. **复杂搜索行为自然涌现**：双重复验、基于失败复用、刻意回退、自适应探索等现象均非硬编码，而是从推理中自发产生。
4. **因果诊断优于无状态生成**：持久上下文让智能体能够定位根因（如 EPLB 的 donor 约束瓶颈）、抽象出数学结构（如 Heilbronn n=12 的 D4 对称性），并拆分/组合复合算法（如 circle packing 的 LP 内循环）。
5. **ML 工作流优化中 harness 差异是主要驱动因素**：差距不是来自指令，而是来自每轮强制重新渲染搜索状态（最佳结果、最近实验、持久教训、停滞警告）。
6. **开放骨干可行但性能有差距**：GLM-5/Kimi-2.5 可支撑 ReASearch，效果略逊于 Claude/GPT 骨干。

## 七、优点

- **范式创新**：消解了"外层控制器 + 内层 LLM"的二元结构，证明推理驱动的代理本身即优化器，具有较高理论与概念价值。
- **统一性**：同一脚手架跨 3 个领域零架构变更，凸显框架的通用性和可扩展性。
- **工具设计的深思熟虑**：将 `python_exec` 作为核心推理工具，使智能体从文本推理器升级为计算推理器；`lessons.md` 持久记忆有效支撑长周期优化。
- **显著的实验深度**：14 任务 + 多轮消融 + 定性轨迹分析 + 开放骨干验证，兼顾广度与纵深。
- **优异的实证结果**：部分任务的解超越已知人类最优，尤其在 Circle Packing 与 Heilbronn 上具有说服力。
- **诚实分析**：详细剖析了与 Claude Code 的差距来源（harness 而非指令），并明确指出验证反馈粒度的过拟合风险。

## 八、不足与局限

- **硬件/算力透明性不足**：未披露 GPU 型号、数量和总训练算力，难以评估实际工程成本与可复现性。
- **最终 prompt 选择的主观性**：允许智能体基于历史合成未验证的新 prompt 并直接在测试集上评估，虽符合"智能体自主决策"的理念，却偏离了严格的无偏验证协议，可能高估测试性能。
- **基线对比不对称风险**：部分对比（如 ARC-AGI-2）中不同方法使用了不同的 backbone 模型（GPT-5 vs. Sonnet 4.6），且 AdaEvolve 的配置未必在每任务上做过针对性调优；领域专用系统的优势（如每任务精细 tuning）未被充分挖掘。
- **开放骨干性能差距**：在 Terminal-Bench 2.0 上，GLM-5 和 Kimi-2.5 的效果（~15% 和 ~8%）远低于 Claude Sonnet 4.6（~23%），说明 ReASearch 的性能高度依赖底层模型的智能体能力。
- **涌现行为的可解释性与可控性**：虽然观察到验证、回退等行为"自然涌现"，但这些行为并非严格保证，不同任务间的一致性有待更多实验验证。
- **高方差问题**：多个任务（如 Terminal-Bench 验证集）的标准差达 5~10%，单次运行可信度有限；Agent 轨迹的随机性使得结论在同一配置上也存在波动。
- **应用边界不清**：所有任务均为个体化优化场景（单实例优化、单数据集调优）；ReASearch 在多任务联合优化、跨域迁移、大规模生产环境中的表现仍属未知。
- **成本与延迟**：虽然 API 成本低于 $20，但长轨迹（数百轮推理）的实际延迟、显存占用与每秒吞吐等指标未报告，限制了在实时系统的部署评估。
