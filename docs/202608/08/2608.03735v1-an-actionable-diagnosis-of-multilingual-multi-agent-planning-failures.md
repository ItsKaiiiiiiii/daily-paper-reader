## 摘要
多语言多智能体系统在英语之外表现出显著的性能下降，然而以往的工作很少明确指出当用户请求被转换为可执行计划时，任务关键信息是如何丢失的。我们将多智能体系统中的规划器视为请求到动作的接口，并从失败的真实世界任务执行中推导出一个可操作的规划-落地失败分类法。基于LLM的分析表明，随着语言资源可用性的下降，这些失败在不成功执行中所占的比例不断增加，在低资源语言中影响最为显著。为了测试该分类法是否支持缓解措施，我们引入了TART，即分类法引导的可操作表示，它使分类法的关键方面对规划器和下游子智能体明确可见。在多种语言、三个LLM骨干、两个数据集和两种智能体配置中，TART始终能提升性能。在多语言GAIA上，它将一个最先进系统的准确率平均提高了5.6个百分点，涵盖了从低资源到高资源环境的十一种语言。

## Abstract
Multilingual multi-agent systems exhibit substantial degradation beyond English, yet prior work rarely identifies how task-critical information is lost when user requests are converted into executable plans. We study the planner in a multi-agent system as the request-to-action interface and derive an actionable taxonomy of planning-grounding failures from failed real-world task executions. LLM-based analysis shows that these failures constitute an increasing share of unsuccessful executions as language-resource availability declines, with the strongest effects in low-resource languages. To test whether the taxonomy supports mitigation, we introduce TART, Taxonomy-Guided Actionable Representation, that makes the taxonomy's key aspects explicit to the planner and downstream sub-agents. Across multiple languages, three LLM backbones, two datasets, and two agentic configurations, TART consistently improves performance. On multilingual GAIA, it raises a state-of-the-art system's accuracy by 5.6 percentage points averaged across eleven languages spanning low- to high-resource settings.

## 1. 论文的核心问题与整体含义（研究动机和背景）

- **背景**：基于语言模型的多智能体系统正被日益多样化的语言用户群用作通用工具。系统需要将用户请求翻译为可执行计划、协调专业智能体、调用工具并生成答案，其可靠性依赖于跨语言保持用户目标和约束的能力。然而，训练数据中的语言资源分布不均，跨语言可靠性成为一个重要挑战。
- **核心问题**：多语言多智能体系统在英语之外表现出显著的性能下降，但以往工作很少从系统内部系统地描述哪些任务关键承诺在请求→计划的转换过程中丢失或扭曲。作者聚焦于**“规划器”** 作为请求到动作的接口，指出了这一界面上的误解尤其致命——因为任何扭曲都可能传播到整个多智能体工作流。
- **核心概念定义**：**规划-落地失败（planning-grounding failure）** 指用户请求与生成计划之间的不匹配，即使计划被正确执行，结果也不会满足原始请求（如替换目标实体、遗漏关键来源或日期、操作顺序错误等）。
- **整体含义**：多语言失败并非随机的、模型特定的错误，而是系统性的、可结构化的错误模式，且这些模式可以被定位和缓解。这一发现为构建更稳健、对多语言用户更友好的多智能体系统提供了根本性的新视角。

## 2. 论文提出的方法论：核心思想、关键技术细节

### 2.1 分类法推导（Taxonomy Derivation）

- **核心思想**：从真实失败样例中归纳出可操作的规划-落地失败分类法。
- **推导流程**：
  1. **计划提取**：筛选出模型在英语查询上成功、但非英语查询上失败的配对案例。
  2. **人工分析协议**：逐个分析失败对，结合成功计划、失败计划和原始问题，诊断任务约束和逻辑推理的差异，并进行分类。
  3. **可操作性要求**：类别必须足够具体，能直接指导计划改进。
  4. **停止标准**：顺序分析直到饱和——即新样本只产生已有类别时停止。
- **开发集配置**：分类法在**与后续缓解实验完全不相交的模型和框架**上推导，防止过拟合——使用 Qwen2.5-32B-Instruct 和 Cohere Aya-Expanse-32B（量化实验未使用），框架为 Open Deep Research。在 80 个失败样本（覆盖 Igbo、Yoruba、Bengali、Swahili、Kyrgyz、Nyanja 六种低资源语言）后达到分类法饱和。

### 2.2 五类规划-落地失败分类法

| 类别 | 定义 |
|------|------|
| **实体落地失败** | 计划误译查询实体、幻觉出查询不存在的实体、或替换了原始问题中从未出现的实体 |
| **来源落地失败** | 计划改变了指定的来源标识符（如附件文件名），或到达正确来源但遗漏了检索后过滤条件 |
| **时间落地失败** | 计划改变了查询中指定的时间段，或完全遗漏时间范围 |
| **操作落地失败** | 计划虽保留所需约束，但采用了不合理的推理或逻辑，在某些情况下改变了任务目标 |
| **答案格式落地失败** | 计划在约束和推理上基本正确，但答案以错误的格式表达 |

### 2.3 TART 缓解方法

- **TART（Taxonomy-Guided Actionable Task Representation，分类法引导的可操作任务表示）** 是一个语义解析协议，在规划开始前生成规划-落地信息的结构化表示。
- **结构对应**：TART 字段与分类法一一对应——实体、时间约束、来源约束、附件类型、操作、答案类型。
- **注入机制**：TART 不只由规划器消费一次，而是注入到规划器、协调器和下游子智能体的系统提示中，使约束在整个流水线每个阶段都保持可见——每一步推理和任务分配都锚定在同一组显式实体上。
- **生成方式**：使用 LLM 将查询（任何语言）转换为结构化 JSON，明确要求不翻译、不回答、不生成计划，只提取显式或强烈暗示的信息。
- **TART 的 JSON 字段**：
  - `entities`（实体列表）
  - `time_constraint`（时间约束）
  - `source_constraint`（来源约束列表）
  - `attachment_type`（附件类型：none/table/document/image等）
  - `operations`（操作：retrieve/extract/filter/compute等）
  - `answer_type`（答案类型：number/string/list等）
- **无需修改模型参数或替换多智能体框架**，纯粹作为语义契约注入现有流水线。

## 6. 论文的主要结论与发现

1. **语言资源梯度效应明显**：随着语言资源可用性从高到低，分类法覆盖的失败占不成功执行的比例不断增加，尤其是"操作落地失败"和"实体落地失败"；相反，未分类的"其他"失败占比和答案格式失败的占比下降。
2. **操作落地失败是最主要的分类法覆盖类别**：三种模型下分别占失败的 24.0%（GPT-5-mini）、36.5%（Mistral-Large-3）和 30.2%（Qwen3-VL）。
3. **TART 持续有效**：跨 3 个模型家族、2 个数据集、多种语言，TART 始终提升性能，且**从未出现显著性能下降**（唯一例外是 GPT-5-mini 在俄语上 -0.6 点的微小波动）。
4. **组件贡献具有累积性**：消融实验表明，表面约束（实体/时间/来源）+ 操作 + 完整表示逐步累加，完整 TART 在所有语言上达到最佳效果。操作字段对最低资源语言（如 Igbo）贡献最大（+7.3/9.1 点），与操作落地失败主导低资源语言的量化结论一致。
5. **Level 3 复杂任务提升有限**：TART 在 Level 1（+9.0点）和 Level 2（+5.0点）有明显提升，但 Level 3 基本无变化。作者通过分析指出这**不是**因为 Level 3 可纠正的规划失败更少（Level 2 和 3 的分类法覆盖率相同，均为 55.2%），而是因为 Level 3 任务本身的复杂性（参考步骤近乎翻倍：7.48→13.00，工具数 2.55→3.38），下游执行链较长、独立出错机会多，即便规划层修复了初始错误。

## 7. 优点

- **分类法兼具诊断性和可操作性**：不只是描述失败的类别，每个类别直接对应 TART 的一个表示字段，做到"识别→定位→缓解"的完整闭环，是首个从失败分类法直接推导出缓解方法的作品。
- **严谨的推导流程**：分类法在不相交的模型/框架配置上推导，防止过拟合；通过饱和性停止标准保证类别的完备性；多位研究员交叉确认分类一致性。
- **多层次验证体系**：LLM judge 的失败量化由人工标注验证（宏F1=0.906），量化结论和 TART 的改进效果相互印证——操作的失败模式恰恰是 TART 所针对的类别，形成逻辑闭环。
- **实验覆盖的广度出色**：11 种语言遍布高资源（英语 40.58% CC份额）到极低资源（Nyanja 0.0008% CC份额）跨五个数量级；3个模型家族涵盖不同规模与厂商。
- **细致的消融与Level分析**：不只报告总体提升，还拆解了各组件的贡献，并且对 Level 3 平台期进行了多角度的归因分析（分类法覆盖率 vs 任务固有复杂度），避免了过度解读。
- **可落地性**：TART 不要求修改模型参数、不替换多智能体框架，只需在现有流水线中注入结构化提示即可实现提升，实际部署门槛低。

## 8. 不足与局限

- **机器翻译引入的偏差**：GAIA-MAPS 的 6 种低资源语言由 Google Cloud Translation 生成，与自然语言使用模式可能存在差异。虽然 Baseline/方法公平性不受影响（两者接受相同翻译），但其外部有效性在真实低资源查询场景下有待验证。
- **分类法推导的采样偏差**：仅从"英语成功+非英语失败"的 80 个样例推导，可能遗漏英语中也普遍存在或跨语言共有的失败模式；低资源语言覆盖有限（仅 6 种），可能未穷尽全部失败类型。
- **LLM judge 的局限性**：大规模失败量化依赖 Claude Opus 4.8 作为 judge，人工验证仅覆盖了一个模型（Mistral-Large-3）的约14%样本，未覆盖 GPT-5-mini 和 Qwen3-VL；judge 在不同语言、模型和类别间的校准可能不一致。
- **运行稳定性验证不足**：仅 GPT-5-mini 做了重复运行验证，Mistral-Large-3 和 Qwen3-VL 基于单次运行，缺乏方差估计，可能高估方法的稳定一致性。
- **Level 3 效果有限**：TART 对最困难的 GAIA Level 3 任务几乎无提升，且 Qwen 模型在 Level 3 上还有轻微下降——对最复杂场景的适用性有限，仍需其他手段补充。
- **未探索交互效应**：分类法对"语义契约"的依赖假设规划失败源于信息丢失/扭曲，但可能在部分场景下（如语言本身与目标领域不匹配）改进受限；未分析与任务类型（如网页交互 vs 文档问答）的交互效应。
