## 摘要
基于多智能体强化学习训练LLM多智能体系统正迅速获得关注，而并行的一类工作则认为这类系统应根据其行为而非仅凭奖励来评判。我们在空间合作游戏中同时探讨了这两条研究路线，其中使用低层动作提示的小型冻结LLM会彻底失败，获得零奖励。在选项/半马尔可夫决策过程框架的指导下——并且由于选项在不同智能体间异步执行，需借助其在宏动作Dec-POMDP中的多智能体扩展——我们为每个游戏配备了一个符号化\emph{选项}库：由符号化规划器执行的类型化、状态可行、短时域行为。每个库由前沿编码模型根据游戏源代码起草；随后通过廉价的随机策略预热回放自动合成过滤各菜单的可行性守卫——只有当守卫能解释反复出现的执行失败且不隐藏任何已记录的成功时才会被采用——因此没有任何守卫是手工编写、选择或通过奖励调优的。每个智能体的LLM充当其选项上的策略，并通过多智能体GRPO的逐智能体变体（PA-MAGRPO）训练私有的逐智能体LoRA适配器；这将冻结的基础模型从零奖励提升到在三个游戏和四个小型骨干网络上的熟练表现。随后的行为审计表明奖励与协作解耦：上升的奖励曲线可能仅意味着一个智能体学会了独自完成整个任务，而其同伴闲置——只有当任务使协作成为必要时，协作才会出现。因此，仅凭奖励不足以可靠评估协作；行为评估必须与之并行。

## Abstract
Training LLM-based multi-agent systems with multi-agent reinforcement learning is rapidly gaining traction, and a parallel line of work argues that such systems should be judged by their behavior, not only their reward. We take up both threads in spatial cooperative games, where small frozen LLMs prompted with low-level actions fail outright, earning zero reward. Guided by the options/semi-MDP framework---and, because option execution is asynchronous across agents, its multi-agent extension in macro-action Dec-POMDPs---we equip each game with a library of symbolic \emph{options}: typed, state-feasible, short-horizon behaviors executed by a symbolic planner. Each library is drafted by a frontier coding model from the game's source code; the feasibility guards that filter each menu are then synthesized mechanically from cheap random-policy burn-in rollouts---a guard is adopted only if it explains repeated execution failures while hiding no logged success---so no guard is authored, selected, or reward-tuned by hand. Each agent's LLM acts as its policy over options, with a private per-agent LoRA adapter trained by a per-agent variant of multi-agent GRPO (PA-MAGRPO); this lifts frozen bases from zero reward to competent play across three games and four small backbones. Behavioral audits then reveal that reward and cooperation decouple: a rising reward curve may simply mean that one agent has learned to run the entire task alone while its partner idles---cooperation emerges only when the task makes it necessary. Reward alone is thus an unreliable readout of cooperation; behavioral evaluation must sit alongside it.

## 1. 论文的核心问题与整体含义

**研究动机与背景：**
- 论文关注两个并行研究趋势的交叉点：一是用多智能体强化学习（MARL）训练基于LLM的多智能体系统；二是该类系统应通过**行为**而非仅凭奖励来评判。
- 核心问题：**小型LLM（2–4B参数）能否被训练为空间合作游戏中的多智能体策略？** 若直接让冻结的小模型输出原始低级动作（如上下左右、交互），模型完全失败、获得零奖励。
- 作者识别出三个核心障碍：
  1. **接地鸿沟（Grounding Gap）**：小模型无法将高层目标（如“清理我北边的脏污”）转化为环境期望的原始动作——它们会幻觉空间前提条件并坍缩到单一“安全”动作上。
  2. **视野问题（Horizon Problem）**：回合长达数百个原始步骤，而奖励是稀疏的团队奖励，优化器几乎得不到逐决策的信用信号。
  3. **特化问题（Specialization Problem）**：合作常要求智能体表现不同，但共享权重的团队训练会平均掉冲突的角色梯度，导致所有智能体收敛到相同行为。

**整体含义**：本文提供了一套完整可行的配方，将小LLM从零奖励提升为胜任的协作策略，并进一步证明**奖励与合作解耦**——奖励曲线上升不必然意味着合作涌现。

## 2. 论文提出的方法论

### 2.1 核心思想
将LLM的决策空间从低级原始动作提升到**符号化选项库（symbolic option library）**，让LLM在每个决策点从一组“当前可行”的选项菜单中选择一个选项；选项的实际执行交由符号规划器完成。LLM只决定“做什么”，不负责“怎么做”。

### 2.2 形式化建模
- 每个智能体的决策问题被建模为**semi-MDP**（因为决策只发生在选项边界）。
- 因为各智能体的选项异步开始和结束，团队级问题被建模为**宏动作Dec-POMDP（macro-action Dec-POMDP）**。
- 选项 z = ⟨I_z, π_z, β_z⟩，其中 I_z 为启动集（initiation set）、π_z 为选项内策略（符号执行器）、β_z 为终止条件。

### 2.3 选项库构建流水线（四阶段）
- **Stage 1（唯一一次模型调用）**：Claude Opus 4.8 读取游戏源码，起草类型化选项库，每个选项带四部分合约：实例化规则、执行器、终止条件、**效果谓词**（post-condition，以差值形式写作）。
- **Stage 2（无LLM）**：用均匀随机策略进行burn-in回放，记录每个选项执行的成败结果（由效果谓词判定，与奖励无关），约55万决策在单CPU核上约70秒完成。
- **Stage 3（守卫合成）**：从burn-in数据中机械地合成可行性守卫：
  - **显式通道**：类型化失败理由出现≥5次即成为守卫。
  - **推断通道**：覆盖≥5次失败且**零成功**的1/2字面量合取被采纳——纯度要求是验收证书，防止策略知识混入守卫集合。
- **Stage 4（菜单组装）**：固定代码为每个目标实例化菜单项，评估守卫进行过滤，并按决策随机打乱菜单字母顺序（防止位置泄露选项身份）。
- **外层合约修复循环**：若Stage 1的合约本身有缺陷（如谓词写成绝对形式、共享状态归因错误），机械层检测到异常后由前沿模型修复schema并重跑Stage 2–3。

### 2.4 训练算法：PA-MAGRPO
- 每个智能体 i 拥有**私有LoRA适配器** θ_i，共享一个冻结的基础模型 f，策略为 π_i(·|o_i) = f ∘ θ_i。
- 算法步骤（每轮）：
  1. 收集 K 条并行联合回放；
  2. 每条回放按共享团队奖励 R_k 评分；
  3. 在队列内归一化得到组相对优势 Â = (R_k − μ)/σ；
  4. 每个智能体仅在自己的决策上做PPO裁剪更新 + KL惩罚，只更新自己的LoRA。
- 更新仅发生在选项边界；由于使用回合制无折扣团队奖励，无需semi-MDP折扣机制。

## 5. 论文的主要结论与发现

1. **配方有效**：四种小型骨干×五种子下，冻结基线全部零奖励，全方法在所有游戏中获得正收益。固定骨干上：Cleanup苹果 0.00→93.25±16.84，Overcooked AA递送 0.20→6.80±1.89（34倍提升），Commons Harvest苹果 95.68±15.63。

2. **两个成分缺一不可**：
   - 去掉选项菜单（Ablation A）：三个游戏全部坍缩为零——原生动作时间尺度下随机探索几乎永远无法产生连贯的多步轨迹。
   - 去掉per-agent容量（Ablation B）：Cleanup仅0.10±0.45，Overcooked仅2.25±1.59（约全方法1/3）——共享适配器无法同时承载“清洁者”和“食客”两种角色。

3. **奖励与合作解耦（双向）**：
   - Cleanup：高奖励伴随真正的角色分工（3吃3清1辅助），无角色标签下涌现。
   - Overcooked AA：高奖励但**无协调**——一个智能体承担约69%装载工作并独立完成全任务，另一个72%时间在等待——奖励高估了合作；FC对照中合作才真正必需且涌现（单干递送为0，合作递送7.57）。
   - Commons Harvest：奖励曲线近乎平坦，但补丁存活率发生质变（冻结基线约200步耗尽全部6个补丁；训练系统400步仍有约2.5个存活）——奖励低估了合作。

4. **合作随任务激励结构涌现，而非随奖励曲线涌现**。

## 6. 优点

1. **“一次模型调用”的流水线设计**：前沿模型仅在构建选项库schema时调用一次，训练、评估、行动选择全程不再查询——训练成本被大幅压缩，且避免了推理时依赖昂贵API。
2. **守卫合成完全机械、可审计**：从随机burn-in数据中统计合成，纯度证书（零成功隐藏）从机制上排除人工策略偏见的注入。
3. **差值形式效应谓词 + 私有转换绑定的设计**：成功修复了绝对形式谓词的静默空操作问题和共享状态归因伪造问题，是工程细节上的亮点。
4. **行为审计方法论**：在奖励之外引入角色划分、等待比例、补丁存活等行为指标，为多智能体LLM评估提供了可推广的范式。
5. **AA/FC构成天然对照对**：在相同配方内比较“可选协调”与“强制协调”，隔离了任务结构对合作涌现的影响。

## 7. 不足与局限

1. **规模局限**：仅验证≤4B的小LLM；更大规模（如7B/70B）或非空间任务是否适用未测试。
2. **选项库为每游戏定制**：缺乏选择选项空间的通用原则，跨游戏迁移时需重新构建库。
3. **偏好与覆盖偏差**：消融套件用单训练种子，行为审计中角色分配检查基于单一seed（作者已承认）；Ablation套件跑在较早的“手工选守卫”接口版本上，与主实验（自动合成守卫）并非完全同版本。
4. **理论深度有限**：解耦发现是行为层面的实证证据，而非一般性理论；缺乏对“何时奖励能/不能预测合作”的形式化刻画。
5. **统计稳健性风险**：部分骨干表现方差极大（如Cleanup上std约等于均值），跨种子稳定性存在疑问；超参数按实验环境分别设定（Cleanup/Harvest vs. Overcooked不同），未做跨环境统一性验证。
6. **无计算成本报告**：未给出完整训练时长、GPU总时数、能耗等资源指标，可复现性和成本评估受限。
