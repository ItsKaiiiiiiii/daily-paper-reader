## 摘要
智能体系统不仅需要决定生成什么答案，还需要决定在回答之前应执行哪些推理和操作步骤。控制器可以直接回答、分解请求、检索证据、执行代码、委托给专家或验证中间结果。现有的路由工作大多独立地选择模型端点、检索深度或工具。我们引入了一个可执行的基准和一个预算感知的元路由器，它从原始任务文本中组合异构操作。该基准包含216个训练任务、72个开发任务、108个保留测试任务和108个锁定词汇转移挑战任务，涵盖数据分析、冻结语料库研究和文档处理。操作执行后，结果由机器进行检查。独立的正则化逻辑头部根据单词和字符特征预测操作概率，在开发数据上进行温度缩放，并在路由成本和操作数量预算下进行贪婪组合。在保留测试集上，学习策略达到了100%的成功率，而强大的静态和固定工作流程为93.5%，成本比静态策略低43%；匹配的学习型一次性路由器达到56.5%。在未接触的挑战分割上，学习成功率降至75.9%，落后于静态路由的93.5%，同时成本降低49%，比一次性路由高出34.3个百分点。这一差距表明，主要限制在于词汇泛化，而非路由执行。这些结果建立了一个可复现的测试平台和有限的可行性证明，并非实时LLM性能的证据。

## Abstract
Agentic systems must decide not only what answer to produce, but which reasoning and execution operations should precede it. A controller may answer directly, decompose a request, retrieve evidence, execute code, delegate to a specialist, or verify an intermediate result. Existing routing work largely selects model endpoints, retrieval depth, or tools in isolation. We introduce an executable benchmark and a budget-aware meta-router that composes heterogeneous operations from raw task text. The benchmark contains 216 training, 72 development, 108 held-out test, and 108 locked lexical-shift challenge tasks across data analysis, frozen-corpus research, and document processing. Outcomes are machine checked after operations execute. Independent regularized logistic heads predict operation probabilities from word and character features, are temperature-scaled on development data, and are greedily composed under route-cost and action-count budgets. On the held-out test, the learned policy achieves 100% success versus 93.5% for strong static and fixed workflows, with 43% lower cost than the static policy; a matched learned one-shot router reaches 56.5%. On the untouched challenge split, learned success falls to 75.9% and trails static routing at 93.5%, while remaining 49% cheaper and exceeding one-shot routing by 34.3 points. The gap identifies lexical generalization, rather than route execution, as the principal limitation. These results establish a reproducible testbed and a bounded proof of concept, not evidence of live-LLM performance.

## 1. 核心问题与整体含义

**研究动机与背景**

智能体系统（Agentic Systems）面临的关键决策不仅在于“生成什么答案”，更在于“在生成答案之前应执行哪些操作”。控制器可能直接回答、分解请求、检索证据、执行代码、委托专家或验证中间结果。然而，现有的路由研究大多集中在孤立地选择模型端点（如 FrugalGPT、RouteLLM）、检索深度（如 Adaptive-RAG）或工具调用，缺乏对不同类型操作间组合与预算约束的系统性研究。

本论文试图回答两个此前纠缠不清的问题：**控制器能否识别相关能力**（capability identification）与**组合多个能力是否优于选择单一能力**（composition benefit）。为此，作者构建了一个**可执行的元路由基准**和一个**预算感知的组合元路由器**，将路由决策从“选哪个模型/检索多少证据”提升到“应该执行哪些类型的推理与执行操作”这一新层面。

论文的核心主张是：**操作组合的价值与词汇泛化的脆弱性应被分开评估**。标准测试集上组合路由的成功不能掩盖其在词汇分布偏移下的显著退化。

## 2. 方法论

**核心思想**

- 将元路由建模为**多标签操作预测 + 预算约束下的贪心组合**。
- 路由器仅从原始任务文本 x 出发，预测应该包含哪些支持操作（支持操作集合 O = {D: 分解, T: 检索/工具, C: 代码执行, G: 专家委托, V: 验证}），并以回答动作 A 终止。
- 操作成本为预注册的归一化成本常数，如 D=0.45、T=1.00、C=1.15、G=1.40、V=0.65、A=0.30；预算 B=4.5，最大操作数 M=3。

**关键技术细节**

1. **特征表示**：从原始文本构造词 uni-gram、词 bi-gram、字符 3–5-gram 特征 φ(x)，共 3,349 维特征。
2. **预测模型**：对每个操作 o，独立训练一个正则化逻辑回归头：
   - p_o(x) = σ(w_o^T φ(x) + b_o)
   - 损失函数为类平衡二元交叉熵加 L2 正则化：L_o = WBCE(y, p_o(x)) + λ||w_o||²₂
   - 超参数：学习率 0.35/√(1+e/50)，λ=0.002，最小文档频率 2，500 次全批量梯度更新。
3. **校准**：在开发集上用 Brier 分数最小化选择温度参数，所有头都选为 0.5。
4. **阈值选择**：在开发集上从 {0.30, ..., 0.70} 中选择阈值 τ，优先优化精确路由匹配率，然后动作 F1，最后成本，最终选 τ=0.40。
5. **组合算法（Algorithm 1）**：
   - 候选集 Q = {o : p_o(x) ≥ τ}
   - 按 (p_o − τ)/c(o) 降序排序（性价比优先）
   - 在满足 |R| < 3 且累计成本 ≤ B 的条件下贪心添加
   - 最终按规范顺序 D, T, C, G, V 排列，后接 A

**执行机制**

- 操作用显式状态转换，而非从标签获得成功分数。
- 执行对顺序敏感：分解先写入子目标/字段需求，检索/代码消费这些产物，验证仅在存在前提证据或计算时才能修正候选答案。
- 若调用不可用操作，执行终止并产生类型化组件失败。

## 3. 实验设计

**数据集 / 基准构成**

共 504 个任务：216 训练、72 开发、108 保留测试、108 锁定词汇偏移挑战。三个工作负载：

| 工作负载 | 任务族 | 最小路由 | 机器检查行为 |
|---------|--------|---------|-------------|
| 数据分析 | 聚合、过滤求和 | C；D,C | 计算数值聚合；代码先于分解时会求错子集 |
| 冻结语料研究 | 事实、多跳、冲突源、中断 | T；D,T；T,V；G | 检索冻结记录、追踪证据链、选择最新证据、检索不可用时委托 |
| 文档处理 | 字段提取、发票对账、本地化日期、跨字段标识 | T；T,C,V；T,G；D,T,V | 解析字段、重算错误合计、规范化日期、合并验证字段 |
| 所有 | 直接字面量 | 无 | 直接返回显式提供的字面量 |

**对比方法（7个基线）**

- **直接（Direct）**：总是直接回答。
- **随机（Random）**：从任务标识符确定性选择 0–3 个操作。
- **关键字（Keyword）**：基于原始文本规则。
- **静态工作负载（Static workload）**：每个工作负载使用一条固定路由。
- **固定代理（Fixed agent）**：总是执行全部 5 个支持操作。
- **学习型单次（Learned one-shot）**：使用相同校准模型但最多选择最高概率的一个操作。
- **Oracle**：执行标注的最小路由，作为上界。

**关键实验对照**

- 学习型预算路由 vs. 静态工作负载路由（评估组合有效性）。
- 学习型预算路由 vs. 学习型单次路由（隔离组合的增量价值）。
- 标准测试集 vs. 锁定词汇转移挑战集（评估泛化稳健性）。

## 5. 实验数量与充分性

**主要实验**

1. 标准测试集主对比：9 个策略 × 108 任务 = 972 次执行（5 次重复取均值用于计时）。
2. 词汇转移挑战集主对比：9 个策略 × 108 任务 = 972 次执行。
3. 消融实验（4 组）：无校准、无预算执行、仅词特征、单操作限制——均在标准测试集上执行。
4. 阈值敏感性分析：τ 从 0.30 到 0.70 共 9 个取值，在两个评估分割上报告。
5. 训练规模实验：在 36、72、108、144、216 个训练任务下重拟合，观察标准/挑战成功率。

**充分性评估**

- **优点**：消融设计合理，特别是**匹配的单次学习对照**和**仅词特征 vs. 词+字符特征**的对比，能较干净地分离组合效果和字符级泛化效果；配对统计检验（bootstrap 区间 + 精确符号检验）增强了结论可靠性。
- **局限**：消融中"无校准"和"无预算执行"的结果与完整模型完全一致，作者自己也承认这两个消融在所选阈值下未激活边界条件，因此**不能将主效果归因于校准和预算机制**；训练规模实验因同一模板的重复值变体而未显示规模效应，但作者正确指出这是冗余而非样本效率的证据；所有实验基于有限的模板化套件，外部有效性有限。

## 6. 主要结论与发现

**核心结论**

- **标准测试集**：学习型预算路由达到 **100% 成功率**（n=108），优于静态工作负载和固定代理的 93.5%（配对 p=0.0156）；成本为 1.76 归一化单位，较静态路由的 3.08 低 **43%**。
- **组合的增量价值**：学习型单次路由仅为 56.5%，组合式路由高出 **43.52 个百分点**（p < 10⁻¹³）——这是组合多个操作带来实质性收益的最强证据。
- **词汇转移挑战集**：学习成功率降至 **75.9%**，落后于静态路由的 93.5%（p=0.0013）；但成本仍低 49.4%，且超过单次路由 34.26 个百分点（p < 10⁻¹⁰）。
- **失败模式的归因**：26 个挑战失败集中在 3 个任务族——12 个聚合任务（代码概率低于阈值，如 pC=0.192）、7 个多跳任务（保留检索 pT=0.882 但漏掉分解 pD=0.051）、7 个冲突源任务（保留检索 pT=0.985 但漏掉验证 pV=0.009）。这证明**失败是特定操作的词汇转换下召回不足，而非执行缺陷**。
- **路由质量的隐藏成本**：虽然标准测试成功率与 Oracle 相等，但学习路由在 77 个任务上调用检索（Oracle 为 49 个），精确路由匹配率仅 0.741，暴露了成功率无法反映的效率差距。

## 7. 优点

1. **可执行的机器检查评估**：与模拟或注释需求抽样不同，操作实际转换任务状态、产生候选答案并遭遇确定性失败条件，评估器精确检查结果，比 LLM 裁判或抽样成功率更客观可信。
2. **组合效应的干净隔离**：通过匹配的"学习型单次"对照，将组合多操作的增量价值从文本监督本身的效果中分离出来，实验设计合理且有说服力。
3. **词汇泛化与执行能力分离诊断**：锁定挑战分割区分了"操作执行"和"操作预测"的困难，并给出细粒度的按任务族失败归因。
4. **预算意识嵌入路由目标**：在成本与操作数量约束下做路由，而非事后优化，符合实际部署的约束条件。
5. **成本效益显著**：学习路由器在标准测试上以 1.76 成本实现 100% 成功（Oracle 1.50），在挑战上以 1.56 成本实现 75.9%（静态 3.08/93.5%），展示了轻量级路由器的可行空间。
6. **方法透明可解释**：浅层逻辑回归 + 词/字符特征，训练仅需 0.12 秒，便于复现、审计和失败分析。
7. **统计严谨性**：使用任务 bootstrap 2,000 次采样区间、精确符号检验，并区分了标准测试（可影响开发的内部结果）与锁定挑战（首轮结果不调参）。

## 8. 不足与局限

**实验覆盖局限**

- **规模与多样性有限**：504 个模板化任务（每族一个训练模板 + 不同数值变体）不足以支撑泛化结论；作者承认训练规模实验的平坦曲线反映模板冗余而非样本效率。
- **组件与真实世界脱节**：操作为确定性 Python 组件，非 LLM 调用、沙箱或网络工具；归一化成本是设计常量而非实际 token 或美元费用。
- **词汇转移类型狭窄**：挑战仅测试变形释义（paraphrase），未覆盖新领域、新语言、新工具或长交互轨迹。
- **外部有效性限制**：相比 SWE-bench、τ-bench、ToolSandbox、PlanningArena 等更真实场景，该基准规模更小、交互更简单。

**偏差风险与内部效度**

- **设计耦合**：最小路由标签与执行器语义是联合设计的，任务族仍编码了作者对"哪些操作应该有用"的假设。
- **开发泄漏**：标准测试集影响了基准和特征开发过程；挑战集虽锁定且首轮保留，但仍基于基准本体论知识构建，不能被视为独立确认。
- **消融不显著**：校准和预算消融结果与完整模型相同，无法验证这两个机制的实际贡献——该消融结论应解释为"边界未激活"而非"机制有效"。
- **阈值敏感性风险**：从标准测试分布选择的阈值在挑战中表现更差（τ=0.60 时挑战成功仅 69.4%），标准分布低估了泛化风险。

**应用限制**

- 100% 成功的退化置信区间不估计外部任务总体表现。
- 本地 0.17 毫秒延迟不可外推到含 LLM/工具调用的部署环境。
- 不执行搜索或观察条件的重规划，适应性弱于 ReAct、SPIRAL 等反思式方法。
- 作者明确声明：基准成功不是安全性或自主决策适用性的证据。
